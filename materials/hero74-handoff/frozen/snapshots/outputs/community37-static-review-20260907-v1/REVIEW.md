# 37 名英雄資料：第二輪靜態評估

日期：2026-09-07。用途：英雄設定／技能機制參考、資料品質與能力選擇評估。

## 結論

這份交接是有價值的「可追溯設計＋可編譯草稿＋待補機制」資料包，**不是可直接採用的正確模板映射資料集**。不能因大多數槽有待補項就判整份無用；也不能因 37 份基礎檢查通過就把映射当成標準答案。

上一輪只指出比利錯配不夠。本輪找到跨角色的行為摘要錯誤、隱含模板預設效果，以及把局部模板限制誤當整體能力缺口的風險。優先修正資料生成來源和能力檢索，不是增加訓練輪數。

本次未訓練、未推論、未重建／重跑編譯或 SimWorld、未解壓或重新驗證 ZIP、未改交接來源、未投稿或修改遊戲程式。僅讀檔、小型 CPU 靜態對照及寫本報告。

## 主要發現

### 1. 22 槽直線掃擊：目前行為摘要與實際去重規則相反

`recipes.mts:18` 共用 line helper 寫「交疊段可重複命中」。全部 22 槽附帶 runtime 的 delayed 卻為 `hitOncePerTarget: true`；現有 `templates/expand.ts` 的 line-sweep 展開亦明示去重。

影響：遊戲 EX、不知火舞 W、承太郎 W、洛克人 Q、卡比 W/R、詩乃 Q/R、伊莉雅 Q/EX、吉爾 R、美琴 Q/R、銀時 Q、埼玉 R、芙莉蓮 Q、刀太 Q/EX、炭治郎 Q/R、蘭斯 Q/R。

應修正摘要為分段推進、同次排程對同目標去重；仍須分別處理扇形／弧形／單束射線與分段圓形區域的幾何差異。不能把「需補去重」機械式保留在已具有該去重的槽上；更不能因此宣布整招等價。

### 2. 6 槽行進波：未交代繼承的終點範圍傷害

八神 Q、不知火舞 Q、洛克人 W、利姆路 Q、鹿目圓 Q、柯南 Q 都省略 `terminalBurst`，但使用 `inheritDefaults:true`。模板預設為 450 wc3u，附帶 runtime 展開為半徑 **8.25 GGD 單位**的 `finalEffects.damageArea`；行進各段半徑則為 1.83。

目前行為摘要只有「四段推進、各段獨立區域傷害」，漏了終點範圍追加，且主波也有 `hitOncePerTarget:true`。這是技能效果／影響範圍問題，不是特效美術微調。每招需核對原設計是否允許此終點效果。

不要直接填 `terminalBurst:0`：目前契約 min=100，零值不是已驗證的關閉方式。應先查允許省略預設、換合適模板或重用正式 effect 的合法編輯路徑。

本次只確認靜態存在的額外 effect，不以此推算實戰必然命中數或傷害。既有 traveling-wave 終點處理議題 #1094 是另一層 runtime 問題；不因該票存在就忽略本批的錯誤繼承／說明缺漏。

### 3. 13 槽連段：不是 N 次近戰命中機會的直接等價物

本批 `tpl-lock-combo` 都展開成 `dot` ＋施法者原地 `leap.onLand` 收尾。展開器定義的是 N 次週期傷害 **再加獨立收尾**，不是「N 段中的最後一段換成重擊」。實際支付次數還受 tick 量化、目標死亡與回合狀態影響，不能拿參數 N 冒充觀測命中數。

DoT apply 預設 `onCasterDeath=continue`；此編譯形狀沒有承諾每段重新檢查近戰距離或受控後取消。對桐人、承太郎等要求逐擊資格的設計，這不是單純傷害數字可調好的問題。

桐人 R 附帶基礎場景記錄 `damage:8`，EX 為 `damage:18`，兩者目標均死亡；這不是 16／20／27 刀完整序列的證據。事件數可能含其他傷害，不應倒算成技能專屬命中數。

桐人 EX 的附帶編譯起手 0.1 秒，R 為 0.5 秒；「EX 更長起手」也還未實現。這是比較所得，不是對未指定的最終起手數值做裁定。

### 4. 不要把 tpl-lock-combo 的 20 段上限當成引擎上限

現有程式存在已註冊的 `comboStrikes`；schema 可接受 `strikes` 或 `steps`，可選收尾、目標重新解析與施法者死亡停止。數量上限來自 `COMBO_MAX_STRIKES=DELAYED_MAX_COUNT=1000`。同時 `tpl-combo-finisher` 已標為 enabled，走 comboStrikes 的家族節奏設定。

**這只證明有可調查的重用路徑，不證明換模板就完成桐人 27 刀。** 家族參照是否合適、逐擊範圍中心、受控中止、總傷害預算、編輯器能否安全表達仍需驗證。

本包 `template-catalog.json` 只快照了實際使用的 **16 種模板**，不是全部可用能力。用這份子集訓練「不支援／要新增」標籤，会有誤拒絕或重造能力的風險。

### 5. 比利 Q/W/E/EX：映射和待補說明都要修

| 槽 | 原意 | 目前草稿 | 問題 |
| --- | --- | --- | --- |
| Q | 有上限時間的近身抓取與配對動作 | 單體物理傷害 | 未列具體抓取缺口，反而落到 base-mapping-needs-behavior-test |
| W | 消耗氣勢防禦，無氣勢仍有弱版 | 拖拉／摔投敵人 | 待補仍在談摔角動作，沒有對回防禦 |
| E | 前衝，首名敵人處停止 | 自身護盾 | 待補談指定友軍與氣勢，原槽沒有這項要求 |
| EX | 附近友軍護盾＋韌性 | 自身護盾＋攻速 | 缺韌性／友軍；待補還新增原文未要求的氣勢消耗 |

源頭位於 `recipes.mts:123` 附近的 moves 順序與 helper 選擇。應改源配方再由原工作流重建，不能只修 Markdown 而讓 JSON/ZIP 留舊答案。本次只回報，不代改。

### 6. 37 個被動全是替代底稿，不能當原意的正確映射

31 槽用普攻追加傷害、3 槽用受傷反擊、3 槽用免死標記。逐對原設計，這些都沒有完整實現所需的特定事件資源、資訊、姿態或再生邏輯。

例如助攻籌碼、精準閃避讀招、靜止蓄力、附近友軍交鋒不是 onBasicAttack；魔力抑制也不是附加傷害。資料包大多已明示這些差異，這是可用的「替代不等價」案例，而非必須刪除的無價值資料。

### 7. 其餘機制缺口應保留，但不直接當引擎缺能力

承太郎局部時停、利姆路吸收／複製、菜月昴單一快照的 R/EX 原子消耗、魯路修每目標成功一次、阿薩謝爾同來源詛咒反轉等規格有辨識價值。阿薩謝爾 R/EX 當前仍各只有單體魔法傷害，反轉是待驗收目標，不是已執行的分支。

先問三件事：模板是否選錯？既有 effects 能否組成？真的缺通用契約？只有完成該檢索及測試後，才可產生「不支援」或「需開發」的標準標籤。

### 8. 基礎測試與動作資料不構成機制通過證明

附帶 222 個逐槽場景的 assertion ID 僅三類：intent-accepted（222）、mana-spent（185）、observable-result（185）。沒有逐槽原設計要求的精確判定。這支持「可執行底稿」；不支持「原意正確」。本次沒有稽核所有 kit/replay 內部路徑，不能把這項統計說成整個測試系統只有三種測試。

185 支主動的 animation `replacesForMs` 一律 350ms，與各槽編譯 `castTimeSec` 不同。兩者不必強制相等（可能包含收招），所以只列為待畫面／事件對齊檢查，不據此直接判 185 支視覺壞掉。特效仍為最低優先。

## 如何用這批資料，而不把模型教壞

| 資料層 | 建議用途 | 限制 |
| --- | --- | --- |
| 身分、版本、完整 Owner 設計 | 參考／需求抽取候選 | 分開原作錨點與 GGD 創編；外部來源未重新核实 |
| HeroProject＋compiled JSON | 學格式／理解目前效果的候選 | 以 compiled 欄位為準，先修手寫摘要；不可貼「忠實原意」標籤 |
| 原意 vs 現有替代 vs 待補 | 語意差異／能力判斷評測候選 | 先校正上述錯誤和能力檢索；不是整批自動金標 |
| 直接 Owner→目前 template 映射 | 暫不進正向訓練集 | 會把時停→暈眩、複製→單擊、資源→普攻教成捷徑 |

保留 37 名原資料於參考區，與舊 train/validation/test 分開。若後續拿任何英雄原文或改寫進訓練，該英雄不得再聲稱「全新未見」測試；應按英雄完整技能組分組，跨槽依賴也一併隔離。

本輪 **核准訓練金標 0 筆** 是尚未完成金標驗收，不是資料有效率 0%。不估算 finetune 能提升幾個百分點：本次沒有模型對照實驗。
