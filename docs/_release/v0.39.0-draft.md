# v0.39.0 —— 🔗 **一個乾淨版本**：四條分支、一輪 CI、零次 `--admin`

> owner 2026-09-05 逐字：
> 「因為我已經準備要讓 codex 編輯器 執行一個 great plan，所以請你把**所有之前的合作包括你自己的 code 都整理乾淨一個版本**，
>  至於**視覺驗收屬於內容而非功能面**的不影響現在 code 合併就不考慮在這個範圍」

⭐ 這一版沒有新功能。它做的是**把今天以前散在四條分支上的東西合成一份**，
⛔ 而在那之前它們**互相擋著誰都合不進去**。

## ⭐ 一句話：三條**互相咬住**的閘，全部是「永遠不會綠」的形狀

| # | 閘 | 它擋住什麼 | ⭐ 為什麼它永遠不會綠 |
|---:|---|---|---|
| ① | `contract` → `editor:accept:release` → `skillforge:visual-advisory:check` | **每一張** PR | ⭐ 那是「**內容還沒被人看過**」的狀態 —— 它在等一個人，⛔ 而 CI 等不到人 |
| ② | `required_approving_review_count: 1` | 每一張 PR | GitHub 禁止批准**自己開的** PR，而這個 repo 的 PR 作者一律是 `adms` |
| ③ | `require_code_owner_reviews: true` | 每一張 PR（②降成 0 之後**仍然**擋） | 同上，⛔ 而它是**獨立的一格** —— 修了②不會連帶修③ |

⇒ ⭐ 三條都是 CLAUDE.md 的**失敗形態⑨**（一條永遠不會綠的閘，而它剛好在說「你還沒過」）。
⚠️ 而②③是我**昨晚才設下的**，今天第一次被真的用到就露出來了 ——
⭐ **一條每次都被 `--admin` 繞過的閘，與一條不存在的閘沒有差別。**

## 🔗 合併方式：一條整合分支，**跑一輪 CI**，⛔ 不是四輪

`required_status_checks.strict: true` 要求分支必須跟上 main
⇒ 每合併一張，其餘三張就要 `update-branch` ＋ **重跑一輪**（`unit` 單獨 26 分）
⇒ ⛔ **4 × 30 分 ≈ 2 小時，而且是序列的。**

⇒ ⭐ 四條合成 `integration/20260905`（**零衝突**），跑**一輪**。
合併用 **merge commit** ⇒ 四條分支的 commit 都成為 main 的祖先 ⇒ ⭐ 那四張 PR 自動標成 merged。

| 來源 PR | 內容 |
|---|---|
| **#1011** | ⭐ 視覺驗收**不是 code 閘**（owner 裁決）＋ `required_approving_review_count` 1 → 0 |
| **#1010** | ⭐ **握手完成 ≠ 已經訂閱** —— presence 推播扇出到一個還不存在的訂閱者 |
| **#994**（Codex） | ⭐ 逐技能隔離視覺審閱指紋 ＋ `brickId` 分組 ＋ **153 顆積木的 `editorForm` 收據** |
| **#1007** | 🧑‍🎨 社群英雄創作與審核發布的**規劃文件**（⛔ 分析，不實作，等 owner 確認） |

## 🧱 這一版真正的技術內容

### ① 🎨 視覺驗收降級成 PENDING（`ebf34f571`）

⭐ 那支腳本**自己早就這樣寫過**（`tools/skill-forge/check.mjs:69`）：
> Codex visual advisory freshness is a **human-image-review gate, not a machine/code failure**

⇒ ⛔ 那句話存在，而 `--release` 這條路徑沒有照它做。改成一律 `--machine-only`。

⭐ **機器驗得了的一項都沒少**：46 份收據 · Sim 預覽路由 · 視覺證據匯入 · 42/46 人審包 ·
46 張接觸表 · capability 收據 · Editor coverage 新鮮度 · VFX Forge · 貼圖×blendMode 契約 ·
Editor typecheck／全測試／production build。
⛔ 只有「advisory 指紋新不新鮮」降級，⭐ 而它**不會消失**（`skills:sync` 豁免表帶著到期條件追蹤，GH#986 的 F）。

### ② 🤝 握手完成 ≠ 已經訂閱（`52397702c`）

presence 推播在對方 socket **還沒被伺服器註冊**的時候就扇出 ⇒ ⭐ 送進空氣。
修法是在 Alice 撥號前插一個 heartbeat/ack 同步點 —— ⛔ 不是加 sleep。

### ③ 🧱 積木清冊換成**量值**（`099f5dc81` · `7ec4c86ad` · `e275c2853`）

⭐ 我那一欄的 `editorForm` 是**代理值**（我從 schema 推的），而 Codex 的收據證明
**153 顆裡有 36 格是錯的**。⇒ 產生器改成**收據優先**：收據一到，那一欄自己就變了，
⛔ 不需要有人記得去改。收據壞掉 ⇒ **擲例外**，⛔ 不讓一份壞掉的收據靜靜變成一個猜測。

### ④ 🔒 兩格 branch protection（`f1d1a4bef` · `25f391914`）

⭐ 有牙齒的三條**全部留著**：四個 status check 必須綠 · **PR 才能進 main** ·
`CODEOWNERS`（自動指派 reviewer ＋ `AGENTS.md` 分工的唯一機器可讀來源）。
⭐ 收緊回來的條件寫在**兩個檔案裡**（⛔ 不是我的記憶）：**第二個帳號能 review 的那一天**。

### ⑤ ⏱ 撥號的期限變成了整條連線的期限（`91cf16c65`，已在 main）

`WSWait = 30s` 根本用不到 —— 撥號用的 context 被拿去當**連線**的 context
⇒ 30 秒的等待預算在撥號成功那一刻就開始倒數。修法是把兩個 context 拆開。

## ⚠️ 誠實欄

- ⛔ **整合分支的代價是失去二分能力**：這一輪紅了我不能立刻說是哪一張造成的。
  ⭐ 緩解：四張各自的 CI 紀錄都留著，而它們的紅**已經逐條歸因過**。
- ⛔ **本版沒有部署**。部署協定第 2 步要 owner 勾（含今晚順手開的 18 張票要不要併進這一版）。
- ⛔ **`unit` job 第一輪紅了，而紅的理由與被測的東西無關。**
  ⭐ 量到：`906 passed | 0 failed`，紅的是 **3 個 `[vitest-worker]: Timeout calling "onTaskUpdate"`**
  —— `replay.test.ts` **單檔 508 秒**（單一測試 93s/86s/80s 的同步確定性模擬）⇒ worker 回不了 RPC。
  ⚠️ ⭐ 而 `Test Files 152 passed | 1 skipped (154)` 的 **152+1 ≠ 154** 才是唯一的訊號，
  ⛔ 而**沒有任何東西在看這個不等式**。⇒ 已開 **#1014**（⛔ 不當場修，第零守則⑧）。
  ⭐ 重跑該 job 後轉綠 —— ⚠️ 而「重跑就好了」⛔ **不是修好了**，那張票要的是那條不等式的閘。

- ⛔ **視覺驗收沒有做完，它是被刻意排除的** —— owner 的裁決是「屬於內容而非功能面」，
  ⭐ 而 `skillforge:visual-advisory:check` **仍然存在**，只是不再擋 code 合併。
