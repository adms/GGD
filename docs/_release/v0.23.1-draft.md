## 2 · 這一版做了什麼（照主題，⛔ 不照 commit 順序）

### A · 地形終於是地形：位移不再穿牆，飛行是唯一的合法例外（#487 · #490）

owner 12:28：「我發現**有許多地圖的牆 瞬移過去** 例如**無限城**等」。

量到的（突變輸出，⛔ 不是推測）：把 `resolveLandingPoint` 換回舊行為 ⇒
**七張 graybox 場地 × 兩種位移 = 14 條全部穿牆**，落點越到牆的另一側 2.60–5.60。

根因是「每一層都對，只有組合是空的」：`relaxBody` 保證的是**終點**不在牆裡，
⛔ 不是**路徑**沒穿過牆。graybox 的牆只有 2 單位厚，身體半徑 0.6 ⇒ 牆另一側
1.6 單位外的落點完全合法。**地形是那張圖的全部設計，而位移讓它整個不存在。**

- 三種位移只修兩種：`dash`／擊退**滑行**走 `moveWithCollision`，本來就撞得到牆 ⇒ **一個字都沒改**；
  `leap`／擊飛（拋物線）與 `blink`（真瞬移）⇒ 修。
- 機制而非 if：`sim/map/lineOfSight.ts` 的形狀分派長出 `grow` 參數（一個 kind 分派兩個消費者），
  新 `sim/movement/wallBlock.ts` 做 14 次固定二分搜尋 —— ⛔ 無 rng／無時鐘／無三角函式／無 `**`。
- 落點合法性仍然只有**一個住處**（`resolveLandingPoint`），三個入口共用。

⭐ **飛行**（#490，owner 15:57 逐字定案）：「**飛行就是可以穿牆 跟 無視所有人碰撞
但地圖標界還是要遵守**」。

| | 飛行時 | 實作 |
|---|---|---|
| 牆體 | ✅ 穿得過 | `flightIgnoresObstacles`（授予缺這格 = true） |
| 單位推擠 | ✅ 無視所有人 | `flightIgnoresUnits`（2026-07-30 起 `MovementSystem` 已在做） |
| 地圖邊界 | ⛔ **必須遵守** | `flightStaysInBoundary`（缺這格 = **true**，極性刻意與上面兩格相反） |

判準綁在 `flightIgnoresObstacles` ⛔ 不是 `isFlying` —— 一份 `ignoreObstacles: false`
的授予是「飛起來但仍然撞牆」，那就**走不過去也不准瞬移過去**，兩個系統**構造上**一致。
`policyFor(rules, mode, flying)` 的第三個參數**必填**（⛔ 沒有 `= false` 預設），
下一個呼叫端不可能「忘了想」而默默拿到 allow。

### B · 上架清單：一鍵清理變身態（#486）

白名單住 `data/curation/whitelist.json`，在 `.gitignore` 裡 ⇒ **`git push` + deploy 碰不到它**。
本機已經是 49、線上仍是 59 ⇒ 只能由營運端動手，所以是**一顆後台按鈕**。

- 名單從 `transform.role === "alternate"` **推導**，⛔ 不是手寫那 10 個 id ⇒ 以後新增的變身英雄自動適用。
- 兩段式：第一顆按鈕**預覽**（逐位列出名字 + id），第二顆才寫入；伺服器端再算一次並比對，不一致回 409。

  而「空的」與「已經乾淨了」長得一模一樣。⇒ 那是**兩個名詞的關係**，⛔ 不是分別檢查每一半。
- 閘接進既有的 `legacyevict` 漏斗：**存不進去**（Save/PUT/bulk/舊 ops bundle 還原）

  剔除後會變成零英雄 → 整條規則跳過並 `slog.Error`。
- ⭐ **變身不會壞**（已驗證）：`allowsChampion` 的四個出貨呼叫點全在「選／生成英雄」那條路；
