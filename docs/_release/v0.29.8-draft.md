## ⭐⭐ 頭條：「今天第五次同型 EACCES」的根因是**機械的**

owner 2026-08-27（逐字）：

> 「今天**第五次**同型 EACCES —— content:build 直寫一個 444 產物而沒自解鎖。走 genrun：
>  **請你尋找污染源、根因有哪些，再來開票提改善計畫**」

量到的（⛔ 不是假設）：

| | |
|---|---|
| `package.json` 的產生器類 script | **40** |
| 其中**寫隔離區產物**的 | 26 → ⭐ 補完推導後是 **41** |
| ⭐ **自帶解鎖的** | **0** |

解鎖只發生在**兩個地方**：`sync.mjs`（`skills:sync` 內）與 `scripts/genrun.sh`。
⇒ ⭐ **任何人打 `pnpm content:build` 都必然 EACCES** ——
⚠️⚠️ 而 **CLAUDE.md 自己在「硬性技術約束」裡叫人打它（3 次）**、`spec:build`（2 次）。

⭐ **規則書指向的指令是壞的。** 這就是「第五次」的原因 —— ⛔ 不是誰記性不好。

### ⭐ 而閘一上線，立刻抓到我自己漏的 15 支

我第一版用正則包了 26 支。閘（**從出貨推導**）當場紅並指名 `mana:audit` · `docs:readme` ·
`contract:numbers` · `treasure:csv` … 補完之後 `spec:build` **還是 EACCES**
⇒ 加**第二個獨立推導**：⭐ **存在 `X:check` 的那些**（`--check` 逐位元組比對的前提就是有產物）
⇒ 又抓到 **10 支**。⇒ 最終 **41 支**。

⚠️ 而 `--step` 這個精準度**買不到正確性**：`pnpm spec:build` 寫的檔在 `sync-io.json` 掛在
**`skillremake:json`** 名下 ⇒ `unlock --step spec:build` 解不開它 ⇒
⭐ **EACCES 照樣發生，而使用者剛剛才「照規矩走了 genrun」**。⇒ 改成解鎖全部。

## 🖼️ owner 回報的兩件事

### ①「連續圖片全部都看不到」—— ⛔ **不是圖片沒傳，是每一張都吃 401**

| 假設 | 查證 | 結果 |
|---|---|---|
| 圖片沒傳完整 | 25 個序列逐目錄比 `ls` vs `git ls-files` | ⛔ 不成立（**檔數逐目錄相同**） |
| 容器讀不到 | compose 的 `..:/srv/repo:ro` | ⛔ 不成立 |
| 串接沒做 | `middleware.mjs:109` 的 handler | ⛔ 不成立 |
| ⭐ **身分** | `needsAdmin("/__review/frame")` → true | ⭐ **就是它** |

⭐ `<img src>` 是**瀏覽器的圖片載入**，⛔ 不是 `fetch()` ⇒ #796 的攔截器**結構上碰不到它**。
⚠️ 而清單走 `fetch()`（是好的）⇒ 頁面照樣寫著「N 張連續圖片」 ⇒ ⭐ **壞掉跟正常長得一模一樣**。

### ②「回合 LAG」—— ⭐ 量到了，⛔ 而**兩個嫌疑犯都是錯的**

分母 **3,194 幀**：`draw 2.70ms(77%)` · `camera 0.40(11%)` · **`vfx 0.30(9%)`** · 其餘 ≈3%。
⇒ ⭐ `vfx` 整段砍到 0 也只省 **0.30 ms** —— **數學上不可能修好 lag**
（與 owner 說的「關掉之後還是 lag」逐字一致）。真正的成本：**≈46% 填充率 ＋ 54% draw-call**。

### ⛔⛔ 而量的過程中撞到一個**比 lag 嚴重得多**的東西

**HEAD 當時完全進不了遊戲**（#760 當日回歸）：**空的 view-gated 集合 Colyseus 根本不送**
⇒ 客戶端讀到 `undefined`（⛔ 不是 `size:0`）⇒ 選人畫面死結 ＋ 每幀擲例外。
實測從 connecting 一路打到 **Round 3**。
