# Task #115 — model LOD tiers, and the setting that now swaps the file

Measurement record for the two halves of #115. The live data is
`content/assets/models/_lod.json` (regenerated by the tool, read by the client);
this file records the numbers and, more importantly, the **network observation**
that the quality setting genuinely changes which `.glb` is downloaded.

## 1. The trap, verified first

`RenderParams` (apps/client/src/render/QualityController.ts) carried
`resolutionScale`, `particleDensity`, `shadows`, `drawDistance`, `antialias`,
`fpsCap`, `damageNumberCap`, `combatTextScope` — **and no model dimension at
all**. `AssetManager.load()` took the model doc's path verbatim. So the
dropdown was not decorative, but "Low" and "High" fetched and drew byte-identical
geometry. There was no LOD file, no resolver, and no `lod` anywhere in
`apps/client/src` or `packages/shared/src`.

## 2. Where the payload actually is

Measured across all 163 shipped `.glb` (36.53 MB):

| category | MB |
|---|---|
| embedded images (231 PNG + 4 WebP) | 12.15 |
| vertex attributes | 9.00 |
| animation samplers | 7.20 |
| indices | 1.13 |

Geometry is **28%** of the bytes. A geometry-only decimation — which is what
"generate LOD decimations" sounds like — would therefore have left most of the
payload untouched. Each tier pulls three levers instead: QEM decimation,
PNG box-downscale, and (on `small`, only where a model doc's `clipMap` defines
which clips are reachable) dropping unreachable animation clips.

## 3. Generated tiers — 87 match-relevant models

`python3 tools/lod-gen/gen_lod.py`. Champions, arena decor, guardians,
hero/intermission props. Deliberately NOT the 74 unreferenced w3x effect
remnants (audit #61).

| tier | bytes | vs base | triangles | vs base |
|---|---|---|---|---|
| authored | 27.15 MB | 100% | 139,701 | 100% |
| `-mid` | 19.90 MB | 73.3% | 74,786 | 53.5% |
| `-small` | 13.58 MB | 50.0% | 40,716 | 29.1% |

Disk cost: **+33.48 MB across 174 new files** (`content/assets/models` 33 MB → 67 MB).
That is the honest trade — LOD buys wire bytes and GPU work per *client*, and pays
for it once in repo/deploy size.

Per-model examples: `mage.glb` 1010 K → 890 K (mid) → 414 K (small);
`knight.glb` 6,952 → 3,812 → 1,936 tris; `heroshana.glb` 235 K → 166 K → 117 K.

**Where reduction falls short of target, and why.** The QEM pass refuses to
collapse any edge touching a topological boundary, which is what preserves UV
seams and silhouette borders. Several w3x imports are stitched from small
disconnected geoset patches that are nearly all boundary, so they under-reduce
(e.g. `guardian_skeleton.glb` reaches only 78.6% of its bytes at `small`,
because 42% of that file is animation it is not allowed to drop — it has no
model doc `clipMap`, so nothing tells the tool which clips the runtime can
reach). Reported rather than papered over.

## 4. Proof the setting changes the fetch

Run in the browser against the live dev server on :39527, driving the **shipped**
seam — `lodTierForPreset(preset)` → `setModelLodTier` → the real `AssetManager`
on a real WebGL `Renderer` — and reading `performance.getEntriesByType("resource")`,
i.e. what the network actually saw. Model sets are the budget report's own
per-screen lists.

| screen | preset | tier | requests | files swapped | payload | on-screen tris |
|---|---|---|---|---|---|---|
| combat-dota | high | high | 10 | 0 | **724,173 B** | 112,796 |
| combat-dota | medium | mid | 10 | 10 | **515,073 B** (71%) | 61,828 |
| combat-dota | low | small | 10 | 10 | **260,304 B** (36%) | 31,412 |
| combat-castle | high | high | 10 | 0 | 615,757 B | 97,446 |
| combat-castle | medium | mid | 10 | 10 | 446,256 B (72%) | 53,430 |
| combat-castle | low | small | 10 | 10 | 214,469 B (35%) | 27,098 |
| intermission | high | high | 15 | 0 | 1,068,076 B | 36,955 |
| intermission | medium | mid | 15 | 15 | 791,961 B (74%) | 20,211 |
| intermission | low | small | 15 | 15 | 506,065 B (47%) | 10,885 |

Recorded URLs at `low` are literally `hex/hex_water-small.glb`,
`hex/tower_blue-small.glb`, `champions/knight-small.glb`, …; at `high` they are
the authored files. **A match's model payload at the low preset is 36% of the
high preset's.**

Three properties held in every run:

* **request count is unchanged** (10 / 10 / 10) — no 404 probe, no fallback
  round trip. That is why resolution goes through a manifest rather than
  try-then-fallback.
* **zero failures** — every resolved path returned a real container.
* **every URL carried `?h=<contentVersion>`**, so the tier files ride the exact
  same `immutable` cache story as the authored ones (nginx `map $arg_h`). They
  are not a fresh set of revalidating requests.

A rendered frame (real WebGL, idle pose, 1 world-unit framing) shows
`knight.glb` at all three tiers side by side: the silhouette and the red cape
read identically at `mid`; at `small` the helmet is visibly faceted into a box
and the cape is a coarse cone. It still reads as the same armoured knight at
combat-camera distance, but `small` is an aggressive tier and should be judged
in a real match before being made anyone's default. `heroshana.glb` keeps its
texture atlas intact at `small` (red hair, uniform) — the PNG downscale did not
break UVs.

## 5. Design decisions worth knowing

* **The tier follows the fixed preset, and "auto" stays at `high`.**
  `AdaptiveManager` re-rungs on a seconds-scale timer; resolution and particle
  budgets are per-frame GPU knobs and are free to move on that clock. A model
  tier is not — changing it evicts the AssetContainer and issues a network
  fetch, and a ladder oscillating around a threshold would issue them
  repeatedly, mid-fight, on the device already struggling. Where it genuinely
  pays is first boot: `autoDetectPreset` puts a weak/touch device on "low"
  before anything is fetched.
* **`AssetManager`'s container cache is keyed on the RESOLVED path.** Keying on
  the authored path would return the previous tier's container after a settings
  change and the setting would silently do nothing again — the exact #115
  failure mode. There is a test for precisely this.
* **A tier change applies to models loaded after it.** Already-adopted meshes
  keep their tier until the scene is rebuilt; swapping a champion's mesh under a
  playing animation is a visible pop, and the next round rebuilds anyway.
* **Failure is always "no swap", never a broken load.** No manifest, an unknown
  path, or a tier that was never generated all resolve to the authored file. A
  `small` request for a model that only has `mid` is served `mid`.
* **The copyright gate still covers the tiers.** nginx's
  `location ^~ /content/assets/models/imported/` is a prefix match, so
  `imported/*-mid.glb` and `*-small.glb` are gated identically to their
  originals (#127). No new rule needed, and nothing leaked.

## 6. Tooling

`tools/lod-gen/` — pure Python 3 stdlib, no new dependencies and nothing
downloaded (`glb.py` glTF reader/repacker, `png.py` PNG codec + box filter,
`decimate.py` QEM half-edge collapse, `gen_lod.py` driver). Re-run it after any
model replacement; it rewrites `_lod.json` in place and is idempotent.

`tools/model-budget/emit_report.ts` now skips `-mid`/`-small` files when walking
the tree. Without that its corpus would have gone 203 → 377 rows and every tier
file would have been classified `role="unused"`, turning the 模型預算 page's
unused list — the thing it exists to make actionable — into noise. Surfacing the
per-model tier saving as a column there is a #99 enhancement, not done here.
