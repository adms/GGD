### 完成條件

1. 兩批共 74 名／444 槽均保留已接受的角色內容，透過現有編輯器自動匯入／生成並完成投稿；創作、修改、保存重開、預覽與續編入口實際可用，不依賴逐名手工修補 JSON 或繞過 UI 的私人流程。AI 關閉時基本流程仍可用。
2. 管理員審查的就是發布版本；通過後，74 名在同一預定上線服務正常上架為正式英雄。基本所有權、防覆寫、下架／回退及既有獨立版本與歷史保留；不能為縮小驗收而放棄這些核心功能。
3. 實際編輯器與遊戲流程可用，角色可選、可進場，技能、機制及特效無阻止使用的重大失效。編譯通過或隔離平台的名單不能單獨當成正常上線證明。

### 任務拆分與平行工作（Owner 2026-09-09）

- 開工先把剩餘 MVP 工作拆成有明確輸入、交付物、責任檔案／服務、完成條件與依賴的短任務。已有獨立子任務時優先平行，沿用現有票據、程式與收據，不為填滿工作流而新增需求或重做已完成事項。
- 可按需要分成三條子工作流：**內容與編輯器主流程**、**後台審查與獨立版本**、**遊戲載入與必要功能確認**。這是分工方向，不代表三條都必須重新實作或重跑；只啟動目前確實有工作的部分，實際並行數依可用資源調整。
- 主線負責任務依賴、共用版本、變更整合、集中驗收、進度文件及對外 commit／push。每個子任務交付改動或發現、適用版本、必要證據與未解阻擋；未發現問題也應結束，不延伸成研究或美術微調。
- 使用本任務的子代理或隔離工作目錄；不擅自把任務派給其他既有 session、不替 Owner 建立新的獨立任務。共用來源、相同檔案、Git 索引／分支、同一服務、資料庫與投稿狀態只能有一個寫入者；需要並行寫入時先隔離，各子流不得自行 push、合併或發布共同服務。
- 有依賴的步驟保持順序：實作整合與版本確定後才重建受影響包，再投稿、審查與發布。正式共同服務的寫入與最終驗收由主線串接；獨立子流可先處理不依賴該步驟的工作，不把「平行」當作繞過審查或用不同版本各自發布的理由。
- 完成的子任務立即回收；若沒有真正可獨立的工作就由主線直接完成。不要建立監控、排程或額外工具來管理這項分工，也不讓等待中的子流反覆查詢或重跑測試。
