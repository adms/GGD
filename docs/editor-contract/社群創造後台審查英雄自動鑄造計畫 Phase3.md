# 社群創造後台審查英雄自動鑄造計畫 Phase 3

**狀態：Owner 於 2026-09-11 啟動；併入 [完整交付目標](社群創造後台審查英雄自動鑄造計畫最終執行版.md)，進行中。**

本階段保存進階品質驗證、視覺完善與可選 AI 能力。原計畫來源在 [歷史附錄](../額外事項待確認.md) §5.2–5.3、§11 的 AI 策略、§12、§15.2；助手後來追加的研究／驗收則另外標明，不冒充原始需求。

## 本輪執行界線

- P3-01 至 P3-05 全部啟動，但只沿既有能力補會影響完整交付的缺口。
- 不新增錄影專案或把全量逐 tick 回放倒掛成 126 名上架門檻；既有確定性測試、服務往返與受影響案例足以回答的項目不重跑。
- 效能基準採平板、iPad mini A17 Pro 近似等效能、30 fps；排除手機，不要求額外 A17 Pro 真機認證。
- 視覺與 AI 都不得阻斷 AI-off 的編輯、投稿與發布路徑；只修會使機制或特效失效的重大問題。

## 不自動收入本階段

新模板、新機制標籤、引擎／市場／地圖／多人共編等新功能，以及角色重設計，仍在 [額外事項待確認](../額外事項待確認.md) 等待具體裁決。不能藉「Phase 3」把原本未核准的設想包成已同意工作。

## 執行限制與結束

P3-01 至 P3-05 已核准；使用既有證據並補足可回答指定問題的最小驗收。沒有新改動或重大失敗，不重跑已通過案例；不能只因數字、畫面或覆蓋率還能更漂亮就延長工作。

每項完成即記錄證據與版本；缺 Main 專屬整合、簽章或發行基礎設施時，用 coordination packet 精確交接，不用假資料補通過。

P3-01 至 P3-04 已依 Owner 縮限完成：沿用仍有效的視覺、確定性、故障與效能證據，只修本輪實際發現的 Hero Forge PBR 冷啟動阻擋，不新增錄影、全量回放或美術微調。P3-05 已把固定模型 manifest、驗證／續傳下載、桌面 IPC、硬體政策、llama runner、216 案例品質 gate 與封裝 gate 接入目前分支；核准模型在 macOS Metal 與 Windows CUDA 的 E8 收據及可發布 runtime artifact 尚未提供，所以 manifest 正確維持 `released=false` 與 `LOCAL_AI_E8_GATE_PENDING`，AI-off 路徑不受影響。
