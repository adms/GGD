## 啟動條件

- MVP 的 74 名／444 槽創作、投稿、審查、正式上架與遊戲使用完成。
- Owner 明確指示開始 Phase 2 或其中指定項目；MVP 完成不會自動啟動本階段。
- 開始時只核對核准項目的既有實作與有效收據，補真正缺口；不做全專案盤點或重跑所有測試。

## 與 MVP 的分界

MVP 仍須有真正可操作的創作、修改、保存重開、投稿、管理員審查與上架流程。基本所有權、防覆寫、審查綁版及獨立版本回退也不能延後；若它們已實際失效並阻止 MVP，現在就屬重大故障。

此處延後的是完整異常情境、產品操作完善與桌面發行證據，不是允許 MVP 遺失資料、越權發布或用手工搬 JSON 代替編輯器。已有能力保留、已有有效驗收沿用；不為分期拆掉產品。

## 執行限制與結束

只執行 Owner 核准的列，沿既有程式、模板、版本制度及 PR／開票規則完成。只驗受影響情境，不自行擴成所有角色、平台和網路狀態的組合。成本未估，不為現在填估算而另做研究。

核准項目完成後交付結果、未完成條件與版本，停止本階段；[Phase 3](<社群創造後台審查英雄自動鑄造計畫 Phase3.md>) 仍需另行明確啟動。
