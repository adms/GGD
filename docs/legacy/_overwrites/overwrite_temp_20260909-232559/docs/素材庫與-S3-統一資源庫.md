> 素材**查詢**的入口在 CLAUDE.md 第一·四之一；這一份講的是**存放與對帳**。

## 一、三個住處，判準是「**誰會讀它、怎麼讀**」

⛔ 分界**不是副檔名**，⛔ 也不是目錄。

| 住處 | 放什麼 | 判準 | 形狀 |
|---|---|---|---|
| **git** | 解析／轉換**程式** · 英雄與技能**設定 JSON** · 版本清單 · SHA-256 · 文件 | ⭐ **有人會讀它的 diff** | 一般檔案 |
| **S3 `assets/`** | ⭐ **要對外服務**的成品：icon · 3d model · voice · music | ⭐ **網站要能拿單獨一顆** | **逐檔可定址** `assets/<sha[:2]>/<sha><ext>` |
| **S3 `legacy/`** | 半成品 · 原始素材 · 大型解析傾印 | 只靠雜湊驗、⛔ 讀不了 diff；⛔ **不對外開放下載** | tarball 封存（分段可以） |

⭐ **一句話判準**：**一個位元組如果只能靠雜湊驗、不能靠 diff 讀，它就不屬於 git。**
⭐ **第二句**：**一個位元組如果網站要單獨拿它，它就不能只住在 tarball 裡。**

## ⛔⛔ 二、`s3_existing` 這個字騙過人 —— 它**不代表** S3 上有那個物件

2026-09-09 量到（Codex 交接 `outputs/` 時）：`coverage.jsonl` 把 **279,523 檔**標成 `s3_existing`。
⭐ 而逐筆讀 `location` 之後，它的意思是：

```json
{"coverage": "s3_existing",
 "location": {"kind": "s3_archive_member",
              "manifest_uri": "s3://…/legacy/…/manifest.json", "member": "…"}}
```

⇒ ⭐ **「這個檔的 sha256 被列在某個 tarball 的 manifest 裡」**，⛔ 不是「S3 上有這個物件」。

| 用途 | tarball 夠不夠 |
|---|---|
| **封存／回復** | ✅ 夠 —— owner 的裁決逐字是「不會對外開放下載使用」 |
| **網站拿一顆 icon** | ⛔ **完全不夠** —— 要先把 49 段全下載、拼起來、解壓 |

⚠️ ⭐ 而 **S3 沒有任何大小限制逼你切段**（單物件上限 5 TB，multipart 是傳輸層的事）。
分段是從 git 的 100 MB 上限帶過來的習慣，⛔ **那個限制在 S3 上不存在**。

⇒ ⭐ **判準：讀到「已上傳」時，先問「它是一個物件，還是某個封存的成員？」**

## 八·四、⭐⭐ 架構定案（owner 2026-09-09）—— **CF 接原站，S3 是純備份**

owner 逐字：

> 「不對，是跟往常一樣 **CF 直接接原站 ggd.adms.ai** 就好了 根本沒差，而 **S3 變成純備份**了」

⇒ ⭐ **這一句作廢了下面第八·五節的整個前提**（那一節量的是「玩家直接從 S3 拿」的路）。
⛔ 那兩個缺口（正式站沒有 AWS 憑證 · bucket 沒有 CORS）**不再是缺口** ——
⭐ 在這個架構下它們**本來就不該有**：S3 是備份，⛔ 不是給瀏覽器讀的。

### ⭐ 素材今天怎麼到玩家手上

```
玩家 → CloudFront（邊緣快取）→ ggd.adms.ai（Mac mini · nginx）→ content/assets/
```

⭐ 客戶端的網址**一個字都不用改** —— 它送的仍然是 `/content/assets/…?h=<contentVersion>`，
而 nginx 早就把帶 `?h=` 的回應設成 `immutable`（`map $arg_h $content_cache`）
⇒ ⭐ CF 的命中率會很高，⛔ 而且**不必清 CDN 快取**（內容版本一變網址就變）。

### ⚠️ 而這個架構有一個 MOBA 特有的決定要先做

CF 擺在 `ggd.adms.ai` 前面 ⇒ **所有流量**都經過它，⛔ **包含 Colyseus 的 WebSocket**。
⭐ CF 支援 WebSocket，⛔ 但它多一跳 —— 而這是 30/60fps 的即時對戰。

| | 做法 | 代價 |
|---|---|---|
| **A ⭐ 建議** | CF 只快取 `/content/*`（一條 behavior），其餘 `Managed-CachingDisabled` 直通 | ⭐ 素材有 CDN、對戰延遲不變；**不用改任何程式** |
| **B** | 對戰走另一個子網域繞過 CF | 要改客戶端連線位址 ＋ 一張憑證 |

### ⛔ 這個架構**不需要**的東西（⭐ 寫下來免得下一輪又做一次）

| | 為什麼不需要 |
|---|---|
| bucket 匿名唯讀 / OAC | S3 不面向瀏覽器 |
| bucket CORS | 同上 |
| 正式站的 AWS 憑證 | ⭐ 只有**上傳備份**要它，⛔ 而那在開發機上做 |
| `asset-cdn.baseUrl` | ⭐ CF 在原站前面 ⇒ 客戶端的相對路徑**本來就經過它** |
| 簽署網址 API（#1124 第 1 項） | 素材由原站供 |

⭐ 而 `asset-cdn` / `asset-downloads` 兩格開關**留著**（出貨都是 `false`）——
⛔ 零成本（消費端只是一個 `return null`），⭐ 而它們是「哪天素材要從別的網域供」的逃生口。

## 八·五、⛔ 玩家端今天**還拿不到** S3 —— 兩個量到的缺口（2026-09-09）

⭐ owner 的交接文件（第六～九節）定的路是**簽署網址**，⛔ 不是 CloudFront：

>  後端依已核准索引，解析精確 S3 object key。後端產生**短效 GET 簽署網址**，例如 15 分鐘。」

⭐ 而 owner 2026-09-09 補了一句，⭐ 它讓 CloudFront 更不必要：

> 「我的 S3 已經是放**台北機房**，應該會比 CF 快才對」

### ⛔ 缺口①：正式站那台**沒有 AWS 憑證與工具**

在 mini 上實跑（2026-09-09）：

```
AWS_PROFILE=vibe-coding AWS_REGION=ap-east-2 aws sts get-caller-identity
  → zsh: command not found: aws
~/.aws → ⛔ 不存在 · /opt/homebrew/bin · /usr/local/bin → 0 個 aws
```

⇒ ⭐ **後端今天簽不出任何網址。** ⛔ 不是權限不足，是工具與憑證都不在那台機器上。
⚠️ ⭐ 這一項**只有 owner 做得到** —— 憑證怎麼進正式站是一個**安全決策**
（環境變數？IAM role？掛載？），⛔ 而把開發機的憑證複製過去違反第八節。

### ⛔ 缺口②：bucket **沒有任何 CORS 設定**

| 測 | 結果 |
|---|---|
| `OPTIONS` 預檢（`Origin: https://ggd.adms.ai`，GET／HEAD，`Range`） | ⛔ **HTTP 403** |
| 簽章 GET ＋ `Origin` ＋ `Range: bytes=0-99` | ⭐ **206** · `Content-Range` · `ETag` **都在** |
| 回應的 `Access-Control-*` | ⛔ **一個都沒有** |

⇒ ⭐ **兩件事分開**：`Range` 本身可用（串流／續傳的底層在），
⛔ 而**瀏覽器 fetch 會被擋**（沒有 `Access-Control-Allow-Origin`）。

**缺什麼**（⛔ 本文件不改它 —— owner：「目前授權未包含修改 bucket CORS」）：

| 需要 | 值 |
|---|---|
| `AllowedOrigins` | `https://ggd.adms.ai`（⭐ 建議連 `https://test.adms.ai`） |
| `AllowedMethods` | `GET` · `HEAD` |
| `AllowedHeaders` | `Range` |
| `ExposeHeaders` | `ETag` · `Content-Range` · `Content-Length` |
| `MaxAgeSeconds` | 3000 |

### ⚠️ 一個量到但**證明不了**的數字

同一顆 149 KB 的檔，從 owner 這台量：站台 **65–80 ms** · S3 台北 **89–175 ms**。
⛔ 而量的人**就在 mini 的區網裡** ⇒ 這證明不了遠端玩家的情況。
⭐ 真正的比較要從**外網**量。
