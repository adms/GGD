## 1. ⭐ 最重要的發現：「讀 0」的根因⛔ 不是沙盒缺 `docs/_daily`，是 **`os.tmpdir()` 是 symlink，探針的前綴比對整個失明**

票文的假設：「沙盒沒有 `docs/_daily/*.md`（或探針對 bash 的 `cat`/glob 讀不到）」。⛔ 兩個都不成立 —— 量到的：

| 問 | 量到 |
|---|---|
| 沙盒有沒有 `docs/_daily/2026-09-06.md`？ | **有**（`cp -Rc` 整棵 clone，19 份日期帳本全在） |
| `board-roll.sh` 讀帳本的是誰？ | `python3 - … <<'PY'` 的 heredoc ⇒ `sitecustomize.py` 探針**蓋得到** |
| 那探針為什麼一筆都沒記？ | `os.tmpdir()` 回 `/var/folders/…/T`（**symlink** → `/private/var/…`）。`trace.mjs` 把這條當 `GGD_TRACE_ROOT` 給探針；而子行程的 `getcwd()` 是真身 `/private/var/…` ⇒ `os.path.abspath()` / `path.resolve()` 出來的每一條路徑都不以 `/var/…` 開頭 ⇒ `p.startswith(_root)` **永遠 false** |
| 為什麼以前量得到？ | GH#1003（`f2055ae4e`，2026-09-05）把暫存根從 `/private/tmp`（實體路徑）改成 `os.tmpdir()`。改之前 board:roll 讀 34,598；改之後讀 0。⭐ 而 #1003 的閘只驗「不再寫死 /private」，⛔ 沒有一條閘問「探針還看得見嗎」 |

實測（在沙盒裡）：
```
py cwd:   /private/var/folders/nh/…/T/ggd-syncgraph-sandbox
node cwd: /private/var/folders/nh/…/T/ggd-syncgraph-sandbox
tmpdir(): /var/folders/nh/…/T        realpath: /private/var/folders/nh/…/T
```

⇒ 這是 CLAUDE.md「一把只驗過單邊的尺」的形狀：mtime 差分（寫）與探針（讀）是兩把尺，**其中一把瞎了而另一把還在說話** ⇒ 「讀 0 寫 1」讀起來像「它真的不讀東西」。⭐ Scope ② 的「空量測拒寫」正是為這個而存在 —— 而它今天就抓到了真的病。

**修法**（`trace.mjs`）：`SANDBOX = realpathSync(...)`（沙盒還沒建時 realpath 父目錄再接名字）。⛔ 沒動 hooks（不在柵欄；而且從 trace 這一頭修一次就兩支探針都對了）。

## 2. 做了什麼（Scope 三件 ＋ 一件根因）

| Scope | 做法 | 住處 |
|---|---|---|
| **① 單步 ⇒ 只動那一步（聯集）** | `--out` 已存在、且它記的 `script` ≠ 這次量的 ⇒ **單步模式**：`mergeStepsInto(existing, traced)` —— reads/writes 取聯集、路徑先 `canon()`（日期戳→glob）、reads 只留有人寫過的（glob 用消費端同一套 `matchesGlob`）、`ms` max / `ok` and / `readCount` max；**其他步驟是同一個 reference** ⇒ 序列化逐位元組相同。戶籍裡沒有的新步驟插在 `existing.chain` 的順序位置（沒有就接在最後）。頂層其他欄位（`passes`、`mergeNote`）原封不動。同一個 script 重量 ⇒ 仍整份覆蓋（兩趟 → merge-io 那條路的前半，行為不變） | `merge-io.mjs`（新 export `mergeStepsInto` / `canon` / `DATE_FAMILIES`；CLI 包進 `isMain`，import 它沒有副作用 —— 聯集邏輯**只有一個住處**）· `trace.mjs` 寫回段 |
