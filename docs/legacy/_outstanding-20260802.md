## 6. 這一輪我判斷錯、值得記下來的

1. **「商店/介面消失是骨架後果」——錯。** 我把一條在程式碼上每一環都成立的推論鏈
   當成結論講給 owner 聽。工作流真的把骨架模式重現出來之後，結果是**方向相反**的：
   骨架模式是「HUD 在、世界黑掉」，owner 看到的是「世界在、HUD 沒了」。
   → 教訓：**推論鏈成立 ≠ 它就是實際發生的那一條**。重現才算數。

2. **`git log -S'"maxHealth"'` 查不出值的變更史。** `-S` 數的是字串出現次數，
   而 key 名從頭到尾都在，所以永遠是 0 變化 —— 我因此一度以為那個檔從沒被改過。
   → 用 `git log -p` 或逐 commit 取值。

3. **守衛掃原始碼會把「註解掉的那行」也算數。** 部署腳本守衛的突變 (b)
   第一次**沒有紅**，因為我掃的是全文。加了剝註解才紅。
   → **「檔案裡出現這串字」與「這件事真的會執行」是兩回事**（失敗形態 ⑥）。
   這個弱點是突變測試逼出來的，不是我先想到的。

4. **既有守衛抓到我一次，而且它是對的。** `HudErrorBoundary` 的 fallback
   第一版寫 `bottom: 8`，`versionBadgeBand.test.ts` 紅了 —— 底部 10px 是版本徽章的
   band（#66，每個畫面都畫）。改放左上。**那條守衛做對了它該做的事。**
