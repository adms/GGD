# §1　#447 傷害級距 —— 從頭講一次

> 你的原話：「**看不懂，你省略太多背景情形**」。這一節每一步都有數字，⛔ 不假設你記得任何上下文。

## 1.1 這是什麼

**技能傷害目前沒有任何規則。** 每一支技能的傷害是當年從 w3x 匯進來的手寫數字，彼此之間沒有關係：

| 這一格的冷卻有多長 | 支數 | 現況中位傷害 |
|---|---:|---:|
| 極小（單體 6 秒 / 範圍 30 秒） | 9 | **300** |
| 小（15 / 45） | 18 | **412** |
| 中（30 / 60） | 19 | **500** |
| 大（45 / 90） | 17 | **350** |
| 極大（60 / 120） | 21 | **500** |

⚠️ **看那一欄：300 → 412 → 500 → 350 → 500。**
**一支冷卻 120 秒的大絕招，傷害跟一支冷卻 45 秒的技能一樣。**
⇒ 「傷害級距」要解決的就是這件事：**讓冷卻越長的技能，傷害真的越高。**

（基礎：84 支帶扁平傷害的技能，滿階值，⛔ 不含 AP 加成。2026-08-20 19:33 掃 `content/abilities/`。）

## 1.2 「錨點」是什麼 —— 為什麼是 20 發

你 08-19 給的 Q1 是一句設計規格：

> 「假設最極端**單體 Q 傷害技能不帶負面狀態冷卻 6 秒**，一回合**連續施展 20 次以內一定要能殺死對方**吧 不然也太爛了」

這句話**直接反算出最低那一格**：

```
單體・極小 = 卡面 6 秒 → 實際 1.2 秒（×0.2 系統倍率）
20 發 × 一發傷害  ≥  對手的血量
⇒ 一發傷害 ≥ 血量 ÷ 20
```

**「錨點」＝ 這裡的「血量」要用哪一級、哪一個空間的。** 定了它，五個級距全部長出來。

## 1.4 錨點算式定案 —— 你選的 🅲（⭐ 而且上一版那個「兜不攏」查出來了）

你 20:18 的原話：

> 「**🅲 保留倍率，但把它從錨點推導裡剝掉** => **OK**，只是**技能說明顯示的數值也會變得動態**」

### ⛔ 上一版說「3,442 可能還含著魔抗」—— **那個推測是錯的**

真正的原因**不是量測污染，是一個算術錯誤**，而且它有名字：

> **初始加成不參與倍率**（你自己 2026-07-28 的裁決，#273：「初始HP/MP/AP⋯**不參與倍率計算**」）

引擎真正在跑的算式是

```
引擎最終 = 純基礎 × 4.0  +  650        ← 加成加在倍率**外面**
```

而上一版把 `11,820 ÷ 4.0 = 2,955` 當成「純基礎」——**那一步把 650 也除以了 4**。
於是回乘的時候差 `650 − 650÷4 = 487.5`，正好就是那個 **+16.5%**。
⇒ **`3,442` 是一個混合量**（基礎與加成被攪在一起），它既不是①也不是②，
所以它跟任何一欄都對不起來 —— 那不是「哪一欄量錯了」，是**它根本不該存在**。

### ⭐ 落地的算式（`packages/shared/src/content/damageTiers.ts::anchorFloorFrom`）

```
LV30 純基礎中位 2,808.6        ← pnpm anchors:build 量的（⛔ 無倍率⛔ 無加成⛔ 無魔抗）
  ÷ 20 發                      ← 你 Q1「20 次以內一定要能殺死對方」
  × HP 倍率 4.0                ← combat-env.maxHealth
  + 初始加成 650 ÷ 20 發        ← base-bonus.maxHealth，⛔ 不參與倍率
  = 594.2
  → 進位到 50（「使五格皆整數的最小單位」是 2，粒度取它的整數倍）
  = 極小 600
```

⭐ **驗算**：`600 × 冷卻比 (1 : 2.5 : 5 : 7.5 : 10)` = **600 / 1,500 / 3,000 / 4,500 / 6,000**，
五格**全部是整數**（那正是「進位」那一步在保證的事 —— 591 的話「小」會是 1,477.5）。

⭐ **達成率**：引擎最終中位 11,884.4 ÷ 600 = **19.8 發** ≤ 你的 20 發 ✅
