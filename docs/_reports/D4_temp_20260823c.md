## ① A4 的 `syncPlan.mjs` —— 接成 `pnpm sync:plan` ＋ `ship.mjs` 的序列段裁剪

### 落地

| 住處 | 是什麼 |
|---|---|
| `package.json` → `sync:plan` | `node tools/parallel-gates/syncPlan.mjs`（印計畫，⛔ 不執行任何產生器） |
| `tools/parallel-gates/ship.mjs` | 序列段的 `skills:sync` 改成**計畫內那幾支** |

`ship.mjs` 的三個路徑集合入口（⭐ 沒有一條是猜的）：

| 入口 | 誰在用 |
|---|---|
| `--sync-paths a,b` | 直接給（測試／手動） |
| `--sync-base <ref>` | `git diff --name-only <ref>`（**含工作樹**）＋未追蹤檔 |
| ⭐ `GGD_DEPLOYED_REF` | **`pnpm ship` 的 `pipeline.mjs` 讀的同一個環境變數**，而 pipeline 是用 `spawn` 起 `ship.mjs` 的 ⇒ 那個起點**自動**流過來，⛔ 不必改 `tools/deploy-timing/`（本 lane 柵欄外） |

### ⛔ fail-closed 三個入口，全部往「全跑」倒

| 情況 | 結果 |
|---|---|
| 沒有人告訴我路徑集合 | **全跑**（⛔ 不是推論成「那就沒改」） |
| 計畫自己說 `full`（路徑對不到輸入表 / `sync-io.json` chain 過期） | **全跑** |
| 算計畫時擲例外（認不得的 ref、git 壞了） | **全跑** |

實測：

### ⛔⛔ 接的時候踩到的**真缺陷**（第一版寫錯了，量到才發現）

第一版把計畫裡的 `content:build` **濾掉**，想靠序列段開頭那一支頂替：

```js
["content:build", ...plan.steps.filter((n) => n !== "content:build")]   // ⛔ 錯
```

⛔ 開頭那一支跑在 `tiers:apply` / `skillremake:json` **之前** ——
它讀到的是**還沒被重寫**的 `content/abilities/**` ⇒ `bundle.json` 會停在舊的那一天，
**而每一支產生器自己都說 OK**。⭐ 那正是 2026-08-01 事故的形狀。

⇒ 正解是**逐字保留原本 `skills:sync` 的行為**（它本來就會跑 `content:build` 兩次）：

```js
["content:build", ...plan.steps]     // ✅ 排序實測: content:build@1 · tiers:apply@4 · content:build@11 · contract:numbers@16
```

### ⛔⛔ 接的當下 `shapes:check` **連紅兩次** —— 而它兩次都是對的

另外兩條 lane 同時在動模板：`tpl-beam-roll` 多了 `soundKey` / `arriveSoundKey`
（家族級音效預設，一格解四支經典光束砲），`tpl-periodic-field` 多了
`damageTier` / `radiusTier`。覆蓋閘兩次都立刻逐格指名：

```
⛔ shape_axes.json 沒有替下面這些欄位做過決定：
     (template:tpl-beam-roll).soundKey  ×1
     (template:tpl-beam-roll).arriveSoundKey  ×1
```

⭐ **這正是那條閘存在的理由**（少了它，那一族技能會被安靜地算成「沒有形狀」）。
⇒ 在 `shape_axes.json` 的 `templateParams.ignored` 裡替**四格**做了決定：
`soundKey`／`arriveSoundKey` ——「**音效綁定是 owner ④ 的範圍，⛔ 不是⑨的時序軸**：
一個聲音鍵沒有壽命、沒有間隔、也不移動」（與頂層 `ignored.soundKey`／`sfxKey` 同一個理由）；
`damageTier`／`radiusTier` ——「級距名」（與既有的 `blastDamageTier`／`blastRadiusTier` 同一格）。

⚠️ **`docs/editor-contract/ggd-skill-shapes.md` 也一起重生成了**（本 lane 路徑柵欄外，
但它是 `shapes:build` 自己的產物）—— ⛔ 不重生成就等於把一條紅著的閘交給主 session。
重生成當下工作樹裡有其他 lane 未 commit 的技能改動，所以形狀分佈有變動
（群數 34→33、「等待＋持續＋續效特效＋多段＋路徑」8→20）。
⇒ **主 session 最後那一次 `pnpm skills:sync` 會從已 commit 的樹重新推導它**，自癒。
