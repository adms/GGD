## ② #763 —— `ImpactTier` 接線的實際形狀

### 有幾個梯度、真的分得開嗎

⭐ **sim 側有 4 個 tier，音效側真的用得到 3 個。**

| tier | 誰決定 | 打擊音 | audio-map gain |
|---|---|---|---|
| `light` | `deriveTier(impact < 60)` | `hit-light` | 0.55 |
| `medium` | `60 ≤ impact < 120` | `hit-medium` | 0.72 |
| `heavy` | `impact ≥ 120` **或** guardBreak | `hit-heavy` | 0.95 |
| `crit` | `crit === true` | ⛔ 不走這條 —— `damage` 那一顆早就播 `crit` | 1.0 |

⇒ **分得開，而且是量到的**：`hitWeightTier.test.ts` 用**出貨的傷害管線**
（`runEffects` → `combatResolveSystem` → 真的 `deriveTier()`）打同一支技能兩發，
只改 `amount.flat`（20 / 400），sim 自己解出 `light` / `heavy`，而出貨的
`combatSfxKey` 分別回 `["hit-light"]` / `["hit-heavy"]` —— **各自恰好一發**。

### ⚠️ 關鍵設計決定：發聲的事件換了一顆

票上給了兩條路（搬到 `hitImpact` / 在 mapper 裡自己推 tier）。**選了前者**，理由是
第〇·四守則：`deriveTier()` **沒有 export**，客戶端自己比一次門檻就等於把
`TIER_MEDIUM_IMPACT` / `TIER_HEAVY_IMPACT` 抄成第二個住處 ——
⛔ 而它會用「音效跟震動對不起來」這種**認不出來的**方式過期。

| 事件 | 現在負責什麼 |
|---|---|
| `damage`（先到） | block / crit / 魔法 / 真傷 四條**識別**路。⭐ 只有「普通物理命中」那一條讓位（回 `null`） |
| `hitImpact`（隨後） | 只在那一條讓位時發聲 → `hit-light` / `hit-medium` / `hit-heavy` |

⭐ 前提查證過（⛔ 不是假設）：全 repo `emit("damage")` **只有一個出貨站點**
（`sim/combat/damage.ts:1347`），而 `applyImpact()` 就在它下面第 23 行、
且檔頭逐字寫著它 **always** 發 `hitImpact`。⇒ 雙生關係成立，⛔ 沒有「damage 有而
hitImpact 沒有」的孤兒路徑。

### rollback 是**資料**，⛔ 不是第二個布林

分層只在出貨音效表**三顆 key 都在**時啟用
（`setHitTierKeys()` ← `AudioSystem.setMap()` ← `config.audio-map@1.sfx`）。

⚠️ **為什麼不是一格 `hitTiering: boolean`**：那一格的三個住處是
`content/config/*.json` ＋ Zod `DEFAULT_*`（`packages/shared`）＋ admin `SHIPPED_*`
—— ⛔ **後兩個都在本 lane 柵欄外**。而且 `audio-map` **今天在 admin 根本沒有頁**
（`apps/admin/src/configDocCoverage.test.ts:239` 把它列在 `KNOWN_GAP` 裡），
所以「加一格布林」在今天也到不了後台。
⇒ 選了**結構上不可能不同步**的那一種：把 `hit-light`/`hit-medium`/`hit-heavy`
任一顆從 `audio-map` 拿掉 ⇒ 分層整條關閉、`damage` 回到 `"hit"`，
**逐位元等於今天**，而 `content/` 是 live bind-mount（⛔ 不必重建映像）。
⚠️ 「開著但 key 不在」那個組合就是靜音 —— 那正是失敗形態⑧。
⇒ 讓「**播得出來嗎**」與「**要不要播**」是同一個問題。

⚠️ 認不出重量時 `hitWeightKey()` 回 `"hit"`（⛔ 不是 `null`）：
舊 server + 新 client 的代價是**舊的那顆聲音**，⛔ 不是整場沒有打擊音。

### 連帶動到的四處

1. `combatSfxSpatial.EVENT_SPATIAL` 加 `hitImpact` —— 位置規則與 `damage`
   **逐字相同**（payload 同形：x/z 是受害者 transform）。不同 ⇒ 同一次命中的
   兩顆聲音會落在兩個地方。
2. `sfxReachability` 三列現在騎**兩條軸**，新增 `altSites`：
   家族軸（`vfx-families.json` 的 `soundImpact`，73 支技能）＋ 重量軸
   （`combatSfx.ts`）。`altSites` 走與 `site` **逐字相同**的檢查（檔案要在、
   要含 key 字面值），⛔ 不把另一條軸的宣稱從機器證明降級成散文。
3. `combatSfx.test.ts` 加兩行釘 `setMap → setHitTierKeys` 那一行接線
   （＋ `audioMapFromDoc` 真的把三顆 key 帶過來了）——
   ⛔ 自己餵夾具的測試看不見這條（失敗形態⑤，`castLayerCap` 就是這樣死過一次）。
4. `sfxManifest.COMBAT_SFX` 加三顆 —— 它們現在是**每一次**普通物理命中的聲音，
   不預載 ⇒ 一回合頭幾拳吃冷 buffer 延遲。

## ④ 最重要的一個發現

⭐ **「後台可調」在 `audio-map` 這一族今天是做不到的，而那不是本 lane 的柵欄造成的。**

`apps/admin/src/configDocCoverage.test.ts:239` 把 `audio-map` 列在 **`KNOWN_GAP`** 裡
—— ⇒ 整份音效表**在後台沒有頁**。所以第一守則的「三個住處」對任何一格音訊參數
今天都只湊得出兩個（content JSON ＋ Zod），第三個不存在。
⚠️ 這表示 `rankUpAudience`（GH#605 已落地的那一格）與本次的打擊分層，
**owner 今天都只能靠改 `content/config/audio-map.json` 來轉** ——
而那**還算便宜**（live bind-mount，⛔ 不必重建映像），⭐ 但它不是「一格下拉選單」。

⇒ 建議開一張獨立的票：**給 `audio-map` 一張後台頁**（把 `KNOWN_GAP` 那一列拔掉）。
它一次解鎖的是**整條音訊線每一格參數**的可調性，⛔ 不是某一個功能。
