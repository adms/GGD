#### ⚠️ 「七彩」怎麼從 4 個 colorStop 做出來（**這是機制，不是妥協的藉口**）

`zVfxDocBase.colorStops` 的上界是 **`.max(4)`**（`schema/vfx.ts:169`）。
所以一份文件寫不出七個色停。做法是**讓粒子彼此不同相**：

* `colorStops` 走完整條色環：白熱 → 紅橙 → 綠青 → 藍紫（4 停）
* `lifetimeSec: { min: 0.16, max: 0.62 }` —— **≈4 倍的壽命散布**

⇒ 同一個瞬間，場上每一顆粒子都停在梯度的**不同位置**，於是一團爆炸裡
同時看得到白／紅／橙／綠／青／藍／紫。⭐ 這是**一份文件**做出來的，
⛔ 不是七個特效疊在一起（票上的硬要求）。

⚠️ **可反駁點**：如果 owner 之後說「顏色分層不夠明顯」，正解是把
`colorStops` 的上界從 4 放寬到 7（`packages/shared/src/content/schema/vfx.ts`，
⛔ 柵欄外），⛔ 不是在這支技能上疊第二份 vfx 文件。

## ③ ⚠️ 最重要的發現：票上的前提與工作樹**不一致**

票面寫「`passive.hooks[onReflectSuccess]` 已經有 `comboStrikes`（family
`excaliburmax`，7 刀）＋ `damageLine` 收尾」。

⛔ **HEAD 上不是這樣。** 出貨的節點是：

```json
{ "kind": "delayed", "shape": "single", "delaySec": 0.12,
  "count": 7, "intervalSec": 0.12, "effects": [...], "finalEffects": [...] }
```

`count: 7` 與 `intervalSec: 0.12` 是**手寫的字面值**，而
`content/config/combo-strikes.json` 的 `excaliburmax` 那一列**已經存在**
（`jassFunc: Trig_ExcaliburMAX_Actions`、`shape: "loop"`、`strikes: 7`、
`finisherDelaySec: 4.0`）⇒ 🔢 **第〇·四守則的「第二個住處」**。

⛔ **我沒有順手改它**（第零守則⑧：排序是 owner 的權力），理由另有一個**技術**的：

> `resolveComboFamilies` 會把 `excaliburmax` 的 **`finisherDelaySec: 4.0`**
> 寫進節點。而 JASS 裡那個 `W4` 是**整段演出結束後清 dummy 單位**的睡眠
> （`seq: ["D","W0.1","W0.3","W0.2","W0.5","W4"]` 的最後一格），
> ⛔ **不是**「約束與勝利之劍在第七刀之後 4 秒才發動」。
> ⇒ 直接換成 `comboStrikes` + `family` 會讓收尾光束**慢 4 秒**才打出去。

**⇒ 給 owner / 主 session 的一個選擇（⛔ 我沒有替你挑）：**

| 選項 | 做什麼 | 代價 |
|---|---|---|
| (a) 先修表 | `tools/jass-combo/extract.py` 的切分讓 `excaliburmax` 的 `finisherDelaySec` 不吃迴圈外的清理 sleep，再把技能換成 `comboStrikes` + `family` | 動產生器 + 重跑 `--check` |
| (b) 先換 kind | 技能換 `comboStrikes` 但**保留自己的 `intervalSec`**（`resolveComboFamilies` 在 row 沒有 `intervalSec` 時不會刪作者的那一格） | `finisherDelaySec: 4.0` 仍然會被寫進去 ⇒ ⛔ 光束慢 4 秒 |
| (c) 維持現狀 | 留 `delayed`，把這一項記在 #541 底下 | 第〇·四守則的違規持續存在（2 個字面值） |

⭐ **本 lane 的四個回饋節點在三個選項下都不用改**：頂層的三個 cue 與
`delayed.effects` / `perStrike` 的兩個節點是同一組 `EffectDef`，換 kind 時整段搬過去即可。

### ⑤ 後台欄位（第一守則 —— 主 session 接 admin，我列規格）

⚠️ **一格都不要開在「這一支技能」上** —— 這些是**全域回饋強度**，
屬於 `config.screen-cues@1`（上面第 3 項），⛔ 不是 `godie-e002.ex` 的欄位。

| 欄位名 | 型別 | 上下界 | 中文標籤 | 它影響什麼 |
|---|---|---|---|---|
| `flashIntensity` | number | `0 … 1`（出貨 1） | 畫面閃爍強度 | 每一支技能寫的 `peakAlpha` 會**再乘這個數字**。設 0 = 全域關掉閃爍（不改任何技能 JSON） |
| `shakeMaxOffset` | number | `0 … 1`（正規化，出貨 1） | 畫面震動幅度 | 技能寫的 `amplitude` 是 0..1 的**正規化**值，真正的位移 = `amplitude × 這一格`。⛔ sim 不知道一格是幾個像素 |
| `respectReducedMotion` | boolean | 出貨 `true` | 尊重系統的「減少動態效果」 | 開著時，作業系統設了 `prefers-reduced-motion` 的玩家自動拿到 0 震動 / 低強度閃爍。⚠️ 螢幕震動是無障礙上最容易致暈的一種 |
| `floatingTextEnabled` | boolean | 出貨 `true` | 顯示特效文字（`1Hit`…`7Hit`） | 關掉 = 連段的段號與傷害數字不冒出來。與傷害數字設定是同一格語意，⛔ 不要開第二格 |

⭐ 這四格全部是**決策點**（第一守則），而且**每一格都會被 owner 改** ——
閃爍與震動是「太少看不到 / 太多想吐」之間的一條線，⛔ 它不該住在 420 支技能的 JSON 裡。
