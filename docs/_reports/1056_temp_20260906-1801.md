# GH#1056 —— parallel-gates 沙盒的兩個量測陷阱（lane 報告）

票：[#1056](https://github.com/adms/GGD/issues/1056) · 日期 2026-09-06 · 柵欄：`tools/parallel-gates/trace.mjs` · `scripts/genrun.sh` · `packages/shared/src/ops/traceSingleStep.test.ts`
（`reconcile.mjs` ⛔ 沒動 —— 隱形的做法不需要碰它）

## 1. 動手之前它今天的行為（baseline）

| 陷阱 | 今天 | 量到的 |
|---|---|---|
| ① 沙盒陳舊判準 | `trace.mjs` 比對**整份** `package.json` 逐位元組 ⇒ 任何一條 lane 改一行 script 就 `rm -rf && cp -Rc` 整棵沙盒 | #1034 報告：53G / 1.6M 個檔 ≈ **8 分鐘**（`rm -rf` 2.5 分 ＋ `cp -Rc` 5 分），量測本身 7 秒 |
| ② 對帳快照被記成讀 | `genrun.sh` 跑 `reconcile.mjs snapshot`/`verify`，它對 content/docs/data 每一份檔 `statSync`，`hooks/node-trace.cjs` 把 statSync 記成 `R` | `sync-io.json` 62 支裡 **56 支 readCount 32k+**、`reads` 從 **308 起跳**（全是被 stat 過的有戶籍產物）⇒ 圖被灌成每支依賴每支 |
| （順帶）鎖檔被記成寫 | `.content-tree.lock` 是頂層檔（沒有 `/`）⇒ `interesting()` 放行；新沙盒裡第一支走 genrun 的步驟會把它量成 write | 假 repo 上實測 g:step 的 writes 多一份 `.content-tree.lock` |

⚠️ 同時量到、⛔ 與這張票直接相關的一個事實：**現有的真沙盒（`$TMPDIR/ggd-syncgraph-sandbox`）HEAD 落後真 repo 332 個檔**（`14098b7c9` vs `ddcb3c1b8`）—— 舊判準只在 package.json 變時才重建，所以「沙盒的產生器來源是舊的」本來就會發生；這張票之後**重用變成常態**，所以增量同步是必要的一半，⛔ 不是加分項。

## 2. 做了什麼

### ① 陳舊判準 → 依賴指紋 ＋ 增量同步（`trace.mjs`）

- `depFingerprint(root)` = sha256(`package.json` 的 `dependencies/devDependencies/optionalDependencies/peerDependencies/pnpm/overrides/resolutions/packageManager/engines/workspaces` ＋ `pnpm-lock.yaml` ＋ `pnpm-workspace.yaml` ＋ `.npmrc`）。⛔ 不含 `scripts`、不含 `name/version/description`。
- 指紋相同 ⇒ **重用**沙盒（留 node_modules），`refreshSandbox()` 用 git 算要搬的集合：
  `git diff --name-only <上次同步的 HEAD>..HEAD` ∪ `git status -uall`（含未追蹤新檔）∪ 上次同步時的髒檔（可能已被還原）；刪除那一半對稱處理。逐檔 `copyFileSync(…, COPYFILE_FICLONE)`（APFS clonefile），444 的先 `rm` 再放。
  ⛔ 為什麼不是 rsync：openrsync 對整棵樹 dry-run 實測 **63 秒**；`git status -uall` 在真 repo **0.34 秒**。
- 戳記 `<沙盒>/.ggd-sandbox-stamp.json`（fingerprint · head · dirty · at）。⭐ 舊沙盒沒有戳記 ⇒ 用它自己的 `git rev-parse HEAD` 當基準（實測：現有的 53G 沙盒**第一次重用就不用 8 分鐘**）。
- 退回整棵重建的四種情況都**出聲指名**：`--fresh` · 沙盒不存在 · 依賴指紋變了 · 基準 commit 在 repo 裡找不到（歷史改寫）。
- ⚠️ `--reset` 走沙盒**自己的** .git（`HEAD~60` 基線、`git status` 找髒檔），而增量同步⛔ 不動沙盒的 .git ⇒ 沙盒 HEAD ≠ 真 repo HEAD 時 `--reset` 會把剛同步進來的檔當髒退回**舊的** HEAD~60（連 `packages/` 一起）⇒ 加一條：`--reset` 且 HEAD 不同 ⇒ 自動重建（訊息指名）。
- 管不到的（誠實）：被 `.gitignore` 的輸入（沙盒留 clone 當時那一份）· 沙盒 .git 停在 clone 時的 HEAD ⇒ 出口仍是 `--fresh`。

### ② 對帳快照對探針隱形（`genrun.sh`）

兩行 `reconcile.mjs snapshot/verify` 前綴 `env -u GGD_TRACE_LOG -u GGD_TRACE_ROOT` —— 探針（`hooks/node-trace.cjs` · `sitecustomize.py`）自己的開關就是這兩個 env，缺一就不裝 hook。產生器本體（`pnpm "$RUN"`）照樣被量。
⛔ 沒動 hooks（柵欄外）；⛔ 也沒選 `GGD_RECONCILE_OFF=1`（#1034 報告的建議）—— 那會讓沙盒裡的量測路徑與正式 genrun 不同，而票的 AC 逐字是「reconcile **後** reads 不含產物路徑」。

### （順帶）`.content-tree.lock` 進 `DROP`（`trace.mjs`）—— 一行，理由寫在旁邊。

## 3. 守衛（`traceSingleStep.test.ts` 加兩條，兩條都校準**兩個方向**）

| 條 | 驗什麼 | 兩個方向 |
|---|---|---|
| ③ | 只改一行 script（＋一份沙盒沒有的新來源檔 `tools/d.py`）⇒ 沙盒重用（沙盒獨有的 marker 檔還在）且新來源檔同步進去（`d:step` reads = `["docs/in.md"]`，沒同步會 exit 3） | 改 `devDependencies` ⇒ 訊息「重建量測沙盒（依賴指紋變了」且 marker 消失 |
| ④ | 走**真的** `genrun.sh`（含 content-tree-lock ＋ reconcile 快照）的步驟，reads 逐字等於 `["docs/in.md"]`、writes 逐字等於 `["docs/out2.md"]` | 真的讀（in.md）看得見 ＝ 探針沒被整個關掉；被 stat 過的產物（`docs/other.md`）⛔ 不在 |

假 repo 現在是一個 git repo（增量同步要有基準），戶籍住 `tools/parallel-gates/sync-io.json`（reconcile 的預設路徑 —— 放別處會讓快照拍不出來而**靜默沒有對帳** ⇒ ④ 假綠）。

### 突變紀錄（一批一條）

`scripts/genrun.sh` 的 snapshot 那一行拿掉 `env -u GGD_TRACE_LOG -u GGD_TRACE_ROOT` ⇒ ④ **紅**：
`expected [ 'docs/_daily/????-??-??.md', 'docs/in.md', 'docs/other.md' ] to deeply equal [ 'docs/in.md' ]` —— 正是污染的形狀。改回來（Edit）。

另外手動走過三條退路（scratch 假 repo，⛔ 不是測試）：舊沙盒沒戳記 ⇒ 重用（同步 2 份）· 基準 commit 找不到 ⇒ 重建並指名 · `--reset` 同 HEAD ⇒ 重用、HEAD 移了 ⇒ 重建並指名。

## 4. 跑了什麼

實作 120 行 / 測試 59 行 = 0.5×。

## 5. ⛔ 沒做到的 / 需要主 session 的

- **真 repo 的 `sync-io.json` 沒有重量測**（柵欄 ＋ 併行禁令）⇒ 那 56 支 32k+ 的 readCount 與 308 起跳的 reads **還在**，下一次 `trace.mjs` 全量兩趟（主 session、全域鎖）才會變乾淨。⚠️ #1034 報告的提醒仍然成立：污染拿掉之後圖會變稀，可能暴露被污染遮住的真漏邊 —— 重量測之後看 `syncPlan`/`graph` 的紅。
- 柵欄外一個都沒動：`hooks/node-trace.cjs`／`sitecustomize.py`（「探針區分 stat 與 read」那條路沒走，不需要）。
- 沒有後台開關：這兩件事 owner 不會轉（CI／作者才會），照「開關的住處看誰會轉」的裁決用 CLI 旗標（`--fresh`）而不是 config。
