## ② 做了什麼

### 12 → **40 條**（`rule` 14 · `tip` 20 · `build` 6）

⭐ 新增 `topic` 軸（14 類），把票文的七個缺口全部補上並讓它們**可被閘檢查**：

| 缺口（票文） | 條數 |
|---|---:|
| 殭屍波次 `mobs` | 4 |
| 殭屍王／特殊殭屍 `boss` | 2 |
| 火圈 `firering` | 3 |
| 三選一 `draft` | 2 |
| 寶具／EX `grail` | 2 |
| 復活 `revive` | 3 |
| 回合評分 `grade` | 2 |
| （既有）`shop` 7 · `statpath` 4 · `objective` 3 · `format` 2 · `round` 2 · `skills` 2 · `team` 2 | |

### ⭐ 每一個數字都是佔位，⛔ 零個字面值

`TIP_VALUES` 是**唯一**讀數字的地方，23 格全部從出貨的共用表解析：
`TEAM_COUNT` / `TEAM_SIZE` / `DEFAULT_FINAL_ROUND` / `DEFAULT_MOB_WAVES_CONFIG` /
`DEFAULT_FIRE_RING_CONFIG` / `DEFAULT_REVIVE_CIRCLE_CONFIG` / `DEFAULT_FLOWER_CONFIG` /
`DEFAULT_GUARDIAN_TOWER_CONFIG` / `INVENTORY_SLOTS` / `SELL_REFUND` / `STAT_TICK_*` /
`CAPSTONE_MIN/MAX_PCT` / `LEGENDARY_ORB_PRICE` / `DEFAULT_ECONOMY.*`。
⇒ ⭐ owner 轉 `statTickTarget`，商人那句話**跟著轉**。

⚠️ 解析不到的佔位 ⇒ **那一條被丟出輪播**（⛔ 不給玩家看到 `{{大括號}}`），⭐ 而閘同時會紅並指名它。

### ⭐ 每一條帶 `source`（出處）

每一列都寫著它描述的機制住在哪個 config 欄位／哪支模組。⛔ 閘驗不了「這句話是真的」，
⭐ 但它逼作者寫下出處，而這一批 40 條就是逐條這樣查出來的（見①）。

### ⭐ 第一條不是隨機的（票文 Known risks）

一次中場 ≈ 25 秒 ÷ 5 秒 ⇒ 玩家一場只看得到 ~5 條 / 40 條。
⇒ `nextTipIndex(-1, …)` 從 `PRIORITY_TIP_COUNT = 6` 的**求生必知**開頭抽
（火圈會殺死你 · 隊友能拉你 · 殭屍是主要收入 · 賽制 · 不會被淘汰 · Ready 語意），
之後才是原本的均勻不重複輪播。
