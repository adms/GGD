## 1 · F-05/13 —— 「限流讀的是誰能偽造的欄位嗎」

**兩層都壞，而且第二層比票上寫的更嚴重。**

### (a) 平台層：`ClientIP()` 無條件相信 `X-Real-Ip`
偽造一次 header ＝ 換一個全新的登入限流桶 ⇒ credential stuffing 的節流是裝飾品。
**修法**：只有在 **socket peer ∈ 可信 CIDR** 時才採信該 header，否則用 socket peer。
預設信任集合 = loopback ＋ RFC1918 ＋ ULA（`httpx.DefaultTrustedProxyCIDRs`）——
平台永遠在 nginx 後面的私有網段，所以這個預設**對現行部署零成本**，而它關掉了
「請求從公網位址進來卻自稱是別人」這唯一真正重要的情況。
⛔ **刻意不釘 edge 的確切位址**：那是 Docker 每次重建容器重配的，釘死＝閘會靜默退化。
旋鈕 `GGD_TRUSTED_PROXY_CIDRS`（`none` = 誰都不信）。

⚠️ 侷限（誠實）：私有網段內的攻擊者仍可偽造。⛔ 但那已經是另一個層級的失守。

### (b) 邊緣層：⭐ **Caddy 後面每一條 `$remote_addr` 規則都是一個全域桶**
記憶裡早記著這條，⛔ 但沒有人把它接到限流上。實際後果（量的是 conf，不是猜）：

| 規則 | 以為的意思 | ⛔ 真正的意思 |
|---|---|---|
| `limit_req zone=authlogin rate=10r/m` | 每個 IP 每分鐘 10 次登入 | **全世界合計**每分鐘 10 次 |
| `limit_conn wsconn 20` | 每個 IP 20 條 WS | **全站合計** 20 條 |
| `proxy_set_header X-Real-IP $remote_addr` | 真實來源 IP | Caddy 的容器 IP |

⭐ 這一半是 **fail-closed** 的：一個人可以把全家鎖在門外。
**修法**：`set_real_ip_from`（私有網段）＋ `real_ip_header X-Forwarded-For` ＋ `real_ip_recursive off`。

⭐ **為什麼 `off` 是安全的**：非遞迴取 XFF 的**最後一個**位址 —— 那是上游 proxy 自己追加的
socket peer；呼叫端自己塞的東西一律落在鏈的**前面**，被忽略。
⭐ **為什麼不可能更糟**：header 不在、或 peer 不可信 ⇒ 什麼都不替換，`$remote_addr` 維持今天的值。

## 2 · F-12 —— token 掛 URL query

`BearerToken()` 的 `?token=` fallback 是**每一條**已認證 REST 路由共享的 ⇒
一次複製的連結、一行 curl 範例，就把一個活的 15 分鐘憑證寫進 `access_log /dev/stdout`。

**修法是「拆」不是「刪」**：瀏覽器的 `WebSocket` 建構子送不了 header ⇒
`BearerTokenWS()` 保留 fallback，只有 `lobby/ws.go` 一處呼叫；`BearerToken()` 不再讀 query。

✅ 逐條查證過**不會擋掉任何合法用戶**：全 repo 只有 `LobbySocket.ts` 用 `?token=`，
而 `approvelink/handlers.go:68` 的 `?token=` 是**它自己的**一次性核准憑證，走另一條路。

## 3 · F-09 —— 四個逾時

⚠️ **這一條差點就是「把玩家鎖在門外」的那一種修補。** Go 的 `ReadTimeout`/`WriteTimeout`
是在 handler 跑之前就武裝在連線上的，而且**撐過 Hijack** ⇒ 直接打開會**準時砍斷每一條大廳
WebSocket**，並且把平台備份匯出**在半路截斷成一份看起來像下載的壞 zip**。
（`coder/websocket` v1.8.15 的 `Accept` **不會**替你清掉那些 deadline —— 讀過原始碼確認。）

⇒ **修法是「逐路由退出」，⛔ 不是「把數字調到夠大」**：
`httpx.ClearDeadlines(w)`（`http.NewResponseController`）用在三處 ——
lobby WS ＋ archive `stage`／`export`。其餘每一條路由才能用「一般 JSON」的尺度。
一個為了 WebSocket 而挑的數字**不是逾時，是一個假裝成逾時的缺席**。

旋鈕：`GGD_HTTP_{READ,WRITE,IDLE}_TIMEOUT_SEC` · `GGD_HTTP_MAX_HEADER_KB`（0 = 回到今天）。

## 4 · F-15 —— CSP（⚠️ 部分）

**enforced 加了三條，⛔ 但 `default-src`/`script-src` 走 Report-Only。**

| | |
|---|---|
| **enforced** | `frame-ancestors 'none'; base-uri 'self'; object-src 'none'; form-action 'self'` |
| **Report-Only** | 完整政策（`default-src`/`script-src`/`style-src`/`img-src`/`media-src`/`font-src`/`connect-src`/`worker-src`/`manifest-src`…） |

⭐ **為什麼分兩個 header**：enforced 的那三條是**讀出來的**，不是賭出來的 ——
逐項查證 client/admin **沒有** `<object>`/`<embed>`、**沒有** `<base>`、**沒有**跨 origin 表單，
所以它們不可能弄壞任何今天能動的頁面。
而 `default-src`/`script-src` 是會**整片白畫面**的那兩條，CSP 又住在**映像**裡
（⛔ 不可 `--content-only`，錯了要一次完整重建）⇒ ⛔ 不可以只憑讀原始碼就上 enforced。

⭐ **Report-Only 本身就是票上要的那一輪量測**，而且它比一次本機 pass 更好：
它在**每一個環境、每一次載入**、對**每一個打開頁面的人**都報一次。

**已量到的證據**（⛔ 不是印象）：
- 兩份 `index.html` **零 inline `<script>`**（只有 `<script type="module" src>`）· 有 inline `<style>` ⇒ 需要 `style-src 'unsafe-inline'`
- client/admin 原始碼 **零 `eval`/`new Function`**；`@babylonjs/core` 唯一命中在 `assets/Basis/basis_transcoder.js`（沒被引用）⇒ ⛔ **不需要 `'unsafe-eval'`**
- **零** CDN／外部 script／字型來源
- 出貨 GLB **零** `KHR_draco_mesh_compression` / `EXT_meshopt_compression` / `KHR_texture_basisu` ⇒ 不會去抓 babylonjs.com 的 decoder
- 沒有 `@vitejs/plugin-legacy`（那個會注入 inline script）
- WS 同源（`wss://${location.host}/colyseus`、`/api/v1/lobby/ws`），⛔ 但 `match_ready.endpoint` 是伺服器給的絕對 URL ⇒ `connect-src` 放寬到 `ws: wss:`

**升級步驟（下一條 lane 兩個字的事）**：跑一輪真的 session（登入 → 選角 → 一場 → `/admin/`）
確認 console 零 violation ⇒ 刪掉 `-Report-Only` 後綴並移除上面那行 enforced。
⛔ 不要逐條升級 —— `default-src` 一旦 enforced，它 fallback 到的每一條也一起 enforced。

⚠️ nginx `add_header` **不跨層合併** ⇒ `/admin/` 那一格必須逐字重述，而重述就是漂移的來源
⇒ 守衛比對兩處逐字相等。

## 6 · F-10 —— per-account 上限 ＋ read limit ＋ deadline

⭐ **邊緣的 `limit_conn` 回答不了這一題**：它 key 在**位址**上，而
①同一個 NAT 後面的一家人共用位址 ②同一個帳號從很多位址重連它完全不管。

- `Hub.register` 現在回傳被驅逐的 client；超過上限**驅逐最舊的**，⛔ 不是拒絕最新的 ——
  ⭐ 現實裡撞到這格的是「重連了但舊 socket 沒被回收」的玩家，拒絕新的會把真人鎖在自己的大廳外。
- ⭐ 驅逐要真的關掉 fd：被踢的 handler 還停在 `conn.Read` ⇒ 加一個 `<-c.closed` 就 `conn.Close` 的 goroutine。
  ⛔ 少了它，上限只擋住了 fan-out，什麼都沒省下。
- `SetReadLimit`（32 KiB）＋ 每次 read 帶 90s 靜默 deadline。
  ⭐ 90s 是**對著 client 自己的 20s heartbeat** 挑的（容忍連掉 4 次），⛔ 不是憑感覺。

旋鈕：`GGD_LOBBY_MAX_CONNS_PER_ACCOUNT`（0 = 不限）· `GGD_LOBBY_WS_IDLE_SEC`（0 = 不回收）· `GGD_LOBBY_WS_READ_LIMIT_KB`。
⭐ 預設值住在**用它的那個 package**（`lobby.Default*`），config 用 `-1` 表示「沒設定」——
⛔ 不把同一個數字抄進 config 變成第二個住處（第〇·四守則）。

⇒ 這一格留給「realip 上線後量到 XFF 真的每一條路徑都在」之後再做。
