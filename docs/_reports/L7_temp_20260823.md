## 相依關係怎麼**推導**的（⛔ 沒有一條是手寫的）

| 半邊 | 量法 | 為什麼是這個 |
|---|---|---|
| **讀** | 語言層探針：`hooks/sitecustomize.py`（`sys.addaudithook`）＋ `hooks/node-trace.cjs`（`--require` 換掉 `fs` 的讀取族） | 32 支全部是 python 或 node/tsx —— 連 `msgledger:build` 都是 `exec python3 - <<PY`，探針蓋得到 |
| **寫** | **mtime 差分**（`find -newer`） | ⭐ 對**子行程**與任何語言都成立。漏一個寫入端 = 漏一條邊 = 併行時互相覆蓋，⛔ 而且兩支都說自己 OK |

⚠️ **一趟是不夠的，而且錯的方向很貴** —— 所以量了**四趟**：

1. **乾淨的樹** —— 讀取的全貌。⚠️ 但有 8 支寫 0 個檔（內容一樣就不寫）
2. **`git archive HEAD~60 content docs data | tar -x`** —— 逼出大部分寫入端（⛔ `tools/` 不回捲：要量的是**現在**的產生器）
3. **每一支跑前都回捲**（`reset-sandbox.sh`）—— 拆掉「上游剛把它的產物寫對了」這個遮蔽。⭐ `anchors:build` 就是在這一趟才交出寫入端
4. **`force-writes.mjs`** —— 把它讀過的每個文字檔加一個換行，逼「不同才寫」的那幾支。⭐ `tiers:apply` 在這一趟交出 **401 個**寫入端 —— ⛔ 少了它，整張圖是錯的

⭐ 逼完仍然 0 寫入的 3 支（`skillremake:provenance` · `speedtiers:build` · `roster:check`）是**就地改寫型**：
它們的冪等判準不是位元組相等（`provenance` 欄位已對就 `continue`；`next === raw` 就跳過），
所以加換行兩邊一起變。⇒ 保守地取 `writes := reads ∩ 產物集合`。
⭐ 這是**可靠的上界**：無條件寫的工具前三趟就量得到了，還是 0 的必然是「讀出來比一比才寫」⇒ 它一定讀得到自己的產物。

## 排程

- **拓撲分層** + ready-queue，優先序 = **到終點的最長路徑**（critical path）。
  ⭐ 這是 LPT 在 DAG 上的正確一般化：純 LPT 只看自己多長，⛔ 看不到「它後面還拖著多少」。
- ⛔ **不 fail-fast**：其餘照跑到底，最後一次列完所有的錯（第零守則：批次撈）。
  ⭐ 但紅了的那一支的**後代會跳過** —— ⛔ 不拿壞掉的產物往下蓋。

## ⚠️ 這一趟抓到的一個真缺陷（我自己寫的）

第一版排程器**同一支會被送出去兩次**：`done[i]` 要等行程結束才變 true，而每次有人收工都會再 `pump()`，
這中間**還在跑**的那幾支前置條件仍然成立 ⇒ 重複送出。
量到：累計 CPU **613s**（串行只要 108s），而且 `skillremake:json` 兩份同時寫同一批 126 個檔 ⇒
**它自己紅了**，25 支後代被跳過，24 個產物跟串行對不上。
⇒ 修法是一個 `started[]` ＋ `launch()` 開頭的重入柵欄。
⭐ **抓到它的是產物逐位元組差分，⛔ 不是任何一條測試** —— 兩邊的每一支都說自己 OK。
