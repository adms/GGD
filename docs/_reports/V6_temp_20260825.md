## 5. ⛔⛔ 量到的缺陷：`tint` 對 luma-keyed stock 特效模型**逐位元無效**

出貨節點寫 `[1,0,0]`，畫面上的閃電是**藍的**。現場逐材質量到：

```
albedoColor  [1,0,0]   ✅ applyFxTint 到了
emissiveColor[1,1,1] + emissiveTexture   ⛔ 沒被碰（applyFxTint 刻意不動 emissive）
```

而 stock 特效模型經 `gltf.py` 的 luma-key 路徑之後，**看得見的顏色住 emissive**
（這一支 7 個材質全是 `additive glow w/o alpha → luma-keyed`）。
⇒ 這一族的 `tint` / `model@1.fxTint` 是「說了但不會發生」（第一·五守則）。

⚠️ **影響遠大於這一批**：locust 計畫的「`fxTint` 回填 133/236 非白 dummy」整條線，
只要目標是 luma-keyed 的 stock 特效 glb，回填就全部是空的。
⚠️ 而 `applyFxTint` 不碰 emissive 是**有理由的**（純黑頂點色在 WC3 是黑色剪影，
把 0 乘進加法層會讓模型整個消失）—— 所以正解是**依材質型別分流**
（additive/emissive 走 emissive、不透明 body 走 albedo），⛔ 不是把註解那條規矩刪掉。

⛔ **本 lane 不修**：`apps/client/src/render/modelFxRig.ts` 是 A6 的柵欄。
⛔ **也不刪**那幾格 tint：值是量到的，刪掉只會讓缺陷隱形。
⇒ **請主 session 開票**（本 lane ⛔ 不 gh 寫入）。
