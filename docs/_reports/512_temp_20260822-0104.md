## 一句話

手把的地面型技能落點從**寫死的 6 單位**改成**技能自己的 `range × envFactor("abilityRange")`**；
長按預覽的 AoE 圓心在手把瞄準時改讀**搖桿方向**；按下去卻沒有指令產生時**答一聲**。

## ① 硬夾限 → 從技能自己的射程推導

**修之前**（`GamepadInput.ts` 舊 :319）

```ts
const reach = Math.min(ability.range, GROUND_CAST_MAX);   // GROUND_CAST_MAX = 6
```

**量到的代價**（腳本掃 `content/abilities/**` × `content/config/combat-env.json`
的 `abilityRange = 0.8`）：

| | 數量 |
|---|---:|
| `castType: "ground"` 的出貨技能 | **70** |
| 其中實際射程（`range × 0.8`）> 6，也就是**被夾掉**的 | **42** |
| 全部帶數值 `range` 的技能中實際射程 > 6 的 | 152 / 420 |

⇒ 稽核講的「42 / 70 支打不到自己的射程」在出貨內容上**逐字複現**。

**修之後**

```ts
export function padCastReach(ability: AimAbility, abilityRangeMult: number): number {
  const mult = Number.isFinite(abilityRangeMult) && abilityRangeMult > 0 ? abilityRangeMult : 1;
  return ability.range * mult;
}
```

⭐ 這個公式**與伺服器是同一個**：`sim/abilities/abilitySystem.ts`
的 `resolveAbilityRange(world, def.range) = range * world.combatEnv.abilityRange`
既是 `ground` 的夾限（:369 `clampLen`）也是 `targeted` 的 out-of-range 判定（:353）。
⛔ 不是第二份會分岔的規則。

⭐ 順帶修掉一個同源的靜默拒絕：`targeted` 的目標搜尋半徑本來餵**卡面值** `ability.range`，
也就是會挑到一個**伺服器一定會回 `out-of-range`** 的敵人。現在也走 `reach`。

### 係數怎麼進來的（⛔ 沒有動 GameApp）

`mapGamepadFrame` 維持**純函式** —— 係數走 `GamepadPlayerCtx.abilityRangeMult`（可省略 = 1）。
填它的是 `GamepadSystem` / `MultiGamepadSystem` 的 poll，預設 provider 是
`() => envFactor("abilityRange")`，讀 `ui/displayFinal` 的即時 singleton
（`GameApp` 每幀用權威的 `MatchState.combatEnvJson` 同步它）。
⇒ operator 在後台改 `combat-env`，手把射程**當場**跟著動，⛔ 不必重新部署。

⚠️ `ctxProvider` 的型別從 `Omit<…,"lastAimDir">` 收窄成
`Omit<…,"lastAimDir"|"abilityRangeMult">` —— **收窄**是相容的，`GameApp` 一行都不用改。

⚠️ `GROUND_CAST_MAX` **保留匯出**：`input/TouchInput`（不在本 lane）的 tap / drag-aim
兩條路還在用它（拖曳有自己的 0..1 magnitude 語意）。檔頭已標成 LEGACY 並寫了量到的代價。

## ② 預覽圓心：手把瞄準向量，⛔ 不是滑鼠

`GameApp.resolveHoldPreview`（**不在本 lane**）唯一的落點來源是
`cursor.inside ? screenToGround(...) : null`，而 `cursor.inside` 只有 `mousemove` 寫得到。
純手把玩家 ⇒ `cursorGround = self` ⇒ **AoE 圈畫在自己腳下**。

⭐ 在**不動 GameApp** 的前提下修掉它：`AimResolver` 新增一格
「無游標瞄準」暫存器，而 `resolveAoeCenter`（GameApp 已經在呼叫的那一支）
在解析之前把 `cursorGround` 換成 `self + dir × ability.range`。

- 距離用的是**傳進來的** `ability.range` —— `resolveHoldPreview` 餵的正是
  **乘過 `envFactor("abilityRange")`** 的那一個 ⇒ 圈心永遠在真的打得到的最遠處。
- ⛔ `hoveredEntityId` 一律丟掉：它是用**滑鼠**落點挑的，手把在瞄準時那個 pick
  與玩家意圖無關。沒有目標就不畫圓 —— 畫一個錯的比不畫更糟（GH#415 的教訓）。
- 生命週期綁在 `PadDescribeHold`（跟 `ui/abilityHold` 同一個）：按住寫、放開／拔掉手把清掉，
  ⛔ 不留一個過期的方向去污染滑鼠玩家的預覽。

⚠️ 誠實記帳：這讓 `resolveAoeCenter` 不再是純函式（`resolveCastTarget` /
`buildCastCommand` 仍然是）。檔頭已經把這個例外寫明白。
替代方案是在 `GameApp` 多傳一個參數 —— 那是別的 lane 的檔，⛔ 不動。

## ③ 按空了要答一聲

`mapGamepadFrame` 新增 `refused?: CastableSlot[]`，兩種情況會進去：

1. `ctx.ability(slot)` 回 null（沒學／EX 沒解鎖／天生技是純被動）
2. `buildCastCommand` 回 null（`targeted` 沒目標、方向退化成零向量）

系統層對每一格叫一次 `abilityActivationCue(slot, { denied: true })` ——
⭐ **復用既有漏斗**：那條路自己接 `uiDenied` 音效 + 震動 pattern +
`castAnnounce.announceCastAttempt` → `predictCastReject` 的句子（冷卻中還有 N 秒／魔力不足／尚未學習）。
⛔ 沒有另造第二條回饋路徑。

⚠️ 在此之前這種按壓是**完全靜音**的 —— 跟一個掉包的封包長得一模一樣，
就是 `ui/castFeedback` 檔頭記的那個 P7 形狀。

## 守衛與突變

新檔 `apps/client/src/input/padAimReach.test.ts`（81 行，4 條）：

1. **承重**：兩支只差 `range` 的 ground 技能 → 兩個不同的落點距離，各自等於自己的射程；
   長射程那支 > `GROUND_CAST_MAX`。⭐ **一個常數不可能同時是它們兩個的射程。**
2. 係數乘得進去（mult 0.5 → 距離減半）
3. 按空的鍵回報 `refused`
4. 預覽圓心：`setCursorlessAim` 之後圓心離開腳下、落在搖桿方向上

⛔ **一個出貨數值都沒有抄進斷言** —— 夾具餵 range/mult，斷言的是關係。

**突變驗證（一批一條，挑承重的）**：把 `padCastReach` 的
`return ability.range * mult` 換回 `Math.min(ability.range, GROUND_CAST_MAX)`
→ **4 條紅**（新檔 3 條 + `GamepadInput.test.ts` 改寫過的 ground 那一條），
訊息直接指名「expected 6 to be greater than 6」與「expected 6 to be close to 3」。改回 → 綠。
