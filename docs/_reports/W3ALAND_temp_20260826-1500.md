## 2. 產生器 —— `w3a:build` / `w3a:check`

```bash
pnpm w3a:build     # 重生成三份產物
pnpm w3a:check     # 唯讀:逐位元組比對,過期回 1 並指名哪一份
```

照 `locust:build` / `jasscombo:build` 的前例，四個性質一個不少：

| 性質 | 怎麼做到 |
|---|---|
| **逐位元組 `--check`** | 重建三份 → 與磁碟上的字串比對；不同就 `exit 1` 並列出檔名 ＋ 修法 |
| ⛔ **零時鐘欄位** | 產物裡沒有任何日期/版號（同 `caps:export` / `spec:build` 的理由：一條被放寬的閘等於沒有閘） |
| **寫入點自解鎖** | `_write()` 先 `chmod 644` 再寫、收工 `chmod 444` ⇒ 產生器是合法寫入者，其餘通道（含 python/node 檔案 API）吃 `PermissionError` |
| **量尺先自證** | 引擎詞彙抽空、`content/abilities` 讀不到 100 份、帳本缺一個軸 ⇒ **硬錯誤 `SystemExit`**，⛔ 不是靜默退回空集合 |

### ⭐ 兩個方向的閘（同 `editorCapabilities.ts` 的判準）

`gap-ledger.json` 的 `axisVocabulary` 每一列宣告「這個 w3x 軸翻到 GGD 的哪一格」，
而產生器**去引擎裡查證**：

| 宣告 | 引擎現況 | 結果 |
|---|---|---|
| `supported` | 找得到那個名詞 | ✅ |
| `supported` | ⛔ 找不到 | **FATAL**：「落點寫錯了，或引擎把它拿掉了」 |
| `missing` | 真的沒有 | ✅ |
| `missing` | ⛔ **引擎已經有了** | **FATAL**：「把那一列改成 supported —— 一列說『這裡沒有』的宣告，下一個人讀到的是『不用做』」 |
| `status` 與 `probe.kind` 脫鉤 | —— | **FATAL**（見 §4 的突變 M-a：這個洞是我自己踩出來才補的） |

⭐ 引擎詞彙**全部從出貨的 TS 推導**（`statTypes.ts` 的 `Stat` 列舉 · `common.ts` 的
`attrRatios.attr` · `_shared.ts` 的 `zResourcePctTerm` 三個列舉），⛔ 不是手寫名單。
順帶量到一件事：**`Stat` 實際有 23 個名詞**，⛔ 不是兩份輸入報告寫的 17 個。
