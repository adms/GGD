## ⛔ 三個嫌疑：兩個**量過不是它**，第三個是**入口不是根因**

### ① `mix-blend-mode` / `mask-composite` / `filter: blur()` 疊在 canvas 上 —— ⛔ **不是**

掃出貨頁全 DOM（含 `::before`/`::after`），與中場 canvas 矩形求交集：

| 形狀 | 幾個 | 宿主 `isolation` |
|---|---:|---|
| `mix-blend-mode: screen`（`.ggd-btn::after`） | 5 | ⭐ 全部 `isolate` |
| `mask-composite: exclude`（`.ggd-btn::before` 家族） | 14 | ⭐ 全部 `isolate` |
| `filter: blur(0.3/0.4px)` | 10 | ⭐ 全部 `isolate` |

⇒ ⭐ **每一條都住在 `isolation: isolate` 的宿主底下**（`buttonFx.css:23`）
＝ 各自的堆疊脈絡 ⇒ **它們從來沒有跟 canvas 混合過**。
唯一沒被 isolate 的是 `MerchantTipBox` 的 `filter: drop-shadow(...)`（24,360 px²），
而它是**靜態**的，⛔ 不動。

**A/B 逐項關掉，量 rAF 幀距（1.2 秒 × 8 個變體）：**

| 變體 | fps | med | p95 | >16ms |
|---|---:|---:|---:|---:|
| base | 119.9 | 8.3 | 9.2 | 0 |
| 拿掉 `blur` | 120.0 | 8.3 | 9.2 | 0 |
| 拿掉 `mask` | 120.0 | 8.3 | 9.2 | 0 |
| 拿掉 `mix-blend-mode` | 120.1 | 8.3 | 9.1 | 1 |
| 拿掉環的無窮動畫 | 120.0 | 8.3 | 9.3 | 0 |
| **`.ggd-btn::before/::after` 全部拿掉** | **120.0** | **8.3** | **9.2** | **0** |
| 拿掉 `will-change` | 120.0 | 8.3 | 9.3 | 0 |
| base（回頭對照） | 119.9 | 8.3 | 9.2 | 0 |

⇒ ⭐ **把整組按鈕特效拿掉，主執行緒幀時間一毫秒都沒動。**
⛔ F3 的「81,449 px² 逐幀重繪」**量得到面積，但量不到代價** ——
那條推論鏈（重繪來不及 ⇒ tile 沒 raster 完）**不成立**。

### ② `backdrop-filter` 讀正在被寫的 canvas backbuffer —— ⛔ **不是（零個）**

商店狀態下**沒有任何** `backdrop-filter` 與 canvas 相交。
全 client 的 `backdrop-filter` 只在 AudioToggle 的**展開**面板、`ControlLegend`、
`AuthScreen`、`LeaveSettlementOverlay`、`MatchEndPanel` —— 這一刻**一個都沒掛載**。

### ③ 兩顆 Babylon engine 同時存在 —— ⭐ **是入口，但根因更下面一層**

兩顆 context 都活著、都沒掉（`perfBus.renderLoopErrors = 0`）。⛔ context 競爭沒發生。
⭐ 但量它的時候撞到真正的東西 ↓

## ⭐ 根因：中場那張 canvas 是一塊**要混合的透明層**

`getContextAttributes()`（兩張 canvas 都一樣）：

```
alpha: true          ← ⛔ Babylon 預設
premultipliedAlpha: true
preserveDrawingBuffer: false
```

引擎 fps 上限 **60**，而這台的合成器跑 **120** ⇒ **一半的幀沒有新內容**。
逐幀取樣 16 次，drawing buffer **完美地一幀有一幀無**：

```
inRaf:     nz=0/alpha=0 · nz=3600/alpha=255 · nz=0/alpha=0 · nz=3600/alpha=255 …（16 次零例外）
inTimeout: nz=0/alpha=0 ×16
```

⚠️ ⭐ **「無」那一半量到的是 `alpha = 0`（透明），⛔ 不是黑。**

⇒ ⭐ **這一格解釋了三個人看到的三種東西，而它們是同一個機制：**

| 誰 | 看到 | 透出去的是什麼 |
|---|---|---|
| L1 / F3 | **黑** | 頁面底色 `#0b0e14` |
| **owner** | **破圖** | 一份**半寫入的 premultiplied buffer**（色版超過 alpha ⇒ 顏色壞掉） |

⛔ 它們**不是兩個缺陷**，是**同一塊 alpha 合成層**的兩種樣子 ——
看到哪一種取決於 GPU/驅動怎麼處理「這一幀沒有新內容」。
⭐ **這正是它在我機器上不重現、在他機器上重現的原因**，也是為什麼
L1 的 CSS 背景與 F3 的合成層提升都只治到了症狀的一半。

⚠️ **誠實的但書**：`preserveDrawingBuffer:false` 的 canvas 在繪製幀之外被讀出來
**本來就規定是空的**，所以「讀到 0」有一部分是規格行為，⛔ 不是缺陷本身的證據。
⭐ 但**不受這個但書影響**的那一半才是重點：這張 canvas 的 context **宣告了 alpha**，
於是合成器**必須**把它當混合層處理 —— 而它的 `clearColor` alpha 本來就是 1，
中場也刻意蓋住底下的競技場。⇒ **那個 alpha 從頭到尾沒有任何用途，只有風險。**

---

## 🔧 修法（一格可回頭）

`INTERMISSION_GPU.opaqueCanvas: true` → `intermissionEngineOptions().alpha = false`。

- ⛔ **不改任何一個像素的外觀**：`clearColor` alpha 本來就是 1。
- ⭐ 合成器走**不透明**路徑 ⇒ 底下（或半寫入的 buffer）**沒有辦法**透出來，
  黑也好破圖也好，兩種樣子一起消失。
- ⛔ **一鍵回頭 = `opaqueCanvas: false`**（`IntermissionScene.ts`）。
- L1 的 CSS backfill 與 F3 的合成層提升**都留著** —— 它們現在是第二、三道防線，成本為零。

⭐ 順帶把引擎選項抽成純函式 `intermissionEngineOptions()`：
在此之前 `engineFactory`（測試的 NullEngine）**整個繞過**建構子那一行
⇒「出貨真的送了什麼選項」**沒有任何守衛看得到**（失敗形態⑤）。

## 🧪 守衛（驗**結構**，⛔ 不驗「畫面上沒有破圖」）

`apps/client/src/render/intermission/intermissionCanvasOpaque.test.ts`

1. 出貨的引擎選項宣告**不透明** context（期望值從旋鈕推導，⛔ 不抄字面值）
2. 每一條 `mix-blend-mode` 都被 `isolation: isolate` 關住
