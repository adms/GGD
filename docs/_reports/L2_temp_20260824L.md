## 這一批解掉的是什麼

原作 285 次 `AddSpecialEffectTarget`（timed 掛件）的形狀是「**一次性特效掛在施法者
模型的骨頭上**」。在此之前 `spawnVfx` 只有 `self / target / point` 三個世界座標落點
⇒ 43 支這種形狀的技能沒有任何機制可以引用（第〇·五守則：**引擎做機制、JSON 做技能**）。
本輪只做**機制**那一半 —— ⛔ 一支內容都沒改（43 支是第 2 批）。

退路，⛔ 不是冗餘欄位。

## ⭐ 為什麼是「世界座標」而不是「把粒子系統認父到骨頭節點」

這條路上的每一份 vfx doc 都被 `frontLoadDoc` 壓成「所有粒子誕生在同一幀」的 one-shot
⇒「掛著跟隨」與「在骨頭此刻的位置爆開」**逐位元等價**，而 pool 的
`(ps.emitter as Vector3).set(...)` 契約不必被打破（emitter 換成節點之後，
下一次複用就是一次 TypeError）。

## 三格退路階梯（⚠️ 每一格都**畫**，差別只有落點；各記一次 log，⛔ 不吞）

1. `resolveAttachment` 命中節點 → **節點世界座標**（`hand,right` 的逗號寫法、
   `handright`、`Bone_Hand_R`、尾空白 —— 六種命名慣例同一條規則解得開）
2. 模型在、鏈上一根都沒有（替身骨架）→ **模型根 + 胸口高度（`ARC_BODY_Y`）**
3. 連 `champ-<id>` 節點都沒有（體素替身／模型還在載）→ **事件座標 + 胸口高度**

## 本輪補的三個缺口

1. **2 個 tsc error（L1 回報的）**：根因是 `VfxSpawnEvent` 寫成 **`interface`** ——
   interface **拿不到隱含索引簽章** ⇒ `world.emit(…, payload)`（要
   `Record<string, unknown>`）與客戶端的 `ev.data as Partial<VfxSpawnEvent>`
   **兩個方向都是紅的**。前一輪用 `as unknown as Record<string, unknown>` 把
   sim 那一半塞過去（⛔ 一個靜默的洞），客戶端那一半就沒地方塞了。
   ⇒ 改成 **type alias**，兩邊直接成立，`as unknown as` 一併刪掉。
   `pnpm typecheck` **EXIT=0**。
2. **出貨鏈守衛**（新檔 `apps/client/src/vfx/VfxSystem.boneAttach.test.ts`）：
   真 Zod → 真 `SimWorld` 跑真 `effectRunner` → **真的事件** → 出貨接縫
   （`ev.data` 原樣轉發，`eventFanout.ts` 檔頭第 2 點；`vfxSpawn` 早就在白名單上，
   本輪⛔ 沒有新事件名）→ 真 `VfxSystem.handleEvent` → **讀回 Babylon 手上發射器
   的世界座標**。⛔ 全程沒有手捏 payload（失敗形態⑤）。
   四條：①骨頭命中 ②替身骨架退回胸口（仍然畫 + log 一次）③無模型退回事件座標
   ④**沒有 attach 的一般 `spawnVfx` 一位元不變**（y=1.0、事件座標、sim ⛔ 不送 attach）。
3. sim 側守衛的 `vfxId` 改成真的存在的文件 id（`fx.w3x.orb.herocloudkfksword.p00`）。
