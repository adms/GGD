# H3 — typecheck 增量化（tsc incremental）

日期：2026-08-23 · lane H3 · 柵欄：各 package tsconfig*.json · package.json typecheck script · tools/parallel-gates/

## 做了什麼

15 個有 `tsc --noEmit -p tsconfig.json` 的 package 全部開增量：

| 群 | package |
|---|---|
| packages | shared |
| apps ×6 | client · admin · game-server · content-api · editor · test-dashboard |
| tools ×8 | anime-arena-map · capability-export · model-budget · role-classify · todo-check · ttk-sim · uptime-probe · voxel-gen |

每份 tsconfig.json 的 compilerOptions 加兩行：

```jsonc
"incremental": true,
"tsBuildInfoFile": "./node_modules/.cache/typecheck.tsbuildinfo"
```

（tools/tts-gen 的 typecheck 是 `node --check`，不適用，未動。）

## 為什麼是這個形狀（⛔ 不是 tsc --build / project references）

- repo 沒有 composite references；apps 是靠 `paths` 直接把 `@ggd/shared` 指到**原始碼**。
  上 project references 要開 `composite` + `declaration` emit，等於改每個 package 的
  typecheck 語意與依賴圖 —— 超出「不可變弱、不可變形」的界線。
- 逐 package `incremental: true` 是 tsc 原生快取：第一次全量推導並把逐檔
  semantic diagnostics 寫進 buildinfo，之後只重推「內容 hash 變了的檔 + 受它影響的檔」。
- **快取失效保守**：tsconfig 變（含 extends 鏈）或 TS 版本變 ⇒ buildinfo 整份作廢、
  自動退回全量 —— tsc 自己保證，不用任何額外機制。
- `.tsbuildinfo` 不進 git：落點在 `node_modules/.cache/`，被既有的 `node_modules/`
  與 `*.tsbuildinfo`（.gitignore 第 21 行）雙重蓋住 —— .gitignore 一行都不用加（柵欄外）。

## 語意不變的證據

- root `typecheck` script 原封不動：`pnpm -r --no-bail --if-present typecheck`。
- 每個 package 的 script 原封不動：`tsc --noEmit -p tsconfig.json`。
- tools/parallel-gates/ship.mjs 呼叫的就是 root `pnpm typecheck`，不用改。
- **突變（⛔ 判準沒有被削弱）**：在 apps/client/src/render/views/mobTint.ts 塞
  `const __h3Mut: number = "not-a-number";` → 增量模式（快取熱）跑
  `pnpm --filter @ggd/client typecheck` → **EXIT=2（紅）**，錯誤 1 行。
  拔掉後檔案逐位元組還原（git diff 空）。

## 量測（機器同時有其他 lane 在跑，數字含 CPU 競爭噪音）

| 情境 | 時間 | 離開碼 |
|---|---:|---|
| ① 冷（刪光 tsbuildinfo，15 包全量） | 38s | 0 |
| ①b 熱・零改動 | 12s | 0 |
| ② 改一行 apps/client（加註解） | 13s | 0 |
| ③ 改一行 packages/shared（加註解） | 15s | 0 |
| 突變（型別錯，只跑 client 包） | 5s | 非零 ✅ |

基準線：任務單給的 110–130s 是 ship 並行段（與 vitest、skills:check 搶 CPU）下的量測；本機單獨跑的全量＝冷跑 38s。⭐ 增量省掉的是「全量→只推改動」那一段，兩種負載下都成立：熱路徑 12–15s ≈ 冷的 1/3，其中大半是 15 支 tsc 進程啟動＋讀 lib 的固定成本。

## 附註

- 量測探針（兩行註解 + 一行突變）全部已還原，`git diff` 對兩個探針檔為空。
- 首次跑會建 `node_modules/.cache/`，tsc 自己 mkdir，不需要任何前置步驟。
- 冷跑（CI、換 TS 版本、改 tsconfig.base.json）仍是全量成本 —— 增量只救日常迭代。
