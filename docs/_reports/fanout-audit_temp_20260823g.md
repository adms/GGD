## 0. 一句話結論

⭐ **扇出的成本不在「閘太多」——36 支 `skills:check` 全跑只要 ⏱45.6 秒。**
真正把「改一格」放大成「半小時」的是三個架構事實：

| # | 根因 | 形狀 | 誰在付錢 |
|---|---|---|---|
| 1 | **出貨值抄進測試**（game-server 7 條 + admin 7 條） | 改一格 ⇒ 14 條紅 ⇒ 被逼走「修測試 commit → 全測 → 全量部署」 | ⏱ 08-23 實測：owner 開口→上線 **59 分鐘**，其中一整個 commit（15:01）只是在修這族測試 |
| 2 | **同一份知識有第二個住處，靠「重生成」對齊** —— 英雄卡內嵌鏡射（含 `effects`、`description`）、cooldown/mana/range 的烘值、90 支技能參數住在 python 產生器 | 每一個住處 = 一個「必須跑 sync」的理由 = 一次**全域鎖**排隊 | 每次內容改動 估 60–120s + 併行 lane 全部停等 |
| 3 | 分級部署與按路徑選閘**直到今天才有工具**（`tune.sh` / `ship.sh`，08-23 落地） | 慣性是全量：typecheck 39s + 七包 223s + 遠端 build 191s | 每次 ⏱ ~7.5 分鐘的機械成本，其中大半與這次改動無關 |

⇒ ⭐ **「3 分鐘」對 T0/T0.5 改動已經在射程內（見 §4），對程式改動（T2）在 build 修好之前
機械下界就 ~5 分鐘 —— 這一句是可反駁的誠實線，⛔ 不要對 owner 承諾做不到的數字。**

## 2. 改動②：一格暈眩秒數（例：`godie-e008.e` 落地後暈眩 1→2 秒）

先列**查證過的事實**（實檔 `content/abilities/godie-e008.e.json`）：

- 暈眩秒數是**字面值**：`effects[].duration: 1.0`。五級距家族（傷害/冷卻/耗魔/距離/範圍）**沒有 duration 一族**，佔位家族（`{{dmg}}/{{cd}}/{{mp}}/{{radius}}`）也沒有 ⇒ 卡面那句「落地後暈眩1秒」要**手改**。
- `effects` 與 `description` **整包鏡射**進英雄卡（`apply_tiers.py::MIRRORED` 含 `"effects"`）⇒ 同一個 1.0 有**兩個住處**，`abilityMirror.test.ts` 在守（2026-08-21 radius 那次量到 30 筆矛盾）。
- 420 支裡 **90 支的參數住在 `tools/skill-remake/heroes/*.py`** —— 直接改那 90 份的 JSON 會在下一次 `skills:sync` **靜默消失**（GH#319，`apply_tiers.py` 檔頭逐字）。

| 下游 | 判定 | 理由 | 現在的成本 | 省幾秒 |
|---|---|---|---|---|
| standalone JSON＋英雄卡內嵌**兩處都改**（或跑 `tiers:apply` 鏡射） | 今天必要；⭐ **該刪（架構）** | 內嵌副本應改成**載入時從 standalone 展開**（第〇·四守則自己的判準：值在載入時解析，⛔ 不烘進每一份文件）。住處消失 ⇒ 鏡射器＋`abilityMirror` 那一族的存在理由一起消失 | 每次多編一份＋一支鏡射閘 | 估 **每次 ~60s** ＋ GH#319／30 筆矛盾**整類事故**歸零。可反駁點見 §6b |
| 卡面文字「暈眩X秒」手改 ×2 | ⭐ **必要**（第一·五守則：卡片不說謊） | 修法方向：補 `{{stunSec}}` 佔位家族（0.4 守則第 4 步的缺口）—— 之後值改文自動對 | 估 ~30s 手改＋一種說謊風險 | 估 **~30s/次** |
| `content:build`（連帶重生成 spec/overview/tiers 三份文件） | ⭐ **必要** | 同①；且 spec 的範例**從 content 抄** —— 這支技能若是範例，文件同步就在這一步完成 | ⏱ ≈9.7s | 0 |
| T0.5 閘子集：`skillnorm`＋`prose`＋`abilityMirror`＋`abilityCodeParityForms` | ⭐ **必要** | prose/skillnorm 抓過真謊話（石化之眼）；mirror/parity 守兩個住處與 join key | 估 ~20–25s | 0 |
| 其餘 30+ 支 check 與 sync 產物（audit／templates／shapes／contract:numbers／90支md／readme／status／board…） | **可自動化** | 今天 T0.5 靠「裁掉不跑」省時間 ⇒ **帳掛給下一個跑 `skills:check` 的人**（他看到紅，還以為是自己弄的）。正解是**增量 sync**：輸入→產物的指紋圖，只重生成吃這一份的那幾支 —— `skillsSyncCoversGenerators` 已把 31 支點名，指紋圖是它的直接延伸 | sync 全鏈 估 60–120s＋**全域鎖**讓併行 lane 全停 | 估 **60–120s/次**＋排隊時間歸零 |
| **若這支是 90 支那邊**：改 `heroes/*.py` → 必跑全鏈 sync | ⛔ **該刪（架構）** | owner 的規格是**內容**不是程式（第〇·五守則自己說技能=資料）。參數表搬進資料檔 ⇒ 90/330 兩條寫入路徑合一，「手改被靜默洗掉」整類消失 | 單值改動被放大成全鏈重生成 | 估 **~2–5min/次**（凡落在那 90 支上） |
| vitest shared＋game-server ⏱109.3s | **可自動化** | 真正的行為閘是 `arenaRules` 全場模擬 —— **⏱3.4 秒**本機打完一場真內容的比賽 | ⏱ 109.3s | ⏱ **~95s** |
| **種子釘住結果的比賽測試**（0.4 守則帳單裡「重掃種子第 5 次」那族） | ⛔ **該刪**（改性質斷言） | 「同種子同結果」是決定性、必要；「種子 X 下贏家是 Y／等級是 Z」是把出貨行為抄進測試的同病 —— 每次平衡改動都要人手重掃 | 估 10–30min/每次平衡改動 | 估 **10–30min/次** |
| T2 `--content-only` | ⭐ **必要** | 08-02 紅線原封不動：碰到 `schema/` 一個 byte 就出局 | ⏱ ~30s | 0 |

## 6. 方法、界限與可反駁點

- 數字來源：⏱ 全部引自 `docs/_reports/deploy-cost_temp_20260823-1547.md`（08-23 當天量測）＋
  `package.json`／`scripts/tune.sh`／`tools/deploy-timing/tiers.json`／`tools/skill-remake/apply_tiers.py`／
  `packages/shared/src/ops/ownerKnobs.test.ts`／實檔 `godie-e008.e.json`。唯讀；sync 全域鎖未跑。
- **(a)** 「anchors/skillnorm/prose 對 combat-env 恆綠」是從推導鏈讀出來的，⛔ 沒有突變驗證過 ——
  若要細分閘選擇，先做一次突變（把倍率塞進 anchors 推導 → 那支要紅）再裁。每支 ~1s，保費極低，**留著也合理**。
- **(b)** 內嵌鏡射退役（序 5）動的是**對外契約**：外部編輯器與客戶端今天讀哪一份副本要先查清楚
  （mirror authority model 是 owner 選過的 STRICT 模型）—— 這條要 owner 點頭，⛔ 不是純內部重構。
- **(c)** 觀察（⛔ 非指控，另一條 lane 施工中）：稽核當下 `tune.sh` 檔頭已宣告 T0.5 需要
  mirror/parity 兩支單檔 vitest，**主體迴圈還只跑 T0 的四支** —— T0.5 收尾時這兩支要真的接上，
  否則暈眩改動正好落在它守的那個洞上（兩份副本互相矛盾而全綠）。
