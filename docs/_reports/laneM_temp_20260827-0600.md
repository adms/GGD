## ① #795 Scope③ —— 報告自動蓋 `HEAD=<sha>` ✅ 落地

### 做了什麼（兩半，缺一半都不成立）

| 半 | 在哪 | 是什麼 |
|---|---|---|
| **① 產生端** | `scripts/visual-proof.sh --new <題目>` | 開一份報告骨架到 `docs/_reports/<題目>_visual-proof_<YYYYMMDD-HHMM>/frames.md`，開頭**自動蓋** `> 📅 …：`HEAD=<sha>`[ 工作樹]` |
| **② 檢查端** | 同一支的閘路徑 | 這次改動附上的報告**沒有** HEAD ⇒ 大聲指名 + 給出可貼的那一行（fail-open）；`GGD_VISUAL_PROOF_HEAD_STRICT=1` ⇒ 升級成擋下 |

⭐ 附帶關掉一個**我自己新開的洞**：`--new` 讓「開一份報告」變成一行指令，

⇒ 骨架帶一行機器可讀哨兵 `GGD_VISUAL_PROOF_SKELETON`，**沒刪掉就不算證據**（閘會指名它）。

### ⛔ 刻意沒做的事

**⛔ 不自動幫既有 23 份報告補 HEAD。** 替一份不知道何時拍的報告蓋一個今天的 sha
＝**捏造證據**，比沒有標記更糟。#795 的 Implementation constraints 逐字寫了這一條。
⇒ Scope④（回頭補）**仍然開著**，而且它是**逐份的考證工作**：
唯一補成功的那一份（`invprim_visual-proof_20260826-1700`）用了兩個獨立出處
（作者自己寫的「工作樹＝`e44bf446`」＋ PNG mtime 與 commit 時間的夾擠），⛔ 不是查表。

### 「以後產出的都帶」是怎麼驗的（⛔ 不是我說的）

`packages/shared/src/ops/visualProofScript.test.ts` 第二條 `it()`
—— **真的把腳本跑起來**（sandbox 是一個真的 git repo），四段一起驗：

1. `--new` 蓋的 sha，拿**出貨的撈取器** `tools/review/features.mjs::evidenceHeadOf()`
   去撈 ⇒ 必須等於 sandbox 的 `git rev-parse --short=8 HEAD`。
   ⭐ 這一段是刻意的：⛔ **不抄一份正則**進測試（那是第二個住處，而它會安靜地漂開）——
   直接 import 那一支，兩邊哪天不同調就紅。
2. 空骨架 ⇒ 閘**仍然紅**，並指名「骨架」。
3. 刪掉哨兵（＝填完）⇒ 綠，而且⛔ 不再吼 HEAD。
4. 手寫、沒有 HEAD 的報告 ⇒ 綠（fail-open）**但一定被指名**；`…HEAD_STRICT=1` ⇒ 非零。

**突變驗證（一批一條，最承重）**：把 `--new` 蓋 HEAD 的那一行 printf 換成「（待填）」
⇒ 第 1 段紅（`evidenceHeadOf` 回 null）。`cp` 還原（⛔ 不是 `git checkout`）。
