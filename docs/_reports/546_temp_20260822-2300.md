## 環 ① —— 六個算繪點：改成呼叫**三態**入口

⛔ **落地之前**：六處全部是舊的兩態形狀，`abilityTileFrameStyle()` 在出貨路徑上
**唯一的呼叫者是它自己的單元測試**。

| 檔 | 磚 | 槽位 |
|---|---|---|
| `AbilityBar.tsx` | 天生技 · QWER · EX | `INNATE_SLOT` · `slot` · `"EX"` |
| `TouchControls.tsx` | QWER · EX · 天生技 | `slot` · `"EX"` · `INNATE_SLOT` |

⭐ **做法不是「六處各加一個 `toggleOn:`」**，那樣下一個新磚家族照樣會漏。
改成一個共用元素 `AbilityTileFrame`（`ui/abilityReadyFrame.ts`）——
它把「**畫哪一種框**」與「**畫出來**」合成同一個東西，
⇒ 一個算繪點想畫框就非得經過三態不可，⛔ 它沒有辦法只畫就緒框。

被取代的形狀（六份）：

```tsx
{isAbilityTileReady({…}) && <div style={abilityReadyFrameStyle(RGB)} />}
```

現在：

```tsx
<AbilityTileFrame rgb={RGB} state={{ …, toggleOn: seatToggleOn(seat, slot) }} />
```

⚠️ `seatToggleOn` 收的是**槽位的名字**（`"Q"` / `"EX"` / `INNATE_SLOT`），
⛔ 不是數字 —— 位元編號 = `CASTABLE_SLOTS` 的索引，而那張表已經存在了。
收數字的話 EX 與天生技那兩格會在四份呼叫端各自手寫 `4` / `5`，
而那正是 `AbilityBar` 檔頭在警告的「螢幕順序 ≠ 線路順序被順手整理」的形狀。

## 環 ② —— `toggleOn` 上線路：**`SeatState.toggleMask`（uint8，六格各一顆 bit）**

### 為什麼**不是** `ENTITY_FLAG` 的六顆 bit（三個理由，寫在宣告上）

| # | 理由 |
|---|---|
| ① | **逐技能** ⇒ 一顆 bit 不夠。`ENTITY_FLAG_FREE_BITS` 只剩 **11 格**，一次拿走 6 格（超過一半）去換一件**只有自己那六顆按鈕會讀**的事，是把全域最稀缺的資源花在最局部的用途上 |
| ② | **逐座位，不是逐實體**。`EntityState.flags` 每一隻殭屍、每一顆投射物都揹著它；切換態只對有技能列的座位有意義。它與 `cooldowns` / `statusIds` 是**同一種資料**（「自己身上的」），所以住同一個地方 |
| ③ | **換算得回來**：bit i = `CASTABLE_SLOTS[i]`，與 `cooldowns` 的索引、`data-cast-slot`、`CastTracker.SLOT_INDEX` **同一套編號**，⛔ 不發明第二套順序 |

uint8 裝得下六格還剩兩格。0 = 全部關著 ⇒ **舊的／還沒投影的快照**讀成
「沒有任何技能開著」，也就是這一格出現之前畫面唯一畫得出來的樣子。

### APPEND-ONLY 遵守情形

`toggleMask: "uint8"` 加在 `defineTypes(SeatState, …)` 的**最後一格**，
⛔ 沒有動任何既有欄位的位置或型別。⇒ 這**不是**不可逆的協定變更
（對比 2026-08-18 的 `ENTITY_FLAG` uint16→uint32），可以用一般部署上。

### 唯一的編解碼器

`packages/shared/src/protocol/schema.ts`：

```ts
export const TOGGLE_MASK_SLOTS = 6;
export function toggleMaskHas(mask: number, slotIndex: number): boolean;
export function toggleMaskWith(mask: number, slotIndex: number, on: boolean): number;
```

⛔ 全專案不可以有第二處手寫 `1 << i`。界外索引一律讀成 false / 原封不動回傳。

⚠️ `protocol/` 刻意**不 import `sim/intents`**（線路層 ⊥ 規則層，這個檔今天一個
GGD 內部 import 都沒有）⇒ `TOGGLE_MASK_SLOTS === CASTABLE_SLOTS.length` 的對帳
放在守衛裡做。有人加第七個 castable slot 時它會紅，⛔ 而不是靜默截掉第七格。

## 守衛（一條承重的 + 一條對帳）

`apps/client/src/ui/abilityToggleWiring.test.ts`（**138 行**，實作側改動 ≈ 150 行）

⛔ **不掃原始碼、不掃 CSS 字串**：把出貨的 `<AbilityBar/>` 與 `<TouchControls/>`
真的用 `renderToStaticMarkup` 渲染出來（這個 repo 的既有做法，見
`components/abilityBarScale.test.ts`），數畫出來的 HTML 裡有幾個元素帶著
`TOGGLE_ANIM_NAME`。

⭐ **夾具讓每一格技能都在冷卻中**（`cooldowns` / `exCooldown` / `passiveCooldown`
全部 > 0）。這是這條守衛的核心：出貨的 20-01 風王結界**開著的期間自己就在 60 秒
冷卻裡**，所以就緒框對它是 false。⇒ 讓就緒框全部不亮，畫面上剩下的每一個框
都只可能來自「開啟中」那條路。

| 斷言 | |
|---|---|
| 遮罩 0 → 開啟框 **0** 個 | 沒有技能開著卻畫了框 = 誤報 |
| 六格全開 → 開啟框 **`CASTABLE_SLOTS.length × 2` = 12** 個 | 少接任何一個算繪點都會低於它 |
| `TOGGLE_MASK_SLOTS === CASTABLE_SLOTS.length` | 加第七格不可以被靜默截掉 |

### 突變紀錄（接線類，一條）

`AbilityTileFrame` 的 `abilityTileFrameStyle(...)` 換回落地前那個形狀
`isAbilityTileReady(…) ? abilityReadyFrameStyle(rgb) : null`
→ 🔴 `expected +0 to be 12`（六個算繪點一個開啟框都畫不出來）。已改回。

⛔ 這條**不驗**顏色 / `sweepMs` / `rimPx` —— 那些是數字，已經有三個住處與漂移守衛。

### ① `apps/game-server/src/net/snapshot.ts` —— 接在 `ss.passiveCooldown = …` 後面

```ts
// GH#546 —— 開關型技能開著沒有,六格各一顆 bit。⛔ 位元一律走 `toggleMaskWith`,
// ⛔ 不要在這裡手寫 `1 << i`(那會是第二個住處,而它漂掉不會報錯,只是永遠關著)。
let toggleMask = 0;
for (let i = 0; i < CASTABLE_SLOTS.length; i++) {
```
