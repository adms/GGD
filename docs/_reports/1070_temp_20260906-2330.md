### 為什麼讀 `inAlternateForm` 而不是 `championFormIndex`

lane 指令說讀 `championFormIndex`（`sim/systems/ChampionFormSystem.ts`）。實際用的是 `sim/formGate.ts::inAlternateForm`，理由：
1. `formGate.ts` 檔頭逐字寫它是「我現在算不算在替身形態」的**唯一答案**（M2 起 = 換了身體 **OR** 身上帶著 tags 含 `form` 的狀態）。`AbilityPassiveRank.whileForm` 讀的就是它 —— 條件葉再讀一次 `championForm` 就是第二個答案（狀態型的形態：卍解／witch-form 會漏）。
2. 對 09-04／11-03／11-04 這三對**換身體**的變身，兩者答案逐位元相同。
3. import 環：`formGate.ts` import 這個檔的 `hasStatusTag`，所以 `condition.ts → formGate.ts` 是一個環。⭐ 它是安全的：兩邊都只在**函式本體**裡用對方，沒有頂層求值（⛔ 不是 `zRef` 那種載入當下就要的常數）。註解寫在 import 行旁。`ChampionFormSystem` 的環更大（→ abilityPassives → formGate → condition，＋ itemSource 那一支）。
