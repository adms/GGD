## 本機來源編輯的失敗復原

實測確認舊 `editor-source` 寫入端在產生器中途失敗時只還原 Python 來源，已寫出的技能、英雄鏡像與索引仍會殘留，卻回報「產物一個位元組都沒動」。現在改寫前先建立獨立復原副本，涵蓋來源、完整 content 樹及該產生器在 sync-io 宣告的其他產物；保存與再次核對完成後才執行既有註冊指令。捕捉到生成失敗時，還原原始位元組與權限、移除新增產物，再核對結果。復原失敗明確回 503，保留檔案對照表及副本，不宣稱已完成復原。

`source-recovery/before.log` 是先確認失敗的回歸。最終案例使用真子行程寫出半套技能、另一英雄受正規化影響的技能、鏡像、索引、唯讀生成文件，刪除二進位壓縮檔並新增產物後退出：7 份原檔逐位元組復原、1 份新增產物移除，無關文件保持不變。成功生成仍保留結果；生成中出現不安全連結時保留可用復原對照並回 503。17 項定向測試及 Content API 型別檢查通過。測試行程內刻意移除復原動作後，回歸確實失敗；突變未改寫工作樹程式，也未影響執行中的服務。macOS `/var` 與 `/private/var` 等價路徑造成的一次測試斷言失敗另存原紀錄，已改用實際路徑比較。

在目前工作樹只做讀取、建立副本與核對，涵蓋 9,825 份檔案、255,946,722 bytes，耗時約 2.94 秒，全部維持原位元組；沒有執行生成器或還原。首次 tsx CLI 因 IPC 權限失敗，改用不建立該 IPC 的 `node --import tsx` 執行同一腳本，原始錯誤及成功紀錄均保留。此修正限於同步本機來源編輯所捕捉到的失敗，不宣稱涵蓋服務被強制終止、外部 CLI 同時寫入或歷史生成器完整重建；既有永久版本庫照常在操作前保存。這輪未重啟 37 名英雄服務、未變更已發布版本，也未重跑整組 Editor 發布閘。
