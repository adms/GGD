所以做成摺疊。

## 2. 做了什麼

### ① 摺疊／展開（`RoundVictoryPanel.tsx`）
- 卡頭多一顆摺疊鈕；收合時**卡身整段不渲染**。
- ⭐ 根節點的 `position/left/top/width/max-height` **一個位元組都沒動** ——
  它是 `absolute + width + max-height`，高度是 `auto`，所以「不渲染卡身」＝ 盒子自己
  縮成一條卡頭。⛔ 改根節點的 `max-height` 會被 `hud/hudSurfacePaint.test.ts` 的
  閉集合允許清單抓到（那條守衛逐一讀回四個邊）。
- ⛔ 不是 `display:none` / `height:0`：那兩種都留著一個看不見卻仍在版面上的盒子。

### ② 預設值 = 後台一格（第一守則，三個住處）
`config.victory-podium@1` 新增 **`roundCardCollapsed`**（`.optional()`，理由同
`podiumZoneSource`：線上已有耐久覆蓋層，少必填欄會讓整份內容被 Zod 退回）。

| 住處 | 檔 |
|---|---|
| 出貨值 | `content/config/victory-podium.json`（`true`）＋ note 補一段 |
| Zod + DEFAULT | `packages/shared/src/content/schema/victoryPodium.ts`（policy 欄位 / DEFAULT / resolve / `VICTORY_PODIUM_FIELDS`）|
| 後台 | `apps/admin/src/configForms.ts` 的 `VICTORY_PODIUM_SPEC` 一列 |

出貨值選 **收合** ＝「不擋到模型」的那一邊（第〇·六守則：優先權大的更新後預設啟動）。
面板每一回合重新掛載，所以玩家展開之後**不會黏到下一回合**。

### ③ 手把
- 摺疊鈕是**真的 `<button>`**（`SfxButton`）—— `PadFocusNav` 的 `FOCUSABLE_SELECTOR`
  只認 button/a/input/[tabindex]，掛 onClick 的 `<div>` 手把永遠摸不到。
- `pointerEvents: "auto"`：卡片根節點是 `pointer-events: none`，不打開的話按鈕
  **畫得出來、聚焦得到、按不下去**。
- `data-pad-back`：B 直接收起來。

## 3. 守衛（一條承重的線 + 一次突變）

`apps/client/src/ui/panels/roundVictoryCollapse.test.ts`（101 行）
- 展開 ⇒ 卡片下緣 **>** 銅牌卡下緣（整片蓋過去 —— owner 看到的那個）
- 收合 ⇒ 卡片下緣 **<** 銅牌卡中線（踩在地上的模型本體整個露出來）
- 收合後的高度**從渲染出來的標記算**（root `padding` + `data-ggd-round-head` 的
  `height`），⛔ 不是讀常數（否則是失敗形態 ⑤）
- 頒獎台幾何**讀 `render/RoundWinnerStage.ts` 的原始碼**（同 `roundReportLayout.test.ts`
  讀 `Minimap.tsx`），⛔ 不抄一份數字；模型列被挪走這一支會跟著紅
- 摺疊鈕：`<button>` + `data-pad-back` + `aria-expanded`
- 後台那一格真的被出貨面板讀到（`roundCardStartsCollapsed()` == `DEFAULT_*`）

**突變（做過一次）**：`{!collapsed && (` → `{true && (`（收合等於沒收）
⇒ 2/2 案例紅（「卡身還在 ⇒ 盒子沒縮」+ 高度斷言），其餘 6 個測試檔全綠。改回。

⚠️ 誠實記錄：1280×720 這個最擠的視窗上，**收合後仍然壓到模型卡最上面約 30px 的
頭頂空白** —— 註冊表把這個 surface 的上緣放在 y=210，模型列從 y≈241 開始，中間只有
31px。⛔ 沒有靠「把卡頭壓到 30px」去讓數字好看（那會讓等第與抬頭讀不出來，而且換一個
視窗又會翻掉）。要完全零重疊得改 `hudSurfaces` 的 `round-victory` 版位，那是 #107 的
lane，⛔ 不是這一條。
