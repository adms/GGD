## ② 機制：`ability@1.persistentVfx`（⛔ 不是為莉娜寫一個 if）

`packages/shared/src/content/schema/ability.ts`

```jsonc
"persistentVfx": [
  { "vfxKey": "attach.ex.midchilder-aura",   // vfx 集合（vfx@1 / ribbon@1 / attachment@1 都可以）
    "attach": "origin",                      // 缺席 = PERSISTENT_VFX_DEFAULT_ATTACH = 腳下
    "when":   { … },                         // 缺席 = 「這支技能在身上就掛著」
    "scale": 1, "alpha": 1 }
]
```

### ⭐ 三個決定，都是為了**不新增第二套東西**

**(a) ⛔ 沒有新的條件葉。** owner 的提示是「等級**或是技能已學習**的 JASS」，
而這兩者在 GGD 都已經寫得出來：

| `when` | 意思 | 對應 JASS |
|---|---|---|
| **缺席** | 這支技能在身上／已解鎖就掛著 | `GetUnitAbilityLevel(u,'A0xx') > 0` |
| `{kind:"stat", subject:"self", stat:"level", op:">=", value:N, mode:"absolute"}` | 等級門檻 | `GetUnitLevel(u) >= 30` |
| `{kind:"status", …}` | 在某形態 | `udg_*Form` 那一族 |

⭐ **`level` 早就在 `PLAIN_STATS` 裡**，所以原作的 `>= 30` 逐字寫得出來，
⛔ 不必造 `condition.ability-learned@1` / `condition.ex-mode@1`。
造了反而糟：那兩片葉子不會被 `drawChances` 的 RNG 順序、`CONDITION_MAX_DEPTH`
的深度上限、`describeCondition` 的文案器、編輯器的渲染器認得（四個地方各要補一次）。

**(b) 為什麼不是既有的 `config.ambient-vfx@1.bindings`。**
那張表是**無條件**的，鍵是 modelKey / championId（「這具身體永遠戴著」）——
「EX 解鎖**之後**才戴」不在它的形狀裡。把常駐特效掛在**技能**上，
「這支技能在不在身上」**自己就是條件**，⛔ 不需要第二張表。

**(c) ⛔ 刻意沒有 `durationSec`。** 常駐特效的終點是「條件變 false」，
給它一個時鐘就是允許「條件還成立但特效沒了」這種兩個真相打架的狀態。

## ③ 客戶端：`apps/client/src/render/views/persistentVfx.ts`

⭐ **這個檔案存在的理由只有一件事：移除。** 「掛上去」repo 裡已經有三條路
（`W3xEmitterRig` / `AmbientVfx` / `ChampionView.setFormAttachment`），
缺的一直是**條件變 false 的那一刻**。

| 假的移除 | 為什麼是假的 |
|---|---|
| `alpha = 0` | 粒子照噴、材質照算 —— #262 特效洩漏就是這個形狀 |
| `durationSec` 給很大 | 時鐘到了就消失，⛔ 條件可能還成立 |
| 什麼都不做等 root dispose | 條件在**同一具身體上**變 false 時 root 還活著 |

承重的兩行（`PersistentVfxChannel.sync`）：

```ts
handle.cancel();            // 真的殺掉
entry.handles.delete(key);  // 而且不再記著（不刪 → 條件重新成立時不會重掛）
```

另外兩個真的洩漏路徑也關了：**句柄自己死掉**（`alive === false`）會被清出帳本；
**換了一具身體**（變身／重建模型，`root !== entry.root`）會先整批 cancel ——
否則就是 #131 的孤兒發射器（Babylon 把子節點丟回世界原點繼續噴）。

`sync()` 是**冪等**的：同一份 desired 連呼叫兩次不重掛（重掛會閃一下，而且是一次洩漏）。

⭐ Port 的形狀**逐字對齊** `W3xEffectHandle`（`cancel()` / `alive`），
⛔ 不是為了測試發明的介面 —— 出貨要接的就是 `W3xEmitterRig.play()` 回的那個東西。
