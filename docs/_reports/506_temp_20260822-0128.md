# K7 · GH#506 — ControlLegend 印了做不到的鍵

日期 2026-08-22 · lane 檔案柵欄：`apps/client/src/ui/ControlLegend.tsx` ·
`apps/client/src/ui/controlLegendModel.ts`（＋它的守衛 `controlLegendModel.test.ts`）

## 一句話

圖例從**一張戰鬥卡**變成**兩張依相位推導的卡**，第二張（選單卡）的每一列都是
**跑真的 `PadMenuNav`** 探出來的；戰鬥卡的 Start 那一列補上它真正會做的第二件事。

---

## 做了什麼

### ① 選單卡 `padMenuLegend()` —— ⛔ 一個字面值都沒有

`probeMenuNavButton(i)` / `probeMenuNavStick()` / `probeMenuNavScroll()` 建一個合成
`PadInfo` 餵進**出貨的 `PadMenuNav`**，回報它真的吐出什麼 `NavAction`。
按鍵**面**也是推導的：從 `BTN` 反查 index → `padFace(name)`，
所以 `NAV_ACTIVATE_BTN` 改成 2 的話卡片會自己印成 `X`。

出來的五列（實跑）：

```
左類比 → 移動焦點
右類比 → 捲動清單 / 說明欄      ← K4 lane 這一輪剛加的右蘑菇捲動，被守衛逼出來的
十字鍵 → 移動焦點
A      → 確定（按下選中的那一顆）
B      → 返回 / 關閉這一層
```

⛔ **刻意沒有 `準備完成` 那一列**：選單相位 `GamepadInput.poll` 已經把 pad0 交給
focus 層，START 送不出任何東西 —— 玩家是把焦點推到準備鍵再按 A，而 A 那一列就是這樣寫。

### ② 戰鬥卡的 Start 不再只說一半

`mapGamepadFrame` 的探針**結構上看不到** `ui/PadFocusNav.tsx` 的 Start→Escape 橋，
所以那一列一直只寫「準備完成」。新增 `PAD_COMBAT_EXTRA`（`DeclaredBinding` + source token，
沿用 `KEYBOARD_ORDER_BINDINGS` 的既有形狀）：

```
Start → 準備完成（同時開啟暫停選單 · 離開比賽的唯一鍵）
```

守衛不只掃 token，還從 `PadFocusNav.tsx` **解析出 `START_BTN = <n>`** 並要求它
`=== BTN.START` —— 那顆鍵搬家 → 紅。

### ③ 出現時機：**哪一張**是推導的，**什麼時候**才是資料

```ts
controlLegendLayer({ phase, round, dismissed, panelCovering, mode, gate? })
  → "combat" | "menu" | null
```

- **哪一張** ＝ `focusNavActive(...)`，就是決定「誰真的在讀這顆按鍵」的那個 predicate。
  ⇒ 圖例**結構上不可能**在選單層擁有 pad 的時候印戰鬥卡（＝這張票的病灶形狀）。
  有人往 `COMBAT_LIVE_PHASES` 加一個相位，圖例同一個 commit 跟著動。
- **什麼時候** ＝ `LegendPhaseGate`（`phases` / `combatRoundLimit` / `gamepadOnly`），
  出貨值 `DEFAULT_LEGEND_PHASE_GATE = { phases: [combat, champSelect, intermission, matchEnd], combatRoundLimit: 1, gamepadOnly: true }`。

涵蓋到的畫面：**選角 · 中場（商店／三選一）· 結算 · 戰鬥第一回合**。

`controlLegendVisible` 保留（boss 血條 / KillCombo 四個檔在用，不在我的柵欄裡），
但改成 **delegate** 到 `controlLegendLayer`，⛔ 不留第二份規則。

### ④ `padFaceForSlot(slot)`

給 `abilityHold.ts:211/236` 與 `AbilityBar.tsx:360/641` 那四處手寫字面值用的共用 helper。
實跑：`EX → LB`、`PASSIVE → RB` —— 正是那四處寫成 `Back` / `✛↑` 的兩顆。
⚠️ 那四處**不在我的柵欄裡**，沒有改。
