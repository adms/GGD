# 🔆 原作 additive 混合補回引擎 —— A/B 終端證據（GH#767）

⭐ 用詞紀律：以下只寫量到的數字。**驗收④亮度過了**，**③飽和度仍然沒過**。

## ⚠️ 我先踩了一次錯的常數（留著，因為它是這一批最貴的一課）

| 常數 | Babylon 的語意 | 亮度中位（t24） |
|---|---|---:|
| `ALPHA_COMBINE`(2) | 一般 alpha 混合（**本版之前**） | **75.4** |
| `ALPHA_ADD`(1) | ⚠️ **`SRC_ALPHA × SRC + DEST`** —— **仍然乘 alpha** | 86.9（只 +15%） |
| ⭐ `ALPHA_ONEONE`(0) | **`SRC + DEST`** —— 完全忽略 alpha ＝ WC3 additive 的真樣子 | **238.2** |

⭐ **為什麼 `ALPHA_ADD` 幾乎沒有用**：`w3xlib/gltf.py` 的 luma-key 把**亮度搬進了 alpha**
（`alpha := max(R,G,B)`）⇒ 再乘一次 alpha，等於把剛剛加上來的亮度**乘掉**。
⇒ `ALPHA_ADD` 是**近似**，`ALPHA_ONEONE` 才是**翻譯**（owner：「翻譯 JASS to 編輯器 JSON」）。

## 量尺先自證（⛔ 不然結論作廢）
`calibrate()` 對已知亮的滿版 control：**462,403 / 462,441 / 462,612**（三輪差 < 0.05%）。

## 開關真的可達
同一頁只換 `?additive=`：7 份材質的 `alphaMode` 實測 `2 ↔ 0` 全部翻過去
（最後一份 `mat2` 的自發光是全黑 ＝ 不透明幾何 ⇒ **刻意不碰**）。

## ❌ 還沒過的：③ 飽和度 —— 而它是**另一個**根因

| | sat 中位 | hue |
|---|---:|---:|
| BLEND（舊） | 0.357–0.439 | 26.7–32.2° |
| ONEONE（本版） | **0.244–0.267** | 15.0–16.5° |
| 原作門檻 | **≥ 0.47** | 金橘帶 |

⭐ 加法疊起來會先讓 R 飽和、再 G、再 B ⇒ 疊得夠多就變**白**。
⚠️ 探針量過：把轉檔器為了補償 BLEND 而加的 `emissiveStrength ×2` 除掉 ——
飽和度只從 0.244 → 0.267（**幾乎沒動**），而亮度掉到 202.6（**變差**）。
⇒ ⛔ **沒有證據支持動那一格**，本版不動它。

⭐ 下一個要查的（⛔ 不要猜）：原作那條光束的 sat ≥0.47 而我們疊完是 0.26，
差別要嘛在**貼圖本身的飽和度**（luma-key 有沒有洗掉彩度），要嘛在**我們疊了比原作更多層**。
兩者都量得出來，⛔ 不需要臆測。
