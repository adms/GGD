## 1. 缺陷（#502 稽核逐字）

> 結算畫面**沒有起始焦點**：第一次推搖桿落在最上最左，⛔ 不是「返回大廳」

根因在 `ui/PadFocusNav.tsx:181-186`：沒有任何元素持有 `PAD_FOCUS_ATTR` 時，
方向事件走 `initialFocusIndex()` —— 那是**純幾何**的「最上、再最左」
（`input/padFocusNav.ts:164`）。結算卡的最上最左不是出口，是收合鍵／排名列。
純手把玩家因此要盲推好幾次才離得開結算畫面。

⛔ 不能靠 `data-pad-back`：B 已經有別的語意，而且稽核要的是**起始焦點**。

## 2. 做法（⛔ 不是第二套機制 —— 照 `LeaveConfirmDialog` 的同一個模板）

`apps/client/src/ui/panels/MatchEndPanel.tsx`：

```tsx
const exitRef = useRef<HTMLButtonElement | null>(null);
useEffect(() => {
  if (cardHeld) return;
  const el = exitRef.current;
  if (!el) return;
  applyPadFocus(el);
  try { el.focus({ preventScroll: true }); } catch { el.focus(); }
}, [cardHeld]);
...
<Btn btnRef={exitRef} onClick={() => void returnToLobby()}>返回大廳</Btn>
```

三個必要條件，缺一個就是「說了但不會發生」：

| | 為什麼 |
|---|---|
| `applyPadFocus` **加上** `el.focus()` | `PadFocusNav.focusedInScope()` 只認得 `PAD_FOCUS_ATTR`。只做 DOM focus ⇒ 第一次推搖桿仍然掉回幾何起點 |
| 用 `Btn.btnRef`，⛔ 不是 `data-*` | `Btn` 沒有 `...rest`（#504 的發現），呼叫端寫 `data-*` 會被**靜默丟掉** |
| `if (cardHeld) return;` | 贏家的卡片被烤雞煙火扣住那段時間，wash 是 `pointer-events: none`、卡片還沒淡入 —— 把焦點放到一顆**按不下去**的按鈕上比沒有起始焦點更糟。放開後 dep 翻轉、效果再跑一次 |

非手把玩家不留痕跡：第一次**真的**滑鼠／鍵盤輸入由 `PadFocusNav` 的 `onUserInput`
（`isTrusted` 才算）把光暈收掉。

⛔ 沒有動 `input/padFocusNav.ts` 與 `ui/PadFocusNav.tsx` —— 那兩支正被別條 lane
改（工作區裡已經多出 `nextOptionIndex` / `scrollStepPx`）。
