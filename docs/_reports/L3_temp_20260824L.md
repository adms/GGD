## 兩個根因，一次轉檔同時修

| 因 | 形狀 | 支數 |
|---|---|---|
| **A：加法輝光被軟刪除** | `gltf.py` 的 `fm >= 3 and not has_opaque_base` 分支把「無 alpha 的加法輝光」寫成 `baseColorFactor [0,0,0,0]` + BLEND，而戰鬥場景沒有 GlowLayer／bloom ⇒ 逐位元不可見。現在改成 **LUMA-KEY**（alpha := max(R,G,B)）：黑底透明、亮處發光 | **15** |
| **B：純 emitter 模型被匯出成空殼** | MDX 有 0 個 geoset（全部是 PRE2 粒子發射器），而 .glb 匯出器只出 mesh ⇒ **0 個 primitive 的空 .glb**。`bake_emitter_quads()` 每顆 emitter 烤三片正交輝光面片，掛在它自己的父骨上、走 fm 3 材質（於是被 A 的 luma-key 接手） | **10** |

⚠️ **B 是知情的粗糙替身**，⛔ 不是粒子系統：它保住 emitter 的版面（DivineRing 的
20 顆 emitter 仍然排成一個環）與父骨跟隨，⛔ 但它不會動、不會噴發。
真正的粒子重製是另一件事，這一批要的是「不要再是 0 像素」。

## ⛔ 救不回來的 3 份，以及為什麼

`collision.mdx` **量到的**是 1,188 位元組的純骨架：**0 geoset · 0 頂點 ·
0 PRE2 emitter · 0 貼圖 · 1 sequence**。
兩條修法各缺一半的輸入 —— A 需要一份材質，B 需要一顆 emitter，**兩個都不存在**。
⇒ 烤一片面片出來是**捏造幾何**，⛔ 不是轉檔。
⭐ 而且它畫不出東西**本來就是對的**：那是原作看不見的**碰撞體積輔助模型**，
出貨內容裡也沒有任何 `spawnModelFx` 節點指向它。
`collision-mid` / `collision-small` 是同一份空來源產出的 LOD 階。

## ⚠️ 順手抓到的第二個缺陷：報告自己會說謊

`reconvert_zero_pixel.py` 原本拿**磁碟上的那一份**當基準 —— 而它自己會**覆蓋**那一份。
⇒ 第二次跑就讀回自己的產物，於是報告替一支出貨時是 0/1 的模型寫著
「shipped: 1/1 visible prims」（第三守則的形狀：一份自洽而錯誤的紀錄）。
修法：基準一律取自 **`git show HEAD:<path>`**，並多一條 `not-zero-pixel-at-HEAD`
判決擋掉「拿一支本來就好的模型去重轉」。報告欄位改名為 `baseline@HEAD`。

## 額外的獨立驗證（⛔ 不只信 primitive 數）

一個 primitive「存在」不等於它畫得出**像素**：luma-key 之後如果 alpha 整張是 0，
primitive 數仍然是 1 而畫面仍然空的（失敗形態⑧的形狀）。
⇒ 逐份解出每一張**真的被可見材質引用**的內嵌 PNG，量它的 alpha：

- 25 份的最大 alpha 全部 ≥ **172**（最低 `bwing`），中位 255
- 最佳貼圖的「alpha > 8 的像素佔比」全部 ≥ **17%**（最低 `awing`），多數 44–100%
- **effectively invisible：0 份**
