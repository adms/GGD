## 0. 先問「這四張是不是同一個根」

⭐ **#325 · #558③ · #723 是同一個根，#757 不是。**

三張的形狀完全一樣：**一條閘的推導源，不是它宣稱在守的那個東西。**

| 票 | 閘在問什麼 | 而真正該問的是 | 兩者為什麼會分家 |
|---|---|---|---|
| **#325** | 「這份 arena 的欄位型別對嗎」 | 「這份 arena **坐得下一隊人**嗎」 | 座位數住在 `constants.TEAM_SIZE`，而 schema 只認得 `.min(1)` |
| **#558③** | 「`schema/` 樹裡有沒有人開了 schema 忘了掛 union」 | 「**出貨內容**裡有沒有 tag 是這個映像不認得的」 | 閘掃**原始碼**，而故障來自**內容** |
| **#723** | 「磁碟上這份技能引用了什麼」 | 「這份技能**展開之後**引用什麼」 | 展開跑在 `registerAll()`，驗證跑在它**之前** |

⇒ 三張都是 CLAUDE.md 第〇·七守則拆檔第 3 條那一句：
**「閘要從『出貨的東西』推導，⛔ 不是掃資料夾」** ——
而三張各自從一個不同的角度違反它。⭐ 修法也同型：**換推導源**，⛔ 不是把閘調鬆。

**#757 是另一個病**：它不是推導源錯，是**一條鏈只做了一半**（有渲染沒有輸入），
而「一半」被登記成一筆**指不到任何票**的 debt。

## 1. #325 —— `zZoneDef.spawns` 的契約缺口 ✅ schema 那一半落地（票**留著**）

### 缺口實際是什麼形狀

⭐ **兩個名詞各自都對，壞的是配對。**

```
schema : spawns = tuple([array(zVec2).min(1), array(zVec2).min(1)])   ← 每側 ≥ 1
消費端 : spawns[side]![slot % TEAM_SIZE]!                              ← TEAM_SIZE = 3
```

⇒ 一份**完全合法**的 `arena@1`（每側 1 個）讓 slot 1/2 取到 `undefined`，
而兩個非空斷言把它一路帶進 runtime。

### 逐行複查補了三件票上沒寫的（2026-08-27 HEAD）

| | |
|---|---|
| 出貨場地是 **13 張**（票寫 6 張） | 每側都是 3 個，royale 是 6 個 —— ⭐ **全部是巧合** |
| **兩條額外的消費路徑，死法不同** | `ArenaDef.ts::royaleSpawnAt` 的 `flat[i % flat.length]` 與 `match/lobbySpawn.ts:65` 是 **fail-open 繞回去**（＝三個人疊同一格），⛔ 不是 `undefined`。**兩種死法都靜默** |
| 產生器那一層**已經**做完了 | `packages/shared/src/map/validate.ts:156-164` 已在保證 `≥ TEAM_SIZE`（GH#324 那一半）⇒ 缺的正好只有**手寫場地**這一半 |

### 做了什麼

- `schema/arena.ts`：`import { TEAM_SIZE } from "../../constants"`；`zZoneDef` 的 superRefine 加一段
  「每側 `< TEAM_SIZE` ⇒ `ctx.addIssue`」，path `["spawns", si]`，
  訊息含 **zone id · 側 · 實際個數 · TEAM_SIZE** ＋「⛔ 不要把消費端改成退回 `spawns[si][0]`」。
  ⛔ **沒有抄 3**（第〇·四守則的第二個住處）；`.min(1)` 保留，讓「零個」與「不夠一隊」得到兩種訊息。
- 守衛 `content/arenaSpawnSeats.test.ts`（3 條 / 65 行）：擋得下 `TEAM_SIZE-1` 且訊息指名 zone 與兩側 ·
  剛好 `TEAM_SIZE` 要過（閘不可以順手變嚴）· 走**真的 ContentLoader + 出貨 content/** 驗 13 張場地已滿足。
- `content/arenaCollision.test.ts` 的 `miniZone` 夾具補到 `TEAM_SIZE` 個（⛔ 用 import 不抄 3）。

### 🔴 這條閘一上線就找到 **3 個柵欄外的真債** —— ⛔ 不是把閘調鬆，是列出來

⚠️ **這一版要一起修，否則 `ship:check` 會紅。每一處都是「把 1 個出生點改成 3 個」。**

| # | 檔 | 現況 | 症狀 |
|---|---|---|---|

## 3. #723 —— 模板展開的引用逃過 `validateReferences` ✅ **關**

### 量到的（Scope 第 1 步）

| | |
|---|---:|
| `content/ability-templates/*.json` | **46** |
| 其中帶硬引用（`modelKey` / `preset` / `statusId`）的 | **13** |
| 採用 template 的技能／英雄文件 | **121**（其中 standalone ability **88** 份） |
| ⭐ **這 88 份實際引用到的模板** | **只有 8 個**：`tpl-single-strike`(32) · `tpl-buff-self`(30) · `tpl-instant-blast`(13) · `tpl-proxy-cast`(8) · `tpl-line-sweep`(2) · `tpl-traveling-wave`/`tpl-orbit-array`/`tpl-ground-nova`(各 1) |
| ⭐⭐ **帶硬引用的那 13 個，被採用了幾個** | **0** |
| ⇒ 今天真實的漏網斷引用 | **0** |

⭐ **這正是「引信已點燃但還沒炸」的樣子，⛔ 不是「沒事」**：
那 13 個模板（beam-roll · line-blast · locust-* · radial-burst · dragon-*）就是為光束／蝗群那一族準備的，
**第一支採用它們的技能上架的那一刻**，`modelKey` / `preset` 這兩格硬引用就整片逃過載入期檢查。

### 做了什麼（⛔ 沒有搬家）

`packages/shared/src/content/refs.ts`：
- `validateReferences(store)` 先從 store 建模板表，
  然後 `refEdgesOf()` 讓 **abilities** 與 **champions 的四個嵌入槽**都以「展開後的樣子」抽 ref edge
  （用的是**出貨的** `resolveTemplateExpansion`，⛔ 不是第二份實作）。
- 展開才長出來的 edge，欄位路徑掛 `template→` 前綴（差集判定）——
  否則作者會去技能 JSON 裡翻一個磁碟上不存在的欄位（2026-08-02 反向追查的形狀）。
- ⚠️ **展開失敗的文件原樣通過** ⇒ fail-soft 不退化（降級仍由 `registries.ts::handleFailure` 負責）。

守衛 `content/templateExpandedRefs.test.ts`（3 條）：
① 量尺自證（>50 份採用 · >10 個模板 · 出貨語料乾淨）
② **拿出貨的那 13 個模板之一**去採用、`modelKey` 填成不存在的 id ⇒ 載入期 `DanglingRefError`，
   訊息含 `template→` 與 `models/<missing>`
③ 展開**失敗**的那一支不被算成斷引用（fail-soft 不退化）

### ⛔ AC 第 2 項（移除 registries 的 template map ＋兩個 wrapper）**刻意沒做**

理由三條：
1. ⭐ **第〇·七守則（lane 交辦時逐字點名）**：順序相依 ⇒ **把順序寫成一條會紅的閘**，⛔ 不是搬家。
2. ⚠️ 票自己的 Known risks 就是「搬進 loader 後把 fail-soft 弄成 fail-closed ⇒ 選人畫面全空」——
   而搬家還會把 `withTiers` / `withProse`（要讀 config 文件）一起拖進 loader。
3. ⭐ 搬家**解不掉多做的那一次展開**：`registerAll` 仍要拿展開後的 def 去註冊。
   現在的成本是 121 份文件在載入時多展開一次（純函式，實測整支守衛 406ms 含載入）。

**Objective 與 AC1 / AC3 都達成**（dangling `modelKey` 現在在**載入時**就被抓到；`templateFailSoft` 全綠）。

### 🔁 一鍵回頭

⭐ **不必新增旋鈕** —— 這次改動的**唯一**行為變化是「展開後的斷硬引用會被隔離」，
而它已經被既有的 owner 旋鈕蓋住了：`config.content-load@1` 的
`cascadeDanglingRefs: false`（斷引用降級成 warning，文件留著）／`policy`。
程式面的回頭是一行：`refs.ts::refEdgesOf` 的 `view = expandedForRefs(doc, templates)` → `view = doc`
（⭐ 突變驗過：改了那一行，守衛 ② 立刻紅，而 ①③ 仍綠 ⇒ 那一行是承重的）。
