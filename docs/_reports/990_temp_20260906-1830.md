## 2. 做了什麼

### ① `vfx-script@2` 的 `call` 段（`packages/shared/src/content/schema/vfxScript.ts`）
- `zVfxScriptCall = {call:{subtype: zRef("vfx-subtypes"), params?}}`；`segments: z.array(zVfxScriptEntry)`，entry ＝ inline 段 **或** call（依「有沒有 `call`」分派到對應 schema，把那一支的錯誤原路帶出來，⛔ 不用 `z.union` 的「Invalid input」）。
- `schema: z.enum(["vfx-script@1","vfx-script@2"])`；⚠️ 出貨檔 tag **留 @1**：`apps/content-api/src/server.ts:316` 釘死 `doc.schema === COLLECTIONS[c].schemaTag`，翻 tag 會讓 forge／編輯器存檔 422（柵欄外，見 §5）。
- 型別拆兩個：`VfxScriptAuthoredDoc`（`zVfxScriptDoc.parse()` 的結果，可含 call）與 **`VfxScriptDoc`**（展開後，全 inline —— 名字刻意留給它：既有 20+ 個 `seg.kind` 讀端一行不改，⭐ 而 parse 結果不能直接指派給它 ⇒ tsc 在 **parse 邊界**紅，那正是要插展開器的地方）。`VfxScriptCall` 的 `kind/on/atMs…` 宣告成 `undefined`：只做比較的讀端照常編譯、`switch(seg.kind)` 的窮舉 `never` 會紅（刻意）。
- `parseInlineVfxScriptDoc(raw)`：手寫 inline 文件用，含 call 就擲。

### ② 展開器（新目錄 `packages/shared/src/content/vfxSubtypes/`）
- `expand.ts`（純、決定性、可進瀏覽器）：`expandVfxScriptEntries` / `expandVfxScriptDoc`（沒有 call ⇒ 回同一個物件）/ `checkCallParams`（不認得的 key、超界、enum 外 ⇒ `VfxScriptExpandError` 指名 script·段·子模組·原因，⛔ 不靜默）/ `vfxScriptCallRefs`（給 refs.ts）/ `canonJson` / `VfxSubtypes` 登錄表 ＋ `registerVfxSubtypes(store)`。
- `loadFromDir.ts`（node 側）：`readVfxScriptExpanded` / `readAllVfxScriptsExpanded` / `vfxSubtypeResolverFromDir` —— 給直接 `readFileSync` 出貨 script 的守衛用（見 §5 ③）。

### ③ 正規化器 `tools/vfx-subtypes/callify.mjs`（`node --import tsx …`）
- 逐顆子模組去比每一支 script 的連續視窗：從視窗**讀出**每一格參數（同一格多個 bind 要一致、值在界內）→ 展開 canon 相等 ⇒ 換成 `{call}`，`params` 只寫 ≠ default 的格子。
- 寫檔前的閘：改完用**同一支**共用展開器展開，與原 inline 逐位元組相等才寫（不等 exit 2、一個位元組不動）。
- `--check`（預設）：每一支都展得開 ＋ 再跑一次 callify 什麼都不會變（＝出貨的是正規式）；`--census` 印 §1 那張表。
- 結果：**8 支改寫**（`--write`），`--check` 綠；呼叫端零個 params（4 對本來就相同）。`genguard` 過（10 支 script 沒有產生器擁有者）。

### ④ 閘
- `packages/shared/src/ops/vfxSubtypesRatchet.test.ts`（既有檔，⛔ 沒開第二份）：`scriptSegments()` 改走共用展開器；② 出處改讀展開後（誠實註記：零 params 的腳本上它退化成地址檢查）；③ 等價（承重）＝子模組預設展開 ≡ 腳本展開後；新 ⑤ 出貨每一支展得開、零 call 殘留、段數 ＝ Σ子模組段數＋inline；sentinel (d) 子模組不存在／參數超界／不認得的參數 ⇒ 擲。**棘輪基準線**：`EXCLUSIVE_VFX_BASELINE` **69**（重量，沒變 —— 子模組動的是 script 層，技能↔特效 key 引用一格沒動）· `CALLLESS_SCRIPT_BASELINE` **10 → 2**（雙向）。

## 5. ⛔ 需要主 session 動的（柵欄外，逐檔逐行）

① **`packages/shared/src/content/registries.ts`**（載入時展開 —— 第〇·四守則的落點；沒有它客戶端 8 支 script 在 runtime 只會 warn 然後零段）
```ts
import { expandVfxScriptDoc, registerVfxSubtypes, VfxSubtypes } from "./vfxSubtypes/expand";
import type { VfxScriptAuthoredDoc } from "./schema/vfxScript";
// …registerAll() 第 503 行那一行換成：
registerVfxSubtypes(store);
for (const d of store.all<VfxScriptAuthoredDoc>("vfx-scripts")) {
  try {
    VfxScripts.register(expandVfxScriptDoc(d, VfxSubtypes.tryGet));
  } catch (e) {
    console.warn(`[content] vfx-script ${d.id} 呼叫段展不開，只登錄 inline 段 —— ${(e as Error).message}`);
    VfxScripts.register({ ...d, segments: d.segments.filter((s) => s.kind !== undefined) } as never);
  }
}
```
