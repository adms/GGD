## 二 · 逐一判斷：該掃全部 vs 只掃上架中（ask #2）

⚠️ ⛔ **不是一律改**。判準是「**這一條紅了，會叫人去修一件玩家拿不到的東西嗎？**」

| 這一族在問什麼 | 掃 | 為什麼 |
|---|---|---|
| **卡片上的字會不會騙到玩家**（無效 modifier、假狀態、靜默夾取的 `dispel.count`） | **上架面** | 玩家拿不到的卡，說謊不花任何人的成本 —— owner M105-1 |
| **知識有沒有無聲消失**（`authoringNote` 被截斷） | **全部** | 第一·五守則：撞字數上限要另存。一段被剪掉的原文不會因為那件道具下架就長回來 |
| **遊戲機制的平手線**（抬移速上限必須同時給飛行） | **全部** | 「有沒有上架」是一格開關 —— ⛔ 未上架 ≠ 永遠不上架，而開關翻開的那一刻沒有人會重跑稽核 |
| **退場物有沒有被誤引用** | **全部** | ⭐ 這正是 GH#472 唯一點名要保留的那一種 |
| **它驗的就是上架面本身**（每一階有沒有一張抽得到的池、owner 階級表 ↔ 三張池） | **全部** | 拿上架面當前提會變成同義反覆 |
| **母體是具名的那幾件**（owner 親筆 49 支文案、格擋四支、死之王三件…） | **全部** | 掃全樹只是為了把那幾件找出來 |
| **對外契約**（`ggd-runtime-capabilities`：這個名字存不存在） | **全部** | 母體是**出貨註冊表**；把未上架的用量藏起來會讓外部編輯器以為某機制沒人用 |
| **逐列標了開不開放的展示清單**（README / `docs/reference/*`） | **全部** | 母體＝顯示，⛔ 不是待修清單 |
| **schema / bundle 完整性 / 鏡像對帳** | **全部** | 一份壞掉的檔就算沒上架，也會讓 `ContentLoader.load()` **整份**失敗 → fail-open 退回骨架（2026-08-02 事故） |
| **平衡量測**（級距／中位／錨點／屬性上限） | **母體 49**（⛔ 不含變身態） | owner 2026-08-21：「查所有屬性級距等**都是不考慮變身態的**」——#485 已完成 |

## 三 · 做了什麼（ask #3）

### ① 新模組：`packages/shared/testkit/shippedSurface.ts`

「上架中」的**唯一推導住處**。三條取得路徑，缺一條就有東西被誤判成拿不到：

```
① 抽  content/loot-tables/*.json 的 entries[].itemId（三選一卡 / 傳說寶玉 / rollItemReward）
② 買  arena-rules.weaponShelfOpen 打開時 cost>0 的都上架；兩個商店服務永遠買得到
③ 合成  ①② 拿得到的東西，它 recipe 指到的元件與卷軸也一定拿得到
        ⛔ 少了這一步，10 件 component 會被誤判成退場物
```

匯出：`shippedChampionIds` · `shippedAbilityIds` · `shippedItemIds` ·
`unreachableItemIds` · `pooledItemIds` · `SKELETON_CHAMPION_IDS` ·
`SHIPPED_SURFACE_PROVENANCE`。**空集合一律 throw**（⛔ 不靜默回空 —— 那會讓每一條用它
過濾的稽核變成「零筆待修」而且每支腳本 EXIT 0）。

⛔ 不讀 `data/curation/whitelist.json`：它是 `.gitignore` 的營運狀態、CI 上不存在，
掛在它身上的閘等於沒有閘。三個來源全部在 git 裡。

### ② 閘：`roster:check` 第 ⑫ 條「稽核母體 ↔ 上架面」

每一支掃 `content/items` 的稽核只有兩種合法狀態：
① 真的 **import** 推導模組（自動偵測，⛔ 不必登記）
② 在 `WHOLE_TREE_BY_DESIGN` 裡帶著**一個能被反駁的理由**（今天 20 列）

⭐ 表**自己也會過期**：某一支改走推導模組了那一列就必須刪掉，否則紅。
⭐ 兩個子樹整棵豁免並帶理由：`tools/w3x-import/`（母體是原作地圖檔，`content/` 是它的
**輸出**）· `tools/icon-gen/`（要替磁碟上每一份備妥圖示，含骨架 —— 骨架沒圖示的話
內容載入失敗那一刻畫面全黑）。

⚠️ 偵測是**一行 import**，⛔ 不是「檔案裡出現這個字」——
第一版寫成後者，`tools/reference/gen_readme_lists.py` 只因為**註解裡提到**
`balancePopulation.ts` 就被判成已收斂（實測）。`.py` 一律要登記（Python 匯入不了 TS）。

⭐ 而且成功那一行**每次都把上架面印出來**：
`上架面：英雄 69 · 技能 412 · 道具 89（另有 53 件⋯）` ——
被稽核略過的東西⛔ 不可以無聲變多。它是**觀測**不是斷言（出貨數值⛔ 不住進測試）。

**突變驗證**（一批一條，挑最承重的）：
把 `retiredItemsAbsent.test.ts` 那一列從 `WHOLE_TREE_BY_DESIGN` 刪掉 → **紅**，
訊息逐字指名該檔並給兩條出路；加回來 → 綠。

### ③ 收斂的稽核

| 檔 | 改了什麼 |

| `packages/shared/src/content/noOpModifierClaims.test.ts` | 四段一模一樣的 `for (const coll of [...]) readdirSync` 迴圈 → **一支 `eachContentDoc(scope, cb)`**。無效 modifier / 假狀態 / `dispel.count` 三條收成 `"shipped"`；`authoringNote` 截斷與移速↔飛行兩條**刻意留在 `"all"`** 並在原地寫下理由 |
