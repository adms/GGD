## 三個必要條件，逐條

### ① 舊語意繼續 work —— 走**相容層**，⛔ 沒有遷移任何文件

`formGatePasses()` 對 `"alternate"` 的答案只是**變寬**（OR 多了一條），
所以 26 對既有變身的行為逐位元不變：換了身體 ⇒ 第一個條件就短路成立。
⭐ 副作用是 **`content/` 一個位元組都沒動 ⇒ ⛔ 不需要 `content:build`**。

⚠️ 唯一可觀測的差異：79-04 卍解**今天已經**同時掛 `championForm` 與
`statusId:"bankai"`，兩者都是 8 秒（`bankai.json` 自己記著「兩個住處記同一件事」）。
兩者若不同 tick 到期，79-002 虛化的格擋會以**狀態**那一邊為準多／少一格。
⭐ 那是這一批想要的方向（狀態是真相），⛔ 不是缺陷。

### ② 狀態 id 住 JSON，⛔ 不是程式裡的一個 if

判準是 `status-effect@1.tags` 帶不帶 `"form"`，走既有的 `hasStatusTag`
（＝條件葉 `{tag:"…"}` 用的**同一支**）。
⇒ 要讓第 N 對變身改走狀態，作者做的事是**在那份狀態文件的 tags 加一個字**。

⛔ 沒有新開一份「哪幾支英雄可以變身」的名單（那種東西必然過期），
⛔ 也沒有在引擎裡寫任何一支技能／英雄的 id。

⚠️ **tag 這個字串本身**（`FORM_STATUS_TAG = "form"`）是 `formGate.ts` 的一個常數。
把它升級成後台一格（`config.form-visuals@1` 加一個 `formStatusTag`，
前例 `config.weakness@1.statusTag`）是**一格欄位的後續**，
⛔ 本批沒做：那要動 `content/config/` + Zod + `apps/admin/src/configForms.ts`，
三者全在本 lane 的路徑柵欄之外（而 `configForms.ts` 此刻正有別的 lane 在改）。
