# GH#1021 —— 玩家公告閘用 `updatedAt` 撈票 ⇒ 舊票擋住新版公告

> lane 6 · 2026-09-06 · 柵欄：`scripts/release-note-players.sh` · `packages/shared/src/ops/releaseNotePlayersRange.test.ts` · 本報告
> ⛔ 沒有 push／`--post`／`skills:sync`／部署。commit sha 見票的 🧭 進度標記（本報告與 commit 同一次落地，⛔ 寫不進自己）。

## 〇、一句話

`updatedAt` 是**候選**，⛔ 從來不是「這一版做了它」的證據 —— 而腳本裡沒有任何一行問過後者。
現在問了：**一張票只有在 `SINCE..NOW` 裡有 commit 指名它（commit 訊息含 `#N`，或它進度標記的 commit 落在區間裡）時才進公告決策**。
量到：`v0.38.2..v0.39.0` 撈到的越界票 **3 → 0**；`v0.37.2..v0.38.0` 仍撈得到 #916 那一行。

## 一、⭐ 祖先檢查為什麼放行了 #971／#916／#838（量到的，⛔ 不是推測）

檔頭 `:43` 說「真正的篩選在下面的 commit 祖先檢查」—— ⭐ **那條檢查只管「這一句要不要發」，⛔ 從來沒管「這張票在不在這一版」**：

| 票 | 進度標記的 commit | 在 `v0.38.2..v0.39.0`？ | 玩家句 | 走的路 | 下場 |
|---|---|---|---|---|---|
| #971 | `6ec4d62d8`（v0.37.x） | ⛔ 是 v0.38.2 的祖先 | 有（後補的） | 祖先檢查跑了 ⇒ 「上一版就有了」⇒ `P=""` | ⛔ 然後**照樣掉進 `else` ⇒ MISSING** |
| #916 | `cd2f8b3b0`（⚠️ 這是 v0.38.0 的 **tag 物件**，peel 到 `57e955735`） | ⛔ 同上 | 有 | 同上 | ⛔ 同上 |
| #838 | `644e70231`（v0.37.x） | ⛔ 同上 | **沒有** | `if [ -n "$P" ]` 為假 ⇒ **祖先檢查整段跳過** | ⛔ 直接 MISSING |

⇒ 兩條路殊途同歸：祖先檢查的結論「這一句是上一版的」被翻譯成「這張票沒寫玩家句」——
⭐ **一個正確的判斷，被接到了錯誤的那一欄**。而 MISSING 在 LINES 為空時 `exit 1` 擋公告。

⚠️ 順帶量到：`gh issue list --limit 300` 的候選 50 張裡只有 **5 張**有進度標記；每張票在此之前打 2–3 次 `gh`（58 秒）。

## 二、修法（`scripts/release-note-players.sh`）

| 改動 | 為什麼 |
|---|---|
| ⭐ 票級的閘：`NAMED`（`git log --format='%s%n%b' SINCE..NOW \| grep -oE '#[0-9]+'`）∪ `in_range(SHA)`（是 NOW 祖先且不是 SINCE 祖先）。都沒有 ⇒ `drop`，⛔ 不進任何一欄 | 判準是**關係**（票 ↔ 區間內的 commit），⛔ 不是名詞（最近被動過） |
| ⚠️ `in_range` 那一半**不可省** | #916 的 commit 在 `v0.37.2..v0.38.0` 裡，⛔ 而那個區間**零個** commit 訊息提到 #916 ⇒ 只看 commit 訊息會把 v0.38.0 那一行黑龍波弄丟（AC 第 2 條） |
| `--until <tag>` | 讓一個舊區間能重算（測試用；只預覽，`--post` 路徑不受影響） |
| `gh issue view --json title,comments` 一次撈 | 每張票 2–3 次 → 1 次 |
| `GGD_PLAYERNOTE_TRACE=1` ⇒ stderr 每張候選票一行 `🔎 #N sha=… → lines\|missing\|skip\|drop` | 給閘讀；玩家句本身不准含票號（`DETAIL_RE`），所以測試沒有別的路拿到票號集合 |
| ⛔ **沒改**：只掃 closed（檔頭 :49 的理由仍成立）· 「沒寫玩家句就不發」那條 `exit 1` · 公告文案 | 票文 Implementation constraints |

## 七、沒做／風險（誠實）
