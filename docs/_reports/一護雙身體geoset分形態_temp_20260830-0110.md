## 2. Gating study —— ⭐ 用 KGAO 判，⛔ 不用頂點數猜

`HeroIchigo.mdx` 的 19 支 sequence 分成兩族：**base**（frame 333–16333，10 支）與
**alternate**（17000–31333，9 支）。每一條 KGAO track 都是 `interp=0`（step），
而且**只在其中一族的每一支 sequence 的起始 frame 各放一個 key**：

| geoset | 頂點 | mat | key 落在 | 值 | ⇒ 語意 |
|---|---:|---:|---|---:|---|
| 0 | 74 | 0 | base 每支起點 | 2.0 | **兩形態都畫**（腳底座） |
| 1 | 540 | 0 | **只有** alternate | 0.0 | ⭐ **常態身體**（卍解時關） |
| 2 | 739 | **1** | **只有** base | 0.0 | ⭐ **卍解身體**（斬月＋外套） |
| 3 | 134 | 0 | **只有** alternate | 0.0 | ⭐ **常態配件**（肩臂） |
| 4 | 349 | 0 | 無 GEOA | — | **兩形態都畫**（頭） |

⭐ **關鍵的第三個欄位是 GEOA 的 static alpha = 1.0**（舊 parser 把它丟掉了）。
一支 sequence 的區間內**沒有自己的 key** ⇒ 落回 static alpha ⇒ **可見**。
於是 geoset1 在 base 可見、alternate 被 key 關掉；geoset2 剛好相反。

⭐ **獨立佐證（⛔ 不是同一個軸）**：geoset2 是**唯一**掛在 `mat1` 上的 —— 它有自己的材質。
⇒ 兩條互不相干的證據指向同一個結論。

**⇒ 分組**：`base = {1, 3}` · `alternate = {2}` · `both = {0, 4}`
（與 #34 用 repo parser 得到的表逐格相同，本輪重新獨立導出。）

⚠️ geoset 6/7（各 10v）是同一組互斥配件，匯入時隨 `TeamGlow3` 丟掉了，⛔ 不必回收。

## 3. ⭐ 根因不是模型，是**那把量尺**

`geoset_alpha_report.py::alpha_at()` 在**全域時間軸**上取樣，並把區間外的 frame
**clamp 到最近端的 key**：

```python
if frame <= keys[0][0]: return keys[0][1]     # ⛔ 這一行
if frame >= keys[-1][0]: return keys[-1][1]
```

geoset1 的 key 最早在 17000 ⇒ **所有 base sequence（333–16333）都被 clamp 成 0.0**
⇒ 判成「每一支 sequence 都隱藏」⇒ `if not vis or not hid: continue`（always-off，
沒什麼好講的）⇒ **整支從普查裡消失**。geoset2 走的是 `>= keys[-1][0]` 那一邊，同樣消失。

⭐ ⛔ **而「沒有找到」與「乾淨」印出來一模一樣。** 這正是 CLAUDE.md 記的
「一把只驗過單邊的尺，會在它最需要說話的時候沉默」。

### 修法

| | |
|---|---|
| `parse_geoa` | 補讀 GEOA header offset +4 的 **static alpha**（原本丟掉） |
| ⭐ `alpha_in_seq(track, static, seq)` | **只取該 sequence 區間內的 key**；區間內沒有 key ⇒ 回 static alpha |
| 新判決類 `forms` | 在一族可見、另一族全隱藏 ⇒ **形態互斥身體**（⛔ 與 `stuck` 不同的病，不重複計） |
| `--selftest` | ⭐ **兩個方向的校準**：已知**有**（一護）量得到 **且** 已知**沒有**（其餘 128 支＋三支既有 strip JOBS）不誤報 |
| `--fixture` / `--check` | 產出／逐位元組比對 `geoset_form_gating.fixture.json` |

## 6. ⛔ 內容層為什麼沒落地 —— 結構性，不是選擇

(b) 需要動兩個檔：`content/models/imported.heroichigo.json`（加 `hiddenPrimitives: [2]`）
與新的 `content/models/imported.heroichigo-bankai.json`（`hiddenPrimitives: [1,3]`），
再把 `content/champions/godie-h01o.json` 的 `modelKey` 指過去。

⛔ **這條 lane 做不到**，理由不是柵欄，是這個：

> `content/bundle.json` 把**每一份 model 文件連同一個 per-doc `hash` 內嵌**進去
> （實測：`collections.models.entries[] = {doc, hash, id}`）。
> ⇒ 任何 `content/` 編輯都必須跑 `pnpm content:build` 重生成 bundle，
> ⛔ 否則 `shippedBundleIsCurrent.test.ts` 紅。
> ⚠️ 而 `content:build` 是**全域單一**，這條 lane 明令禁跑。

⭐ 更糟的是**半套**：一張 champion 卡指向一份不在 bundle 裡的 modelKey
= 內容驗證整份失敗 = fail-open 退回 2 隻骨架 —— **正是 2026-08-02 的線上事故形狀**。
⇒ ⛔ 寧可不動，也不留一個半套。
