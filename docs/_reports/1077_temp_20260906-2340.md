# GH#1077 —— CI `unit` 間歇紅：content-api 沙盒 `chmod -R u+w` 在 runner 上偶發失敗

lane 報告 · 2026-09-06 · 柵欄：`apps/content-api/src/testSourceSandbox.ts`（沙盒建立那一段）＋ 同目錄新守衛

## 1. 先量：失敗的是哪一個路徑（⭐ 從 run 34034796464 attempt 1 的 unit log 逐字抓的）

```
chmod: cannot access '/tmp/ggd-source-sandbox-Zzhdee/.git/objects/01': No such file or directory
chmod: cannot access '/tmp/ggd-source-sandbox-Zzhdee/.git/objects/04': No such file or directory
… 共 10 個 bucket：01 03 04 05 08 0b 0d 0f 12 14（log 裡出現 40 行 = 同 10 條印了 4 次）
→ Command failed: chmod -R u+w /tmp/ggd-source-sandbox-Zzhdee
```

| 量到的 | 值 |
|---|---|
| 消失的路徑 | **全部在沙盒自己的 `.git/objects/XX/`**，⛔ 不是 444 產物、⛔ 不是 symlink、⛔ 不是別的 worker 的沙盒 |
| runner 的 git | **2.55.0**（log 第 60 行）；本機 **2.39.2**（Apple Git-143） |
| `gc.auto` | actions/checkout 對**真 repo** `git config --local gc.auto 0`（log 第 85 行）—— 沙盒是 `git init` 出來的第二個 repo，⛔ 沒有這一格 |
| 沙盒 commit 的物件數 | `content/abilities` 在 HEAD 有 **422** 份 ⇒ ≈ 425 個 loose object，≈ 222 個 bucket 目錄 |
| 本機重現 | 600 檔的假 repo commit 之後 `ps` 看不到任何 `git gc/maintenance` 背景程序、222 個 bucket 都在（git 2.39.2）⇒ **本機造不出來**，與票文「本機 3/3 綠」一致 |

### 根因（量到的那一半 ＋ 推論的那一半，分開寫）

⭐ **量到的**：`chmod -R` 用 fts 走 `.git/objects/` —— readdir 拿到 256 個 bucket 名字之後逐一 stat，
而在那幾毫秒之內 10 個 bucket 目錄被**別的程序 rmdir** 了 ⇒ stat ENOENT ⇒ chmod exit 1 ⇒ `execFileSync` throw
⇒ 整條測試紅，⚠️ 而它與「來源改動撐不撐得過 sync」**沒有任何關係**（同一顆 commit attempt 2 綠）。
消失的 10 個全是**低編號 bucket（01–14）**，與「一個按 00→ff 順序走 bucket 的程序」和「chmod 按 readdir hash 順序走」互相追趕的形狀一致。

⚠️ **推論的**（⛔ 沒有釘死）：那個 rmdir 的程序是沙盒 `git commit` 之後 git 自己分離出去的背景維護
（`maintenance.auto` 預設開；2.55 的 release note 逐字寫著「"git maintenance" that goes background …」）。
我讀了 v2.55.0 的 `builtin/gc.c` 摘要仍**說不出**哪一個 task 在 425 個物件的 repo 上會 rmdir bucket
（`too_many_loose_objects` 門檻 gc.auto=6700 應該碰不到）。⇒ 修法刻意**不依賴**這個推論：三道防線任何一道成立就不會再紅。

## 2. 修（⛔ 不加 retry、⛔ 不改斷言；只動沙盒建立）

`apps/content-api/src/testSourceSandbox.ts`：

| 防線 | 做什麼 |
|---|---|
| ① 沙盒的 git 呼叫全部帶 `-c maintenance.auto=false -c gc.auto=0` | 沙盒 commit 之後**不再分離任何背景 git**（兩個 key 分別對 ≥2.29 與更舊的 git） |
| ② `chmod -R u+w <root>` → `ensureUserWritable(root)`（Node 逐檔走） | readdir → lstat → chmod；**ENOENT 一律當「它剛消失」略過**（回傳 `vanished` 計數）；其他 errno ⛔ 不吞，指名路徑 |
| ③ `.git/` 整個跳過 | 隔離區的 444 全在 `content/` 與 `tools/`；loose object 本來就是 444 —— 舊的 `chmod -R` 每次都白白改寫 ≈425 個 git 物件的權限 |
| ④ symlink 一律不碰 | chmod 會跟著走 ⇒ dangling 就 ENOENT；symlink 本身沒有權限位可解 |

`lstat` 可注入，只為了讓守衛能**確定性地**造出「走到一半消失」（真的競態在測試裡造不出來）。
