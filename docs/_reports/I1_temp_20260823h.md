# I1 黏住累積保險絲 —— lane 報告（2026-08-23）

## 做了什麼

一個 **stuck-guard**（黏住累積保險絲），住 sim、決定性、後台四格可一鍵回頭。

### 機制（`packages/shared/src/sim/combat/hitstopHold.ts`）

| 件 | 內容 |
|---|---|
| 累積 | 逐英雄記「**想動**（nav 有 moveTarget）但被**挨打型凍結**按住」的 tick 數。挨打型 = hitstop victim-hold ＋ 擊倒（`world.knockdown`）；位移覆寫（擊退滑行/dash）**不算**（那是在動）；碰撞推擠**不算**（G1 量過它反而幫人走） |
| 歸零 | 連續**自由**走滿 `windowSec`（出貨 0.5s）累積歸零 ⇒ 連段（凍 5 tick 放 2 tick）跨空檔照樣累積，正常走路偶爾挨一下不會誤跳 |
| 釋放 | 累積 ≥ `thresholdSec`（出貨 **2s**，owner 的數字）⇒ 接下來 `releaseSec`（出貨 1.5s）挨打型凍結按不住腳：hitstop victim-hold 在 `hitstopHoldsBody` 讓路、擊倒的 root 部分在 `movementHoldWithStuckRelease` 用「暫時遮掉 knockdown 再問 `movementHold`」的方式讓路（⛔ 零第二份 root 判斷） |
| 可見 | 釋放當下頭上冒「**掙脫**」—— 走 `floatingText` 既有事件路（typed payload、fanout 已放行、`FloatingTextFx` 真的在畫），⛔ 零新協定欄位 |

### ⭐ 界線（我挑的，owner 常設「自己判斷+留開關」）

- **治**：hitstop victim-hold（G1 出貨已關，保險絲備而不用 —— 它管的是那格哪天被
  回開＋未來任何新挨打型凍結）＋ **擊倒的 root 部分**。
- **⛔ 不治**：stun／root／施法自鎖／recovery 鎖 —— 硬控是設計、有圖示、可被淨化。
- **累積也只數治得了的 tick**：被 stun 同時按住的 tick 不數（放不了人就不喊掙脫）。
- **只看英雄**（`world.stats` gate）：小怪不吃保險絲 —— 救的是玩家的方向盤，也省
  1,000 隻殭屍逐 tick 的 movementHold 開銷。
- 與任務書的差異：任務書寫「累積…不管凍結來自哪裡」；我把**累積與釋放對齊**成同
  一族（挨打型），理由如上（fuse 跳了就保證真的走得掉）。想改界線 = 改
  `stuckGuardTick` 的 `beatenHeld` 一處。

### 後台四格（三住處齊全，戰鬥手感 → 命中定格）

`hitstop.stuckGuard.enabled`（出貨 **on**）· `thresholdSec`（**2**）·
`windowSec`（0.5）· `releaseSec`（1.5）。
住處：`content/config/combat-feel.json` ＋ Zod（`schema/config/combatFeel.ts`，
夾限 0..10 與 `normalizeStuckGuardRules` 逐字相同，admin 鏡射測試比對過）＋
admin 欄位表（`apps/admin/src/combatFeel.ts` 四條標籤，欄位清單本身由 Zod 推導）。
