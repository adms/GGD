## ⭐ 結論一句話：`mktemp` 那一族**是同一個根因**，而它是**腳本真的會在 CI 上壞掉**

> **`/private/tmp` 是 macOS 專屬的路徑**（`/tmp` 是它的 symlink）。
> Linux 上 `/private` **不存在**，而且非 root **建不出來**。

外加一個同族的第二形：**`mktemp -t <前綴>` 是 BSD 專屬的形式**——
GNU coreutils 要求模板帶至少三個結尾 `X`，否則 `mktemp: too few X's in template`。

⭐ 兩者都在 **`debian:bookworm-slim` / `python:3.12-slim`（`--user 1001:1001`）容器裡逐條量過**，
⛔ 不是從錯誤訊息推的：

| 探針 | Linux 實際 |
|---|---|
| `mktemp /private/tmp/lane-plan_temp_XXXXXX` | `failed to create file via template … No such file or directory` ← ⭐ **CI 逐字的那一句** |
| `mktemp -t ggd-deploy-step` | `too few X's in template 'ggd-deploy-step'` |
| `mkdir -p /private/tmp/ggd-ship` | `cannot create directory '/private': Permission denied` |
| `echo hi > /private/tmp/x.md` | `No such file or directory` |
| `mktemp "${TMPDIR:-/tmp}/…_XXXXXX"` | ✅ `/tmp/lane-plan_temp_bKvngW` |

⇒ ⭐ 這一族**全部**落在「腳本本身在 CI 環境下會壞」那一格 ⇒ **修腳本**，

## ⭐ 兩個**順帶在 Linux 上量出來的真缺陷**（⛔ 不是為了讓測試變綠）

### ① `run_step` 的失敗訊息**永遠印 `exit 0`** —— 一個指著錯方向的錯誤訊息

```bash
if r "$cmd" > "$log" 2>&1; then … return 0; fi
local code=$?        # ⛔ 永遠是 0
```

bash 的 `if cmd; then …; fi` 在**條件為假且沒有 else** 時，整個結構回 **0**。
⇒ GH#968 那條守衛守著的 `die "⛔ 「$label」失敗（exit ${code}）"`，
逐字印的是「**失敗（exit 0）**」——⭐ 而那正是它要防的那種「輸出騙人」。

修法：離開碼**自己接住**（`local code=0; r … || code=$?`）。
實測 macOS：修前 `exit 0` → 修後 `exit 1`；兩個方向（rc=1 停 / rc=0 往下走）都重驗過。

### ② `commit-ref-lint.sh` 的 `stat` fallback 在 GNU 上**不是 fallback**

```bash
$(stat -f %m "$CACHE" 2>/dev/null || stat -c %Y "$CACHE" 2>/dev/null || echo 0)
```

GNU 的 `stat -f` 是「印**檔案系統**狀態」⇒ 它 **exit 0** 並吐出一份多行報告
⇒ `||` 那條路**永遠到不了**，`$(( … ))` 拿到整段文字後炸開。
容器裡實測：每一次跑都噴一段 `missing ')'` 算術錯誤，而 `cache_is_fresh` 的答案是垃圾。

修法：**GNU 的 `-c` 先試**（BSD 對 `-c` 是乾淨的 `illegal option` ⇒ 才輪到 `-f`）＋ 數字白名單。
⚠️ macOS 回歸已驗：`stat -c` → `illegal option` exit 1 → `stat -f %m` → `1788559801`（⛔ 沒有退化成永遠 stale）。
