## 5. 尺本身的三個設計決定（每一個都有代價，所以寫下來）

### ① 演出鏈跟著 `EnableTrigger` 走，⛔ 不是「同名的那個函式」

WC3 的時序演出幾乎不寫在同一個 trigger 裡。42-04 的 rawcode `A05D` 只出現在
`The_End_ofWorldStart`（1 次扣血），而卡面承諾的連續打擊住在它 `EnableTrigger`
起來的 `The_End_ofWorldCasting`。⛔ 不走這條邊，audit 會對著一支
「原作只打 1 下」的技能報「沒有缺口」—— **一個綠燈，而缺口有 11 下**。

⭐ 這是守衛第二條釘住的那條線（突變驗過）。

### ② 字面上界的 `loop` 要展開

`Trig_SuperFF7_Actions` 是 `loop … exitwhen udg_SupI > 7 … endloop`。
⛔ 不展開只數到 2 拍 / 2 次扣血；展開後是 **44 拍 / 14 次扣血** ——
而「連斬七次」正是卡面承諾的那個數字。
上界解析三段式：字面值 → 回頭找 `set N = <字面值>` → 都不是就標 `unboundedLoop`（⛔ 不猜）。

### ③ 「N 次」不一定是打 N 下 —— 需要扣血語彙才算數

第一版全收，於是傷害軸的第一名變成 **58-04 瘋狂皮卡丘**（「極限是刺激**50次**」＝層數上限），
第二名是 **52-00 十二道試煉**（「跨回合共享**12次** [試煉] 標記」＝標記數）。
⛔ **一張排錯的表比沒有表更糟**，因為它把注意力帶去錯的地方。
⇒ 判準改成：命中的前後 24 字要出現 `傷害` / `斬` / `命中` / `打擊`。
⚠️ 被駁回的候選**一律留在 JSON 的 `promised.rejected` 裡**，⛔ 不靜默丟棄。

## 6. ⛔ 這支工具**沒有**任何技能專屬的 if（第〇·五守則）

三支標本只以 id 出現在 `audit.py` 的 `CALIBRATION` 那一格 ——
那是「合約文件要展開哪幾支」的**顯示清單**。

判準全部從資料推導：
- 扣血葉 = `kind` 以 `damage` 開頭，或節點帶 `damageType`
  （量過：出貨的 5 種扣血 kind 都有它，其餘 32 種一個都沒有）⇒ 新增扣血 effect 自動跟上
- 作者意圖 = provenance ∈ `{jass-literal, w3a-override, w3h-override}`
  （`stock-inherited` 不算 —— `provenanceContract` 自己寫著它「NOT intent」）
- 失效參數 = 模板 `params[*].inert` 自己宣告的
