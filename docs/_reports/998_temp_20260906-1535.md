### ⭐ 為什麼今天沒接進 `skills:sync`（決策點，主 session 一步就能翻）

`tools/parallel-gates/sync.mjs` 閘①：**package.json 的 `skills:sync` 字串與 `sync-io.json` 的 `chain` 不一致 ⇒ exit 2 拒跑**。
`ship:check` 走 `sync:converge` → `sync.mjs`。⇒ 只改 package.json 而不同步 `sync-io.json`，今晚主 session 的 `ship:check` 會被我擋住。
而 `sync-io.json` 在這條 lane 的柵欄外 ⇒ 兩件事要**同一個 commit** 落地。前例 `7e6153c3e`（typecat）與 `6332029f2`（lod）都是這樣做的。

**主 session 要翻它只要三步**（⭐ 建議做，第〇·五守則的「一條指令」才完整）：

```bash
# ① 量（⛔ 不是手寫）—— 在沙盒裡只跑這一支
node tools/parallel-gates/trace.mjs --script collections:build --out "$TMPDIR/collections-io.json"
# ② 把量到的 step 併進 sync-io.json：writes 應為 ["apps/platform/internal/contentoverlay/collections_gen.go"]
#    （reads 只留有人寫過的 —— 這一支讀的是 schema/*.ts，過濾後大概是 []；readCount 照量到的填）
#    並把 sync-io.json 的 chain 對齊 package.json
# ③ package.json 的 skills:sync 在 `pnpm caps:export` 後面加 `&& pnpm collections:build`，
#    然後刪掉 skillsSyncCoversGenerators.test.ts 裡 CHECK_STEP_NO_SYNC 的 collections:check 那一列
```

⚠️ 如果主 session 選擇**不**翻：一切照樣是綠的；新增 collection 時 `collections:check`（skills:check）
