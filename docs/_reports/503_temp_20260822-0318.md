## 機制（⭐ 一個機制，16 個缺口）

`PadFocusNav.tsx` 的 `handle("activate")` 在此之前唯一的動作是 `cur.click()`。
對 `<button>` 那是對的；對 `<input>` 它**只是把游標放進去**，一個字元都產生不了 ——
而全 repo 沒有任何 on-screen keyboard。於是登入 / 註冊 / 改密碼 / 房名 / 邀請碼 /
房內聊天 / 好友搜尋 / 排行榜搜尋 / 選角搜尋 全部是死路（#503 的 16 條逐點清單）。

現在 activate 分支多一個判斷（`shouldOpenPadKeyboard`），命中就 `openPadKeyboard(el)`。

⭐ **鍵盤自己不讀手把，一行都沒有。** 它畫出來的每一顆鍵是普通 `<button>`，
外層宣告 `data-pad-scope="pad-keyboard"` + `priority 90`，`完成` 鍵帶 `PAD_BACK`
（`data-pad-back`）。於是既有的 `PadFocusNav` 迴圈原封不動地驅動它：
`pickSpatial` 走格子 · A 按鍵 · B 關閉 · 新 scope 自動落焦（#505/#506 的既有基礎建設）。

### 三個關鍵決定

1. **priority 90** —— 贏過 `ui/padModalScope.ts` 梯子上的每一格（最高 60）。
   理由不是「它比較重要」，是**它一定開在某個 scope 上面**（改密碼 46 / 建房 45 /
   房內聊天都是 modal）。它是那些 modal 的子層，⛔ 不是同級競爭者。
2. **寫值走原型 setter** —— 受控的 React `<input>` 帶 `_valueTracker`，
   直接 `el.value = x` 會被 React 判定「沒變」丟掉。`setNativeInputValue()` 走
   `HTMLInputElement.prototype` 的 setter 再派 `input` + `change`。
   （與 `PadFocusNav` 私有的 `setNativeValue`（#505 為 select/range 寫的）是同一個機制的
   兩個呼叫點；那一支是私有的，合併它要動不屬於這條 lane 的檔，所以留成交叉引用。）
3. **`createRoot` 掛進 body** —— 交給共用 chrome 元件渲染要動 `ui/GlobalChrome.tsx`
   （別條 lane），而且鍵盤必須蓋在**每一個** modal 上面。body 尾端是唯一與
   「誰渲染了誰」無關的位置。

## ⚠️ 兩個必須留下來的事實

1. **`input/padKeyboard.ts` 而不是 `ui/padKeyboard.ts`** —— 票上寫的是後者，但
   `ui/PadKeyboard.tsx` 與 `ui/padKeyboard.ts` 在 macOS 的**大小寫不敏感檔案系統**上
   只差大小寫，`import "./padKeyboard"` 會解析到錯的那一支（而且 `tsc` 的
   `forceConsistentCasingInFileNames` 會直接紅）。⇒ 改用這個 repo 自己的慣例：
   `input/padFocusNav.ts`（純） ↔ `ui/PadFocusNav.tsx`（DOM）。
2. **版面沒有進 `content/config/*.json`** —— 這是輸入手感資料，與
   `input/padFocusNav.ts` 的 `NAV_REPEAT_MS` / `scrollStepPx` 同一族（沒有卡片會提到它、
   設計師不會調它）。而且新增一份 config 會逼著動 `apps/admin/src/store.ts` 與
   `ui/App.tsx`（`configDocCoverage.test.ts`），那是別條 lane 的共用檔。
   ⇒ 一張表住在 `CHAR_ROWS`，⛔ 不散在元件裡。**要進後台的話這是一張現成的表。**

## 已知的一個小papercut（⛔ 不是這條 lane 修得掉的）

鍵盤關掉之後，`PadFocusNav` 的落焦規則（`landedScope !== scope` → `landInitialFocus`）
會把焦點環丟回**整個畫面的左上角**，⛔ 不是回到剛剛那個輸入框（DOM 焦點有回去，
`onClose` 有 `target.focus()`，但焦點環會被下一幀蓋掉）。
修它要動 activate 分支**以外**的落焦條件 —— 超出這條 lane 的檔案柵欄。建議另開一張票。

  不看 mode，所以這一格是真的會打開的。
