### ⭐ 承重的兩行

1. **`trail.attachTo(node, nowMs)` ⛔ 不傳 `reference`。**
   `RibbonTrail` 的檔頭逐字寫著「world speed is useless — a champion walks at ~6 u/s」——
   那句話對**刀光**是對的，對**移動拖曳**剛好相反：`SWING_ON_SPEED`(3) → `SWING_FULL_SPEED`(8)
   正好把「走 ~6 / 衝刺 ~9」映射成「淡 → 全亮」＝ owner 的「速度越快越明顯」。
   ⇒ ⛔ 零行新的緞帶引擎（`RibbonTrail` / `ribbonMath` / `RibbonBudget` 一字未動）。
2. **節奏 = `onInterval` hook，⛔ 不是 `delayed`。**
   hook 掛在暴走增益上 ⇒ **隨增益生、隨增益死**（到期 / 被拔掉 / 死亡）。
   ⇒ 「出暴走**當場**清乾淨」；順帶解掉 `DELAYED_MAX_COUNT` 32 發的上限
   （12 秒完全暴走原本只能把 hz 壓到 2.5 硬塞）。

### 判準：這個 vfxId 是不是拖曳？「**它是不是一份 `ribbon@1`**」

⛔ 不是一張 id 名單、⛔ 更不是 `if (championId === 初號機)`（第〇·五守則）。
⇒ 任何一支技能想要移動拖曳，只要在內容編輯器裡把 `spawnVfx.vfxId` 指一份緞帶文件，⛔ 零行程式。

## 出貨值（我挑的，⛔ 不是 owner 說的）與理由

| 格 | 值 | 為什麼 | 住哪（＝後台/編輯器改得到的地方） |
|---|---:|---|---|
| `color` | `[0.72, 0.34, 1, 0.85]` | EVA-01 紫。alpha 0.85：additive 下已經夠亮，1.0 會把身體洗白 | 緞帶文件 |
| `lifespanSec` | **0.2** | `RIBBON_MAX_LIFESPAN_SEC` 的上限值 —— 拖曳要的就是**最長**的那條尾；且 < `RIBBON_FADE_BUDGET_SEC` 0.25 | 緞帶文件 |
| `widthAbove/Below` | **0.6 / 0.6** | 寬度沿**世界 Y** 展開（`buildRibbonPaths`）；配錨點 y=0.95 ⇒ 光幕約 0.35–1.55 ＝**整具身體**高，⛔ 不是地板痕。上限 0.7 | 緞帶文件 |
| 心跳 | **0.25 s** | 夠密（兩拍之間身體最多走約 1.5 格，緞帶自己 60Hz 取樣不會斷）也夠疏（12 秒 48 則，⛔ 不是每 tick 30 則） | 技能 JSON `internalCooldown` |
| hold | **0.4 s** | **> 0.25**（否則兩拍之間斷格 ⇒ 拖曳變閃爍）且 **< 0.5**（#569） | 技能 JSON `spawnVfx.durationSec` |
