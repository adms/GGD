## 2. ⭐ 最重要的一個發現：`adminAccountId` 出貨成 `""` 會是一個**只轉得動一邊的旋鈕**

後台通用表單引擎的 `parseFieldInput` 對 `text` 型欄位有一條：

```
if (raw.trim() === "") return { ok: false, error: "不可以是空的" };
```

⇒ 如果照直覺把 `adminAccountId` 出貨成 **空字串**（＝「自動」），那麼 owner 只要**填過一次 id**，
就**再也回不到自動** —— 後台不接受他把那一格清空。那正是第一·五守則講的形狀：
schema 收得下、後台存得起來、卡片上寫著「留空＝自動」，而那句話**做不到**。

**修法**：出貨值改成字串 **`"auto"`**（Zod `z.string().min(1).max(128)`），
平台把 `""` 與 `"auto"`（不分大小寫）當同義字 —— 手改過的檔案仍然讀得回來，⛔ 但不出貨空字串。

其餘三個決策點（第一守則：⛔ 不停下來問）：

| 欄位 | 出貨 | 理由 |
|---|---|---|
| `enabled` | **true** | owner 原話是「所有人**預設**都會加」；第〇·六守則：優先權大的更新預設啟動 |
| `backfillExisting` | **true** | owner 的「所有人」的另一半。冪等，第二次開機零寫入 |
| `overrideBlocked` | **false** | 「強制」指的是「⛔ 不必請求」；**封鎖是玩家明確按下去的動作**，把它變成對管理員無效是站方該自己決定的事，⛔ 不該由預設值決定 |

⚠️ 後台那一格的說明**寫了隱私後果**（票裡點名的）：被指名的管理員會出現在每一個玩家的好友名單上，
而好友名單顯示**在線狀態**（online / in-lobby / in-match）⇒ 等於讓那個帳號看得到全站每一個人在不在、在幹嘛。
