## #667 —— 三種靜默的資料流失，⭐ 而 #668 與它**不同源**

### 量到的（`--out-dir` 逐位元組比對，⛔ 不是推測）

| 流失 | 量 | 為什麼看不見 |
|---|---|---|
| `ambient: true` 被刪 | **5 份**（`godie-gumdam-p0/p2` · `godie-ye-wuqi1-p0/p1/p2`） | `isSwingTrailDoc()` 靠它認刀光 ⇒ 鋼彈刀光當場消失，零錯誤 |

### 根因（⭐ 不在抽取器，也不在資料，在兩者的**關係**）

`ambient = is_hero and not anim_driven and visible_ratio >= 0.5`，
而 `is_hero = stem in champ_model_slugs` —— 那是讀 `content/champions/**`。
英雄 `godie-hlgr` 被搬進 `content/_legacy/champions/` 之後，`imported.gumdam` 不再是
champion modelKey ⇒ **抽取器一個位元組都沒動而它的輸出從此不一樣**；
side-car 又合法地說「這些位元組是我寫的」（實測 5 筆 sha256 全中）
⇒ `classify_doc` 判 STALE ⇒ 蓋掉。

### 修法

- `HAND_OWNED_DOC_KEYS = ("ambient",)` 逐鍵從出貨檔帶過來，**在取雜湊之前** ——
  所以第二次跑分類成 `reproduced`，⛔ 不是在 stale / hand-tuned 之間振盪。
  逃生口 `--drop-hand-owned`（⭐ 預設 ON：它防的故障是靜默的，它可能造成的是漂移閘會指名的）
- `write_ambient_config()`：合併改成逐 `vfx` id、保住 prior 鍵序、`ensure_ascii=False`
- 「preserved」那一段**寫完再讀回來比對**，不一致就對 stderr 大叫

## #769 —— 兩條驗收都變成會紅的閘 ＋ 一個「閘跑不起來」的洞

- ① `--dry-run` 之後兩個目錄逐位元組不變（機制在 `3af61cc3`，這裡是釘住它）
- ② `--check` → EXIT=0 `✓ 轉檔紀錄 10 筆,對不上 0 筆`（幽靈紀錄 lane C `496d2a37` 收掉）
- ⭐ **`check_records()` 只讀 JSON，卻因為模組頂層 `from w3xlib.blp import decode_blp`
  拖進 Pillow 而連啟動都不行**。這台機器上 `python3` 是 universal2：
  **從 node spawn 出來是 arm64**，而使用者 site 的 `_imaging.so` 是 x86_64 ⇒
  任何 vitest 守衛去 shell 它都吃 `ImportError`，**而那個紅與「閘抓到東西」長得一模一樣**。
  ⇒ 轉檔相依改成可失敗的 import，需要它的子指令在 `main()` 裡**指名原因**退 2。
- 票上 Scope 剩下的兩條經查**沒有東西要修**：`invisible_prim_census.py` 只在 `--apply`
  與顯式 `--json <路徑>` 寫檔；`convert_all` 住 `w3xlib/models.py`（⛔ 不是票上寫的 `gltf.py`）且無 dry-run 路徑。
