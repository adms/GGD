# Lane W —— GH#676 室外場景**有機率**下雨（2026-08-24）

> owner 2026-08-24（逐字）：「只要是**室外場景**，都**有機率**下雨，而**非一定會下或不會下**」

#654 第一版（`484d80c1`）的 `rainEnabled` 出貨 false ＝「不會下」—— 正是他說不要的二元。
本批把「下不下」改成**每場開賽一次的決定性擲骰**。

## 設計（三個問題、三個住處，⛔ 沒有第二張表）

| 問題 | 住處 | 實作 |
|---|---|---|
| **下不下** | `config.weather@1.rainChance`（0–1）× matchSeed | `matchRainRoll(policy, seed)` —— avalanche hash（鏡照 `ArenaDef.ts` 場地輪替的形狀，鹽 `0x7261696e`＝"rain"，與場地輪替串流獨立）。`chance>=1 ⇒ 必下`、`<=0 ⇒ 必不下` 是**精確**分支不靠浮點運氣。⛔ 無 Math.random / Date.now |
| **淋不淋得到** | `arenas` 級別的 id 前綴（既有資料 —— 任務要求③：`weatherKindIsSheltered()` 已存在，⛔ 不必動 arena schema） | `weatherLookFor` 裡 `!weatherKindIsSheltered(kind)`；室內**永遠不進機率池** |
| **下多大** | `WEATHER_KIND_WEIGHTS[kind].rain` | GH#676 之後這一欄**只管強度**：室外四級全 1、室內兩級 0（保險帶） |

### 我做的裁決（owner 沒明說的，各自帶開關/退路）

1. **`rainChance` 出貨 0.3 是 Claude 挑的**（owner 沒給數字；票裡已記）。判準：一晚五場遇到一兩場雨。後台一格滑桿，挑錯成本＝owner 改一格。⛔ 不要寫進 release note 的「owner 裁決」節。
2. **擲骰是每場一次、⛔ 不是每回合**（票的字面「每場開賽擲一次」）。室內回合雨停、回到室外又下 ——「這一場是雨天」是比賽的事實，「淋不淋得到」是場地的事實。
3. **沒列在 `arenas` 表上的圖⛔ 不進機率池**（`declared` 檢查）。理由：沿用檔案自己宣告的保守方向 ——「一張新地圖不會因為忘了填而突然下雨」這句既有承諾在 #676 之後**仍然為真**；反向（未分類就下雨）的失敗形態正是 owner 抱怨過的「室內下雨很奇怪」。
4. **沒有 seed（開機骨架、還沒進房）＝不下雨** —— 雨是一場比賽的事實，沒有比賽就沒有那一次擲骰。
5. `rainEnabled` 翻 true 之後語意＝**止血閥**（一鍵全關的急救口），照票第 1、4 點。

## 守衛（`weatherRainRoll.test.ts`，票的三條全對上）

① 同 seed 兩次＝同結果（matchRainRoll ＋ 出貨路徑 weatherLookFor 都驗）
