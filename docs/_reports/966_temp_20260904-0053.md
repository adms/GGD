## 二、⭐⭐ 最重要的一個發現：**這個功能今天有兩道門，票文只看到第二道**

```
zipSafety.ts:159   ZIP_ALLOWED_ROOTS = ['authoring','compiled','validation','reports']
zipSafety.ts:170   ZIP_ALLOWED_EXTENSION = '.json'
```

⇒ `assets/icon/abilities/hero.q/source.png` 在 **`checkZipSafety`** 就被判
`ZIP_PATH_NOT_ALLOWED`，⛔ **整包退回** —— `fromZip()` 的那兩行根本走不到。

⚠️ ⭐ 而票文的 S4 那一列寫著「**已覆蓋** ⇒ `zPackagePath` 的正則已經允許這個形狀（已驗）」。
⭐ **那半句是對的** —— 正則確實允許。⛔ 而它問的是**錯的名詞**：
擋路的不是 `zPackagePath`（schema 層），是 `checkZipSafety`（傳輸層），
⭐ 而那兩層**各自都對**，⛔ 壞掉的是它們的**關係**。

⇒ ⭐ 這正是 CLAUDE.md 記過的「**配對式後置條件**」同型（2026-08-02 事故）：
逐項檢查每一個名詞都會說「沒問題」，⛔ 而功能是死的。

**修法**：`ZIP_ALLOWED_ROOTS` 加 `assets`，並且**每個前綴有自己的副檔名白名單**
（文件那四個收 `.json`；`assets/` 收 `.png/.webp/.jpg/.jpeg`）——
⛔ 一份共用清單會讓 `authoring/x.png` 也通過。

## 三、落地了什麼

### 3.1 契約（對外，Codex 那一側看得到）

| 檔 | 改了什麼 |
|---|---|
| `packages/shared/src/content/import/packageSchema.ts` | `role` enum ＋ `"asset"`；`zManifestEntry` ＋ `mime` / `targetField`（**enum，白名單只有 `icon`**）/ `baseSha256`（CAS，`nullable`）；`zEditorImportPackage` ＋ `assets[]`（ZIP-only 的二進位通道） |
| `packages/shared/src/content/import/diagnostics.ts` | ⭐ 六個新診斷碼，**全部 `failClosed: true`**：`ASSET_ENTRY_INVALID` · `ASSET_BYTES_MISMATCH` · `ASSET_FORMAT_REJECTED` · `ASSET_DIMENSIONS_TOO_LARGE` · `ASSET_BASE_CHANGED` · `ASSET_UPLOAD_DISABLED` |
| `packages/shared/src/content/import/contractIndex.ts` | `REPRESENTATIONS` ＋ `icon-asset@1`（`packageKind: "binary-asset"`、`promotionPolicy: "review-required"`）。⭐ `acceptedRuntimeSchemas()` 只收 `runtime-document` ⇒ 它**不會**污染 `RAW_RUNTIME_SCHEMA_TAGS` |
| `packages/shared/src/content/import/zipSafety.ts` | `ZIP_ALLOWED_ROOTS` ＋ `assets`；新增 `ZIP_ALLOWED_ASSET_EXTENSIONS` |
| 新 `ZipFormatError` 碼 | `ZIP_ENTRY_UNDECLARED` · `ZIP_ENTRY_MISSING` |

**zip 路徑約定**（照票文）：`assets/icon/<collection>/<docId>/source.<ext>`
**落點**：`content/assets/icons/<collection>/<id>.webp`（⭐ 與 `tools/icon-gen` **同一個公式**）

### 3.2 轉檔只有一個住處（AC #5）

新 `packages/shared/src/content/icons/encodeIcon.ts`：
* `ICON_ENCODE = { edge: 128, quality: 90 }` —— ⭐ **唯一住處**
* `sniffImageHeader()` —— PNG(IHDR) / WebP(VP8·VP8L·VP8X) / JPEG(SOFn) 的 magic bytes ＋ 檔頭長寬，⛔ **零 decode、零相依**
* `encodeIcon()` —— `execFileSync("cwebp", …)`（⭐ 放這個目錄是刻意的：#967 的守衛就掃這裡）

`tools/icon-gen/convert-webp.mjs` → **`convert-webp.ts`**，改成 `import` 上面那支：
自己的 `pngSize()` 與 `execFileSync("cwebp")` **都刪掉了**。npm script `pnpm icons:webp`。
⚠️ `tools/` 不進 `pnpm -r typecheck`，所以那次轉換有實跑驗證（`--dry-run` EXIT=0）。

### 3.3 傳輸層（AC #2 —— ⭐ 本票最重要的一行）

`fromZip()`：
* entry 一律先留 **`Buffer`**；`role:"asset"` 的**保持 Buffer**，其餘才 `.toString("utf8")`
* ⭐ **兩個方向都走**：zip 有而 manifest 沒宣告 ⇒ `ZIP_ENTRY_UNDECLARED` **指名那個路徑**；
  manifest 宣告而 zip 沒有 ⇒ `ZIP_ENTRY_MISSING` **指名那個路徑**
* `manifest.json` 是唯一的結構性豁免（⭐ 一份清單不可能列出自己）

⚠️ ⭐ 舊迴圈是**失敗形態⑫**的教科書實例：它從「宣告」那一頭走，
⇒ ⛔ 結構上看不見「有實體而無宣告」的那一種。

### 3.4 驗證（純函式，S1–S3 ＋ CAS）

`packages/shared/src/content/import/iconAssets.ts::checkIconAssets()` ——
⭐ **順序是承重的**：位元組事實（sha/size）→ 位元組上限 → magic bytes →
**檔頭長寬（decode 前）** → CAS。⛔ 任何把長寬排在 decode 之後的寫法都讓那道檢查變裝飾。

⭐ 它**不碰檔案系統、不跑 `cwebp`** ⇒「先驗後解」是**結構上**成立的。

### 3.5 落地（`/apply` only）

`apps/content-api/src/iconLanding.ts`：轉檔 → 冪等比對（sha 相同就**不寫**）→ 寫檔。
`importRoutes.ts` 的 `/apply`：
* ⭐ **先寫位元組、再原子換文件樹**（icon 在沒有文件指向它之前是惰性的）
* ⭐ 文件的 `icon` 欄位在**逐份雜湊驗過之後**才改（⛔ 驗證之前改＝自己把驗證繞過去）
* 回應多了 `iconAssets[]`（含 `unchanged`）與 `pendingReview`
* `requiresReview` 開著時寫一筆 `content-import.icon-pending-review` 稽核列

### 3.6 開關（三個住處）

`config.icon-upload@1` —— `content/config/icon-upload.json` ＋ `DEFAULT_ICON_UPLOAD`
＋ `ICON_UPLOAD_SPEC`（`apps/admin/src/configForms/specs/authoring.ts`）＋ App.tsx 導覽列。

| 欄位 | 出貨 | 是什麼 |
|---|---|---|
| `enabled` | `true` | ⭐⭐ **一鍵 rollback**。關掉 ⇒ 帶 icon 的包**明確拒絕**（⛔ 不是靜靜丟掉） |
| `requiresReview` | `true` | 上線後留待審紀錄（⛔ 不是事前審批門 —— owner 的「先上線、可一鍵否決」） |
| `preserveAlpha` | `true` | `cwebp` 預設即保留 ⇒ 零額外工作 |
| `maxSourceEdgeMultiple` | `32` | ⭐ **倍數**（× `ICON_ENCODE.edge` = 4096²）—— ⛔ 不存 4096（第〇·四守則） |
