⭐ **`runtime` 是 undefined**。而 emitter 的形狀（一圈 / 一條龍捲）完全來自
`W3xEmitterRig` 的 `runtime.pivotOffset`（`W3xEmitterRig.ts:290`）。
⇒ 施法路徑上 **pivot 整個被丟掉**，20 顆 DivineRing 的 emitter 會**從同一點噴**。

## 三、退件理由 B —— **1 支已經做完了**（`godie-e002.w` / `godie-e00l.w`，20-01 風王結界）

⭐ 這一支**唯一**通過四道閘，而它**早就上線了** —— 走的是 GH#529 的另一張表：

```json
// content/config/ability-vfx-bindings.json
{"abilityId": "godie-e002.w",
 "vfxKeys": ["fx.w3x.particle.holyawakening.p00", … "p05"],   // ⭐ 6 層全播
 "source": "w3a-override:art:caster", "rawcode": "A0DZ", "confidence": "CONFIRMED"}
```

`ContentDb.ts:365` 真的 `setAbilityVfxBindings(...)`；
`godie-e002.w` 的 `vfxKey` 是 `fx.prim.wind.tornado`（階 4）⇒ 落到**階 3 的表**
⇒ `playCastVfx` 的 **RUNG 0**（`if (layers && layers.length > 0) { playLayeredCast(); return; }`）。

⛔ **RUNG 0 在 `const art = w3xArtFor(abilityId)` 之前 return。**
⇒ 對一支已經進綁定表的技能補 `promoted`，那一格**逐位元讀不到** —— 第一·五守則的「說了但不會發生」。

### 而且補了會**弄紅**

`w3xAbilityArt.test.ts:53`「the ability's shipped vfxKey IS the promoted primary」
逐支斷言 `content/abilities/<id>.json` 的 `vfxKey === promoted.primary`。
⇒ 任何一列新的 `promoted` 都**強制**要同時改 `content/abilities/<id>.json` ——
而那是本 lane 的**柵欄外**（GH#563 那條 lane 在動 `content/abilities/`）。

⭐ 這一條同時解釋了為什麼 §M2 的「零引擎改動、只改一份 JSON」在**任何一支**上都不成立。

⇒ 再寫一條就是**第五個住處**（第零守則⑦：測試行數上限／不重複驗同一件事）。
