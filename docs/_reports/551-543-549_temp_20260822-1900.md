## 一、做了什麼

四個 kind 進 `EffectDef` 聯集 + Zod 聯集 + 註冊表 + variants 檔（四向閘 `effectShardWiring.test.ts` 綠）：

| kind | 票 | sim 做什麼 |
|---|---|---|
| `spawnModelFx` | #551 | 路徑求值 + `onTouch` 逐段取樣 + `onArrive` 落點結算 + 一則 `modelFxSpawn` 視覺事件 |
| `screenFlash` | #543 | 解出收件人 → `world.emit("screenFlash", …)` |
| `screenShake` | #543 | 同上（**共用**同一支 `cueRecipients`） |
| `floatingText` | #549 | 同上 + `{{i}}` 佔位符在**執行時**解析成段號 |

### 承重的三個設計決定

1. **⛔ 零個新的排程器**（第零守則⑨）。`spawnModelFx` 的班表推進**既有的**
   `SimWorld.delayed`，由**既有的** `delayedSystem` 付款 —— 走的是 `advance`
   （GH#393 沿向量分段推進）+ `reresolve: circle` + `struck`（一人一次）三格既有機制。
   ⇒ 決鬥結束停手 / 施法者死亡停手 / `incoming` 定基，一行都沒重寫。
2. **⭐ `onTouch` 與 `onArrive` 是兩串佇列，⛔ 不是一串。**
   `delayedSystem` 的 `struck` 過濾**同時**套用在 `effects` 與 `finalEffects` 上，
   掛成同一串的 `finalEffects` 會讓「被光束掃到的人**不會**被落點爆炸打到」——
   而那不是任何一張卡的意思（失敗形態②）。
3. **⭐ 等分角度沿用 `pull.ts` 的 `ringPoints` / `RING_UNIT_ROTATION`**（單位旋轉常數表），
   ⛔ 不是第二份。`sim/**` 禁止三角函式（`sim/purity.test.ts` 綠）。
   `radial` 的單位方向 = `ringPoints({x:0,z:0}, 1, count)`，`orbit` 的環位置 = `ringPoints(centre, distance, count)`。

### `{{i}}` 這條線（#549 的核心）

`EffectContext.sequenceIndex`（新，RUNTIME、從不 authored、無 Zod）由
`delayedSystem` 填 `index + 1`。⇒ 克勞德「1Hit…7Hit」是 `comboStrikes.perStrike`
裡的**一個** `floatingText` 節點寫 `"{{i}}Hit"`，⛔ 不是七個各寫死一個數字的節點
（第〇·四守則）。缺席時解析成 **1**（一發單獨的效果就是它自己的第一段）。

## 二、L1 ↔ L2 介面：**照約定，加了四格選填**

⚠️ 約定的欄位一格都沒改名、沒改語意。加的四格全部 optional，L2 不理它們也不會壞：

| 新欄位 | 在哪 | 為什麼 |
|---|---|---|
| `touchRadius`（有 `onTouch` 時**必填**） | `spawnModelFx` | 沒有半徑的碰觸永遠碰不到人；⛔ 不用一個藏在程式裡的預設值（那是第〇·四守則的反面） |
| `touchSide`（`enemies`／`allies`，預設 `enemies`） | `spawnModelFx` | ⚠️ 頂層 `side` 被 `refineDispelShape` 綁在 `shape:"circle"` 上，所以 `path:"forward"` 的光束用它講不出「掃友軍」 |
| `touchOncePerTarget`（預設 **true**） | `spawnModelFx` | 穿過身體的模型應該打你一次，⛔ 不是每 tick 各一次 |
| `radius` / `side` / `maxTargets` | 四個 kind | E1 硬約束要求的幾何組（`refineDispelShape` 共用同一份檢查） |

### ⚠️ 兩個 L2 一定要知道的讀法

- **`distance` 在 `path:"orbit"` 時是「環半徑」，⛔ 不是「走多遠」** —— 繞圈沒有終點，
  `orbit` 的終點是 `lifeSec`（schema `refine` 強制 `orbit` 必填 `lifeSec`）。
- **`screenShake.amplitude` 是 0..1 的正規化強度，⛔ 不是像素。**
  真正的位移量 = 這個數字 × `config.screen-cues@1` 的上限（見下一節）。

### 送出去的四個事件（payload 逐格）

```
modelFxSpawn { caster, modelKey, path, speed, x, z, zone, scale?, spinDegPerSec?,
               instances: [{ x, z, dx, dz, dist, durationSec }] }   ← 一次施放一則
screenFlash  { colorRgb:[r,g,b], peakAlpha, durationSec, broadcast, subjects[], caster, zone }
screenShake  { amplitude, durationSec, broadcast, subjects[], caster, zone }
floatingText { text, colorRgb?, sizeScale?, riseSpeed?, durationSec?,
               subjects: [{ id, x, z }], caster, zone }
```

⭐ `broadcast: true` 時 `subjects` 是**空的**（⛔ 不是「全部的人」）：一份會隨場上
人數變長的名單過線是純浪費，客戶端要的答案是一個布林（「這一則有沒有我」）。

## 五、⛔ 沒有做、而且是刻意的

| | 為什麼 |
|---|---|
| `floatingText` ⛔ 不接管浮動**傷害數字** | 那一族由 `damage` 事件在客戶端自己算。接管它 = 把一個已經在跑的機制換掉，⛔ 沒有人要求 |
