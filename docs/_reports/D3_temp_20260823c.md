## 量到的（M-series，best-of-3，Redis 沒開 ⇒ 只有檔案層）

### ① 內容載入本身（`loadContentCached()` 直接量）

| 模式 | total | 拆解 |
|---|---:|---|
| `GGD_CONTENT_CACHE=off` | **333 ms** | `load` 333（1,727 次 readFile + 1,712 次 Zod） |
| 檔案層命中（暖） | **129 ms** | `fingerprint` **107** + `hydrate` 23 + `read` 0 |
| 冷（第一次，要寫快取） | 474–537 ms | 上面那些 + `write` 33 |

⇒ **2.6× · 省 204 ms／次**。1,727 次 `readFile` → **1 次** `readFile`（594 KB 的 `.gz`）。

### ② 產生器的 wall-clock（含 `npx tsx` 啟動 ≈ 1.4 s，它壓過快取的絕對值）

| 指令 | cache off | cache auto（暖） | 差 |
|---|---:|---:|---:|
| `spec:build`（`gen_spec.ts --out`） | 1.86 s | **1.73 s** | −0.13 s |
| `tiers:check`（`gen_tiers.ts --check`） | 1.67 s | **1.50 s** | −0.17 s |
| `ttk-sim` `loadRoster()`（不含啟動） | 431 ms | **260 ms** | −0.17 s |

⚠️ **`pnpm tiers:apply` 量不到這條線** —— 它是 `python3 tools/skill-remake/apply_tiers.py`，
根本沒有走 `ContentLoader`。所以上表換成 `tiers:build`／`tiers:check` 這一支 TS 產生器。

## ⭐ 最重要的一個發現：**省下來的 204 ms 裡，剩下的 129 ms 有 107 ms 是「算快取鍵」**

`fingerprint`（git ls-tree ＋ 髒檔逐檔雜湊 ＋ `packages/shared/src` 程式碼雜湊）= **107 ms**，
佔暖路徑的 **83%**。真正的 hydrate 只有 23 ms。

⇒ 這條優化的**天花板就是 ~205 ms／次**，⛔ 不是「330 ms 全部省掉」。
`pnpm skills:sync` 一次付十幾次載入 ⇒ 全鏈實際省 **≈ 2.5 s**，
⛔ 不是把 `skills:sync` 從幾分鐘壓成幾秒。要再往下就得攤掉 fingerprint
（例：同一個 process 內快取 fingerprint，或改成一支 daemon），⛔ 而那不是這條 lane 的範圍。

## ⚠️ 第二個發現：`gen_spec.ts --out <路徑>` 的產物**根本不經過載入的內容樹**

```ts
const md = buildSpecMarkdown();                       // ← 這一行在載入**之前**
registerAll((await loadContentCached({ … })).store);  // ← 載入
const proseJson = buildProseJson();                   // ← 只有這一份吃註冊表
```

而 `--out` 會把 `proseOut` 設成 `undefined`（＝ **不產生** prose JSON）。
⇒ ⛔ **拿 `--out` 兩份 md 做 md5 比對來驗「快取沒改變產物」是空的** ——
那份 md 是 `readdirSync`/`readFileSync` 直接掃 `content/` 出來的，跟快取無關。
（我第一次就是這樣驗的，md5 相同但**什麼都沒證明**。）
⇒ 驗 `gen_spec` 要走 `--check`（它會**先**逐位元組比對 prose JSON）。

## 突變驗證（一批一條，挑最承重的）

⭐ 直接改**快取檔的內容**，看產生器的產物會不會跟著變 —— 這是「產生器真的在吃快取」
唯一驗得到的方式（⛔ 不是掃原始碼有沒有 `loadContentCached` 這個字）：

```
1. 暖快取 → gen_card_prose --out base.md
2. gunzip 快取 .gz，把 godie-e001.e 的 name 從「22-03 五吋釘」改成「MUTATED」，重新 gzip
3. gen_card_prose --out mut.md
   ⇒ 產物第 80 行變成 `### godie-e001.e MUTATED`   ✅ 紅（＝它真的讀快取）
4. rm -rf 快取 → 重跑 ⇒ 逐位元組回到 base.md      ✅ 還原
```

⚠️ 這一條也順便否證了「gen_spec `--out` 的 md 會反映快取」——
同一個突變對那份 md **一個位元組都沒動**（見上面第二個發現）。
