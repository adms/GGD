## 1. ⭐ 最重要的那一題：`gen_lod.py` 有沒有安全路徑？

### ⛔ **沒有（改動前）。** 三個根據，逐條可以自己驗：

| # | 根據 |
|---|---|
| ① | `argparse` 只有 `paths` / `--tier` / `--dry-run` / `--quiet` —— ⛔ **沒有任何 `--manifest-only`** |
| ② | `--dry-run` **不寫 manifest**：整段寫檔包在 `if not args.dry_run:` 裡（舊 `gen_lod.py:360`）⇒ 它對「修好 manifest」是**零用處**；而且它的 size 是**估計值**（`len(json.dumps(gltf))+len(data)+28`），⛔ 不是真檔案大小 |
| ③ | 正常跑必然 `glb_mod.write(out_path, gltf, data)`（舊 `gen_lod.py:340`）**逐 tier 覆寫**每一顆 `-mid`/`-small.glb` —— ⭐ 包含 Codex 在 `35b231ef3` 剛修好的 **6 顆**（bulbasaur/herorider/linainvers × mid+small）⇒ **修法會把它要修的那個 commit 撤掉一部分** |

⇒ ⭐ 照指示**停手，⛔ 沒有跑它**。

### ⭐ 而「只更新 manifest」是**可以安全做到**的 —— 我把它做出來了

新增 `--manifest-only`（＋ `--check`）：對 manifest **已經指名**的每一條路徑
`os.path.getsize()` ＋ `Glb.triangles()`（`open(path,"rb")`，⭐ **純唯讀**），
然後只重寫 `_lod.json`。⛔ 不 decimate、⛔ 不寫任何 `.glb`、⛔ 不新增也不刪除任何一列。

**⭐ 而「這樣做是對的」是量出來的，⛔ 不是因為它比較便宜：**

```
83 列 · 250 個檔重量測
  bytes  漂移：16        ← 全部落在 35b231ef3 換掉的那 69 顆上
  tris   漂移： 0        ← ⭐ 幾何一個三角形都沒動
```

⇒ `repair_material_metadata.py` 是**保幾何**的 material metadata 修復
⇒ 磁碟上那些 `-mid`/`-small.glb` **仍然是它們 base 的誠實 decimation**
⇒ ⭐ **純重量測就是正解**，⛔ 不只是「不敢跑完整版」的替代品。

### ⚠️ ⭐ 這條閘看不到什麼（誠實寫在程式檔頭裡，⛔ 不要被綠燈誤導）

它證明 `bytes`/`triangles` 與磁碟一致。⛔ 它**證明不了** `-mid.glb` 是**今天這顆** base 的
decimation —— 把 base 換成**另一顆模型**，重量測照樣是綠的。那一類要完整跑。

### ⭐ 兩個方向都驗過（⛔ 單邊校準的尺不算自證過）

| 方向 | 結果 |
|---|---|
| 已知**壞**（16 格陳舊） | `--check` **EXIT=1**，逐格印出 16 行 `舊 → 新` |
| 已知**好**（修完之後） | `--check` **EXIT=0**，「與磁碟上的 83 顆模型一致（逐位元組）」 |
| **突變**（把 `guardian_beast.glb` 的 `bytes` 改成 `1`） | **EXIT=1** 並**指名那一列**；`pnpm lod:build` 還原後 **EXIT=0**，diff 回到剛好 16 行 |

### ⚠️ 過程中量到的第二件事：`ensure_ascii` 會讓這條閘**每次都紅 36 行**

出貨的 `_lod.json` 裡 `quarantineNote` 帶著**字面的** `→`
（GH#36 的隔離判決是 `2697d7898` **手工**加進去的，⛔ 沒有第二支腳本在寫它），
⛔ 而 `json.dump` 預設 `ensure_ascii=True` 會寫成 `→`
⇒ 一次**零資料變更**的重生成就會動 **36 行**。
⭐ 修法：`render_manifest()` 統一 `ensure_ascii=False`，而且**兩個模式共用同一支 renderer**
（⛔ 第二個 `json.dump` 呼叫點 = `--check` 會因排版差異而紅，而那種紅沒有人修得動）。
⇒ 實際 diff：**16 行進 16 行出**，⛔ 零 .glb 被動到（`git diff --numstat -- content/assets/models/` 只有 `_lod.json`）。

## 2. 戶籍（⭐ 這才是根治）

⛔ **改動前的狀態**（每一項都實查過）：

```

  → ✓ 沒有**產生器**擁有者,而且沒有被隔離區鎖過。      ← ⛔ 而 gen_lod.py:377 是唯一寫入端
grep '"lod' package.json                                → 0 筆      ← ⛔ 而檔頭在說「下一次 pnpm lod:gen」
sync-io.json 有沒有 assets/models 的 reads/writes       → 0 筆
```

⇒ ⭐ **三層同時瞎**（genguard 放行 · 隔離區不鎖 · 沒有 `--check`），
69 顆資產被換掉而唯一叫出來的是一支 vitest。

### ⭐ 補上的四件（一件都不能少）

| # | 做了什麼 |
|---|---|
| ① | `tools/lod-gen/gen_lod.py` 檔頭加 `# ggd:writes content/assets/models/_lod.json` —— ⭐ 單一住處，跟著程式碼走（`merge-io.mjs` / `reconcile.mjs` 的 `staticWrites()` 收割） |
| ② | `package.json`：`lod:build`（**走 genrun**，⛔ 不裸跑）· `lod:build:raw` · `lod:check` |
| ③ | 接進聚合指令：`skills:check` 加 `pnpm lod:check`（在 `models:check` 之後）· `skills:sync` 加 `pnpm lod:build`（在 `editorcov:build` 之後） |
| ④ | `sync-io.json`：新增 `lod:build` 步驟（`writes: ["content/assets/models/_lod.json"]`，`readCount 250`，`ms 115`）＋ `chain` 同步更新 |

⚠️ ④ 為什麼**必須**手加一列：`genguard.sh` 與 `product-quarantine.sh` 讀的是
`io.steps[].writes` 的**字面**，⛔ 它們不跑 `staticDeclared()`。
⭐ 而 `writes` 那一格的**內容**仍然只有一個住處（①的宣告）—— 這一列只是讓那三個消費端看得見它。
⚠️ `chain` 必須與 `package.json` 的 `skills:sync` **逐字相等**，否則
`syncPlan` 的 `chainStale` 永遠為真 ⇒ 每一次 sync 都退化成全跑。已驗：`chain==pkg` `True`、
`chain==names` `True`（62 == 62）。

（那正是它要逼人做的「選擇」：⛔ 我沒有走豁免那條路。）
