### 2.2 ⛔ 被丟掉的 2 支，以及**為什麼這不是刪除**

| PRE2# | emitter | 判定 |
|---:|---|---|
| 0 | `BlizParticle05white02` | ⛔ **modulate 疊全白 ⇒ 逐像素恆等** |
| 1 | `BlizParticle05white03` | 同上 |

推導（⛔ 不是判斷，是代數）：Babylon 的 `BLENDMODE_MULTIPLY` = `(DST_COLOR, ONE_MINUS_SRC_ALPHA)`

```
out = src.rgb·dst.rgb + dst.rgb·(1 − src.a)
    = dst.rgb·( tex.rgb·color.rgb + 1 − tex.a )
```

⭐ **量到的**：`content/assets/textures/particles/` 的替代精靈圖是「調色盤 + tRNS」PNG，
**RGB 逐格追著自己的 alpha**（實測 `smoke_09`：`(50,50,50)@a=26`、`(8,8,8)@a=5`、
`(218,218,218)@a=202`）⇒ `tex.rgb ≈ tex.a = t`。配上白色 doc 顏色：

```
out = dst.rgb·( t + 1 − t ) = dst.rgb        ← 恆等，每一個像素
```

⇒ 它們**不是「比較淡」，是逐位元的零**。原作靠 `Clouds8x8Mod.blp` 的 **alpha 形狀**做
modulate 淡霧，而我們的替代貼圖重現不了那個形狀；**自己編一個 tint 讓它亮起來是創作，⛔ 不是抽取**。
⇒ 知識沒有消失：它們逐支記在 `STOCK_VFX.json` 的 `models[].droppedEmitters`（含理由），
而且抽取器每跑一次就印一次。

### 2.3 ⭐ 為什麼要重新編號（這是這一批最容易被誤讀的一格）

`w3xAbilityArt.ts` 的 `MAX_STOCK_EMITTERS_PER_MODEL = 3` 是一個**固定的窗**：執行期只問
`p00 / p01 / p02`。照舊的「檔案順序」編號，`mark` 家族拿到的會是

```
p00 = white02（恆等）· p01 = white03（恆等）· p02 = 022222（紅星拖尾）
```

⇒ **3 格裡有 2 格是零**，而兩個巨環（`shockwaves02` / `shockwavesYellow`，家族說明逐字寫的
「在目標身上炸開一圈符印光」）落在 p04/p05，**永遠播不到**。

⇒ 抽取器現在：**先丟掉不可能畫出像素的，再按 `visual_weight = peak α × peak size` 遞減編號**。
⚠️ 那個 key 是**粗排序用的**，⛔ 不是保真度宣稱、⛔ 不是預算數字；同分保留檔案順序 ⇒ 全序 ⇒ 決定性。

## 4. 粒子預算影響（#660）

`VfxSystem.frontLoadDoc()` 把每一份 continuous 文件塌成 **一次** burst，
`burstCount = min(MAX_FRONT_LOAD_BURST=80, rate × 平均生命)`：

| doc | 授權密度 | front-load 後 | 到得了執行期？ |
|---|---:|---:|---|
| p00 | 30 × 1.0 = 30 | **30** | ✅ |
| p01 | 30 × 1.0 = 30 | **30** | ✅ |
| p02 | 80 × 0.46 ≈ 36.8 | **≈37** | ✅ |
| p03 | burst 26 | 26 | ⛔ 超出 `p00–p02` 窗 ⇒ **0** |
| | | **≈97 顆／次施放** | |

- 對照：`shockwaveRing` 已經出貨的是 **109 + 109 = 218 顆／次**（66 支技能）。
  ⇒ ⭐ **`mark` 的 ≈97 顆不到既有家族的一半，⛔ 不是預算事件。**
- 三份都沒碰到 `MAX_FRONT_LOAD_BURST=80` 的天花板 ⇒ 之後調 rate 仍有頭空間。
- 執行期另有 `particleBudgetScale(particleDensity)`（0–1 線性）與每 doc 池上限 4 ——
  這一批**沒有新增**任何池 key 以外的成本。
- ⚠️ 一格要盯的**不是數量是尺寸**：`p00` 的 end size **7.386 世界單位**（原作 segmentScaling 265.9 × 1/36）。
  它就是「巨環」本人，⛔ 不是 bug，但它在近鏡頭下會佔掉不少畫面 ——
  `mark` 家族的 `scale 0.85` 與後台 `scaleGain/scaleMax` 是調它的地方。
