## A. GH#819 —— 回合間 purge

**票況**：#819 CLOSED（「每回合開始前清理→重新盤點→載入完成才進入戰鬥（預設啟動）＋手動按鈕」）。
出貨檔位：`content/config/vfx-cleanup.json` → `"roundPurgeMode": "full"`。

### A1. roundPurge.ts 清什麼（apps/client/src/render/roundPurge.ts，247 行）

`RoundPurgeCoordinator.purgeNow()` 本身不清任何東西 —— 它是**協調器**，按檔位委派三段：

| 段 | 委派（出貨接線） | 實際清掉的類別 |
|---|---|---|
| soft ① | `roundFx.registry.resetForRound("leave")` | 整張回合邊界註冊表再扇出一次：各 FX 池「還回 free-list／修剪到 cap」（＝#819 之前既有的邊界清理，幾何與共用容器**不動**——檔頭自己這樣量過：geo 172→344→394 單調長） |
| soft ② | `vfx.hardResetModelFx()` → `ModelFxRig.hardReset()`（VfxSystem.ts:857） | **模型即特效這一條路**：活的實例＋free-list＋軌全部真的 dispose、容器引用整批放手（rig 繼續可用） |
| full 追加 | `assets.purgeFxContainers()`（AssetManager.ts:~218） | 只 dispose 快取裡 **tags === {"fx"}** 的 AssetContainer；shared 與雙標籤一份不碰（GH#558① 教訓）；in-flight 條目移出快取、落地那刻才 dispose |
| full 追加 | `reinventory()`（roundPurge.ts:186） | 重新盤點本場資產（英雄 glb＋技能特效 glb，`game/roundInventory.ts`）逐份重載，全落地才 ready；就緒閘 `gateActive()` 蓋「回合準備中 N/M」遮罩，保險絲 `GATE_FUSE_MS = 10_000` 到期放行並 console.warn |

**量測軸**（`PurgeCounts`，before/after 各量一次進 console 報表）：`geo / mat / tex / ps / node / mesh` 六類。

**沒有的軸（逐類點名）**：
- **音源**：零軸。全 client `new Sound(` **0 個呼叫**（grep 證實）——音效全走 WebAudio（`audio/*.ts`、`ui/buttonSfx.ts`、`beat/` 等有 AudioContext），Babylon 場景計數看不到它，purge 也不碰它。循環音登記表（vfxSoundLayer 單例）只在 GameApp.dispose 經 `roundVfx.exit()` 歸還（GH#560，GameApp.ts:~1336）。
- **DOM**：purge 只動一件——`showRoundLoadOverlay/hideRoundLoadOverlay`（遮罩）。其餘 DOM/HUD 不在範圍。
- **訂閱/observer**：完全不碰（`onStateChange.remove` 等收在 GameApp.dispose:~1331）。
- **shared 容器與其材質/貼圖**：**刻意不碰**（AssetManager.ts:148-157：shared 族常以 `cloneMaterials:false` 直掛容器來源材質，dispose 當場破圖）。⭐ 標籤預設是 `"shared"`（GameApp.ts:947 註解「判不出來寧可永不 purge」）⇒ 任何**誤標/漏標 fx** 的資產永遠不會被 purge——這是結構上留下的洩漏面。
- **GreasedLine**：全 client `CreateGreasedLine` 0 個呼叫（35 檔全 line=0）——「軌」都是 modelFx rig 的軌，由 hardReset 收。
