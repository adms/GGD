## ⭐ 最重要的一個發現（它推翻了票上對②的假設）

票上寫「② 手部跟隨特效 —— ⭐ 機制已經有了：`ability@1.persistentVfx`（#539）＋
`attach: "hand,right"`」。**那一半不成立，而且照著做會做出逐字相反的東西。**

`zPersistentVfx.when` 復用 `condition@1`，而 `condition@1` 的葉子只有：
`stat` · `status` · `equipment` · `chance` · `periodic` · `kind` ＋ 五種幾何形狀。
`PLAIN_STATS` 是 `str/agi/int/ad/ap/armor/magicResist/moveSpeed/attackSpeed/level`
（`packages/shared/src/sim/content/condition.ts:177`）。

⇒ **今天沒有任何一片條件葉問得出「現在在 alternate 形態 / 這顆切換鈕開著」。**
而 `when` **缺席**的語意是「這支技能**在身上／已解鎖**就掛著」——
所以現在把 `persistentVfx` 填進 20-01 風王結界，得到的是
**從開場到結束手上一直有風** ＝ 比現在更糟（開/關依然分不出來，而且多了一個
永遠拆不掉的特效）。

### ⭐ 但有一條**不需要新機制**的路，而且它今天就精確

出貨的兩支切換技**都是用 `championForm` 換身體**的：

| 邏輯技能 | 本體 championId | **開著時**的 championId（alternate） |
|---|---|---|
| 20-01 風王結界（亞瑟王 - Saber） | `godie-e002` | **`godie-e00l`** |
| 70-00 紮根（白木老樹精 - 白木卡迪那） | `godie-e00s` | **`godie-e010`** |

⭐ 也就是說「開著」在客戶端**就是一具不同的身體**，而
`config.ambient-vfx@1.bindings` 是 **keyed by modelKey / championId** 的
「這具身體永遠戴著」表（`godie-e00x` 已經是現役用例），
`AmbientVfx.attach()` 的重掛條件逐字就是 **modelKey 變了**
（`apps/client/src/vfx/AmbientVfx.ts:149`）。

⇒ **把手部特效綁在 alternate 那一列，等價於「只有開著的時候戴著」**，
零新機制、零新條件葉、拆卸由既有的換身體流程負責。

**建議填的兩列（⛔ 我沒有動 `content/`，這是給主 session 的）：**

```jsonc
// content/config/ambient-vfx.json → bindings
"godie-e00l": [ { "vfx": "fx.prim.wind.pulse-sm" } ],   // Saber 開著風王結界：手上纏風
"godie-e010": [ { "vfx": "fx.fam.shine.nature.s150" } ] // 白木卡迪那 紮根：根部光
```

⚠️ `attach` 走 `vfx@1` 文件自己的掛點（`right,hand` —— **WC3 的順序是
qualifier,base**，`render/vfx/attachment.ts` 的檔頭第 1 點逐字說明
`right,hand` 是**一個**掛點寫成兩個逗號 token，naive `split(",")` 會把它拆成
兩個都不存在的掛點）。票上寫的 `"hand,right"` 解析器也吃得下（token set 正規化），
但**寫進內容時請用 `right,hand`**，與 schema 的 `PERSISTENT_VFX_DEFAULT_ATTACH`
那一族的文件一致。

**如果 owner 要的是「不換身體的切換技也能掛」**（未來的切換技不一定走
`championForm`），那就需要**一片新的條件葉**，⛔ 不是為風王結界寫一個 if：
`{ kind: "form", subject: "self", form: "alternate" }`，或
讓 `championForm` 順手 `applyStatus` 一個具名狀態讓 `status` 葉問得到。
⭐ 一片葉子解鎖：所有切換技的常駐特效 ＋ 所有「只在某形態成立」的內容條件。
**這是一張新票的大小，⛔ 不是這條 lane 的柵欄內。**

## ① 圖示流轉 —— 已落地

### ⛔ 為什麼「就緒框亮一下」解不掉

出貨的 20-01 風王結界 `cooldown = [60,60,60,60]`，而**開著的期間它自己在冷卻裡**
⇒ `isAbilityTileReady()` 對它是 **false**。

⭐ **所以在這條線之前，「一支開著的切換技」與「一支單純在冷卻的技能」在畫面上
逐位元一模一樣**：沒有框、有一圈冷卻掃描。這正是 owner 說的「看不出是開還是關」，
而它**不是**「就緒框不夠亮」，是**少了第三種狀態**。

### 做了什麼

| 檔案 | |
|---|---|
| `apps/client/src/ui/toggleAbility.ts`（新，155 行） | `config.toggle-ability@1` 的 client 現值（形狀逐字照抄 `rangeGuideConfig.ts`）＋ 掃光 `@keyframes` 的自掛載 |
| `apps/client/src/ui/abilityReadyFrame.ts`（+82 行） | `AbilityTileState` · `abilityToggleFrameStyle()` · ⭐ `abilityTileFrameStyle()` = **四個磚家族的唯一入口** |
| `content/config/toggle-ability.json`（新） | 出貨值 |
| `apps/client/src/ui/toggleAbility.test.ts`（新，68 行） | 承重守衛 |

**視覺 = 兩半，刻意分開：**

* **常駐鑲邊 + 外暈** —— 說「它是開著的」。**永遠在**，減少動態也在。
* **掃光（owner 點名的「流轉」）** —— 動作。`prefers-reduced-motion` 下**整段消失**。
  ⭐ 保留那句話、拿掉動作 —— 與 `cooldown.css` 兩支動畫同一個教條。

⚠️ 掃光的機制**刻意重用** `buttonFx.css` 的 `ggd-btn-glow`
（`background-size:300%` ＋ 推 `background-position`），⛔ 不發明第二種流轉；
⛔ **不用會轉一圈的 conic 鑲邊**：磚自己的 `transform` 已經被按下動畫與拒絕抖動
佔走（`paintCastFlash` 直接寫 `el.style.transform`），而一個會 `rotate` 的方形
子元素會轉出磚外。`background-position` 動的東西不碰版面。

⚠️ `@keyframes` 掛在**畫這個框的人**身上（`ensureToggleKeyframes()`，冪等、
沒有 DOM 就 no-op），⛔ 不是再叫 `main.tsx` import 一支 `.css` ——
一支忘了被 import 的 `.css` 讓動畫**靜默地不跑**，而「不動的鑲邊」跟關閉態
在畫面上差不多（失敗形態②）。動畫名是**一顆共用常數** `TOGGLE_ANIM_NAME`，
所以「keyframes 名字與 animation 引用漂掉」在結構上不可能發生。

### ⛔ 第〇·五守則

這裡沒有為風王結界寫任何一個 if。`toggleOn` 是**一格狀態**，
出貨的兩支切換技（4 份文件）與未來每一支都走 `abilityTileFrameStyle()` 同一條路。
⛔ 呼叫端也不要自己 `if (toggleOn)` 再挑一支 style —— 那就是把這個決定寫四遍
（天生技 / QWER / EX / TouchControls），而它們一定會漂（#166 的虛線邊框當年就只在
其中兩個家族上）。

### 沒有做成欄位的那一格（帶理由）

「開著的時候要不要**同時**保留就緒框」——⛔ **沒有做成欄位**。
開著的期間那支技能本來就在冷卻，就緒框在出貨內容上**不可能**同時亮 ⇒
一格切不出任何差別的欄位就是第一·五守則說的「說了但不會發生」。
