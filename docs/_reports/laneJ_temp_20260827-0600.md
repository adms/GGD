## 5 · F-17 —— 字面前綴看不見 symlink

**在此之前**兩支 dev/preview 的靜態 middleware 都只有

```ts
if (!file.startsWith(rootDir + sep) || !existsSync(file) || !statSync(file).isFile()) return next();
```

⇒ `content/x.json → ~/.ssh/id_ed25519` 的**字面**前綴完全合格，middleware 會把它串流出去。
⭐ 這不是理論路徑：`client-lan`（`--host`）正是 owner 實際遊玩的那條路，它對整個區網開著。

**修法**：`confineToRoot(rootDir, file)` —— 字面柵欄 → `realpathSync` 兩邊 → 再比一次前綴。

⭐ **root 自己也要 realpath**（這一格才是「⛔ 不要把人鎖在門外」）：
macOS 的 `/tmp → /private/tmp`、以及把 repo 或 `data/blizzard-overlay/` 放在符號連結底下的機器，
只 realpath 檔案就會**每一個請求都 404**。實測 repo 現況 `find content -type l` = **0 條**，
⇒ 這次改動對今天的每一條合法路徑**行為不變**。

⭐ 順帶關掉一個同型的洞：**precompressed sidecar**（`foo.glb.gz`）走的是**另一條**解析路徑，
所以 `freshSidecar()` 也改成過同一道柵欄 —— 少了它，`.gz` 自己就可以是那條逃出去的 symlink。

🔁 **rollback**：`GGD_DEV_ALLOW_SYMLINK_ESCAPE=1` 回到 #724 之前的字面比對。
（只影響 dev/preview server —— 出貨的靜態檔由 nginx 服務。）

### ⚠️ 守衛只能住在 `vite.config.ts` 裡面，而那需要兩行設定

柵欄不允許新開測試檔，而「掃原始碼有沒有寫 `realpath`」是**屬性**⛔不是行為（失敗形態⑥）。
⇒ 用 **in-source test**（`if (import.meta.vitest)`）：真的 `mkdtemp` 一棵樹、真的掛一條
指向 root 外的 symlink、真的呼叫出貨的那支 `staticHandler`。兩件必須一起做：

| 為什麼 | 改了什麼 |
|---|---|
| vitest **預設** `exclude` 含 `**/{…,vite,…}.config.*` ⇒ `includeSource` 會**安靜地收集到零個檔**（⛔ 而且不會有東西紅 —— 我第一次就中了） | `exclude: configDefaults.exclude.filter((p) => !p.includes(".config.*"))`（⭐ 從 `configDefaults` **推導**，⛔ 不抄一份會過期的清單） |
| `import.meta.vitest` 的型別不在 `vitest/config` 裡（`tsconfig.json` 在柵欄外） | 檔頭加 `/// <reference types="vitest/importMeta" />` |

## 7 · F-21 —— refresh token 不再**長住** localStorage（後台那一半）

### 形狀：**加法**，⛔ 不是替換

`/auth/{register,login,refresh,account/password}` 現在**照舊**把整組 token 放在 body 裡
（⇒ 遊戲客戶端逐位元組不受影響），**同時**把 refresh token 種進一顆 cookie：

```
ggd_rt   HttpOnly · Path=/api/v1/auth · SameSite=Strict · Secure(僅在 https) · MaxAge=refreshTTL
```

並在 body 多一個 `"refreshCookie": true` 說它種了。
`/auth/refresh` 與 `/auth/logout` 在 **body 的 token 是空的**時候改讀那顆 cookie（body 優先）。

### ⭐ 為什麼旗標由伺服器發，⛔ 不是前端自己決定

httpOnly 的意思就是**瀏覽器永遠驗證不了那顆 cookie 在不在**。
前端如果用猜的，一次「後端把旋鈕關掉」就會讓 token 掉在地上 ⇒ 把 operator 鎖在門外。
⇒ 伺服器是唯一真相，而這也讓 rollback 變成**一格環境變數**：

🔁 **`GGD_AUTH_REFRESH_COOKIE=0`** ⇒ 不種 cookie、不發旗標 ⇒ admin 端自動退回
「把 refresh token 寫進 localStorage」 —— ⛔ **不必重建前端**。
（`config.AuthRefreshCookie`，預設 **1**；`internal/testutil` 的 fixture 也明寫 `true`，
⛔ 不讓新旋鈕靜靜停在零值 —— 那會變成「測的不是出貨的那個」。）

### ⭐ 三個刻意的降級設計（每一個都是「⛔ 不要把人鎖在門外」）

| 決定 | 為什麼 |
|---|---|
| **記憶體裡仍握有完整的 refresh token**，只有**寫到磁碟的那一份**被抽掉 | cookie 沒種成功時，**這個分頁完全照舊**；只有下一次重新載入才需要 cookie。同一個分頁裡的 XSS 本來就能直接呼叫 API ⇒ 留在記憶體沒有多讓出東西；F-21 要關的是**跨頁存活**的那一份 |
| **Secure 只在 https 才加**（`httpx.RequestIsHTTPS`） | Secure cookie 走 plain http 會被瀏覽器**直接丟掉** ⇒ 下一次重載就是一次無聲登出。而 LAN dev 正是 plain http |
| **`setTokens(null)` 在 cookie 模式且手上沒 token 時補打一發 best-effort logout** | 重載後 `store.ts` 的 `if (token) apiLogout(token)` 會整個跳過 ⇒ 那顆 cookie 會活到 TTL。⭐ 「簽出沒有把憑證還回去」比 localStorage 更糟，因為**畫面上永遠看不出來** |

### ⚠️ `/__review` 與 `/__live`（#796）沒有被動到

`liveAuth.ts` 讀的是 **access token**，而 access token **仍然**存在 localStorage（它 15 分鐘就過期，
⛔ 不是 F-21 指的那顆長效憑證）。⇒ 重載之後 `readToken()` 立刻有值，批核頁的行為零變化。
✅ `apps/admin` 全套 **113 檔 / 1,241 條**綠。

### ⛔ 遊戲客戶端那一半沒做

落點 `apps/client/src/ui/platform/session.ts` 在**禁改清單**上（`apps/client/src/**`）。
⭐ 伺服器那一半對它是**完全被動**的：它照舊送 body token、照舊忽略新欄位 ⇒ 零風險，
⛔ 但它的 refresh token 仍在 localStorage。**AC 7 因此尚未完整成立。**

### ⚠️ 這一輪自己踩到的一個 —— 一份知識差點多一個住處

第一版把「哪些 peer 可信」的判斷（loopback／RFC1918）**抄進 `internal/auth`**，
被既有守衛 `TestAuthPackagesNeverReadAnAddress` 當場擋下（`RemoteAddr` / `X-Real-Ip` / `httpx.ClientIP`）。
⭐ **那道閘是對的**：可信集合是 operator 可調的（`GGD_TRUSTED_PROXY_CIDRS`），
抄第二份 = 兩份會各自漂的真相（第〇·四守則）。
⇒ 改成 `httpx.RequestIsHTTPS(r)`，讀位址的事留在 httpx，`internal/auth` 一個位址欄位都不碰。

## 4 · F-15 CSP —— ⛔ 不升級，而且這一輪**量到了阻擋物**

前一輪留 Report-Only 是為了先量一輪。**這一輪拿不到那份量測**（⛔ 不 ssh/curl 正式站），
所以照指示不升級。⭐ 但靜態複查找到一個**具體的、會在 enforced 下爆掉**的東西：

> `apps/admin/src/ui/AudioAuditionPage.tsx:158` 有一個 **`<iframe src={tab.url}>`**，
> 而 `tab.url` 來自 **`VITE_CLIENT_URL` / `VITE_ADMIN_URL`**（`config.ts:68`）。

- `default-src 'self'` 一旦 enforced，`frame-src` 就跟著 fallback 到 `'self'`；
- client 與 admin **不同源**的部署（dev 是 `:39527` vs `:60721`，以及任何把 client 放在別的 host 的設定）
  ⇒ **試聽頁整格空白**。
- ⭐ 好消息：Report-Only **現在就會報這一條**（它也 fallback 到 `default-src`），
  所以那一輪量測會自己把它列出來 —— ⛔ **不需要**先改 nginx。

⇒ **升級的完整前置條件（下一條 lane）**：
1. 跑一輪真的 session（登入 → 選角 → 一場 → `/admin/` **含 音效試聽頁**）收 console 的 violation 清單
2. 若清單只有這一條 ⇒ 決定「`frame-src` 放行同源以外的 client URL」或「該頁改成開新分頁」
3. 清單清空後才刪 `-Report-Only` 後綴並移除那行窄的 enforced
⚠️ ⛔ 不要逐條升級：`default-src` 一旦 enforced，它 fallback 到的每一條也一起 enforced。

## 部署注意

⚠️ 這一版**必須完整重建 platform 映像**（cookie 與 `httpx.RequestIsHTTPS` 在映像裡），
⛔ 不可 `--content-only`。nginx 這一輪沒動，edge 映像可不動。

⭐ 煙霧測試多看一件事：**登入後台 → F5 重新整理 → 仍在 console 裡**（⛔ 不是被丟回登入頁）。
那一次重載就是 F-21 的全部風險面；不對的話 `GGD_AUTH_REFRESH_COOKIE=0` 一格退回。
順便照舊看 console 的 **CSP Report-Only violation** —— 那就是 F-15 升級的清單。
