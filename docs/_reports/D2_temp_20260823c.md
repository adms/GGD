## 修法

### `apps/client/src/render/screenFx.ts`（純數學那一層，⛔ 沒有 DOM/Babylon）
- `ScreenCueSink`（結構型別）· `screenCueViewportMask(cue, viewers)` · `dispatchScreenCue(type, data, viewers, sinks)`
- `installSplitScreenCueRouter(on)` / `splitScreenCueRouterInstalled()`
- `screenCueIsForViewer()` 在路由裝上後一律回 `false` —— ⭐ **全螢幕那一層在分割畫面下沒有觀眾**。
  ⛔ 少了這一行 = 同一發演出出現兩次（全螢幕一次 + 那一格一次）。

⚠️ 派送迴圈刻意住在 `screenFx.ts` 而**不是** `GameApp`：`GameApp` 在測試裡建構不出來
（`new Engine(canvas)` 要真的 WebGL），寫在那個檔案裡的決策**沒有守衛**（同 #223 那一段的教訓）。

### `apps/client/src/GameApp.ts`（只動 viewport / screenCue 那一段）
- `installScreenCues(playerCount)` —— 逐格容器（`cssRects()`）＋ **逐格一個 `ScreenFxLayer`**。
  ⭐ **重用出貨的圖層類別**，⛔ 不抄一份合成邏輯：容器上 `contain:paint`（＋`transform:translateZ(0)` 保險）
  讓子層的 `position:fixed; inset:0` 被夾在**自己那一格**裡（CSS 包含塊）。
- `screenCueViewers()` —— 每一格現在的主角；與 `burnTintFrame` / `updateSpectatorCam` **同一條座位規則**，⛔ 不是第二份真相。
- `routeScreenCue(ev)` 掛在 `handleDrainedEvent`，排在 `applyCombatFeedback` **之前**（它要先把震動排進佇列）。
- `authoredShake` 從純量 → **逐格陣列**；`applyCombatFeedback` 逐格套用，
  第一格仍與命中反應**合流取較大的一發**（⛔ 不是各震一次），其餘各格照自己的 cue 抖。
  ⭐ **仍然只有一個 `.addShake(` 呼叫點**（`combatCameraWiring.test.ts` 在守）—— 迴圈裡的那一個。
- `tickScreenCues(dtMs, phase)`（推進 + 換 phase 清場）· `dispose()` 收 overlay 並 `installSplitScreenCueRouter(false)`。

## 守衛：`apps/client/src/render/splitScreenCues.test.ts`（4 條，115 行）

建**四個真的 `ScreenFxLayer`** + 四個 `addShake` 計數器，跑**出貨的** `dispatchScreenCue`：
1. ★ 指名玩家 2 ⇒ `[false,false,true,false]` 且 shakes `[0,0,1,0]`
2. ★ 指名 player 0 ⇒ ⛔ 不會蓋到 1/2/3
3. broadcast ⇒ 四格都要有（含還沒有主角的那一格）
4. 路由裝上後 `screenCueIsForViewer` 回 false（⛔ 否則同一發出現兩次）

⛔ 一個出貨數字都沒有進斷言（第二守則：驗機制不驗數字）。
