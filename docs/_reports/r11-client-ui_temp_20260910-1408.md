## ③ ⚠️⚠️ **這一批唯一推導不乾淨的東西：換邊／旁觀**

### 為什麼

伺服器**有**權威答案：`MatchController.round11ReconnectRole(seatId)` →
`"champion" | "boss" | "spectator"`。⛔ **而它今天送不出來** —— 送它要 `SeatState`
多一格，也就是 `packages/shared/src/protocol/schema.ts` 的 `defineTypes` 變更：
⭐ 不可逆（APPEND-ONLY，加錯回不去），⛔ 而且那個檔**不在這一批的柵欄裡**。

⚠️ ⭐ 而換邊在**快照上與復活長得一模一樣**：`convertWipedTeamsToBosses` 重用
**同一個 `entityId`**（`bossEntityId: seat.entityId`）並把 `hp.alive` 設回 true。

### 今天的判準（`round11Model.round11SelfRole`）

```
!alive                                         → spectator
alive && roundDeaths > 0 && 全隊有實體的每一格都死過 && deadPlayersControlBoss → boss
其餘                                            → champion
```

條件②來自伺服器自己的規則：**只在整隊團滅時換邊**（`round11TeamShouldConvert`），
⭐ 而一次復活圈需要一個**還活著的**隊友。

### ⛔ 它仍然不是 100%（⭐ 我沒有把這個洞藏起來）

`A 死 → B 用復活圈救 A → B 之後才死` ⇒ 兩格都 `roundDeaths > 0` 而 A 活著
⇒ **會把 A 誤報成王**。

⭐ **真正的修法是送那一格**（一個 `SeatState` 的 uint8 role，或高半部一顆
`ENTITY_FLAG`）。⭐ 誤報的方向是刻意選的：把換邊誤報成換邊，比**完全不說**好
（票逐字要的是「角色換邊／旁觀」看得出來）。
