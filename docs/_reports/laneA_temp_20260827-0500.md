## #791 — genguard 把 heredoc 內文當成重導

**根因兩段。** 舊碼只 `re.sub` 掉 heredoc 的**分隔符**，內文原封不動留在字串裡 ⇒
`cat > x.sh <<'SH' … SH` 的內文（註解、markdown 表格、`rm -rf /`）被讀成一道道重導。
而它 2026-08-27 才爆，是因為 #771 把「鎖著(444)但戶籍無主」從**靜默放行**改成**擋** ——
解析缺陷一直都在，只是在此之前看不出來。

**修法兩件**（`scripts/preserve-before-overwrite.py`）：
1. `_strip_heredocs()` — 起訖標記之間整段丟掉（認得 `<<-` 的 tab、引號分隔符；`<<<` 不算）
2. `_looks_like_a_file_target()` — 解析成 repo 根／檔案系統根／父目錄不存在 ⇒
   **放行並印「解析不了」**（exit 0）。⛔ 沒有放寬「鎖著無主 ⇒ 擋」那條裁決本身

**⚠️ 過程中的一個真教訓（守衛第一版不承重）**：① 原本只在 heredoc 內文放 `rm -rf /`，
突變（`_strip_heredocs` 改成 `return cmd`）之後**照樣綠** —— 因為那個 `/` 會被第 2 件的
sanity 濾網吃掉。兩個修法對這個輸入是**冗餘**的，於是測試量到的是濾網不是剝離。
改成內文帶一份**真的 444 產物路徑**（＝「腳本內文寫用法範例」這個真實形狀）之後才承重：
突變 ⇒ ① 紅，訊息指名那份產物 —— **復現了回報的症狀**。

## #772 — `listing_of()` 的失敗是啞的

**先更正票上的敘述**（量到的，⛔ 不是推測）。舊腳本 + 3 檔夾具 + 中間那檔 `chmod 000`
+ `GGD_ASSET_STRICT_READ=0`：

```
EXIT=1 · sha256sum: ./b.bin: Permission denied
SHIP.sha256 行數: 1     ← 3 個檔的集合
SHIP.txt: 不存在
```

⇒ 不是「靜默漏掉一個檔」，是 **`set -e` 把迴圈的 subshell 打死，一份截斷的 SHIP.sha256
被留在磁碟上**，而 `count_of` 仍數 3。⚠️ 而**哪幾個檔進得去是 shell 相依的**：
bash sh-mode 第一個失敗就中斷；不在那個 subshell 套用 `set -e` 的 shell 會走完整組、
只漏掉壞的那幾個 —— 而 edge 跑 busybox ash、owner 的 Mac 跑 bash。**兩種都驗得過**。

**修法**：逐檔收離開碼（失敗路徑穿過一個暫存檔，因為迴圈跑在 pipeline 的 subshell）→
指名 → 非零；`cmd_manifest` 不再留半寫的清單，並加「**SHIP.sha256 行數 == `count_of`**」
的關係檢查（全腳本唯一同時握有兩半的地方）。
沿用 #749 的**同一格**逃生口 `GGD_ASSET_STRICT_READ`，⛔ 沒有開第二格；`=0` 逐位元回到
舊行為，**連「留下一份 1 行的 SHIP.sha256」這個特徵都保住**。

## #769 — `--dry-run` 寫下一筆沒發生過的事實

紀錄迴圈本來**無條件**執行 ⇒ dry-run 寫出 `verdict:"ok"` 的 `convert-<slug>.json`，
而 `.glb` 一個位元組都沒動；⚠️ 而且它會**覆蓋一份真的紀錄**（洗掉 `installed`），
於是「發生過」與「沒發生過」的差別只剩**一個鍵的缺席**。

**⭐ 新的 `--check` 上線就抓到一筆真的，而且它在 main 上**：
`convert-tornadoelemental.json` 與 `.glb` 在**同一個 commit**（`aa5e776c`）進來，
而 `git show` 出來那份是 `verdict:"ok"` / 無 `installed` ⇒ **那份被 commit 的量測紀錄
本身就是 dry-run 的產物**，旁邊的 `.glb` 卻是真的。

⛔ 沒有順手修：正解是重跑真的安裝，而它寫 `content/assets/models/imported/`（柵欄外）。
⛔ 沒有刪掉它（會丟掉要跑一趟 MPQ 才有的 textures / emitterAlpha 量測）。
⛔ 沒有為了讓票變綠而放寬 `--check`。
⚠️ `--check` **刻意不比 mtime**：`git checkout` 重設整棵樹的 mtime ⇒ 那條斷言在乾淨簽出的
樹上必定紅，只會被放寬或關掉。查得動的關係是「紀錄宣稱安裝了 ⇒ 那個檔真的在」。
