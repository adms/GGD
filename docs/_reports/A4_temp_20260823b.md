## ⭐ 最重要的發現：`reads` 的裁剪讓六個集合對計畫**隱形**

`merge-io.mjs` 的 `reads` **刻意只留「有人寫過」的檔**（否則 `sync-io.json` 20KB→2.5MB）。
⇒ 一整個**沒有任何產生器在寫**的集合，對每一支的 `reads` 都是**空的**。

實測 `content:build`：

| | |
|---|---|
| 真的讀 | **8,944** 個檔（`readCount`） |
| 表上留下 | **563** 個 |
| 其中 `content/status-effects/` | ⛔ **一個都沒有** |

⇒ 改一份狀態效果文件，計畫只挑 **3 支**，而 ⛔ **`content:build` 不在裡面**。

**受害的六個集合**：`status-effects` · `maps` · `arenas` · `projectiles` · `skins` · `loot-tables`
（`vfx` / `models` / `items` / `augments` / `ability-templates` 也各缺一到多支）。

⚠️ **後果正是 2026-08-01 事故的形狀**：`bundle.json` 停在舊的那一天，
而那份 bundle 逐字內嵌這些文件（實測 `content/bundle.json` 的 `status-effects.entries` 有 43 筆，
`alcohol-enema` 就在裡面）。過期的 bundle 帶著全綠的測試上線 ⇒ 內容載入失敗 ⇒ 退回骨架。

### 修法：**證據就在它自己的產物上**（第 ④ 個推導來源）

`content:build` 寫了 `content/status-effects/_index.json` ——
⭐ **一份索引不可能在沒有列舉那個目錄的情況下產生出來。**

⇒ 規則：**「寫進 `<dir>/` ⇒ 讀過 `<dir>/`」**。
對索引／打包型的產生器這是**推導**；對其餘的是**保守的上界**
（多算 ⇒ 多跑一支，⛔ 不會漏掉一支）—— 與 `graph.mjs` 對「就地改寫型」的處理同一個方向。

⚠️ depth-1 的裸 root（`content` / `docs`）仍然**只**算宇宙：`content:build` 也寫 `docs/`，
把 `docs` 當成它的前綴會讓每一次文件改動都拖著它跑（⛔ 而它不讀 docs）。
