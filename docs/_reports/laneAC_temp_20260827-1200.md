## 3. ⭐ 反查抓到的第一個誤譯：08-03 用 `scaleAxis` **拉長一具去假裝十具**

### 逐行 JASS（`Trig_DraBom`，A05J）

```
j:28827  PlaySoundOnUnitBJ( gg_snd_ThunderClapCaster )        → sfxKey 已對
j:28836  loop  udg_Dragon = 1 .. 10
j:28838    CreateNUnitsAtLoc( 1, 'e003', …, PolarProjectionBJ(origin, 150×i, facing), facing )
j:28839    UnitApplyTimedLifeBJ( 1.00, 'BTLF', GetLastCreatedUnit() )
j:28857  （sleep 0.5 + 2.0 之後）ForGroupBJ(…'e003') → KillUnit + RemoveUnit
```

⭐ **迴圈體裡真的有 `CreateNUnitsAtLoc`** ⇒ 它是 **10 具實體**
（⛔ 不是 `GetUnitsInRangeOfLocMatching` 的傷害班表、⛔ 不是沿線 `AddSpecialEffect`）。
這正是 `tpl-beam-roll.params.count.origin` 自己寫著的那一句：
「⭐ 真的沿線 N 具的是 **08-03** 的 e003（j:28838, i=1..10×150）與 09-04 的 h006
（j:31926, i=1..6×200）…**而後者現在有自己的節點**」——⇒ **前者一直沒有**。

### 出貨的樣子（2026-08-27 之前）

```json
{ "kind":"spawnModelFx", "preset":"tpl-beam-roll",
  "modelKey":"w3x.stock.reddragonmissile",
  "scaleAxis":[1,1,7.09] }          ⇐ 一具龍息彈沿行進軸拉長 7 倍
```

⛔ 那是 owner 2026-08-26 明令禁止的**第三條路**：「用現有參數湊一個看起來像的」。
⚠️ 而它在 schema／`content:build`／既有守衛面前**逐位元一樣綠**。

### 改成（4 份文件：standalone ×2 ＋ champion 內嵌鏡射 ×2，⭐ 變身對子兩邊一起動）

```json
{ "kind":"spawnModelFx", "preset":"tpl-beam-roll",
  "modelKey":"w3x.stock.reddragonmissile",
  "count":10, "spacing":1.2 }
```

| 格 | 出處 |
|---|---|
| `count: 10` | **j:28838** `loop udg_Dragon = 1..10` |
| `spacing: 1.2` | ⭐ **誠實的偏離**（見下） |
| `scaleAxis` 移除 | 它的存在理由是「讓**一具**橫跨射程」；有了 10 具就變成 10 道各自橫跨射程的光柱 |
| 家族預設 `count` 仍是 **1** | 那 8 個 j: 行號講的是**光束 dummy**，e003 是龍息彈 ⇒ 兩件事，⛔ 不因一支沿線就改整族 |

**`spacing: 1.2` 為什麼不是逐字的 2.75**（⛔ 這是偏離，寫下來是為了讓下一輪反駁得了）：
逐字換算 150 wc3u × `GGD_PER_WC3`(11/600) = **2.75** ⇒ 10 具鋪出 24.75 長的線，
而競技場只有 **24×18**、這一支自己的 `range` 是 **12**（w3a `cast_range` 750 × 11/600 = 13.75，取級距後 12）。
⇒ 沿用 `tpl-beam-roll` description 已經立過的同一條規則 ——
**渲染長度 ≈ 這一支自己打得到的距離** ⇒ `spacing = range 12 ÷ count 10 = 1.2`。
⭐ rollback：把節點那一格改回 **2.75** 就是逐字原作尺度（⛔ 那條線會超出射程一倍，
卡面與畫面互相說謊，第一·五守則）。
