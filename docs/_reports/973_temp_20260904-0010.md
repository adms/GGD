## ⓪ 一句話結論

⭐ **守護塔那兩欄是活的（票文的假前提被推翻），真缺口是「殭屍擊殺零欄」** ——

## ② 做了什麼

### (a) 欄位表從**手寫陣列**變成**帶來源宣告的註冊表**

`apps/client/src/ui/panels/settlementModel.ts`

```ts
export type SettlementDatum = keyof PlayerMatchStats | "mobKills";
export interface SettlementColumn {
  key: string; label: string;
  sources: readonly SettlementDatum[];   // ⭐ 機器可讀,⛔ 不是註解
  render(stats, extras): string | null;  // null ⇒ 這一份封包沒有 ⇒ 不印(⛔ 不是印 0)
}
export const SETTLEMENT_COLUMNS: readonly SettlementColumn[] = [...];
export const SETTLEMENT_DATA_WITHOUT_COLUMN: Readonly<Record<string,string>> = {...};
```

⭐ `sources` 是這張票真正的產出：在此之前欄位表是一個手寫陣列，
於是「**有資料而沒有欄位**」在結構上**問不出來**（第二守則⑫：只從一頭走的掃描必然失明）。

### (b) 補上「殭屍擊殺」那一欄 —— ⛔ **零個協定改動**

⭐ 那個數字**已經在線上了**：`MatchSettlement.rounds[*].players[*].mobKills` 是
`world.mobKills` 的每回合差值，而 `foldFinalRoundResidual()` 保證最後一回合把殘量摺回去。

⇒ **量到的恆等式**：`Σ(線上每回合差值) ≡ 伺服器的 world.mobKills`
—— 三場 × 12 席逐席比對，⭐ **36/36 逐位元相等**。

⇒ ⛔ 所以**沒有**加 `SettlementPlayer.mobKills`：那會是同一個事實的**第二個住處**（第〇·四守則）。
新函式 `settlementMobKills()` / `settlementExtras()` 讀已經有的那一份。

⚠️ **插入位置是有理由的**：兩個消費端的格線都是 2 欄，守護塔那一對必須落在偶數索引
（「打了多少」與「打掉幾座」分開看沒有意義）⇒ 新欄位插在那一對**之後**，
⇒ ⭐ 連「舊伺服器沒有這一欄」的情況都不會把守護塔那一對拆到兩橫列。

### (c) 兩個出貨消費端接線

`MatchEndPanel.tsx`（`StatBreakdown`）· `LeaveSettlementOverlay.tsx`（`StatGrid`）
—— 兩者都改成吃**整份結算**而不是只吃 `player.stats`。

## ③ 守衛（兩支，⛔ 都不是掃字串）

### `apps/game-server/src/match/settlementColumns.test.ts` —— 跑**真的比賽**

載入**出貨的**守護塔／殭屍波設定 → 跑**出貨的** `MatchController` → 拿**真的**
`MatchSettlement` → 餵進**客戶端出貨的** `buildStatBreakdown`
（`curation/curationVsContentModel.test.ts` 早有跨 app 讀純模型的前例）。

| 條 | 問什麼 |
|---|---|
| **A** | 每一欄都宣告了來源，而且每一個來源都是真的存在的數字（key 不重複） |
| **B** | ⭐ **反方向**：每一個真的會非零的數字，要嘛有欄位、要嘛在豁免表上帶著一個可被反駁的理由 —— **這是 mobKills 缺席好幾個月時唯一會紅的那一條** |
| **C** | 殭屍擊殺印得出來，且**數字與伺服器逐位元相等**（含 calibrate：這一場真的有殭屍死掉） |
| **D** | 封包沒帶 `rounds` ⇒ 那一列**不印**，⛔ 不是印 0，而其餘欄位一格都不少 |

⚠️⭐ **A 刻意是結構性的，⛔ 不是「每一欄在這一場至少有一席非零」** ——
2026-09-03 量到為什麼：`healingDone` 單獨跑時 36/36 席非零，
**與別的 suite 同一個 worker 跑時是 0/12**，因為 `randomChampionPool()` 讀的是
**行程級**註冊表，別的測試註冊過內容就換一批英雄，而有沒有治療技能完全看抽到誰。
⇒ 那是一個**行為相依的量**（它是區間，不是一個數字）；拿它當門檻會間歇性紅，
而一條會亂紅的守衛遲早被關掉 ＝ 沒有守衛。
⇒ 「這一欄永遠是 0」改由豁免表的 `coinsCollected`（帶到期條件）承擔。

⚠️ 殭屍波**只有間隔**被壓密（出貨是第 3 回合才開）：這一份驗的是「接不接得到線」，
⛔ 不是「出貨排程夠不夠密」——一條靠「應該會有人補到刀」才綠的守衛就是失敗形態⑩。

### `apps/client/src/ui/panels/mobKillsSettlementRow.test.ts` —— 渲染**出貨的 markup**
