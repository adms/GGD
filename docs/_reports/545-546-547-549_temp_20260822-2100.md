## 0. ⚠️ 最重要的一個發現：交辦單上的欄位名 `spacing` 是**死的**

交辦單寫「`config.victory-podium@1` 加一格 **`spacing`**」。
⛔ 照著做會做出一格**後台存得起來、畫面永遠讀不到**的欄位。

消費端早就寫好了，而它讀的鍵名不是 `spacing`：

```ts
// apps/client/src/render/RoundWinnerStage.ts:169
export function podiumSpacing(cfg: VictoryPodiumPolicy): number {
  const raw = (cfg as VictoryPodiumPolicy & { podiumSpacing?: number }).podiumSpacing;
  const v = typeof raw === "number" && Number.isFinite(raw) ? raw : PODIUM_SPACING_FALLBACK;
  return Math.min(PODIUM_SPACING_MAX, Math.max(PODIUM_SPACING_MIN, v));
}
```

⇒ **我用了 `podiumSpacing`**。這一個字的差別決定這一票是「落地」還是
「三個住處都對、遊戲一輩子看不到」（第一·五守則的形狀 ——
`content:build` 綠、全套測試綠、schema 收得下、卡片上印著那句話，而什麼都不發生）。

⭐ 而且因為客戶端那個 cast 是 `podiumSpacing?: number`，**接上去不需要動客戶端一個字元** ——
Zod 的鍵一存在，`RoundWinnerStage` 當場就讀到了。⛔ 這是這一批唯一不需要主 session 接線的一票。

## 5. ⏸ 卡在 owner 身上的一個決定：`reducedMotionMode` 三選一

⚠️ 出貨值我先填 **`weaken`**，⭐ 但那是**我挑的，owner 沒有裁決過**。
三條路影響的是**別人的身體**，⛔ 不是畫面好不好看：

| 選項 | 玩家實際看到 | 代價 |
|---|---|---|
| `off` | 開了「減少動態」的人**完全不震不閃** | 最安全，但那群人**拿不到**這一層唯一想給的東西（「有事發生」）⇒ 他們回到 owner 抱怨的那個狀態 |
| **`weaken`（我填的）** | 強度打折；閃爍改成一次**沒有陡峭上升緣**的緩慢呼吸 | 資訊在、誘因大幅降低，但**不是零** —— 光敏性癲癇的門檻因人而異 |
| `ignore` | 照原樣播 | ⛔ 明知後果仍要關掉這個行為。留著只是為了「一鍵回頭」，⛔ 不推薦 |

⭐ 三者都已經是**一格下拉**（第一守則：先問「這能不能是一個欄位？」），
所以 owner 改主意的成本是「存一次檔」，⛔ 不是一次部署。
