## 1. 設計（⭐ 全部在柵欄內，零個柵欄外必要改動）

### 一格新通道：`caster.castFx`（封閉詞彙表 `VFX_SCRIPT_YIELD_CHANNELS`，唯一住處 `schema/vfxScript.ts`）

| 通道 | 它是什麼 | 與既有格哪裡不同（`abilityPresentation.ts` 逐字要求） |
|---|---|---|
| `caster.action`（舊） | 施法者**身體**的剪輯（`AnimPulse`） | —— |
| ⭐ `caster.castFx`（新） | GGD 在**沒有人作者化**時替一次施法**預設畫在身體周圍**的裝飾：施法光柱 · 家族美術 `playCastVfx`（`vfxKey`／綁定表）· EX `layeredPop` · `arcCastPlan` 電弧 · 地面焦痕 · 彈道 `muzzle` | 身體 vs 身體**周圍**；一個 script 想「自己畫聚氣、但施法者照樣揮手」正好需要兩格分開（Codex：「粒子或光束不能取代施法動作」） |

**不含**：真相提示（telegraph · 施法條 · EX 推鏡／壓暗）—— 它們說「打到哪、還要多久」。
**不含**：ability JSON 作者寫的 `spawnVfx`／`spawnModelFx`／`screenFlash`／`floatingText`／命中演出 ——
Codex `35b231ef3` 的論點成立（「shipped scripts intentionally add only the pieces missing from ability JSON」），
而且盤點結果是 **0 / 10** 支要它們讓路 ⇒ 第〇·五守則：⛔ 不做沒人要的格。詞彙表是陣列，要加再加。

### 宣告在 **doc-level**（`yields`），⛔ 不是逐段 `replaces`

- 身體動畫的接管是**一個時刻**的事（哪一段觸發就接管那一窗）⇒ 逐段 `replaces` 對。
- 施法裝飾是**一次施法**的事 ⇒ 屬於 script，不屬於某一段。而且 e002.ex 那種 17 段全在 `strike` 的 script
  根本沒有 castStart 段可以掛 `replaces`。
- ⭐ 這讓 `replaces: z.enum(PRESENTATION_CHANNELS)` 那一行**一個位元都不動** ⇒ 收據正則不翻、
  `PRESENTATION_CHANNELS`（對外契約）不動、`VfxScriptPlayer` 不動。

### 誰登記：`VfxSystem.noteScriptYields()`（`abilityCast`／`castBegin`），⛔ 不是 `VfxScriptPlayer`

- 播放器登記的是「觸發器 → frame → 受體」的**逐段**通道；施法裝飾的登記時刻就是 `abilityCast` 那一幀，
  那是 `VfxSystem` 自己在消費的事件 ⇒ 在這裡登記就不必把觸發器↔事件映射抄第二份。
- 窗口：`abilityCast` ⇒ `DEFAULT_TAKEOVER_MS`(320)；`castBegin` ⇒ 詠唱長度 ＋ 320（castEnd 才生的彈道也問得到）；
  `castInterrupt` ⇒ `channelTakeover.release()`（新增，⛔ 不是 `clear` —— 不吃別的通道）。
- ⛔ 不是「有 script 就讓路」：只讀宣告。`vfxScriptOverride.test.ts` 的兩個禁字（`this.scriptPlayer.hasScript(` · `abilityIdOfAuthoredOrigin(`）**沒碰**，而且是實質上沒碰（沒有換名字寫回同一個邏輯）。

### 開關（owner 會轉 ⇒ 三個住處；⚠️ 三個住處全在柵欄外，見 §5）

`config.vfx-scripts@1.yieldDefaultCastFx`（預設 **true** ＝ 新行為）：
`false` ⇒ 每一份 `yields` 當成 `[]`（逐位元回到 `35b231ef3`）。
⭐ 同時跟著既有 `enabled` 走：播放器休眠時裝飾一定回來（舊實作「讀 player 的 live rollback switch」的性質保住）。
客戶端已經在讀這一格（`castFxYieldEnabled()`），三個住處補上之前退到 `DEFAULT_VFX_SCRIPTS` 再退到 on。
⭐ 逐支 rollback 不必等：把那一份 script 的 `yields` 改回 `[]` 就是（內容編輯器那一頁）。
