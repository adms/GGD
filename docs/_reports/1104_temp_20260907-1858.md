## ① 我用了哪一條路：**(a) 呼叫出貨那一支**

新增 `tools/w3a-translate/expand_abilities.ts` —— 一支**只寫 stdout** 的小 CLI，
它 import 出貨的 `resolveTemplateExpansion()`（→ `mergeExpansion()`），把
`content/abilities/*.json` 421 份攤開後倒成一份 JSON；`gen.py` 用 `subprocess`
跑它（`node_modules/.bin/tsx`，0.75s）再讀 stdout。

**為什麼是 (a) 不是 (b)：**

| | |
|---|---|
| ⛔ (b) 落地一份「展開後快照」 | 那份快照**是產物** ⇒ 要進 `sync-io.json`、要有 `--check`、要有人記得重生成 —— ⭐ 而它過期時 `gen.py` 讀到的是**一個舊世界**，也就是這張票在修的同一個病的第二次 |
| ⭐ (a) 直接呼叫 | 零新產物、零 `sync-io.json` 改動、零隔離區戶籍。成本是每次 `w3a:build`／`w3a:check` 多 0.75 秒 |

⛔ **沒有在 Python 裡重寫 `mergeExpansion`**（第〇·四守則）——
`toLen()` 的單位換算、`COMPOSABLE_KEYS` 的保留規則、`expandStackOrThrow` 的多卡堆疊
今天三樣都還在動，一份 Python 複製品必然漂開。

⚠️ 兩個必要細節：
- ⭐ **`template` 一定要在展開後拿掉** —— `mergeExpansion` 會保留它（#1065 的可組合鍵），
  不拿掉的話同一個半徑會被數兩次：一次在展開後的 `radius`（GGD 格 4.5），
  一次在 `template.params.radius`（wc3u 245.45），⭐ 而 `gen.py` 取 `max()`
  ⇒ **wc3u 那一份永遠贏**。（同一條註解逐字在 `tierFlatExclusive.test.ts::expandOne`。）
- **展開失敗不靜默降級**：`failures` 非空 ⇒ `SystemExit` 並指名那幾支
  （今天 206/206 全部展得開，0 失敗）。

## ④ 守衛 · 突變 · 反方向

**守衛**：`packages/shared/src/ops/w3aTranslationGaps.test.ts` 的第 ⑥ 條
「⭐ 同一支技能，接模板前後這支普查給出同一個答案」——
它跑 `python3 tools/w3a-translate/gen.py --verify-templates`，
⭐ **斷言比對訊息內容**（`toContain("展開前後同一個答案")` ＋ 從訊息裡正則撈出母體
`接模板 206 支 · 未接 215 支` 並各自驗下限），⛔ 不是只看離開碼。

⭐ 它餵的是**兩份真的不同的 JSON**（⛔ 不是同一份比自己）：
磁碟上那一份（數值住 `template.params`）與同一支被出貨展開器攤開的樣子（＝`eject()`），
兩份走**同一條**掃描路徑（`axes_of()` × 五個數值軸），答案必須逐格相等。

**突變**（`gen.py::_prepare()` 的展開那一行改成 `return doc`）：

```
w3a:verify-templates 失敗 —— 這支普查看不穿模板（GH#1104）:
  ⛔ 47/206 支接了模板的技能,接模板前後給出**不同的答案**:
  godie-hvsh.passive —— radius: 接模板後 (245.45, True) ≠ 接模板前 (4.5, True)
  godie-o00k.e —— radius: 接模板後 (500.0, True) ≠ 接模板前 (9.17, True)
  …還有 27 支
```

⇒ ⭐ **紅，而且指名受影響的支數（47/206）與逐支逐軸的差**。vitest 端同時紅了兩條
（①逐位元組 ＋ ⑥），訊息逐字含上面那段。已改回並復驗綠。

**反方向**（兩條，互相獨立）：

1. **腳本內**：215 支**沒有**接模板的技能，`_prepare()` 必須是 identity ——
   `drifted` 清單為空（訊息會指名前 10 支）。
2. **實測**：把改動前後的 `gaps.json` 逐 `(w3a rawcode, ggd id, axis)` 比對 ——
   ⭐ **動到的 24 支技能，24 支都接了模板；沒接模板的 0 支被動到。**
