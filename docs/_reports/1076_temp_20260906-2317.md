## 修法：方案一（0 ＝ 不設上限），卡面與模板文字**一個字不改**

「其他呼叫者可能依賴零容量」—— 量過：沒有這種呼叫者；而「一支永遠不召喚的召喚」本來就是第一·五守則的違反，沒有合法用途。

| 檔 | 改了什麼 |
|---|---|
| `packages/shared/src/sim/effects/summon.ts` | `capRaw = floor(e.maxAlive ?? DEFAULT_SUMMON_CAP)`；`maxAlive = capRaw <= 0 ? +∞ : capRaw`。ABSENT 仍 = 8（安全預設不變）、1..20 不變、⭐ 0 = 無上限。173 行的「cap is 0」註解改掉（現在不可達，留作保險） |
| `packages/shared/src/content/schema/effects/summon.ts` | JSDoc 補一句「⭐ 0 = 不設上限 (the tpl-summon-agent default — GH#1076)」（只改描述） |
| `packages/shared/src/sim/effects/variants/summon.ts` | `maxAlive` 的 JSDoc 補 `0` = no cap（**只改註解**；柵欄外一步 —— 它是 handler 讀的 EffectDef 型別，grep 到的消費端契約。主 session 不要就 revert 那 4 行） |
| `packages/shared/src/sim/effects/summon.test.ts` | 追加一個 `describe`（GH#1076），重用既有 `rig()` |
