### ③ `gg_snd_sawch` —— ⛔ 上一輪的診斷是錯的，這不是抽取器的 bug

上一輪報「`wc3_path` 是 `war3mapImported\sawch.mp3` 卻被標成 `kind:"stock"` ⇒ 抽不到」。
**兩半都查了：**

| 查什麼 | 結果 |
|---|---|
| 抽取器有沒有照 `kind` 去錯的封存找？ | ⛔ **沒有** —— 它早就用 `wc3_path` 的 `war3mapImported\` 前綴路由（第 116 行） |
| 那檔案在不在地圖封存裡？ | ⭐ **不在**。`has_file` 對兩份封存都是 `False` |
| 對照組 | 同兩份封存裡 `4die.mp3` / `87joke.Mp3` 都 `True` ⇒ ⛔ 不是讀取器壞了 |

原作 `war3map.j`：
```
3555:  set gg_snd_sawch = CreateSound( "war3mapImported\\sawch.mp3", ... )
40249: call PlaySoundBJ( gg_snd_sawch )
```
⇒ ⭐ **原作宣告並呼叫了它，但從來沒把檔案打包進地圖 —— 那兩支技能在原作裡就是啞的。**
這不是我們欠的帳，**也不可能靠重跑抽取補上**。

⚠️ **而那句錯的建議已經出貨了**：`ability-sfx-cues.json` 的兩列 `reason` 寫著
「補它要先跑 tools/w3x-import 的抽取」。手寫的衍生檔就是這樣腐爛的 ——
每一個零件都對，只有結論是假的，而**沒有任何東西會紅**。

**修了什麼（`extract_stock_sfx.py`）：**

| | 之前 | 之後 |
|---|---|---|
| 工作清單 | `kind == "stock"` | ⭐ `extracted_file` 是不是空的（**推導**）。⛔ 完全不讀 `kind` —— 它有 **2 列是假的**（`sawch`、`gy2`）。實測工作清單**逐項相同（61）**，＝只拿掉一個會說謊的住處，⛔ 沒有動輸出 |
| 失敗 | 一種 `MISS`，一律 exit 0 | ⭐ 用 `has_file` **probe 每一份可能的封存**，分成 `absent_from_archive: true/false` |
| 離開碼 | 永遠 0 | **不在封存 → exit 0**（原作的事實）；**在封存卻解不開 → exit 1**（真的是解碼器壞了） |

實跑：`60/61`，`MISS gg_snd_sawch [ABSENT]`，exit 0，MANIFEST 多出
`absent_from_archive/archives_probed/holders`。
⚠️ fail-open 那一半**刻意保留**（一支 dangling ref 不可以擋住其餘 60 支），
但它**不再是靜默的** —— 那才是第二守則說的缺陷。

### ④ 分層播放（17 列）—— 評估：⛔ 這一版不做

| | |
|---|---|
| 涉及 | **15 支**技能、**17 列**、**12 個**第二 cue |
| 那些 clip 有沒有出貨？ | ⭐ **全部有**（都在 `audio-map`）⇒ 位元組是現成的 |
| 只有 2 支各有**兩個**附加 cue | `godie-u00l.q` / `godie-umal.q` |

**為什麼不做**：`combatSfxKey()` 的契約是**一個事件回一個 key**
（`abilityCast → string | null`）。要分層就得讓它回一個**陣列**，
而它是全部戰鬥音的單一入口 —— 改簽章會動到 `sfxReachability`（一列一 key 的模型）、
`SpatialSfxQueue` 的併發夾制、`sfxPreloadPolicy`。
⇒ ⭐ **這是一個機制（第〇·五守則），不是 17 列資料**，而它的收益是
「15 支技能的施法音多一層」——⛔ 不值得在這一版動戰鬥音的核心簽章。

⭐ **建議做法（留給 owner 排）**：做成 `cues.*.layer2` + 後台一格
`abilitySfx.layeredCast`（預設 **off**）。⛔ 我沒有替 owner 決定，也沒有先做一半。
