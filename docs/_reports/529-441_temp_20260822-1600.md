## 1. 做了什麼（#529）

### ⭐ `WC3_ABILITY_SFX` 從 TypeScript 搬進 JSON —— TS 那份**真的刪掉了**

| 之前 | 之後 |
|---|---|
| `apps/client/src/audio/combatSfx.ts` 裡一個 52 個字面值的 `ReadonlySet` + 52 行註解記著哪支技能用哪個 | `content/audio-manifests/ability-sfx-cues.json`（`audio.ability-sfx-cues@1`） |
| 改一個 cue = 重建 client 映像 + 一次完整部署 | 存檔就生效（`content/` 是 live bind-mount） |
| 52 行註解是 prose，沒有東西在守 | `ggSnd` / `origin` / `note` 是欄位，`unmatched` 帶理由，三條守衛在守 |

**檔案：**
- `content/audio-manifests/ability-sfx-cues.json` — `cues`(52) · `bindings`(覆蓋層) · `unmatched`(19) · `fields`(欄位說明)
- `apps/client/src/audio/abilitySfxCues.ts` — 註冊表 + 解析器 + 兩支解析函式
- `apps/client/src/audio/combatSfx.ts` — `WC3_ABILITY_SFX` **刪除**；`wc3CastKey()` 只剩一行委派
- `apps/client/src/audio/sfxReachability.ts` — 那 **52 列的 `site` 改指 JSON**（`ABILITY_SFX_CUES_SITE`）
- `apps/client/src/audio/AudioSystem.ts` — `loadAbilitySfxCues()`，開機時與 `loadPreloadPolicy` 並排（不 await）

### ⛔ 退路是**推導**的，不是第二份名單

`derivedAbilityCastCues()` 從 `SFX_REACHABILITY` 走出來：每一列 `kind:"combat"` 且
`payload.abilityCast` 含 `"sfxKey"` 的 key。那張表本來就一列對一個 audio-map key，
而且 `sfxReachability.test.ts` 兩個方向都釘死。

⇒ **fetch 404 / JSON 壞掉 / 內容還在載 = 行為與今天逐位元相同**，⛔ 不是靜音。
（這就是為什麼可以放心把 TS 那份刪掉。）

### `bindings` 覆蓋層（今天是空的，⛔ 但它不是裝飾）

`abilityCast` 事件本來就帶 `abilityId`（`sim/abilities/abilitySystem.ts:485`），
所以「技能 id → cue」可以在執行期解析。解析順序：

```
abilitySfxCueForAbility(abilityId)   ← JSON 覆蓋層（live-editable）
  ?? wc3CastKey(sfxKey)              ← 技能文件自己宣告的
  ?? castElementKey(vfxKey)          ← 元素風聲
  ?? "abilityCast"                   ← 通用
```

⛔ 一支技能不可以同時出現在 `bindings` 與自己的 `sfxKey` —— 守衛在擋（兩個住處必然分岔）。
⇒ 上面那題 owner 選了 (2) 的話，**一列 JSON 一支技能**，⛔ 不必動 420 份 ability JSON、⛔ 不必重建映像。

### 守衛（`apps/client/src/audio/abilitySfxCues.test.ts`，3 條）
1. JSON 宣告的每一個 cue，`SFX_REACHABILITY` 都要有一列說它由 `abilityCast/sfxKey` 播
   （憑空多一個名字 ⇒ 執行期是 audio-map miss＝靜音，⛔ 不是退回風聲）
2. **承重**：換一份文件，註冊表真的換掉；schema 不符／空 `cues` 一律不動現行值
3. `bindings` 不可與技能文件的 `sfxKey` 重疊；`unmatched` 每列要有理由且指真的技能

**突變驗證（跑過，兩個都紅並指名）：**
- 拿掉 `applyAbilitySfxCuesDoc` 的 `registry = parsed;` → 守衛 ② 紅
- 從 JSON 刪掉 `wc3.moongo` 一列 → `sfxReachability.test.ts` 紅：
  「`content/audio-manifests/ability-sfx-cues.json` no longer names "wc3.moongo"」
  ⭐ 這一條證明 **JSON 真的在管事**，⛔ 不是一份沒有人讀的文件
