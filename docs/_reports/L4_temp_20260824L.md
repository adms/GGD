## 量到的三件事（⛔ 不是判準，是跑出來的）

### ① `attach:"hand,right"` 客戶端真的解得到（失敗形態⑧的形狀）

用**出貨的**那一支 `apps/client/src/render/vfx/attachment.ts::normalizeAttachName` 跑
（⛔ 只讀不寫，L2 lane 在同一支檔上）：

```
"hand,right"     -> ["hand","right"]   ← persistentVfx.attach（我們寫的）
"Bone_Hand_R"    -> ["hand","right"]   ← vfx 文件的 anchorBone（真正決定掛點的那一格）
"handright"      -> ["hand","right"]   ← JASS 原文
"Hand Right Ref" -> ["hand","right"]   ← MDX 掛點節點
"right,hand"     -> ["hand","right"]   ← schema 註解裡的正典寫法
```

⇒ **五種寫法同一個 key**，兩個住處⛔不會漂到不同的手。

而 `Bone_Hand_R` **真的是 `imported.herosaber.glb` 的節點**（36 個節點裡的第 11 個，
連同 `Hand Right Ref` / `Weapon Ref` 一起在）⇒ `AmbientVfx.findBoneNode` 逐字比對得到，
⛔ 不會退回 root（那會讓金粉噴在腳底下 —— 一個看得見卻查不出來的錯）。

### ② 粒子的實際掛點是 `anchorBone`，⛔ 不是 `attach`

出貨路徑是 `GameApp.persistentVfxFor()` → `AmbientVfx.attach(..., extraVfxIds)` →
`buildItem()` → `findBoneNode(root, doc.anchorBone)`。
`persistentVfxRequests` / `PersistentVfxChannel`（會讀 `attach`）今天**沒有接在 GameApp 上**。
⇒ `attach` 這一格對粒子而言是**記帳**（WC3 掛點的正典寫法），
⭐ 所以它與 `anchorBone` 必須指同一隻手 —— 那正是上面①在驗的東西。

### ③ ⛔ 刻意**不帶** `ambient: true`

`isSwingTrailDoc`（`apps/client/src/vfx/swingTrailMath.ts:93`）逐字是
`ambient === true && mode === "continuous" && anchorBone !== undefined` ——
三件齊 ⇒ `shapeSwingTrailDoc` 把它當**刀光**重塑：夾生命期、按 live-count 壓 rate、
`swingEmitScale(relSpeed)` 讓**站著不動時 emitRate 掉到地板**。
⇒ 一顆掛在手上、角色不揮劍時就該持續發亮的金粉，會被壓到近零 ——
**與「沒做」在畫面上長得一模一樣**（第二守則失敗形態②）。
`buildItem` ⛔ **不要求** `ambient:true`（常駐特效走 `extraVfxIds` 那條路，
`acquireEmitter` 已經給了 `persistent: true` 的三秒兜底豁免，GH#570），所以不帶它是**免費的**。

## 守衛與突變

`packages/shared/src/content/saberWeaponDust.test.ts`（2 條，⛔ 不驗任何顏色/速率/尺寸數字）：

1. standalone 與 champion 內嵌鏡射**兩份**都帶 `persistentVfx`、`slot === "E"`
   （`persistentVfxKeysFor` 用槽名去 `abilityRanks[2]` 問「學到了沒」）、`when` 缺席
   （＝客戶端今天算得出來的那一批），且兩份**逐位元相等**。
2. `vfxKey` 指的文件：**檔名 = doc id**（那是它進不進得了 `_index.json` 的判準 ——
   不合就是「檔案在 repo 裡而客戶端一輩子拿不到」）、過 **`validateDoc("vfx", …)`**
   （`content:build` 用的**同一支**驗證器，⛔ 不是另寫一份 Zod）、`mode:"continuous"`、
   有 `anchorBone`、⛔ 沒有 `ambient:true`。

**突變（一批一條，挑最承重的那條線）**：把 `heroes/godie-e002.py` 那一列的
`vfxKey` 改成 `fx.saber.gold-dust-MUT` → `python3 tools/skill-remake/batch1.py --check`
**EXIT=1**，逐字指名 `⛔ 1 份出貨技能與產生器的輸出不一致：godie-e002.e.json`。改回 → EXIT=0
（`產生器印記一致：90 支`）。⇒ 出貨產物**真的**是那一列表格產生的（第〇·五守則的鏈）。

→ 守衛當場紅在③那一行。移除 → 綠。

### ⭐ 突變過程中量到的一件事（⛔ 不是缺陷，是 A-6 的設計）

第一次突變我把整列 `persistent_vfx=` **刪掉**，而 `--check` 是**綠的**。
根因：`common.py` 的 A-6 denylist「規格沒有重新定義的欄位一律原樣保留」——
`persistentVfx` 不在 `SPEC_OWNED` 裡，所以它會**從舊文件沿用**。
⇒ 語意是「**表格填了就贏，沒填則沿用**」，與 `vfxKey` / `sfxKey` 那一族美術綁定
**同一個既定規矩**（那也正是這一格被放在 A-6 setdefault **之前**的理由）。
⇒ 拿掉表格那一列**不會**讓金粉消失（沉默 ≠ 移除）；要它退場得走 `retire=` 留紙本痕跡。
