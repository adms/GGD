## 三、⛔⛔ 為什麼是白的 —— **貼圖本身就沒有顏色**（決定性，⛔ 不是推測）

`stockglow_visual-proof_20260826-1520/README.md` 把這題留成兩個候選：
「差別要嘛在**貼圖本身的飽和度**，要嘛在**我們疊了比原作更多層**」。
⇒ 這一輪直接讀出貨 `.glb` 的**貼圖像素**（最亮 2% 的平均 RGB）：

| primitive | 材質 | 尺寸 | 最亮 2% RGB | **sat** |
|---|---|---|---|--:|
| p0 | `TeamGlow0` | 32×32 | (116.9, **1.2**, **1.2**) | 0.989 ← **純紅**（team-colour 通道） |
| p1 | `mat1` | 32×32 | (170.8, 171.0, 159.8) | **0.066** |
| p2 | `mat2` | 64×64 | (122.1, 122.1, 122.1) | **0.000** |
| p3 | `mat3` | 64×64 | (122.1, 122.1, 122.1) | **0.000** |
| p4 | `mat4` | 64×64 | (255, 255, 255) | **0.000** |

⇒ ⭐ **答案是第一個候選：5 張裡 4 張是無彩度的（灰/白），第 5 張是純紅。**
把一疊灰色加起來只會得到更亮的灰色 —— **沒有任何混合模式做得出金橘色。**
`sat ≥ 0.47` 用今天這份 `.glb` 是**結構上到不了**的，⛔ 不是一格參數的事。

⚠️ 這與 `tpl-beam-roll` 自己記著的「誠實偏離 (a)」是同一件事：
原作那條金橘色光帶住在 `.mdx` 的 **`PRE2`（粒子）chunk**，而 `convert_stock_model.py`
**只轉 geoset** ⇒ GGD 只拿得到核心，而核心的貼圖本來就是白/灰的高光。
