# Hero74：生成前固定的評分邊界

2026-09-09。對 `hero74-eval-plan-v1/public-cases.jsonl` 的 17 個完整英雄題逐份讀取 public request 後固定；v21 正在訓練，尚未啟動此次 base／LoRA 生成。這是評分政策，不是已完成的語意評分器或模型成績。它不修改訓練／dev、prompt、目錄、教師答案、checkpoint 或解碼設定。

## 不同題型的成功定義

| 題型 | 完整英雄數 | 依據 | 不得使用的捷徑 |
|---|---:|---|---|
| 明確六槽來源還原 | 2 | public request 的 `identity` 與 `slots`，包含事件、友敵、條件、時序、機率、持續時間與跨槽連動 | 只看名稱、模板存在或基礎連招；把台詞解讀為機制 |
| 核准改編創作 | 11 | public request 的身分／採用版本／定位及 `approvedPolicy`：合法積木、有實際決策的招牌玩法、核心連動與反制 | 要求猜中教師私有六槽、用舊原稿逐條否定使用者已接受的簡化政策 |
| 指定定位開放創作 | 4 | public request 的角色／作品／theme／origin／task：至少兩條實質因果連動、角色契合、可說明代理外觀 | 把換名稱／特效／數值算成新玩法；以教師專屬 combo 的 slot 或模板判替代方案錯誤 |

兩個來源還原題為 `godie-edem:HERO`、`godie-h02v:HERO`；四個開放創作題為 `b2-uncle:HERO`、`b2-haga:HERO`、`b2-fushi:HERO`、`b2-nube:HERO`。其餘 11 個 HERO 題為核准改編。單槽 102 題僅輔助，不能膨脹完整英雄主分母。

## 相同的強制檢查

1. 來源身分／採用版本與必要設定正確；出身明示時必須相符。文字可合理改寫，不採逐字相同作唯一判準。
2. 六槽完整；機制實際作用的對象、觸發、条件、時序、資源／狀態與跨槽關係符合該題要求。合法 schema 但語意錯誤仍失敗。
3. 數值按該題固定來源與引擎共同規則驗證；要分開記 authored tier／override 與 runtime 生效值。不能用升版後的公式代替原版本，或用「正規化」掩蓋未授權機制／數值變更。
4. 同題相同公共目錄與素材權限。完整欄位、模型／動作／素材依賴、編譯、保存重讀、隔離匯入、選取進入對局均須有實際證據。
5. 正向及反例測試涵蓋必要機制；測試不能注入模型應自行建立的必要標記／資源，不能只因最終有傷害就算連動成立。
6. 三組同用驗收標準。教師控制組亦可能不滿足需求，不預設教師 100%；不同但功能等價的方案可接受。歷史教師模型／effort 不可得時維持 unknown。

`publicSpecialPolicy` 是公共來源的一部分，但不能只因它被共同附帶，就推論每名角色都必須擁有該特殊招式。適用性須有該題來源／明示要求，不能借教師輸出倒推適用範圍。

## 未驗證不通過；診斷不代替驗收

目前的 generation-compile 只證結構與磁碟重讀；package-admission 增加實體素材與 Main 基礎模擬。兩者都不能獨自判斷角色定位、幽默、整套創作的新意、必要機制忠實度或真實上場成功。既有 teacher-specific combo 腳本可驗教師自洽，但不得原封不動充當所有功能等價生成方案的唯一評分器。

若尚無對某項要求的可靠評分／行為測試，記為 **unverified**，不能自動通過或漏掉該項。語意判讀若需研究階段人工審查，記錄為 reviewer intervention；任何人工補填／補機制均另計，該產物不屬零人工生成成功。不能把未測項填 0 錯誤後宣稱「危險接受 0」。

完整支援主組仍以英雄級至少 95% 且危險錯誤接受觀察數 0 為目標；17 名 internal-dev 的 95% 門檻須 17/17，且不證明高機率泛化。失敗、拒絕、未驗證須保留，不縮分母。另一批使用者未見英雄仍未提供，不能把這 17 名改名為盲測。

## 後續執行

凍結本政策後，優先執行既有單輪與配對推論腳本；不為了補齊這張政策而重開資料擴充／重標／訓練 sweep。生成後按要求列出實測證據與未驗證缺口。若測試腳本需修錯，須對 base／LoRA／教師一體重評、保留修正理由與舊收據，不能用候選輸出反向修改成功定義。
