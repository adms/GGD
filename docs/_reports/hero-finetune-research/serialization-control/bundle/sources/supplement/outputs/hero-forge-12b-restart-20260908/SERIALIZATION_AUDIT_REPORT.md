## 可確認的事實

這次是前一個负面實驗後的診斷，不覆寫原始答案、資料或評分器。所有工作先以 CPU 核對，再另立有界 GPU 對照。

- 14 筆原始目標 JSON 都有效，原始 token ID 可由固定 tokenizer 精確重建；實際入訓仍是同 8 筆合成資料。
- 14 筆的最後根物件括號及 `<turn|>` 停止符號都有 direct loss，不支持「根本沒有訓練停止／結尾 token」的假說。
- 4276 個 JSON 結構標點中，499 個沒有 direct loss。其中 168 個在刻意排除的值內，另外 **331 個在排除值外**，卻因 tokenizer 將它們與被排除值合併到同一個 token 而一起被遮罩。
- 前輪 LoRA 五個非法 JSON 都在診斷上剩一個未關閉的根物件；全部記錄 `finishReason: stop`，不是 8192-token 預算耗盡。歷史收據沒有逐 token ID，不能從文字反推出真正停止 token 的 ID。
- 檢視固定的 MLX-VLM 0.6.17 實作可見，結束前會 finalize detokenizer 並 yield 最後片段；研究 worker 也會累加該片段。這是程式檢查，不能當成已完成逐 token 回放證明。

## 已完成的 CPU 修正控制

`serialization_boundary_control.py` 預先列出三種空白方案，只以 tokenizer 邊界與長度選擇，不讀模型分數：單一空格、換行、換行加空格。第一種即達到要求，沒有執行後兩種。

在被排除值前後各加一個空格後：

- 排除值之外被連帶遮罩的標點 **331 → 0**。
- JSON 值、原文字串、值的型別、欄位順序、資料切分、模型 prompt 及所有被排除值的原始位元組均不變。
- 最長訓練序列 7943 tokens，仍低於既有 8192 上限；沒有截斷來源或目標。
- 仍然整個排除重疊 token，不以解除未知參數的遮罩來換取標點通過。
- 另用不同實作逐字去除字串外空白，確認 14 筆只有空白差異；不依賴 Python 的 `True == 1` 弱型別相等。

稽核與邊界控制各有 6 項 CPU 測試，執行控制有 4 項切分／語意守衛測試，獨立位元組核對有 5 項測試。這些是工具正確性證據，不是模型準確率。

## 邊界

331 個標點的遮罩問題已由 CPU 精確量到，但它是否造成前次 JSON 退化，仍須看對照結果，不能先宣稱找到唯一根因。即使本次格式改善，也不能推論完整英雄設定、機制或獨立泛化已合格。

這項介入同時改變 teacher-forcing 的序列化空白、token 邊界與對應遮罩，因此是「序列邊界方案」的對照，不是將遮罩權重與訓練上下文分離的純因果消融。不同 direct-loss token 分母的 loss 也不宜直接解讀成品質增益。

資料仍是單一家族的 8 train／4 dev 及 2 位已曝光真實控制。沒有擴大資料量，沒有新盲測，没有參數微調或視覺驗證，沒有自動採用模型。
