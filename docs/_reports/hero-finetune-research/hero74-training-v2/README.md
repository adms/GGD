## 切分與資料洩漏界線

同一英雄與全部六槽在同一邊；已知第二批相似玩法組、目前結構重複／近似組及相同正規化名字採連通群組一起切分。新 74 名固定 59 訓練、15 驗證；群組大小與固定雜湊決定分配，因此兩批驗證人數不相等。既有原生樣本保留舊分組；比對新英雄名字沒有發現需跨組調整的匹配。

`grouping.json` 可逐英雄追蹤 split。結構診斷有 74 個不同 kit、345 個不同單槽結構，最多一種單槽被 27 名共用；不代表玩法新穎性或完整語意去重已證明。

**這是 internal dev，不是獨立盲測。** 兩批已有歷史審查／測試曝光，第一批改編也參考第二批；本次授權後，第二批不再保留為全新外部測試集。未來宣稱泛化效果仍需使用者提供未見的新英雄需求，再同條件比較 base 與 adapter；目前沒有新的獨立 test 集，也沒有模型改善分數。

## CPU 長度預檢與訓練狀態

固定本機 Gemma 4 12B IT 8-bit 基底 tokenizer，revision `200bb6db075e137a4deb08838865ac4ddb86292e`。僅 prepare，不載入模型權重、不跑梯度：

- 訓練總 tokens：11,194,038；其中答案 tokens：363,628。
- 驗證總 tokens：2,686,466；最長完整序列：29,996；最長訓練答案：8,049。
- 500 筆訓練全部納入預定單輪遍歷，沒有縮成小樣本，也沒有截斷問題或答案。
- 長上下文成本主要來自完整共用目錄／提示，單槽辅助樣本亦有此成本。不能把 619 筆視為短文本訓練。
- **GPU 尚未啟動、optimizer steps 本次為 0、沒有新 adapter。** 先前 full-context gradient 的記憶體保護阻擋仍待解決，不能把 CPU prepare 當成可訓練證明。下個 GPU 動作須先通過修正後的最長樣本容量與梯度檢查，不能原樣重試已失敗流程。

`token-preflight.json` 為實測摘要；`preflight-source/` 保存當次 CPU 預檢使用的程式快照，不表示 GPU 部分已驗收。可重建 token IDs，不把大型可衍生 tokens.json 再重複版本化。
