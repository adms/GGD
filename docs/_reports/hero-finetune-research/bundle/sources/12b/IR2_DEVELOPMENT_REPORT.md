# 12B 重啟：精確契約對照與 37 英雄來源審查

更新：2026-09-08（Asia/Taipei）。本輪不是 finetune 品質實驗，原始模型權重未變。

## 結論

自動產生精確 JSON Schema，比手寫型別說明更可靠：同四名開發英雄首次有 **2/4 通過 IR 契約及真實編譯**，執行的局部行為探針 **7/7** 通過。但完整英雄仍 **0 份獲准自動接受**。人工複核在其中一份已編譯答案發現 R 漏機制、EX 多機制，不能把 7/7 宣稱為完整成功。

37 名／222 槽的完整來源、角色採用版本及文末審查重點已逐份閱讀並留下人工註記；舊模板映射全部繼續隔離。正式訓練准入 0，新盲測 0。這次完成的是資料審查與系統基線進展，尚未证明微調改善。

提示未明列 identityEvidence 的 array 型別，使用非標準 nullable 描述、缺可執行完整 schema；移除舊範例後格式反而退步。因提示多處一併改動，這只是可能成因，未做單因素因果證明。

因此新增 `ir-json-schema.mts`，從實際 Zod IR2 產生標準 JSON Schema，保留必填、數字上下限、array、null、enum、遞迴動作和禁止額外欄位。Ajv 與 Zod 正反測試 17/17；沒有 coerce、補預設或刪非法欄位，也沒有啟用 grammar-constrained decoding。輸出契約不再靠兩份手寫型別維護。

**7/7 的盲點具體可見：**既有李星探針只驗被動 ICD 與 EX 不需 Q 即可跳躍並落地命中，沒有測 R 的移動與傷害，也沒有測 EX 不該擊退。所以會全綠但仍做錯技能。該結果保留为局部測試通過；下一版必須補來源要求的正反條件，不重算這一輪為完整英雄成功。

同理，引用原文只證明文字存在，不證明引用與動作一致；兩版都會引用「未萎靡」卻放进 present 分支，或引用「近身拳」卻輸出 attack_proc。這是微調應針對的語意監督點，不是 JSON 包裝能修好的問題。

1. **固定這份機器生成契約作後續配對基線**。這輪已足夠分辨「包裝有改善但語意仍錯」，先不連續換 prompt 挑最好的一次。
