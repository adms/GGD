## 人工看過全部四份原始輸出的洞察

以下是對未修復原始答案的內容檢查；不是把非法 JSON 修好後重新計分。

- 沃維克：摘要有寫出「低於 35%」及「2 秒冷卻」，實際被動欄位卻沒有這兩個條件。Q 選了不接受 anchor=target 的 periodic-field，且自療填 0；E 用 fear 的名字卻填 root；R 說沒有無敵，卻沒覆蓋 lock-combo 預設 casterGuard=all，並使用 stun 取代 root。EX 發明不存在的 tpl-shield。
- 李星：正確保留 Q／EX 獨立，不擅加 Q 命中才能用 EX；但被動只寫冷卻摘要，沒有可執行冷卻欄位。W 的 stat=as 搭上 msBonusTier，未正確落實 20% 攻速，護盾值為 0。此處「語意摘要有提到」和「成品能執行」顯然不同。
- 好運姐：摘要提到 Q 連鎖兩人，但實作只有重複單體 damage，將必要連鎖留給「引擎處理」。E 在提示明示總額分攤限制後仍用 periodic-field；R 把落點彈幕選成 line-sweep。EX 仍發明 tpl-shield；「掩護換位」被擴寫為必須執行換位動作，也應列為來源解讀疑義。
- 阿薩謝爾：關係摘要識別到三層資源及 R→EX 反效果，是可保留的正向線索。但把作品名稱填成 origin；負面能量填成不存在的 stat；把「萎靡降低輸出」寫成 root；反噬沒有寫到自身與 1 HP 底線；EX 用 weightedBranch 加字串條件冒充狀態分支，未落實同一來源限制、原子消耗及 AD/AP 反轉。不能因摘要講對大意就放行。

四份都自稱 full，系統關卡沒有採信。這說明目前拒收機制有攔住這批失敗，但**全拒收不能算創建能力達標**。

## 不應誤算成模型機制錯誤的部分

使用者重視機制分類，未明示的傷害／護盾量等可留人工調整。本版 smoke 把 unresolved 空陣列與 full 綁得太緊：單純「護盾量待微調」不應與「缺少連鎖、資源條件」混成一類。下一版會分開 mechanismGaps 與 tuningNotes。此版協定與分數不回改；上述 3 份 JSON 錯誤及非法欄位也不是這個政策缺陷造成的。

同時，填 0 傷害／0 護盾造成必要效果實際不生效，不只是數值建議未精調，不能用「參數次要」豁免。

本批輸入約三萬 tokens，含大量無關模板的長說明；hook/effect 參考仍是精簡片段，不是完整 schema。它適合診斷直寫引擎 JSON 的問題，不能單獨證明 12B 的理解能力上限或 fine-tune 無效。

## 真正的本機 LoRA 驗證

已完成 **1 步**技術 smoke：末層 q_proj／o_proj、rank 4、僅 96,256 個 adapter 參數；基底全部凍結。使用一個可逐字追溯、已曝光的「Q／EX 獨立」短 fixture，不是正式英雄訓練集，也沒有將隔離映射升級成正例。

- 反向傳播有限、梯度非零、adapter 權重確實改變。
- 初始零 adapter 的 loss 與基底完全相同；儲存、回復零 adapter、重新載入後結果一致。
- 單一步驟約 0.315 秒、Metal 峰值約 12.33 GiB。序列很短、只訓練末層，**不能據此估算正式長序列訓練時間**。
- loss 4.09850 → 4.10241，並沒有改善；本測只證明技術路徑能運作，不當作學習收益，也不採用這個 adapter 作成品。
- 第一個嘗試在 CPU 前綴檢查就停止，原因是 Gemma 的「assistant 歷史」不帶空 thought channel，但不推理生成前綴有帶。已按釘選模板對齊訓練／推論 token 邊界後，才在新 v2 目錄執行上述步驟；舊失敗紀錄保留。

收據：[技術驗證結果](lora-compat-v2/result.json)、[token 遮罩界線](lora-compat-v2/tokenization.json)。只訓練完成詞元，不訓練 prompt 或推理內容，不更新基底模型檔。

## 下一個有明確假說的實驗

1. **縮小模型的輸出責任**：先抽取有來源證據的機制中介資料（目標、時序、條件、資源、跨槽關係），由 script 產生受控模板與引擎欄位。保留模型推薦能力，但不要求它記憶所有巢狀 API 拼字。這符合「script 負責合法組裝」的原計畫。
2. **控制前後變因**：在同一組曝光 dev 英雄比較「直寫模板」與「中介資料＋確定性組裝」；記錄相同硬體與精度、來源需求漏失、錯誤支援宣告、完整英雄是否真的能執行。這是系統設計對照，不包裝成 fine-tune 收益。
3. **再做有意義的微調**：針對中介資料中仍錯的否定、條件、同來源與原子分支，建立來源審查＋行為證據的 train/dev；先做小 LoRA，再與同輸入契約的未微調 12B 配對。測試資料不得回灌。
4. **擴充來源與獨立性**：繼續 44 名的逐槽校正，不用數量湊訓練集；最後另建真正未参与調參的英雄／機制家族留出集。現在仍未達到新 goal 的完整驗收。
