## 完整原文與答案人工診斷

[逐英雄、逐槽審查](IR4_CONTROL_MANUAL_REVIEW.json)已讀完兩份原始答案，綁定 [raw](ir4-controls-base-v1/raw.json) 的 hash。

拉克絲主要動作選擇相當接近人工控制組：單人鎖足、自身護盾、逐秒地面脈衝、四段可重複命中與自己回血加速均辨認到。仍因 E 的零延遲／null 半徑不符 IR4、拼接引文及多餘獨立關係而不能放行，且把未知平衡值誤放在機制缺口。這不等於模型完全不懂英雄，也不能因摘要合理便宣稱成功。

齊勒斯有實質分類錯誤：W 區域爆破變單體，R 固定落點三發變成沿線三段；只保留正確次數不足。Q 辨認四段及大級距，卻用 self 並把 windup 留 null；IR4 會把 null 起手降為零。EX 正確選到自己回 15% 最大魔力和魔法護盾，但未知護盾秒數的 null 又被現契約拒絕。Q 是否重複命中來源未指定，不拿模型的 per_segment 當錯誤或把人工 once_per_cast 當唯一正解。

## 為何這次仍不直接開始 SFT

已做出的遮罩控制組，拉克絲 697 個完成 tokens 中保留 480 個直接 loss，齊勒斯 811 中保留 492；token 邊界和 next-token 位移均已驗證。它解決「不要把研究參數當直接標籤」，但不解決以下問題：

1. 遮罩值仍在 teacher-forcing 上下文，存在間接影響，不是完整隔離。
2. 齊勒斯 Q 的 0.3 秒是研究參數，遮罩它合理；但現表示法沒有另外一個必須受監督的「需要吟唱」選擇器。這會把真正重要的機制訊號一起弱化。
3. 兩位是同家族、已曝光的工具控制組，不能冒充足夠的訓練集或新的盲測。

因此這兩份完整 IR 控制組維持 `trainingAdmitted=0`。這是新推論與資料審查找到的具体缺口，不是缺 GPU 授權。既有輔助判讀資料／LoRA 的歷史資格與成績不回改。

## 下一個實作切片

- 在新的版本中明確分開「是否需要吟唱」與「吟唱秒數」，必要機制為 supervised selector，未知數值由 script 提供有標記的有界預覽；不要一律放寬所有必填欄位。
- 讓未知半徑、短效護盾秒數等與真正機制缺口分開。原文明示數字和級距仍須嚴格保留。
- 補完整來源的對照資料，專測「單位／地面落點／向前沿線」「同樣三發但錨點不同」「未知時長不等於無效果」，再擴到其他來源家族；不能只訓練關鍵詞或命中次數。
- 固定修正後契約、逐欄准入及同 prompt／同精度 base–LoRA 對照，再啟動有界機制輸出 SFT。已提供的本機 GPU 授權有效，不需再次確認；仍一個 worker、接電與資源保護、雲端支出 0。
