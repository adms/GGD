2026-09-08，Asia/Taipei。目標持續進行；本批沒有新 LoRA 更新、沒有正式模型升級。GPU 兩個有界推論作業皆已退出。

## 結論

少寫引文、null 與重複欄位，可以減少輸出，但目前沒有提高完整英雄正確性。新版短契約 IR3 的正式 JSON Schema 小測只有 **1/4 通過契約與編譯**，低於前版 IR2 的 2/4；全部仍為 0 隻完整英雄核准。不能把「JSON 都合法」或「更快」當成成功。

接下來不擴大原文分類 LoRA，也不再無目標地輪流調提示詞。先補完整六槽的可執行正例、負例與行為判準，尤其是動作順序、資源／狀態引用、重複命中及未支援判斷；再做同契約 base／LoRA 配對。

## 4. 釐清三種「IR 不會表達，但引擎已存在」的能力

[原生能力 v3 行為收據](extension-admission-v3/manifest.json)：兩個 seeds、**12/12** 測試通過，均為通用合成能力探針，不是完整英雄。

| 能力 | 已確認 | 明確限制 |
| --- | --- | --- |
| 純位移 | 開放路徑移動、不自動增加技能傷害，沒有敵人強制位移事件 | `toPoint` 只決定方向，衝刺固定距離；碰到身體仍有普通分離，不能宣稱敵人完全不動或撞人即停。 |
| 自身回魔 | 扣施法消耗後，加最大魔力的 15%；不設定為 15%；溢出封頂 | 自然回魔另算；施法成本、冷卻仍保留。 |
| 直線分段 | 4 段可各命中一次，或整串每目標最多一次，依明示政策選擇 | 使用原生沿線圓形分段判定；不是視覺光束驗證，不自動加入終點爆炸或追蹤。 |

[native-mechanism-actions.mts](native-mechanism-actions.mts)已建立三個嚴格操作及確定性轉換，拒絕附加傷害、把加回魔改成設定魔力、錯誤對象及缺失重複命中政策。**目前是研究擴充模組，尚未接入 frozen IR3、任何新模型提示或訓練集**；不能寫成模型已學會這三項。

另外，`tpl-mark-stacks` 的免死設定不能用現有參數關掉附帶無敵：0 秒被拒，最小 0.1 秒仍輸出 invulnerable。這只是該模板暴露的能力邊界，不是「整個引擎做不到無無敵的免死」。因此卡爾瑟斯舊免死配方不能僅靠編譯成功就升格來源正例。

### 保留的測試失敗，不報成產品回歸

- v1 **4/8**：純移動測試把普通身體分離誤當技能擊退；回魔測試用 -10000 回魔率「關閉回魔」，實際變成每 tick 扣魔。v1 manifest 提前寫的 `existingEngineSupports` 不可靠，以後續逐能力收據取代解讀，原檔未改。
- v2 **8/12**：改用 override=0 仍有全域基礎加成，最後回魔率 10/s，測試對 0 的斷言正確失敗。
- v3 **12/12**：不再改回魔率；先在施法當下驗加法／對象／上限，再獨立算自然回魔。碰撞測試保留普通分離事實，加開放路徑對照，不放寬「沒有技能伤害／敵人強制位移」檢查。
- 擴充模組首次測試 **25/26**：誤要求編譯後傷害級距仍與作者輸入逐字相同；正式編譯器本就展開 flat／perRank。測試改為核對原語意級距及全部非數值欄位，另驗級距展開形狀；未把傷害數值調到迎合結果，未改引擎。
