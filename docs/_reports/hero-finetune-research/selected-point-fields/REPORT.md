# 指定落點領域：完整英雄准入的新增失敗

本輪没有 GPU 推論或訓練，沒有改引擎、原文、配方或歷史模型分數。原本接近完整的拉克絲候選仍不能准入：指定落點附近出現偏心敵人時，領域圓心改成該敵人的初始位置，而非玩家指定點。相同問題也在好運姐 E、齊勒斯 R 重現。

## 實際證據

`selected-point-fields-audit-v2` 使用原有 IR5 候選、未修改編譯器和真正的 SimWorld；核對每槽 registry mirror、完整英雄原文保存、12 個腳本／資料 pins，以及執行前後引擎與能力目錄 pins。

| --- | --- | --- | --- |
| 拉克絲 E：在落點留下光域 | 2/2 通過、每例 3 發 | 2/2 通過、每例 3 發 | 0/2 通過、每例 0 發 |
| 好運姐 E：指定落點魔法領域 | 2/2 通過、每例 3 發 | 2/2 通過、每例 3 發 | 0/2 通過、每例 0 發 |
| 齊勒斯 R：選定落點三發轟擊 | 2/2 通過、每例 3 發 | 2/2 通過、每例 3 發 | 0/2 通過、每例 0 發 |

所有情境的玩家指定點及 abilityCast 回報均為 (-36, 10)，未被射程夾限。偏心情境初始敵人在 (-35, 10)，排程圓心也變成 (-35, 10)。原有预覽半徑為 4.5；排程後把同一敵人放在 (-40.3, 10)，距離指定圓心 4.3，距離錯誤圓心 5.3。它在 180 個實際模擬 frame 都未移動，卻漏掉全部三發。友軍未被傷害。

這是 12/18 情境通過、6/18 具體來源配方失敗，不是模型準確率。兩個 seeds 是確定性重現，不代表統計母體成功率。

## 原因與適用範圍

釘選引擎的 `packages/shared/src/sim/effects/delayed.ts:283–287` 在非前進掃線分支優先採用 `frozen[0]` 的位置；`anchor:'point'` 並未改成以 `ctx.point` 優先。後面的 `anchor` 分支只判斷是否跟隨 caster。因此原文要求「玩家指定落點」的研究配方，在附近有偏心敵人時不忠實。

Main 與研究快照的相關 handler git blob 核對為 `0972e657136c96eca1ce2c56035b8399d1adb912`。這不等於證明所有合法組合皆不可能實現，也不宣稱所有歷史 delayed 契約都是新回歸。原有點位語意需要 Main 提供可驗證的合法組合或明示修正；不能把原文改成「以最近敵人為圓心」。

這與先前 randomArea 的「空地回退 caster」是不同程式分支、相同來源落點保真議題；沿用既有 `question.ground-barrage-anchor` 協作題追加證據，不冒充視覺 brick-request。

## 測試工具校正保留

v1 已看到相同圓心偏移，但邊緣受測敵人與 caster 太近，普通身體碰撞會改變其位置。該版保留為初步證據，不用來主張「受測點固定在圓內」。v2 在排程後將 caster 移開，保留普通碰撞，並逐 frame 驗證受測敵人零位移；結果仍為控制 12/12、偏心 0/6。

首次複製命令使用錯誤工作目錄，發生模組不存在；當時未執行測試或產生結果。更正路徑後才取得 v1/v2 真實執行結果。這項環境操作失誤不是產品失敗。

## 資料與後續處理

新增三個技能配方問題；原 `source-admission-ledger-v1` 的八項紀錄不覆寫，這次屬增補而非已重算的新版全量清單。仍沒有正式完整英雄訓練准入或獨立留出。

IR5 的來源已知標籤與 null 預覽參數未改。不能因這個引擎／配方缺陷把模型的正確「指定落點」答案訓練成最近敵人目標，也不能只把測試放寬就算模型改善。先補合法點位實作，再以相同空地、置中、偏心、進出與友敵反例重驗；之後才談整隻英雄正例准入。
