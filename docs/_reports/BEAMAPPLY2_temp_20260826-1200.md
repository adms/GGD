## 3. 新機制：`spawnModelFx.scaleAxis`（非等向縮放）

| 層 | 檔 | 改了什麼 |
|---|---|---|
| 上界 | `packages/shared/src/sim/effects/kindLimits.ts` | `MODEL_FX_MAX_SCALE_AXIS = 8`（把 1.56:1 拉到 12.5:1 已比參考擷圖更細長） |
| schema | `packages/shared/src/content/schema/effects/spawnModelFx.ts` | `scaleAxis: z.tuple([…×3])`，缺席 ⇒ `[1,1,1]` |
| 變體型別 | `packages/shared/src/sim/effects/variants/spawnModelFx.ts` | `scaleAxis?: readonly [number,number,number]` |
| 線路＋sim | `packages/shared/src/sim/effects/spawnModelFx.ts` | `ModelFxSpawnEvent.scaleAxis` ＋ 轉發（缺席就不送） |
| 客戶端 | `apps/client/src/render/modelFxRig.ts` | `setAll(s)` → `set(s*ax[0], s*ax[1], s*ax[2])`，缺席仍走 `setAll` |
| 模板可繼承 | `packages/shared/src/content/modelFxPreset.ts` | `PRESET_FIELDS` 加 `scaleAxis`（出貨模板目前一份都沒宣告 ⇒ 逐位元不變） |

⭐ **軸是行進座標系的**：掛在 `root`（⛔ 不是 `axis`）。Babylon 的合成是
`S_axis · R_axis · S_root · R_root` ⇒ `root.scaling` 作用在**已經照 `fxLongAxis` 橫放好**的
座標系上：`+Z` 恆為行進軸。而 `roll`（`spinDegPerSec`）也繞 `Z` ⇒ 兩者可交換，翻滾不會把光束甩歪。

⛔⛔ **它引用不到任何一行 JASS，這件事寫在四個地方**（schema / 變體型別 / kindLimits / 模板 description）：
WC3 的 `SetUnitScale(u,x,y,z)` **只讀第一個參數**，而這一族在 `war3map.j` 寫下的三軸值
**逐字相同**（j:31908 · j:32326 · j:32328 · j:47758）⇒ 原作是等向的。
它的出處是 **owner 2026-08-23「這四個經典總是要看到橫放的光束砲吧」＋ 一個量到的缺口**（§4）。
