## 二、⛔ 而 **B2 在英雄這一層沒有落地** —— 包裡是 30 格算好的數字

投稿包送出去的英雄文件是 `packages/shared/src/content/import/heroPackage.ts:164`：

```ts
{ collection: "champions", id: compiled.champion.id, document: json(compiled.champion) }
```

⭐ 而 `compiled.champion` 是 `resolveChampionRuntimeStats()` 的**輸出**。實跑印出來：

| | 作者稿（`generateHeroDraft` 的產出） | ⛔ 包裡送出去的（`compiled.champion`） |
|---|---|---|
| `origin` | `"鬥士"`（模板 ref） | `"鬥士"` |
| `statOverrides` | `{"armor":"大"}` | ⛔ **`undefined`** —— 被 `delete out.statOverrides` 刪掉 |
| `baseStats` | `{}` | ⛔ **15 格數字** |
| `growth` | `{}` | ⛔ **9 格數字** |
| `attributes` | `undefined` | ⛔ **6 格數字**＋`primary`＋`source` |

⇒ ⭐ **合計 30 格算好的數字**，而作者稿只有 **2 格**（出身 ＋ 一格覆寫）。
⇒ ⭐ 這正是票上 AC「那個包裡英雄的十一屬性是**模板 ref ＋ 覆寫**，⛔ 不是十一個算好的數字」**沒有滿足**。

### ⭐ 根因：同一個病治好了特效那一半，英雄這一半留著

`CompiledHeroDraft` 早就有 `authoredVfxScripts`，而它的型別註解逐字寫著
「⛔⛔ 不要拿展開後那一份當出貨文件」——
⭐ **`champion` 就是同一個形狀，而它沒有對應的作者稿欄位**：

```
hasAuthoredVfxScripts = true
hasAuthoredChampion   = false      ← 2026-09-19 量到
```

⇒ ⭐ 出身表（`content/config/stat-normalization.json`）因此有了**第二個住處**：
包一旦送出去，`byOrigin` 之後怎麼改，那份英雄都**不會跟著動**（第〇·四守則）。

## 三、這一輪做了什麼（⭐ 柵欄內）

| # | 檔 | 做什麼 |
|---:|---|---|
| 1 | `heroForge/generator.ts` | ⭐ `CompiledHeroDraft` 加 **`authoredBodies`**（`champion` ＋ `relatedChampions` ＋ `needsCounterpart`）—— 稀疏作者稿，⛔ 十一屬性不烘 |
| 2 | 同上 | ⭐ 把 compile 尾巴的解析鏈抽成 **`resolveAuthoredHeroBodies()`**（匯入那一側），而 `compileGeneratedHeroDraft()` **自己呼叫它** ⇒ ⛔ 不是兩份會各自漂的實作（失敗形態⑤：被測的不是出貨的那個） |
| 3 | `heroForge/authoredChampionRoundTrip.test.ts` | ⭐ 承重守衛（新檔） |

⚠️ **測試預算（量到的，⛔ 不是估的）**：守衛 **71 行**（其中 16 行是說明與空行 ⇒ 程式 **55 行**），
實作新增 **56 行**。⇒ 體驗層兩條線都過：`55 ≤ 56`（測試 ≤ 實作）且 `71 ≤ 80`。
⚠️ ⭐ commit 訊息裡寫的是「71 行 < 實作行數」—— **那句話的算法不對**（71 > 56），
正確的比較是**程式行**那一組；本節是更正（第三守則：⛔ 不要留著一個沒量過的數字）。

### ⭐ 守衛驗的兩件事

1. **匯出→匯入一輪逐位元組相同**：作者稿是稀疏的（`baseStats`／`growth` 為空、
   `attributes` undefined、`statOverrides` 在），而
   `resolveAuthoredHeroBodies(draft.authoredBodies, configs)` 的結果與出貨的
   `draft.champion` ＋ `draft.relatedChampions` **`JSON.stringify` 相等**
   （⛔ 不是「看起來一樣」；兩具身體一起比，變身態不可以掉）。
2. ⭐ **兩個方向**（⛔ 不是一把單邊的尺）：把 `byOrigin.mr.鬥士` 與
   `byOrigin.armor.鬥士` 同時改成「極大」⇒
   **沒覆寫的 `mr` 跟著動** 且 **有覆寫的 `armor` 不動**。

### ⭐ 突變驗證（終端證據）

拿掉 `generator.ts` 的 `statOverrides: plan.statOverrides` 一行 ⇒ **兩條都紅**：

```
× 匯出的是稀疏作者稿… → expected undefined to deeply equal { armor: '大' }
× 改出身表：沒覆寫的 mr 跟著動，有覆寫的 armor 不動 → expected 180.18 to be 90.09
```

⭐ 第二條的數字就是這條守衛的意義：少了覆寫合併，armor 從 **90.09 跳到 180.18**
（跟著出身表走），⛔ 而它應該停在覆寫的「大」。改回來之後 `2 passed`、
`tsc -p packages/shared` EXIT=0。
