## 1. 做完並有終端證據的兩件（都在 #744）

### 1.1 cry 英雄的選角確認終於播叫聲

**根因**：`nameVoice.play()` 的第三段**永遠**是 `quotes/<id>.mp3`（macOS `say` 的
Kyoko/Otoya 唸整句）。對七位 `voiceClass: cry` 的英雄那是玩家聽得到的謊。

⭐ **一顆音檔都不用錄**：`voices/champions/MANIFEST.json` 早就為這七位各出貨一條 `quote`，
用他們自己的 CosyVoice3 複製聲唸成叫聲，七顆 mp3 全在磁碟上（10–26 KB）。
三個零件各自都對，壞的是「確認 × 叫聲」這個**配對** —— 失敗形態⑧。

| 檔 | 做了什麼 |
|---|---|
| `apps/client/src/audio/cryConfirm.ts`（新） | 純決策：cry 七位回 pack 的 `quote` clip，其餘原樣回 TTS。`CRY_VOICE_CHAMPIONS` 是**釘住的**，測試對照 `_voice-casting-plan.json` 的 `identity.voiceClass === "cry"` |
| `apps/client/src/audio/nameVoice.ts` | 第三段改走 `confirmTailClip`；新增 `packLoader` 注入 ＋ `loadPack()` ＋ `setPackLoader()`；`reset()` 一併清 `packPromise` |
| `apps/client/src/audio/championVoice.ts` | `championNameVoice.setPackLoader(() => championVoice.loadPack())` |

⭐ **注入方向是刻意的**：pack manifest **949 KB**，`championVoice` 早就為 rung-2 點擊單飛快取它
⇒ 在 nameVoice 自己 fetch = 同一 MB 的第二個住處；而且反向 import 是循環
（championVoice 已經 value-import nameVoice）。

⭐ **rollback 是資料**：把 `quote` 從 MANIFEST 拿掉 ⇒ 立刻退回 TTS，逐位元等於今天。
⚠️ 刻意沒有旗標 ——「播得出來嗎」與「要不要播」是同一個問題。

⚠️ **本票外**：`playQuote`（回合結束／比賽結算）仍播 TTS 名言。AC 只寫「確認」，
而那一拍還牽動 `roundEndVoice` 的 `machine` 閘（換成角色自己的聲音之後還算不算「機械語音」
是 owner 的語意裁決）⇒ 刻意沒有順手做。已寫進 #744 留言。

### 1.2 `sfx/fx/GENERATE.sh`：假理由底下藏著兩條互相遮蔽的死線

檔頭寫「WHY .wav and not .mp3」而目錄是 32 mp3 / 0 wav。真的跑一次才看得到全貌：

| 量到（2026-08-27） | |

| 修之前 | **EXIT=1，31 支只寫出 24 支** |

| 修之後 | **EXIT=0 · 0 個 .wav · 32 個 .mp3**，檔名集合與出貨目錄 `diff` **完全相同** |

修法：`synth`/`synth_mp3` **融合成一支**（只差最後一行編碼器＝第〇·七守則的「重複」，

（保持 stereo：UI 提示音不進 PannerNode）· 檔頭改成說真話。

⭐ 檔頭寫下**量到的**事：32/32 都帶 LAME `Info`(Xing) frame ⇒ gapless 的 delay/padding
中繼資料在 ⇒ 當年那個「編碼器延遲糊掉 40 ms 暫態」的顧慮在這裡有答案。
mono 仍是硬需求，但那是 **PannerNode** 的事，⛔ 不是容器的事（以前兩件事混在一起）。

⛔ **出貨檔一個位元組都沒被覆蓋** —— 驗證是把腳本複製到 `/private/tmp/laneX-fxgen/` 跑的
