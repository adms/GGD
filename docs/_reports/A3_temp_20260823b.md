## ⭐ 結論：⛔ **不要換 Go。** 慢的不是語言，是**一行 O(F×N) 的二次方掃描**

`audit:check` 的慢**有 86% 來自一行程式**。把它改成增量游標之後，
**Python 自己就快 11.3×，而輸出逐位元組相同** —— 而我照著票寫出來的 Go 版
**比修好的 Python 還慢 8%**。

| 版本 | parse_jass 中位數（9 次） | 對照 |
|---|---:|---|
| Python 現況（二次方） | **3.0962s** | 基準 |
| ⭐ **Python 修掉二次方** | **0.2737s** | **11.3× 快** |
| Go 逐條移植 | 0.2958s | ⛔ 比修好的 Python **慢 8%** |

⇒ 票裡的驗收條件是「③ 綠 **而且** ④ 真的快很多，才換 package.json」。
**③ 綠了（逐位元組相同），④ 沒過（Go 更慢）⇒ ⛔ 一行都沒有換。**

⚠️ **Go 版留著的理由**：它是這個負面結論的**證據**。下一次有人想「把 Python 換成 Go」時，
這裡有一個量過的數字說「在這種 regex 密集的工作上 RE2 比 CPython 的 `re` 慢」，
⛔ 不必再重寫一次才知道。

⚠️ **移植上的一個真陷阱**（如果之後要拿它跑別份 `.j`）：
Go 的 `\b` / `\w` 是 **ASCII** 語意，Python 的 str 正則是 **unicode** 語意。
兩者只在「中文字緊貼著 `UnitDamage(` 這種呼叫」時分岔 ——
本份 war3map.j 沒有這種寫法（所以輸出相同），但那是**運氣**，⛔ 不是保證。

## 🧭 這一條該推廣的判準

> **一支 script 慢的時候，先問「它是不是在做一件 O(n²) 的事」，
> ⛔ 不要先問「它是不是用了慢的語言」。**

這次的成本對比：換語言 = 移植 1,537 行 Python（`audit.py` 739 + `axes.py` 462 +
`jassfacts.py` 336）＋ 永久維護兩份語意；刪二次方 = **改 3 行、輸出逐位元組相同、快 11.3×**。
