### ⭐ 中性音效是從哪裡來的 —— 3 個檔，⛔ 一個都沒有下載

全部來自 **`content/assets/audio/sfx/fx/`**，那一批是 **`fx/GENERATE.sh` 用 ffmpeg 合成的**
（`fx/MANIFEST.json` 逐檔記著配方與長度）。

**為什麼確定它們沒有主人**（⛔ 不是我判斷的，是既有推導器判的）：
`tools/sfx-bind/ownership.ts` 只有兩個主人來源 —— ① `champion-voices.json` 的 `select`
② `SFX_BINDINGS.json` 的 JASS 綁定（**只認 `war3mapImported\` 前綴**）。
自製合成音兩者都不沾 ⇒ `clipOwners` 裡查不到它們。
量到的結果：**通用池 0 個污染 · 跨角色誤用 0 列**（產生器輸出的最後一行）。

逐檔理由：
- `whiff.mp3`（0.22s 空氣揮擊）—— ⭐ 在 `audio-map` 裡**沒有任何其他 cue 在用**
  （`whiff` 這個 cue 早就換成 `lab/whiff-sword.mp3`）⇒ ⛔ 不會跟同一拍的任何一層撞成回音。
- `chime_burst.mp3`（0.8s）—— MANIFEST 逐字寫它是「the **reward payoff**」，
  而擊殺正是一個獎勵時刻（它會給金幣）；音色與所有 hit/impact 分得開 ⇒ 讀起來是「確認擊殺」。
- `draft-confirm.mp3`（0.605s 科技鎖定聲）—— 語意就是「你的選擇定案了」；
  它另一個用途 `draftConfirm` 在**局內**抽卡畫面，⛔ 與選人畫面不同時出現。

⚠️ **⛔ 沒有動 `lab/` 那一批**：`sfxLabCredits.test.ts` 逐檔比對 `mapKeys` ↔ `audio-map`，
而修那份 credits 要動 `apps/client/src/ui/**`（不在本 lane 柵欄內）。

⭐ **原本那 10 個角色語音一個位元組都沒刪**，它們回到自己的主人身上：

### 🚨 斷點在這裡（⛔ 不是音訊層）

`GoldPickupFx.spawn()` 第一件事是取**屍體位置**：

```
const from = this.deps.entityPos(mobId) ?? this.lastBody.get(mobId) ?? null;
if (!from || !target) return;          // ← 這裡 return ⇒ 不生金幣、不播音效、不播音階
```

`lastBody` 由 `GoldPickupFx.noteBody()` 餵，而**全 repo 只有一個呼叫端**：
`apps/client/src/vfx/VfxSystem.ts:2079`，它在 `syncGroundEntities()` 裡
**只走 `frameBus.champions`**。

⇒ ⭐ **殭屍（`KIND_MOB`）根本進不了 `frameBus.champions`** ——
`apps/client/src/GameApp.ts:3874-3890` 的 mob 分支在建立錨點**之前就 `return`** 了
（那個迴圈是給小怪血條用的）。所以 `noteBody` **從來沒有替任何一隻殭屍記過位置**。

⚠️ 而 `VfxSystem.ts:2075-2078` 的註解**逐字預測了這個後果**：
「殭屍在事件到達時通常已經從快照裡消失了⋯`entityPos()` 會回 null。**少了這一行，
金幣不是掉錯地方就是根本不掉** —— 而畫面上看起來只會像『這個功能有時候沒作用』」。
⇒ ⭐ 那一行**確實存在**，但它掛在一個殭屍永遠不會出現的迴圈上 ⇒ 這條保護是死的。
剩下唯一的機會是 `views.posOf(mobId)`（`EntityViewRegistry.lastPos`）在事件被 drain
的那一幀還沒被清掉 —— 那是一個**時序賭博**，正好解釋 owner 說的「沒有」而不是「偶爾有」。

⛔ **修法要動 `apps/client/src/vfx/VfxSystem.ts` 或 `apps/client/src/GameApp.ts`，
兩個都在本 lane 的禁止清單上，而且 `GameApp.ts` 是撞車重災區。**
⇒ 交給有那兩個檔的 lane。最小修法：在 mob 那個分支 `return` 之前補一行
`this.vfx.gold.noteBody(es.id, mp)`（或讓 `syncGroundEntities` 也走 `frameBus.mobBars`）。
⭐ 這同時修好 owner 的**另一半**抱怨「金幣卻不是飛向我」——因為金幣根本沒生出來。

## ④ 層數上限（owner 的混合方案，四件事）

| owner 要的 | 落在哪 |
|---|---|
| **上限** | `content/config/audio-map.json` 的 `castLayerCap`（`enabled` / `maxLayers` 1–8 / `whitelist` ≤200）＋ Zod `zAudioCastLayerCap` ＋ 逐格降級解讀 `readCastLayerCap` |
| **名單** | ⭐ **產生**的一節：`docs/音效使用表_temp_20260823-0234.md` §五，列出 **15 支**已頂到 5 層的技能、**技能 id 可直接貼進白名單**、以及上限再降一格會安靜的是哪幾層 |
| **白名單** | `castLayerCap.whitelist`（`ability@1.id` 陣列），命中就完全不受限 |
| ⛔ **不砍設定** | 夾在 `VfxSoundLayer.cue()`（**播放的那一刻**）。`content/vfx-families.json` 與逐支覆寫**一個位元組都沒動** ⇒ 上限放寬／進白名單，聲音逐位元回來 |

**層序（唯一一份，工具 import 它）**：施法音 → 特效發射 → 特效命中 → 特效循環 → 特效消散。
超過的**從尾巴丟**，⭐ 施法音永遠留著（⛔ 不會出現無聲施放）。

### ⚠️ 出貨預設 `maxLayers: 5` ＝ **今天一層都沒有被夾掉**（⛔ 這是刻意的）

第一版我設 3，結果**當場關掉 `flamePillar` 那一族的循環與消散音**，
`sfxPolicyGate.test.ts` / `vfxSoundWired.test.ts` 四條（GH#390/#440 的守衛）全紅。
⇒ ⭐ 那等於我替 owner 挑了一個會砍聲音的數字（第一守則：「可調」≠「我可以轉」）。
現在出貨值 = 層序長度 ⇒ **行為逐位元等於這一格出現之前**，而那張表照樣把 15 支拿給他審。
⭐ **他把 `maxLayers` 改成 4 或 3 就會真的變安靜，⛔ 我沒有替他挑。**
