## #707 —— 兩個閘對**同樣 388 份檔**意見相左

### 量到的（主樹 HEAD，逐檔 `stat`）
| | |
|---|---:|
| `genguard.sh` 回 `NORMALIZER`（＝「這一支不擋你」）的檔 | **388** 份 |
| ⭐ 其中**仍然 chmod 444、改不動**的 | **388**（100%） |
| 反方向的洞（真作者的產物卻可寫） | **0** |

⇒ 意見相左是**全部**，方向只有一個。⚠️ 而它是今天早上放大的：
`7f1bb7f0`/`4c3197ee` 把 `skillremake:provenance` 與 `speedtiers:build`
從 AUTHOR 改判成 NORMALIZER ⇒ 從 0 份變成 388 份。

分佈：`content/abilities` 331 · `content/champions` 56 · `docs/_data` 1。

### 根因：一份知識三個住處，而**第三個住處根本沒有那份知識**
正規化器清單有**兩份手寫副本**（`genguard.sh` + hook），而
`normalizerListIsReal.test.ts` 只比對那兩份 ⇒ 全綠。
⭐ `product-quarantine.sh` 連「正規化器」這個概念都沒有 —— 它的擁有者表同樣是
`sync-io.json` 的 `writes`，而 sync-io 只知道**誰寫過**，⛔ 不知道**誰擁有**。

### 修法（採 Scope a＋b＋c，⛔ 不是擇一）
1. 清單搬進 `tools/parallel-gates/normalizers.json` —— **唯一住處**，三支腳本一起讀。
   每一格帶**能被反駁的理由**（逐行讀過那支程式），`$rejected` 也留著
   （`apdmg:build` 是作者 · `prose:apply` 是幽靈名）。
2. ⭐ `lock` 的語意從「一律加鎖」改成「**把隔離區推到正確狀態**」：
   有作者認領 ⇒ 鎖；只有正規化器認領 ⇒ **主動放行（444→644）**。
   ⚠️ 「主動放行」⛔ 不是「跳過」—— 跳過的話那 388 份永遠停在 444。
   ⇒ `genrun.sh` / `sync.mjs` 的「解鎖→跑→重鎖」自動就對了（走同一個 lock）。
3. ⭐「誰認領」對**全部**步驟算，⛔ 不是只對 `--step` 那一支 —— 否則
   `lock --step skillremake:provenance` 會把「provenance ＋ skillremake:json 共同認領」的
   **107 份真產物**誤判成手編檔而放行。
4. genguard 的 NORMALIZER 分支多一把**量尺**：說「不擋你」而檔案是 444 ⇒ 指名 #707 並回非零。
5. 兩邊 fail-**loud**：genguard 讀不到表 ⇒ ERROR + 非零（⛔ 不再靜默印 ✓）；
   隔離區讀不到清單 ⇒ 大聲 + fail-closed（全部當產物鎖，保護產物那一邊）。

### 兩個方向
| 驗什麼 | 結果 |
|---|---|
| ① 該放的真的放得過 | `open(p,'a')` → WRITABLE ✅ |
| ② 該擋的仍擋（真作者產物） | EACCES ✅ |
| ②' 正規化器＋作者共同認領 ⇒ 仍是產物 | EACCES ✅ |
| ③ ⭐ 收工後仍然對（模擬 genrun 解鎖→跑→重鎖） | 388 份仍可寫、107 份鎖回去 ✅ |
| ④ 出貨態掃描（⛔ 不看 diff） | stuck **388 → 0** ✅ |

主樹收斂後：`鎖著 254 · 可寫 388 / 追蹤 642`。

### 突變 + 量尺校準
- `if author and writable:` → `if writable:`（＝修復前行為）⇒ ①③ 一起紅。改回。
- ⭐ **量尺自證**（CLAUDE.md：量尺自己會說謊）：④ 掃到 642 份戶籍 / 388 份正規化器專屬

⚠️ **超出柵欄一步**：改寫了 `normalizerListIsReal.test.ts`（非 laneY 前綴）——
它是**這份知識自己的閘**，知識搬家它必須跟著搬（regex 抽不到清單時它會大聲失敗，

```

scripts/ticket-lint.sh --dupes all    # 連已關的一起掃
```

## #804 / #810 —— 根因在**解析**，⛔ 不在權限也不在探針

```
--script vfxfam:build   修復前 ok:false·exit 1·讀 0·寫 0
                        修復後 ok:true ·exit 0·讀 399·**寫 80**
```
⭐ 範圍遠比一支大：用**出貨的 package.json** 當母體重跑舊解析 ——
**142 支 script 裡 140 支（99%）會被解析成幽靈名**。
只有 `skills:sync` 剛好是對的，而那是唯一被指過的目標 ⇒ 沒有人發現。

### 兩層（第二層是我第一版自己造的）
| 層 | |
|---|---|
| ① 鏈的每一節⛔ 不一定是 `pnpm <script 名>` | 舊碼 `split("&&").map(replace(/^pnpm\s+/,""))` 再 `spawn("pnpm",[那一節])`。**葉子**（`tsx apps/client/…`）與**多 token**（`pnpm --filter @ggd/shared content:build`）都 ⇒ Command not found ⇒ `ok:false · writes:[]` |
| ② 我第一版改成 `bash -lc "tsx …"` ⇒ **exit 127** | `tsx` 不在 login shell 的 PATH 上 —— 同一個病的第二層：把 pnpm 的工作自己重做一遍。⇒ 葉子的正解是**原封不動跑 `pnpm <SCRIPT>` 本人** |

### ⛔ 為什麼上一輪往權限與探針查了兩圈
⭐ **訊息指向錯的地方**：摘要只印「⛔ exit 1」，收尾那行寫著
「⚠️ 沙盒裡紅了 N 支(**⛔ 不影響 I/O 量測**)」——⛔ 那一句在這情況是**假的**。
⇒ 現在解析出不存在的 script 名 ⇒ **當場 exit 2 並指名**「這是 trace 的**解析**問題」。

解析層搬進 `tools/parallel-gates/chainSteps.mjs`（純函式）——
⛔ 不是為了整潔：`trace.mjs` 一 import 就會建沙盒，守衛載不動它 ⇒ 這一層本來**驗不到**。

1. 要先進 `skills:sync` 的鏈 ＝ 改 `package.json`（柵欄外）。只登戶籍不進鏈 ⇒ 那 80 份
   變成「鏈永遠不會重生成的產物」＝ 死路。
2. ⭐ **量到的代價**：80 份 writes 裡 **79 份目前無主且可寫** ⇒ 登記會讓 79 份變 444。
