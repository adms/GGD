### ⭐ 解名字：⛔ 不開第二份對照表（第〇·四守則）

`clip` 先當 **`model@1.clipMap` 的邏輯狀態名**查（`idle`/`death`…），查不到才當**軌名逐字**。
⇒ `clip:"death"` 在 `flamestrike1` 解成 `death`、在 `darkraor` 解成 `Death`
—— **大小寫與命名慣例是那份 .glb 的性質**，⛔ 不是引用它的技能該知道的事。
`birth`（WC3 一次性序列，不在六格裡）走逐字那一段，所以表達得出來。
比對兩段：完全相同 → **不分大小寫的字尾**（因為量到的前綴 `modelfx-<serial>-`）。
⛔ 名字對不上就一條都不播（與 `attachment@1.anim` 逐字同一條規矩）。

⇒ **`model@1` 一格都沒新增**，`content/models/*.json` 一個位元都沒動。

### ⭐ 回池重用與洩漏（量到 ④ 逼出來的三件事）

* `release()` → `stopClip()`：⚠️ `setEnabled(false)` 只關渲染，⛔ **不關動畫** ——
  一條沒停的軌在 free-list 裡還在每幀被推進，而下一發（`clip` 缺席、⇒ 完全不呼叫
  `startClip`）會播著**上一支技能的動畫**。
* `retire()` / `trimPoolTo()` → `disposeClipGroups()`：AnimationGroup **不是節點**。
* `dispose()`：軌**先**收（趁目標還活著）—— 與 `ChampionView.dispose()` 的順序逐字相同。

### ⭐ 首發那一具（容器晚到）

`clip` / `clipTimeScale` 存在 `LiveModelFx` 上，`ensureContainer` 的回填（GH#673-①c）
在容器落地的當下補呼叫 `startClip`。⛔ 少了它＝**每一支技能的第一次施放**都有模型但
不播動畫（第二次以後正常 ⇒ 看起來像「偶爾沒動」，⛔ 不像缺陷）。

## 2. @visual-proof 守衛（`modelFxRig.test.ts`，1 條）

真 `ModelFxRig` ＋ **真的** Babylon `AnimationGroup`（⛔ 不 mock）＋ 真的 `scene.render()`：

3. ⭐ **量尺自證**：原速那一具**必須**真的動（`> 1`），否則 0/0 讓比值永遠成立。

**突變（一批一條，挑最承重的）**：`startClip()` 拿掉
`g.speedRatio = item.clipTimeScale ?? 1;` → 🔴「clipTimeScale 沒有到達 Babylon 的
AnimationGroup」→ Edit 還原。
