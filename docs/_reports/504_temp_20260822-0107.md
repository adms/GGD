# K2 · GH#504 — modal 宣告 `data-pad-scope`（lane 報告）

日期 2026-08-22 · 分支 `main` · ⛔ 未 push

## 根因（issue 已經指出，這裡確認過）

`apps/client/src/ui/PadFocusNav.tsx:221`

```ts
const root: ParentNode = scope ?? document.body;
```

找不到 `[data-pad-scope]` 就退回 `document.body`，而同檔 `isVisible()`（:51-66）
**不做遮擋判定** ⇒ 方向鍵把焦點移到遮罩**底下**仍然可見的按鈕，
而 pad 的 A 走 `el.click()`（:166）—— scrim 擋得住滑鼠，**擋不住手把**。
再加上 `input/padFocusNav.ts` 的 `focusNavActive` 在 `hasScope=false` 且相位是
combat/resolution 時回 **false**，於是「離場結算卡」那一格是 blocker：
兩顆按鈕對純手把玩家**根本不存在**。

## 做法：一個模板，⛔ 不是 12 次手打

新檔 `apps/client/src/ui/padModalScope.ts` —— **priority 的唯一住處**：

| scope | priority | 為什麼是這一格 |
|---|---:|---|
| `champ-select` | 20 | 相位面板不是覆蓋層；briefing/augment-draft(40) 要贏過它 |
| `shop` | 30 | 三選一(40) 開著時要贏過商店（#504 裁決） |
| `briefing` | 40 | 畫在 champ-select 上 |
| `champion-picker` | 42 | 公告(45) 蓋得過它 |
| `announcement` | 45 | 跟著 z-index 90 |
| `change-password` | 46 | 跟著 z-index 100 —— 玩家**自己開的**對話框不可以被公告關住 |
| `device-login` | 50 | 登入頁上的 QR modal |
| `match-end` | 55 | 蓋過 pause(50) |
| `credits` | 56 | 版權頁 |
| `device-link` / `leave-settlement` / `rally-confirm` | 60 | 與既有 `leave-confirm` 同級；三者不可能同時在場 |

⭐ 既有的六個 scope（augment-draft 40 / settings 45 / create-room 45 / purchase 45 /
pause 50 / leave-confirm 60）住在**別的 lane 的檔案**裡，所以它們只以**參照**的形式
寫進 `padModalScope.ts` 的檔頭，⛔ 沒有被改成第二份定義。

`padModalScope(name)` 回傳 `Record<string, string>`（JSX 對帶橫線的屬性不做欄位檢查，
但**展開**具名型別會被檢查 —— 同 `LeaveConfirmDialog` 的 `{...{ [ATTR]: "" }}` 前例）。

## ⛔ 兩條迴圈的那一格（issue 的 blocker）

`DeviceLoginPanel` 原本自己跑 `startGamepadFocus(..., () => true)`（永遠啟用），
而全域的 `PadFocusNav` **從來沒有停過**。兩條迴圈同一幀讀同一顆 A、兩邊都寫
`applyPadFocus` ⇒ 焦點環在「QR 面板的取消」與「PadFocusNav 漂到的 body scope」
之間互搶。現在只剩一個讀者。

⚠️ 這造成 `ui/focusGlow.test.ts` 的一條既有守衛紅：它斷言
「pad focus driver ≥ **2**」。那個 2 是「當時剛好有兩條迴圈」的**數字**，
而不是機制。已把下限改成 **1** 並在原地寫明理由與 ⛔「不要為了湊數再加一條 driver」。
（下限存在的目的是抓「掃描壞了 = 0 hits」，不是規定迴圈數量。）

## 守衛

`apps/client/src/ui/padModalScope.test.ts` —— **渲染出來的 DOM**，
⛔ 不是 `grep`（第二守則失敗形態⑥）。用 `react-dom/server`
（本 package 的 vitest 是 `environment: "node"`）真的把每一個 modal 畫出來再讀 markup。

⭐ 為什麼一定要渲染：`Btn` 不轉發未知 props，所以一個寫在 `<Btn>` 上的
`data-pad-back` 會被**靜默丟掉**，而字串掃描是綠的。

三條 `it()`：
1. 每個可渲染的 scope 都畫出了 `data-pad-scope` **且** priority 與梯子相符
2. 梯子上每一格都有 render 或一個**能被反駁的理由**（⛔ 不准無聲漂移）
3. 有取消/關閉的 modal 把 B 做成**契約**（`data-pad-back`）

**兩格豁免**（理由可被反駁，改掉了就搬上去）：

- `shop` —— `MerchantShop` 只在 gate 通過且卡片展開時才畫，需要活的 seat + whitelist + intel SimWorld
- `champ-select` —— `ChampSelectPanel` 會拉進 Babylon 預覽舞台，node 環境載不動
