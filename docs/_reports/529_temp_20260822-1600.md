## ⭐ 最重要的一個發現

票說：**「110 份 `fx.w3x.*` 沒人用，89% 的技能綁通用原型 ⇒ 這是接線問題」**。

⛔ **逐份追下去之後，這個結論站不住。** 三個量到的事實：

| # | 量到的 | 為什麼推翻了「接線漏掉」 |
|---|---|---|
| ① | 票的「110 份沒人用」只數了 **`ability.vfxKey`** 這一條路 | 真正的孤兒是 **80 / 120**。另外 40 份走的是 `config.vfx-ability-art@1.promoted`（20 份）、家族原型的 stock emitter 規則（2 份）、`FireRingFx` 直接點名（4 份）與技能文件（15 份，含重疊） |
| ② | 那 80 份裡 **44 份**的模型在原作地圖裡**沒有任何技能引用**（`models[stem].referencedBy` 是 `[]`） | `darkraor` / `1hswd-01` / `demonfilth` / `herosaber` / `babyface` / `blackhole` / `blackhole1` / `heroraichus3` / `lasercannonfinalred` / `musiccast` / `oblivionaura` / `sephboom` —— 它們掛在單位/道具/裝飾物上。**硬接 = 玩家看到一個原作裡根本不屬於這支技能的東西** |
| ③ | 其餘大多數被一道**已經存在、已經量過**的閘擋住 | `apps/client/src/render/vfx/w3xAbilityArt.ts` 檔頭逐字寫著：`divinering` 的 20 顆 emitter 掛在 `BlizParticle*` 動畫節點上，用世界座標重播會**全部從同一點噴出** —— 一團而不是一圈。「Binding those would make legibility WORSE」 |

⇒ ⭐ **這一輪的產出因此不是「把 110 份接上去」，而是把那道推導從散文變成一支
`--check` 會紅的產生器** —— 證據一動（抽取器多收模型、技能退休、emitter 被砍），表就過期，
而過期會被逐位元組比對抓到。

⚠️ 而且票的第二個前提也要修正：**`config.vfx-ability-art@1.promoted` 已經是這張共用表**
（34 列，`primary` + `extra`，`ContentDb.load()` → `setAbilityArtBindings` 真的在消費）。
⛔ 再開一份無關的表就是第〇·四守則的第二住處 —— 所以新表**配了跨表對帳**（見下）。

## 四道閘（`scan.py`，一列必須全過才叫 CONFIRMED）

| # | 閘 | 沒有它會怎樣 |
|---|---|---|
| 1 | `joinConfidence == CONFIRMED` | rawcode↔技能 的 join 是猜的 → 綁到**別支技能的特效** |
| 2 | `provenance ∈ {w3a-override, w3h-override, jass-literal}` | 暴雪內建繼承**不是作者意圖**（provenance 檔自己的 `provenanceContract` 這樣寫） |
| 3 | `rootAnchored == emitterTotal > 0` | ＝ 既有的可渲染性閘。⛔ 這裡只是把它從散文變成程式，**沒有推翻它** |
| 4 | emitter 文件都出貨了、技能還活著、家族 ≤ 6 顆 | 綁一份不存在的文件 = 這一招完全沒特效（第一·五守則的空宣稱） |

沒過的**每一份**文件都進 `unmatched`（95 筆），帶著**能被反駁的理由**與量到的數字
（例：「20 顆 emitter 只有 0 顆掛在模型根節點」），⛔ 不是「還沒收」。
⭐ 已經由別條路徑使用的會標 `⚠️ 已由其他路徑使用(…)`，避免 `unmatched` 被讀成孤兒清單。

### 四階覆蓋順序（寫進 `vfxBindings.ts` 檔頭）
1. 技能文件的 `vfxLayers` → 2. 技能文件的**原作** `vfxKey`（`fx.w3x.*` **或 `godie-*`**）
→ 3. **綁定表** → 4. `fx.prim.*` / 空（下游元素 fallback）

⚠️ 第 2 階的判準是「是不是原作藝術」，⛔ 不是「是不是 `fx.w3x.`」——
出貨的 27 列裡有 **5 列**的技能文件指著舊批次的 `godie-*` 文件
（`godie-tectonicfury-p0` · `godie-fireblast-p3` · `godie-bladestorm-swordeffect-p0`）。
漏掉 `godie-` 前綴 = 那 5 支被表換成**另一族**的特效，而畫面上看起來完全正常（失敗形態 ②）。

### 為什麼一列存 `vfxKeys`（陣列）而不是票上寫的 `vfxKey`（單值）
一次原作施法 = **一組** emitter（`holyawakening` 是 6 顆）。同時存「主」與「其餘」＝
「主是哪一顆」變成一個**存下來的值**，而它是一條規則算得出來的（`vfxKeys[0]`）——
第〇·四守則的第二住處。⇒ 只存有序整組。

## ⭐ 給 owner 的一句話
「原作特效沒接上」這件事**大部分不是漏接，是刻意不接**（原作裡那個模型根本不屬於任何技能，
或者它的形狀來自模型自己的動畫節點、拆成粒子系統會變成一團）。
真正漏掉的只有 **2 支**，另外有 **7 筆**綁在已經退休的技能上（等於沒有）。
這一輪把那道判斷做成一支會紅的檢查，⛔ 而不是為了衝數字亂接。
