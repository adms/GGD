## 一、先量再修 —— 跑真的 `SimWorld`，逐 tick 記淨位移

判準是 **淨位移 vs 意圖位移**（`移速 × dt`），⛔ 不是「身上有沒有狀態」。

### ① 狀態表：**一筆都沒有**

被持續普攻的英雄身上 `world.status` 全程是空的 —— ⛔ 不是減速、⛔ 不是 root、
⛔ 不是 stun。`movementHold()` 回的 `rooted` 全程 `false`、`speedMult` 全程 `1.00`。

### ② 碰撞推擠：**量過，不是主因**（這一條最容易被誤判）

被 2/4/6/8 個敵人圍住、往外走 100 tick：

| 圍住的人數 | 淨位移 / 意圖位移 |
|---:|---:|
| 0（對照） | 0.99 |
| 4 | 0.97 |
| 8 | 1.22（**推擠反而幫他離開**） |

⇒ 推擠會把人**推開**，⛔ 不會把人釘住。

### ③ 真正歸零的是 **hitstop**（`MovementSystem` 最上面那一段）

```ts
if ((world.hitstop.get(id) ?? 0) > 0) { t.vel = {0,0}; continue; }   // ← 修之前
```

一發普攻 `combat/damage.ts` 給 2–8 tick，`bumpFreeze` 取 max，而**每一發傷害重新上值**
⇒ 連段。量到的「**完全動不了**（位移 < 意圖 5%）」tick 數，100 tick 窗口：

| 場景 | 完全動不了 | 身上的 hitstop tick |
|---|---:|---:|
| 1 個攻擊者、出貨攻速 0.571 | 4 | 4 |
| 1 個攻擊者、攻速 4（上限 10） | **26** | 26 |
| 3 個攻擊者、攻速 4 | 25 | 48 |
| 8 個圍住、攻速 2 | **39** | 39 |

⇒ 一群怪貼身時，**近四成的 tick 玩家的方向盤是被拔掉的**。
（`sim/combatFeel.ts` 的 `DEFAULT_AUTO_ENGAGE` 檔頭 2026-07-30 就寫過同一句：
「被兩三個單位輪流打的人 hitstop 是接續的，連起來超過 30 tick 一點都不難」。）

### ④ 客戶端那一半：**它結構上預測不到** ⇒ 症狀被放大成橡皮筋

* 快照裡**沒有** hitstop 的位元 —— `apps/game-server/src/net/snapshot.ts` 的
  `ROOTED`/`STUNNED` 只從 `status` 推導（第 650–651 行），hitstop / knockdown 都不在。
* `LocalPrediction` 的影子世界也沒有 `world.hitstop`（`LocalPrediction.ts:598` 自己寫著
  「也沒有 hitstop」）。
* 而挨打是**遠端**攻擊者觸發的 ⇒ 影子每個 hitstop tick 照走，然後 `reconcile()` 把它
  snap 回權威座標，誤差進 `err` 用 100 ms 半衰期化掉。
  ⇒ 玩家看到的是「推了搖桿、人往前一點、又被拉回來」——**正是 GH#370（原地小步來回）
  的形狀**，只是這一次連 `predictionHold` 都救不了：那條路要一顆新的 `ENTITY_FLAG`，
  而且扣留期間還要多等一趟 RTT。

## 二、判 **①「不該有的定身」**，修掉

owner 給的兩條路是互斥的。這一格判①，三個理由都不是手感偏好：

1. **預測不到**（見 ④）—— 任何由遠端事件觸發的走位凍結都一定會橡皮筋。
2. **沒有任何回饋** —— 頭上沒圖示、身上沒狀態，畫面上和「網路卡了」一模一樣。
3. **它連段** —— 單發 67 ms 是節拍，連起來 1.3 秒是拔方向盤。

### ⛔ 但這**不是**「把 hitstop 拿掉」

保留下來的三半：

| 保留 | 為什麼 |
|---|---|
| **出手的人**照凍 | 他本來就得站定才打得出來（`standstill`）⇒ 這一段不花任何走位權 |
| **位移覆寫**（擊退／衝刺）照凍 | 「先定格、再滑出去」是 #133 的節拍，那段位移本來就不是玩家的方向盤 |
| `world.hitstop` / `world.hitstun` 兩張表 | **一格都沒動** ⇒ 前搖／施法／收招的暫停與 `digest` 全部照舊 |

### ⭐ 「誰是挨打的那一方」用的是**零新狀態**的判準

`world.hitstun` 是挨打者專屬的表（`damage.ts` 只對 `target` 寫），恆 ≥ 同一發的 hitstop、
且和它在同一個 `age()` 裡遞減 ⇒ 直接讀它，⛔ 不必新增第二張表（新表要進 digest、進快照、
多一個會漂走的住處）。

## 五、⚠️ 量到但**修不了**（在這條 lane 的柵欄外）——擊倒是 owner 的②，而它是隱形的

**`knockdown`（擊倒）才是真的「特殊狀態」，而它今天在畫面上完全不存在。**

| | |
|---|---|
| 什麼時候 | 未格擋、非法術、單發 `impact ≥ 170` |
| 效果 | `KNOCKDOWN_TICKS = 14`（0.47 秒）**root + stun**（連轉身都凍） |
| 量到的 | 攻擊力 250 的攻擊者：100 tick 裡 14 tick 擊倒（`kdT=14`），⛔ 而且 `world.status` 仍然是空的 |
| ⛔ 頭上沒有圖示 | `movementHold()` 從 `world.knockdown` 讀它，而 `net/snapshot.ts:650` 的 `ROOTED`/`STUNNED` 只從 `status.effects` 推 ⇒ **這顆位元從來沒有亮過** |
| ⛔ 客戶端也預測不到 | 同一個原因 ⇒ 每次被擊倒都有 0.47 秒的橡皮筋 |

⇒ **兩行就能同時修好圖示與預測**：在 `snapshot.ts` 組 flags 的地方
`if ((world.knockdown.get(id) ?? 0) > 0) flags |= ENTITY_FLAG.ROOTED | ENTITY_FLAG.STUNNED;`
—— 那顆位元一亮，`predictionHold` 的 `rooted`/`stunned` 兩格（出貨已經全開）**自動**接手扣留影子，
頭上的狀態圖示那條路也拿得到它。
⛔ 但 `apps/game-server/**` 與 HUD 都在這條 lane 的柵欄外，所以**沒有動**。建議開一張票。
