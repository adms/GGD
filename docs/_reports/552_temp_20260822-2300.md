## 2. ⛔⛔ 最重要的發現：**沒有一條「純內容」的下架路徑**

三條看起來可行的路，逐條被既有的閘擋掉 —— 全部是量到的，⛔ 不是推測：

| 路 | 擋它的東西 | 為什麼 |
|---|---|---|
| ① 把變身態卡搬進 `content/_legacy/champions/` | `packages/shared/testkit/formPairShipping.ts` 的 `halfMigrated` | 「**a transform pair must move wholesale**」—— 本體上架 + 變身態封存 = 那個會**每 tick 讓整房掛掉**的狀態，四支變身測試全部斷言它是空的。而這五位的本體都是上架英雄，⛔ 不能一起封存 |

## 3. ⭐ 接線只有一處、一行 —— 一張表 + 一條規則（⛔ 不是五段 if）

`packages/shared/src/sim/systems/ChampionFormSystem.ts` 的 `destinationFor()`（約 :191）：

```ts
const counterpart = Champions.tryGet(champ.championId)?.transform?.counterpartId;
if (counterpart === undefined) return undefined;
if (isRetiredChampionId(counterpart)) return undefined;   // ⭐ #552,就這一行
return Champions.tryGet(counterpart) === undefined ? undefined : { nextId: counterpart, nextIndex: 1 };
```

`import { isRetiredChampionId } from "../../content/championRetirement";`

為什麼是這個形狀：

- ⭐ **回 `undefined` 走的是既有的拒絕路徑** —— `applyChampionForm` 發 `castRejected("no-form")`、
  **一個位元都不寫**，而同一支技能 `effects[]` 裡的 `applyStatus` / `applyBuff` **照常執行**。
  ⇒ owner 的「效果及增益可以用效果狀態及增益狀態完美替換」在結構上本來就成立。
- ⭐ **後台一格勾選就能回頭**（🎭 英雄上下架那一頁寫 `retiredChampions`），⛔ 不是一次部署（第一守則）。
- ⭐ **一張表 + 一條規則**，五位共用，⛔ 沒有任何一支技能需要自己檢查（第〇·五、第零守則⑨）。
- ⚠️ **純度安全**：`championRetirement.ts` 只讀 `Configs` registry，無 `Math.random`／時鐘／`**`。
  `sim/` → `content/` 的 import 早有先例（`sim/abilities/abilityAugment.ts:74`）。
- ⚠️ 既有守衛已經**用同一個模型**在推理了：`championFormVisibility.test.ts:222-230` 把
  `retiredChampions` 當成「這個變身沒有入口」在算 `expectedReachable`（e007 就是先例）。

## 4. 差集 → 狀態／增益（⛔ 逐支對照，不是憑印象）

⚠️ 五個變身態的 `growth` 全部停在**未正規化的 w3x 匯入值**（例：`godie-hjai` maxHealth 成長 77.87
vs `godie-h020` 的 32）。⇒ ⭐ **今天變身其實是把玩家的成長曲線砍半**，那不是設計，是票上說的
「變身之後拿到的是舊的」。下面只列**設計上的**差，⛔ 不把匯入殘留當成要補的增益。

### ① 04-002 惡夢魔王的碎片（`godie-hjai.ex`，20 秒）

| 差 | 本體 → 變身態 |
|---|---|
| `maxMana` | 100 → **5000** |
| `manaRegen` | 0.1 → **1000** |
| `int` | 27 → **127** |

現有 `effects`：`championForm` + `applyBuff { ad pctAdd 0.35, 6s }`
⚠️ **`ad` 對一個 INT 主屬性法師幾乎是空的**，而且 6 秒 ≠ 卡面寫的 20 秒 —— 兩處都該一起修。

要補（20 秒）：
```json
{ "kind": "grantAttribute", "attr": "int", "amount": 100, "durationSec": 20 },
{ "kind": "applyBuff", "duration": 20,
  "modifiers": [ { "stat": "maxMana", "op": "flat", "value": 4900 } ] }
```
⏸ **`manaRegen 1000/s` 是決策點，⛔ 我不替 owner 挑**：那是 w3x 寫「這 20 秒不用管魔」的手法。
兩個選項 —— (a) 照抄 `manaRegen flat +999.9`；(b) 做成「期間技能不耗魔」。
⭐ 照第一守則應該做成一格後台下拉，預設 (a)（現況＝高層級贏的那一邊）。
