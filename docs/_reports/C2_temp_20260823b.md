## ① `echoloop:check` 是瞎的 —— 38 格只看得見 2 格

**根因**（票面說對了）：`measure()` 吃一個從 `docs/平衡錨點量測.md` **正則出來的 `baseHp` 常數**。
換掉 env 之後它一個位元都不會動 ⇒ 九格屬性換算係數在偵測器眼裡全部是「⚪ 不在這條路上」。
⭐ 這是第〇·四守則的形狀：**一個算得出來的值被烘成了常數**。

**修法**（`tools/balance-alert/echoLoop.ts`）：

1. `measure(env)` **每一次都重量母體** ——
   `median(balancePopulationDocs().map(d => championStatBase(d, MaxHealth, LV30, env)))`。
   ⭐ 走出貨的那一支（它自己會讀 `env.strToMaxHealth`），⛔ 一個公式都沒有重寫。
2. 血量端從 `envChain(MaxHealth, env)` 取（出貨的 `STAT_ENV_CHAIN`），⛔ 不是手寫 `env.maxHealth`。
3. 傷害端補上**出貨真的有**的第二層：AP 加成 —— 中位 AP（`championStatBase(…, AbilityPower, …)`
   × `envChain(AbilityPower)`）餵進出貨的 `apDamageMult()`。
   ⚠️ 那個 world 只填 `apDamageMult` 讀得到的兩格 ⇒ 跑的是**真的**函式，⛔ 不是重寫 `1 + ap × rate`。
4. `hpBonus` 改讀 `content/config/base-bonus.json`；env 先與 `COMBAT_ENV_DEFAULTS` 合併。

**量到的**（`npx tsx tools/balance-alert/echoLoop.ts`）：

| | 修之前 | 修之後 |
|---|---|---|
| 看得見的旋鈕 | **2**（`damageDealt` · `maxHealth`） | **5**（＋`abilityPower` · `strToMaxHealth` · `intToAbilityPower`） |
| 出貨「一發極大＝血條」 | 5.8% | **8.6%**（＝複驗用真 SimWorld 量到的數字） |

⭐ `strToMaxHealth` 現在是**傷害端與生命端一起動**的那一格 —— 正是回音迴圈的形狀，
而它動得到佔血條（扁平的 `base-bonus` 打破對稱），所以判定是「⭐ 真的旋鈕」。

### ⭐ 我挑的那一格：`proportionality.maxTiersAboveMin` = **1**

> owner 常設：「沒做完以前別問我了自己判斷 但是留後台開關可以簡易 rollback」

**後台欄位名**：`編輯器創作規則` → **「傷害級距最多高出最低要求幾格」**
（path `proportionality.maxTiersAboveMin`）。

| 候選 | 為什麼不是它 |
|---|---|
| **0** | ⛔ **結構性錯誤**：最低那一側用 `tierAtLeast`（無條件**進位**），所以一個**恰好照公式填**的節點本來就會落在原始要求之上最多一整級。帶寬 0 會把「完全正確」判成違規 |
| **2 以上** | ⛔ 今天**一格都指不到** ＝ 一個永遠不會紅的閘 ＝ 沒有閘 |
| ⭐ **1** | 帶寬兩格（最低、最低+1）。217 個節點裡 **215 個在界內**，點名 **2 個**。它是一道**天花板**，⛔ 不是一張要重填的清單 |

**一鍵 rollback**：把那一格填 **4**（＝ `MAX_TIERS_ABOVE_MIN_MAX`，整條梯子）⇒ 上限完全不構成限制。
⛔ 上界不是字面值：梯子加一格它自己跟著動。

**三個住處**（第一守則）：

1. `content/config/authoring-rules.json` → `proportionality.maxTiersAboveMin: 1`
2. `packages/shared/src/content/schema/config/authoringRules.ts` → Zod `.int().min().max()` ＋ `DEFAULT_AUTHORING_PRINCIPLES`
3. `apps/admin/src/configForms.ts` → 一格欄位（說明從表**推導**，⛔ 不抄字面值）

**⭐ 它真的會發生**（⛔ 不是一格「說了但不會發生」的欄位）：
`authoringRules.ts` 新增 `proportionalityCeilingRules()`，發出
`principle.proportionality-max.<形狀>.<冷卻級距>`，與下限**共用同一張**最低表
（`proportionalityBand()` 只推一次）。
⛔ 只發**真的構成限制**的那幾格（上限 = 最高格 ⇒ 不發）；
⛔ 豁免的形狀（`expectedHits = 0`，出貨「變身」）**整列不發**——它的回報軸不是傷害。
