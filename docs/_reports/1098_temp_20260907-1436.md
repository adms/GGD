## ④ 那當時那兩個錯是怎麼來的？—— ⚠️ 這一節是**假說**，⛔ 不是量到的事實

⭐ 依 CLAUDE.md「票裡凡是 owner 說的一律引言，其餘一律是我的推測」，這一段標成推測：

`ReferenceError: X **is not defined**` 與 `Cannot access X before initialization`（TDZ）
**不是同一個錯**。模組頂層的 `const` 就算真的被提前讀，JS 給的是**後者**。
⇒ 「is not defined」代表**那個識別字在被執行的那份程式碼裡根本沒有宣告**。

⚠️ 而票文量測的當下，那棵樹上有**八條 lane 同時在改檔**。
⭐ 最省事的解釋是：vitest 讀到的是 `victoryPodium.ts` 的**半寫入狀態**
（或 vite transform 快取裡一份跨越 GH#992 那次改動的中間態）——
GH#992 正是「把 `PODIUM_CLIP_OPTS` 從 `apps/admin` 搬回 schema」那一次，
也就是說**存在一個真實的中間狀態：使用端已經寫進去、宣告端還沒有**。

⚠️ 同理 `keyValidator._parse is not a function`：那是 `ZodObject` 的 `shape[key]` 是
`undefined`，一份半寫入／半轉譯的 schema 檔會直接產生它。

⭐ **這個假說有一個可以反駁它的預測**：在一棵**沒有人在寫**的樹上，它應該重現不了。
⇒ ③ 的 50 次全綠與它一致。⛔ 但一致不等於證明 —— 所以它留在假說欄。

### ⛔ 我**沒有**做的事（刻意）

- ⛔ 沒有改測試去容忍偶發（retry / `--no-file-parallelism`）。
- ⛔ **沒有為了「修一條環」而去動 `content/schema/**` 的 import** ——
  那裡今天沒有環，動它是拿一個真的改動去治一個假的前提。
- ⛔ 沒有動 `sim/` 那兩個 SCC：它們**是真的**，但它們**碰不到** `content/`
  （`content/` 的模組永遠在 SCC 之外被求值），所以它們解釋不了這兩個症狀。
  ⇒ 那是**另一張票**的事，⛔ 不是順手修（第零守則⑧）。

### ⭐ 我做的：把「`content/` 零執行期環」這個**今天成立的性質**變成一條會紅的閘

`packages/shared/src/content/runtimeImportCycles.test.ts`（118 行，其中斷言本體 ~40 行）

- 判準**從 import 圖推導**（TS compiler API → Tarjan/DFS），⛔ 不是 grep 字串。
- ⭐ **只算執行期的邊**：`import type` / `export type` / 全部 specifier 都帶 `type` 的
  具名 import 一律不算。⚠️ 這一格是這條閘的**全部價值** ——
  不做這件事的話它今天就是紅的（170 條假環），而一條天生紅的閘等於沒有閘。
- 紅的時候**逐檔印出整條環**。

**突變紀錄（實跑，兩個方向）**

| 突變 | 期望 | 實際 |
|---|---|---|
| **M1** `victoryPodium.ts` 加一行**值** import `import "./config/index";`（＝票文主張的那條環） | 紅 | ✅ **FAIL**，訊息逐字印出 `content/schema/config/index.ts -> content/schema/victoryPodium.ts -> content/schema/config/index.ts` |
| **M2** 同一行改成**型別** import `import type { ConfigDoc } from "./config";`（madge 會把它算成環） | 綠 | ✅ **PASS** |

⭐ M2 是刻意的：它證明這條閘**不會**被型別邊誤報 ——
⛔ 一條看到 madge 那 424 條就紅的閘，第一天就會被人加進豁免表然後永遠關著。

還原用 `python3 scripts/edit-or-die.py`（⛔ 不是 `git checkout`）；
`git diff -- packages/shared/src/content/schema/victoryPodium.ts` **為空**，逐位元組回到 HEAD。
