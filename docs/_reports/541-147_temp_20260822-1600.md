## ② `comboStrikes` —— ⛔ 第二個排程器一個都沒有

### 卡面已經承諾、引擎不存在的那一格

| 技能 | 卡面 | 今天的實作 |
|---|---|---|
| `godie-hart.r` 01-04 超究武神霸斬 | 「**連斬七次**，每一次斬擊皆造成極大傷害」 | `applyStatus×2 + invulnerable + dot×2` |
| `godie-e002.ex` 20-002 解放·約束勝利劍MAX | 「**連續七次斬擊**…**最後**施展約束與勝利之劍」 | `effects: []` —— **完全空的** |

`dot` 不是連段：沒有 N 次獨立命中判定（＝ N 次 on-hit 扇出 / N 次減傷結算 / N 次記分）、
沒有 N 次演出、沒有收尾那一發。這是第一·五守則的原型。

### ⭐ 設計決定：它**騎在既有的 `delayed` 排程器上**

`comboStrikes.apply` 把班表 `push` 進 **`SimWorld.delayed`**，付款的是**同一支** `delayedSystem`。

* 零個新的 `SimWorld` 欄位
* 零個新的 `step()` 掛載點
* 決鬥結束停手 / 施法者死亡停手 / 目標死亡跳過 / `incoming` 定基 —— 六件事一行都沒重寫，
  而且**結構上不可能與 `delayed` 分岔**（第零守則⑨）

那 `delayed` 為什麼不夠？三件它表達不了的事：

| | `delayed` | `comboStrikes` |
|---|---|---|
| 節奏 | 只有等間隔 `intervalSec` | ⭐ **不等間隔** `steps[]`（JASS 多半是這種） |
| 段數從哪來 | 作者手寫 `count` | ⭐ **家族表** `family` → `config.combo-strikes@1`（第〇·四守則） |
| 收尾 | `finalEffects` 只能與最後一段**同一個 tick** | ⭐ `finisherDelaySec` —— 「七刀之後停半拍，再劈最後一發」 |

第三項在引擎裡只花了 **`delayed.ts` 的一格 + 一行**：
`DelayedStrike.finisherOnly?: boolean`（省略 = false = 既有 wave 逐位元不變）
與 `delayedSystem` 的 `if (strike.finisherOnly !== true) runEffects(wave.effects, ctx);`。

### 第〇·四守則怎麼落地

```
content/config/combo-strikes.json   ← L1 lane 的檔（⛔ 我沒有碰）
  ↓ 載入期
sim/effects/comboFamilies.ts::resolveComboFamilies(def, table)
  ↓ 寫進節點的 steps / strikes / intervalSec / finisherDelaySec（⭐ 級別贏過手寫值）
sim/effects/comboStrikes.ts::apply   ← 只看解析後的班表
```

形狀刻意逐字比照 `content/displacementTiers.ts::resolveDisplacementTier`
（同一種「載入期遞迴重寫」長得一樣，下一個級距欄位就不會再發明第三種）。

⛔ **`family` 查不到時不是靜默退回一段**：`comboStrikes.apply` 擲一個**指名 family** 的錯誤。
前例是 `summon.killCredit: "owner"`。載入期那一層再多一道 Zod refine：
`family` / `steps` / `strikes` 三個都沒有 → **解析錯誤**，⛔ 不會等到比賽中。

## ③ `pull` —— ⛔ 它不是 `knockback` 的一個模式

| | `knockback`（`from:"pull"`） | `pull` |
|---|---|---|
| 作者填的是 | **一段長度**（推多遠） | **一個落點**（搬到哪） |
| 距離減法 | 走 GH#193 的 `afterGap`（離越遠移動越少） | ⛔ 不適用 —— 那對吸引是**反過來**的 |
| 目標從哪來 | 上游解好的 `ctx.targets` | 自己的圓（`shape:"circle"` → 同一支 `shapeTargets`） |
| 終點 | 算出來的（起點 + 方向 × 長度） | **指定的**（`caster` / `point` / `anchorRing`） |

用擊退去寫 A091「把 `250+100×等級` 半徑內的人吸到 `2×等級` 個錨點上」
（war3map.j:28224-28233）會得到「每個人往我這邊挪一小段」—— 卡面看起來對，場上完全不是那個技能。

**它不新增任何位移機制**：走的是 `knockback` 已經在用的 `nav.override` 地面滑行
（`authored: true`，讓 `combat/damage.ts` 第 8 格的仲裁不覆寫它）+ `world.knockdown` 行動鎖
（`lockOut` 從 `knockback.ts` **import**，⛔ 不是抄第二份）。
半空中的身體先 `cancelLeap` 再搬（與 `knockback` 逐字同一條，否則 `world.airborne` 那一格
會永遠留著 ＝ 失敗形態①）。

### ⭐ 錨點環：**沒有三角函式**

`sim/**` 禁 `Math.sin/cos`（`sim/purity.test.ts`）。N 個等分點用一張**單位旋轉常數表**
`RING_UNIT_ROTATION[N] = (cos 2π/N, sin 2π/N)`，然後複數乘法遞推：只有 `+ − ×`，
逐位元跨平台相同。表長 12（A091 最多 8 個錨點，`PULL_MAX_ANCHORS` 12 留了頭）。

⚠️ 那張表是**幾何常數**不是平衡數字，所以住在程式裡不違反第〇·四守則
（與 `GGD_APEX_PER_WC3` 同一個立場）。⭐ 「幾個錨點、環多大」是設計，在 JSON 上。

## ④ 守衛與突變

`packages/shared/src/sim/effects/comboAndPull.test.ts` —— **134 行**，
對上 **822 行**實作（0.16×，遠低於「測試行數 ≤ 實作行數」）。

兩條，都跑真的 `SimWorld.step()` 並讀最終世界狀態：

1. **連段**：N 段 + 收尾 = **N+1 次獨立結算，落在 N+1 個不同的 tick**；
   收尾在最後一段**之後**（`finisherDelaySec`）而且**只跑收尾**
   （夾具讓收尾比一般段**輕** ⇒ 「有沒有連本體也跑一次」變成一個**方向**問題，
   ⛔ 不必把任何數字寫進斷言）。
2. **吸引**：兩具身體都**抵達**錨點環（距離圓心 = 環半徑），而且去的是**不同**的錨點。

### 突變紀錄（一批一條，挑最承重的那一行）

```
sim/effects/comboStrikes.ts   atTick: world.tick + off   →   atTick: world.tick + off * 0
```
＝ 七段全部塞進同一個 tick，也就是這個 kind 存在**之前**唯一寫得出來的東西
（＝ 01-04 今天那份 `dot×2` 的形狀）。

→ 🔴 紅：`連段沒有分散在不同的 tick 上 —— 那在畫面上是「一下」不是連擊: expected 2 to be 4`

已用 `Edit` 改回來（⛔ 不是 `git checkout`）。
