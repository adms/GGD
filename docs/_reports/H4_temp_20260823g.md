# H4 —— vitest 按依賴方向裁包（2026-08-23）

> 北極星（owner 逐字）：「你的目標是**最多3分鐘(包含來回改錯)**就一定要 push note deploy」

## 做了什麼

七包 vitest 全跑 237s，而依賴方向是單向的（apps/* 依賴 packages/shared，反過來沒有）。
現在 `ship.mjs` 的並行段按 **git diff 的路徑集合**裁 vitest 包：

| 改動 | 跑哪幾包 | 怎麼決定 |
|---|---|---|
| 只動 `apps/client` | 只跑 `apps/client` | ⭐ 遞移依賴閉包：沒有包依賴 client ⇒ 其餘結構上不可能被弄壞 |
| 動 `packages/shared` | **6/7**（test-dashboard 除外） | 5 個 app 的 package.json 都依賴 `@ggd/shared`；test-dashboard 零內部依賴 ⇒ 推導地排除 |
| 動 `content/` | 全包 | fail-closed：每個 runtime 載入時吃它，package.json 看不見這條邊 |
| 動 `tools/<x>` | `src/ops` 的宿主（推導＝packages/shared）＋ `tools/<x>` 自己的測試（extras） | ops 守衛驗的正是 tools 腳本 |
| 對不到規則（docs/·scripts/·根設定…） | 全包 | fail-closed |

⭐ **依賴邊從 package.json 讀出來**（dependencies/devDependencies/peerDependencies 遞移閉包，
`tools/parallel-gates/packages.mjs::suitesForPaths`），零手寫表、零包名字面值
（連「ops 守衛住哪」都是掃 `src/ops` 目錄推導的）。
`--suites`（pipeline 算好的）仍然贏；沒路徑集合 ⇒ 全包（預設不打折）。
⛔ 只裁「跑不跑」——每包 vitest 指令、判準、離開碼逐字不動；fail-closed 四個入口全往全包倒。
