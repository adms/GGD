## 2. 🔴 **最重要的一個發現** —— 產生器的 `rng` 參數對 90 支**整個是死的**

`tools/skill-remake/common.py` 的 A-6 denylist（`SPEC_OWNED`）上有 `radiusTier`，
**卻沒有它的雙胞胎 `rangeTier`**。於是：

```
hero.py 的 A(..., rng, ...)  ──►  doc["range"] = rng
舊 JSON 的 rangeTier  ──(A-6 原樣救回)──►  doc["rangeTier"]
tierize()::_apply_geometry  ──(級別贏)──►  doc["range"] = 級距表[rangeTier]   ← rng 被覆蓋
```

2026-08-21 的五級距全轉替**全部 90 支**填上了 `rangeTier` ⇒ 從那一刻起，
**改 hero 檔的 `rng`，重生成出來的 JSON 一個位元都不會動**，⛔ 而且沒有任何東西會紅。

### 實測（突變驗證，⛔ 不寫檔，`build()` 是純函式）

```
① 出貨（rangeTier ∈ SPEC_OWNED）— hero 檔改成「中」： {'44-01': ('中', 6.0),   '79-02': ('中', 6.0)}
② 突變（rangeTier ∉ SPEC_OWNED）— 同樣改成「中」：   {'44-01': ('極大', 12.0), '79-02': ('小', 4.5)}
```

⇒ 修法：`rangeTier` 進 `SPEC_OWNED`。這一行就是這批的**承重線**。

### ⚠️ 它順帶掀出來的：44-01 的「極大」原本只活在 JSON 上

`tools/skill-remake/heroes/godie-emns.py` 的註解**逐字寫著**它在靠這個洞：

> 「出貨文件早就有 `rangeTier: "極大"`（⋯而 `rangeTier` 不在 SPEC_OWNED，
>  所以 A-6 的 denylist 每次重生成都把它救回來）⇒ ⛔ 不動 `rng=2`」

⇒ 洞補起來的那一刻 44-01 會**靜默回滾成極小/3**。已經把裁決搬進產生器：
`rng = TIER_RANGE["極大"]`（⛔ 不寫 `12`，那會是 `range-tiers.json` 的第四個住處）。

⭐ 為此在 `common.py` 加了 `TIER_RANGE`（**讀 `content/config/range-tiers.json`**，
與既有的 `TIER_R` 同一個做法），hero 檔用 `TIER_RANGE["小"]` / `["極大"]`。
