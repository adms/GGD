## ⭐ 第一段：`sim/` 那兩支是 **timeout**，⛔ 不是斷言失敗

CI 的 failed-tests 區塊把**共用同一則錯誤**的測試印在一起，然後印一次錯誤。
那一組是這樣的（逐字，去掉 ANSI）：

```
FAIL src/content/abilityAffordableAtUnlock.test.ts > …
FAIL src/content/abilityRadiusWithinZone.test.ts   > …
FAIL src/content/skillTierLadder.test.ts           > …
FAIL src/sim/economy/itemTiers.test.ts   > legendary is DRAFT-ONLY > 而且 0 元是…
FAIL src/sim/effects/abanTwoStrike.test.ts > … > ⭐ 印記還在 ⇒ 挨十倍…
FAIL src/sim/effects/abanTwoStrike.test.ts > … > ⭐⭐ 印記必須活得比 B 段的延遲久…
Error: Test timed out in 5000ms.
⎯⎯⎯[6/34]⎯
```

⇒ ⭐ **6 個 FAIL 共用一則 `Test timed out in 5000ms`**，我負責的 3 個（itemTiers ×1、
abanTwoStrike ×2）全在裡面。⛔ **一個斷言都沒有失敗** ⇒ 這不是靈魂層的真缺陷，
按 CLAUDE.md 的判準是「只是超時 ⇒ 放寬**時鐘**，⛔ 不是放寬斷言」。

**為什麼會超時**（量到的，⛔ 不是猜）：
`packages/shared/vitest.config.ts` 沒有 `testTimeout` ⇒ vitest 預設 **5,000ms**。
這兩支都在 `it` 內部跑整棵出貨內容樹的 `ContentLoader.load()`（1,900+ 份文件）：
CI 上 `itemTiers.test.ts` 整檔 **13,678ms**、`abanTwoStrike.test.ts` **10,080ms**。
本機（M 系列）同樣兩支合計 1.4 秒。⇒ 差的是**機器**，⛔ 不是內容。

⚠️ ⭐ abanTwoStrike 為什麼三條都補、而 CI 只紅兩條：`load()` 用 `ready` 旗標記憶化，
而它是**載完之後**才設 true ⇒ 第一條逾時被砍時 `ready` 仍是 false ⇒ 下一條重載一次、
再逾時一次。⇒ **哪幾條紅取決於執行順序**，只補紅過的那兩條，下一次換順序就換兩條紅。

## #6 的細節：⛔ 不是放寬成 `expect(true)`

```ts
if (out.includes("沒驗到")) {
  // ⭐ 反向閘：白名單明明在卻走到這條路 ⇒ 紅（否則這條閘等於被關掉）
  expect(existsSync(resolve(ROOT, "data/curation/whitelist.json"))).toBe(false);
  expect(out).toContain("data/curation/whitelist.json");   // 指名哪一個檔
  expect(out).toContain("GH#995");                          // 留下追下去的線索
} else {
  expect(out).toContain("up to date");                      // ⭐ 原斷言逐字保留
}
```

**驗過**（2026-09-05，把 `data/curation/whitelist.json` 暫時搬走約 0.4 秒再搬回，
`cmp` 確認逐位元組相同）——產生器實際印出的是：

```
⚠️ **沒驗到** —— `data/curation/whitelist.json` 不存在（全新 clone / CI）。
   這支產生器的輸出**取決於它**（OPEN 名單），所以在這台機器上「過期」與「沒過期」量起來一模一樣。
   ⇒ 刻意 exit 0，⛔ 而不是靜默跳過。要在 CI 真的驗它，見 GH#995。
```
⇒ 三條 `toContain` 全部對得上，exit 0。

## ⚠️ 留給 owner / 主 session 的兩件事（⛔ 不在這條 lane 的柵欄裡）

1. ⭐ **`w3xFilterModeContract` 的 8 條在 CI 上會是 `skip`，⛔ 不是綠。**
   `.github/workflows/ci.yml` 已經為了 `cwebp` 加過一步 apt 安裝，而那一步的註解
   逐字寫著「這一步存在是為了讓測試**跑得起來**，⛔ 不是為了讓它跳過」。
   ⇒ 同一個判準套在這裡就是 **CI 要 `pip install Pillow`**（一行）。
   這條 lane 禁止動 `.github/**`，所以只做到「大聲說沒驗到」。
2. `readmeListsFresh` 在 CI 上走的是「沒驗到」那條路 ⇒ ⭐ **README 的內容漂移在 CI 上
   仍然沒有人在驗**（產生器自己的註解也誠實寫了這個洞）。根治是 GH#995：
   「產生的文件不要烘進營運狀態」（第〇·四守則）。
