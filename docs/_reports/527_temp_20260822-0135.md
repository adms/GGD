## ② 做法：一個決策點，三支播放器來問

⛔ 沒有在三個呼叫點各寫一個 if（那是三份會各自腐爛的程式）。
新增 **`apps/client/src/audio/roundEndVoice.ts`** —— 這一拍「誰可以出聲」的唯一一份答案：

* `roundEndVoiceAllows(policy, source, ctx)` 純函式（`champion` / `machine` 兩種聲源）
* 模組層單例（形狀抄既有的 `voiceMixPolicy`）：`openRoundEndVoiceBeat()` / `closeRoundEndVoiceBeat()` / `grantRoundEndVoice()`
* **這一拍關著時 `grantRoundEndVoice` 永遠回 true** ⇒ 比賽結束的結算、選角確認的名言、點自己英雄、戰鬥中的每一句，逐位元不變

三個接點：

| 檔 | 接了什麼 |
|---|---|
| `audio/victoryTaunt.ts` `playRound` | `machine`。⚠️ 回傳 `null` 而不是「選了台詞但不出聲」——`onSpeak` 是**字幕**的驅動來源，讓它照跑等於畫面上留著一句沒有人講的嘲諷（第一·五守則） |
| `audio/nameVoice.ts` `playQuote` | `machine` |
| `audio/contextualVoice.ts` `playContextual`（`category === "victory"`） | `champion`。⚠️ 問得**很晚**（所有節流層之後、commit 之前）是刻意的：早問會出現「名額燒掉了但沒有人講話」＝一整拍安靜而畫面完全正常（失敗形態②） |
| `ui/AudioDirector.tsx` | 只發訊號：`phase === "resolution"` 開、`prev === "resolution"` 關。它本來就是全 app 唯一持有 phase 的音訊擁有者（同一個形狀已經用在 `setCombatSfxSeat`） |

**⚠️ 為什麼要「這一拍開著沒有」這個訊號**：`victoryTaunt.playRound` 只在回合結束用，
但 `playQuote` 與 `contextualVoice("victory")` **同時**服務比賽結束（`MatchEndPanel:533/536`）
與選角，從播放器裡分不出來。

**⚠️ 循環匯入**：`fallback` 模式要同步問「這位英雄有沒有自己的 victory 台詞」，
但 `roundEndVoice → contextualVoice → championVoice → nameVoice → roundEndVoice` 會成環
（ESM 底下的症狀是模組層常數變成 `undefined`，一個不會報錯的壞法）。
⇒ 用 `setRoundEndChampionLinePort()` 註冊，`contextualVoice.ts` 在載入時接上。

### 為什麼是「三選一」而不是一個 bool

⭐ **量到的覆蓋率：英雄語音包只有 51/113 位**（`MANIFEST.json` 的 `champions` 有 51 筆，
每一筆都有 `victory`）。所以 `off` 之下**另外 62 位英雄的回合結束是真的安靜**。
安靜好不好是**體感取捨不是事實**，只有 owner 在真機上聽過才知道 ⇒ 第一守則：做成一格下拉，
⛔ 不是我替他挑。

* `off` —— **出貨值**，owner 那句話的字面意思（第〇·六守則：優先權大的更新預設啟動）
* `fallback` —— 只有沒有語音包的英雄才退回機械語音
* `on` + `minGapSec: 0` —— **逐字的一鍵 rollback**

`minGapSec` 是「重複播放太吵了」那一半：兩種聲源**共用**同一個名額，而角色那一句在 t=0
被呼叫、嘲諷在 t=2200ms ⇒ 先搶到的永遠是角色本人。

⛔ `git add <檔>` 會把整份工作區（含他們的改動）進暫存區，`git commit <pathspec>` 更糟（它直接吃工作區、跳過索引）。
⇒ 改用：把 **HEAD 版本 + 只有我的兩處修改**算成一個 blob（`git hash-object -w`），
用 `git update-index --cacheinfo` 直接寫進索引，然後 **`git commit` 不帶 pathspec**（提交索引）。
`git diff --cached` 覆核過：那兩個檔的 staged 內容**只有我的改動**，工作區維持兩條 lane 的合併狀態。
