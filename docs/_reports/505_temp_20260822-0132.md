# K3 + K4 — `<select>`/`<range>` 改不了、捲動容器捲不動（#505 / #506，18 個缺口）

**lane 名下檔案**：`apps/client/src/ui/PadFocusNav.tsx` · `apps/client/src/input/padFocusNav.ts`
**新增**：`apps/client/src/ui/padFocusNavCapabilities.test.ts`（守衛）

---

## 一、做了什麼（四個機制，⛔ 不是逐點修）

稽核的 18 個缺口分群後只有四個根因，全部落在 `PadFocusNav` 的**同一個輪詢迴圈**上。
照第零守則⑨（N 個同型 = K 個模板），做的是機制不是逐檔案 if。

### ① `<select>` / `<input type=range>` 改得動（#505/K3，8 個缺口）

**根因**：`handle()` 的 `activate` 分支只有 `cur.click()`，而**合成 click 打不開原生下拉**
（瀏覽器只認 trusted 事件）；方向分支一律 `pickSpatial` 移焦點。⇒ 全遊戲每一格下拉
（離線競技場、房間地圖、Bot 難度、大廳場地）與每一支滑桿（音量、解析度縮放、靈敏度）
**焦點停得上去、焦點環會亮、就是改不了**。

**修法**（純邏輯在 `input/padFocusNav.ts`，DOM 派事件在 `ui/PadFocusNav.tsx`）：

| 新增 | 是什麼 |
|---|---|
| `padValueKind({tag,type})` | 純函式：這顆是不是「要就地編輯」的控制項 |
| `nextOptionIndex(cur,len,delta,wrap)` | 方向鍵**夾取**（摸得到清單兩端）；A **繞回**（最後一項按 A 不能是死的） |
| `nextRangeValue({value,min,max,step},delta)` | 步長讀**元素自己的 `step`**，⛔ 不在這裡發明數字，否則手把跟滑鼠會對同一支滑桿講不同的話 |

DOM 側：
- **左右 = 調值**（⛔ 不移焦點），**上下仍然移動** ⇒ 玩家不會被關在滑桿裡出不來。
- **A 對 `<select>` = 下一個選項（繞回）** —— 合成 click 打不開原生下拉，
  「循環」是 A 唯一能誠實做到的事（第一·五守則）。
- ⭐ **`setNativeValue()` 走 prototype setter**：受控的 React `<select>`/`<input>` 身上有
  `_valueTracker`，直接 `el.value = x` 會**同時**更新 DOM 與 tracker，React 一比對發現沒變、
  把事件丟掉 ⇒ 畫面上會「動一下又跳回去」。走 prototype setter 才繞得過 React 換上去的
  instance setter。`input` 與 `change` **兩個都派**（React 的 `<select>` 走 change、
  `range` 走 input）。

### ② 可捲動容器捲得動（#506/K4，10 個缺口）

**根因**：唯一的捲動來源是 `setFocus()` 裡的 `scrollIntoView` ⇒ **容器裡沒有可聚焦子元素就完全捲不到**
（champ-select 的 技能/數值/玩法/故事 四個分頁內文整片是純 `<div>`，六格技能說明必定超出一屏）。

**修法**：新增一個 **scroll 事件家族**，兩條進入路徑：

1. **右搖桿**（axes 2/3，`NAV_SCROLL_AXES`）→ `NavScroll` = `scroll-up|down|left|right`。
   右搖桿在焦點層本來沒有用途，⛔ 不會跟左搖桿的焦點移動打架。
   重複率 `NAV_SCROLL_REPEAT_MS = 32`、**無初始延遲**（握住要滑順，⛔ 不是一格一格跳）。
2. **方向鍵走到邊界時**（`pickSpatial` 回 -1）→ 不再死在邊緣，改捲同一個容器。

`scrollTargetFor()` 的取捨：**先找焦點元素最近的可捲動祖先**（玩家站在哪一格就捲哪一片），
找不到才退回**scope 裡面積最大的可捲動框** —— 因為分頁內文是分頁鈕的**兄弟**而不是祖先，
而且它裡面一顆可聚焦元素都沒有，焦點層根本看不見它。

`hasRoom()` 讓已經捲到底的框**不吃掉這一下**，nudge 會落到下一個候選。

### ③ 新 scope 自動落焦

**根因**：焦點只在第一次方向鍵時才出現 ⇒ 任何剛開的對話框/畫面，**第一次按 A 是啞的**。

**修法**：迴圈裡 `landedScope` —— 每個 scope **落焦一次**。
- 會**持續重試**直到真的落上（React 剛掛載的那一兩幀 scope 是空的）；
- 落上之後就停手 ⇒ 玩家改用滑鼠（trusted 事件會 `clearPadFocus`）**不會被下一幀拉回來**。

### ④ 停用的控制項：可聚焦但無效

**根因**：`FOCUSABLE_SELECTOR` 每一行都掛 `:not([disabled])`。
滑鼠玩家看得到灰掉的按鈕、讀得到它的價錢與理由；**手把玩家是用「走」的**，
被排除的控制項不是「停用」而是**不存在** ——
買不起的造型、沒有的英雄、還沒 armed 的 Ready 鈕**整列隱形**，
而且**後面的格子會無聲位移**（焦點跨過那個洞），玩家看到的格線與搖桿走的格線對不起來。

**修法**：`button` / `input` / `select` / `textarea` 一律收進來，
`activate` 分支**拒絕 click 停用的元素**（真瀏覽器本來也會吞掉），
`findBackControl` 也把停用的候選濾掉（B 按到一顆死鈕，看起來就是「B 沒反應」）。

## 二、守衛與突變

`apps/client/src/ui/padFocusNavCapabilities.test.ts`（jsdom，**掛的是出貨的 `<PadFocusNav/>` 本人**）

- 只換掉三樣：手把來源（`listPadSources`）、`appStore`、`hudStore`（後兩者只被讀 `screen`/`phase`）。
  ⛔ 不掃原始碼字串（失敗形態⑥）、⛔ 不直接呼叫被抽出來的 helper（形態⑤）。
- jsdom 沒有排版 ⇒ rect / `scrollHeight` / `clientHeight` / `scrollBy` 由測試餵。
- 一條測試把三件事串成**一次真的操作序列**：
  ① 掛載後第一幀就有 `data-pad-focused` → ② 右 → `selectedIndex` 0→1 **而且真的派出 `change`**
  （⇒ 下游收得到，⛔ 不是只有 DOM 動了）、焦點**還在原地**
  → ③ 下 → 焦點進到捲動容器 → 右搖桿下 → `scrollBy` 收到**正的 top**。
- 第二條：停用鈕**拿得到起始焦點**（舊選擇器下它整個不存在），但按 A **不會觸發 click**。

**突變（一次，挑最承重的線）**：把 `handle()` 方向分支的
`if (kind && (ev === "left" || ev === "right"))` 改成 `if (false && …)`
→ 紅：`expected +0 to be 1`（`padFocusNavCapabilities.test.ts:86`）。改回 → 綠。

## 三、⚠️ 兩件要讓主 session 知道的事

### (a) `NavAction` 加寬是**跨 lane 的**，而且是刻意的

`NavAction` 從 `NavDir | activate | back` 加寬成含 `NavScroll` 四個成員。
我一度把它拆成獨立的 `PadNavEvent` 想避免影響別人，**那是錯的**：
K7 lane 的 `ui/controlLegendModel.ts` 已經把 `NAV_LABEL` 宣告成
`Record<NavAction, string>` 並補上四列「捲動清單」，**而且它的註解明說**
「when the focus layer grew a scroll stick, this line is what stopped compiling」——
那正是第一·五守則的鏡像（做得到卻沒有說）。⇒ 已改回加寬，`pnpm typecheck` EXIT=0。

### (b) `ui/PadFocusNav.tsx` 這一個檔被**兩條 lane 同時改**

#508 lane 的 commit `9abccba6` **沒有帶 `PadFocusNav.tsx`**（他們的 commit message 自己寫了
「該檔不在我名下」），但它已經 commit 了 `ui/hud/padHudFocus.ts` 與
`controlLegendModel.ts` 的 `Record<NavAction,…>` ⇒ **那個 commit 之後的 HEAD 是紅的**
（`controlLegendModel.ts(531)` 缺四個 `scroll-*`，`padHudFocus` 沒有人 import）。

⇒ 我這一次 commit 的 `PadFocusNav.tsx` **同時帶著他們的 #508 接線與我的 K3/K4**，
這是唯一能讓 HEAD 回到綠的組合（⛔ 只 commit 我那一半會留下一個 import 不到的檔）。
`apps/client` 的 `tsc --noEmit` 在這個組合下 EXIT=0。

## 四、第一守則（三個住處）—— 為什麼這一批沒有新的 config 欄位

新增四個常數 `NAV_SCROLL_AXES` / `NAV_SCROLL_REPEAT_MS` / `NAV_SCROLL_PAGE_RATIO` /
`NAV_SCROLL_MIN_PX`，**刻意留在 `input/padFocusNav.ts` 而不是 `content/config/*.json`**：

它們與同一個模組裡**已經住在這裡**的 `NAV_REPEAT_MS` / `NAV_INITIAL_DELAY_MS` /
`STICK_NAV_THRESHOLD` 是同一種東西 —— 與幀率耦合的輸入手感，設計師讀不懂、
玩家看不到、⛔ 不會出現在任何一張卡片上。**把一個家族的四個數字拆到兩個住處，
本身就是第一·五守則講的 drift 起點。**
⇒ 判準保持一致：**玩家或 owner 會想調的數字才進 config**；
這四個要動的時候，動的是整個手感家族，那是一次程式改動不是一格後台。

⚠️ 若 owner 之後說「捲動太慢／太快」，正解是把**整個家族**（含既有三個）一起搬進
`content/config/`，⛔ 不是單獨替新的四個開一格。
