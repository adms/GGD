## 逐個嫌疑的答案

| 嫌疑 | 量到的 |
|---|---|
| `SimWorld.delayed` 回合邊界沒清 | **確實沒有任何一行在回合邊界清它** —— 但它自己排空：30 個回合的開打時刻**全部是 0**。`delayedSystem` 結尾的 compaction（付完的整串移除）就是承重的那一行 |
| 實體死了/despawn 了，班還在嗎 | 在（`spawnModelFx` 刻意 `stopOnCasterDeath:false`），但**到期就付完並移除**；而且 `settledZones` 那一格會在回合結算的當下把整串沖掉 |
| `spawnModelFx` 的 `onTouch` 取樣 | 出貨最重的一顆是 `godie-n01g.r`（`radial count:12` + `onTouch`，`touchRadius 2.5`）：**一次施法 = 24 條 wave / 300 發 strike**，60 tick 內排空。⭐ 極端壓力（100 次連續施法、每 tick 一發、場上 41 個實體）：峰值 552 條 wave、**ms/tick 平均 0.55、最大 3.25**、結束時佇列 0 |
| `comboStrikes` 每次 7+1 | 出貨只有 **1 個節點**（`godie-hart.r`）。峰值反映在上表的 `delayed` 峰值 6–8 |
| `persistentVfx` 每 tick 求值 | ⛔ **`packages/shared/src/sim/` 底下沒有這個東西** —— 它是 client 那一半的概念 |
| 事件佇列（modelFxSpawn/screenFlash/screenShake/floatingText） | ⛔ **不可能累積**：`SimWorld.step()` 的**第一行**就是 `this.events.length = 0`。單 tick 峰值 145（中場的回合開始那一發），戰鬥中 5–89 |
| `world.knockdown` / `nav.override` | 整場量到的 size 是 **0**（`knockdown` 從沒出現在容器 dump 裡）；`dashOnEnd` 的付款條件是「override 不見了」，實體被 destroy 時 `nav` 一起刪掉 ⇒ 下一 tick 就付完移除 |
| `invulnerable` / `flight` / `killTracking` / `mobKills` | 只增不減，但**上界是實體數**（2→7、1→3、11、9），⛔ 不是回合數的函式 |

## 落地的守衛

`apps/game-server/src/match/roundLoadNoGrowth.test.ts` —— 開一場真的十回合比賽，斷言：

1. 每一回合開打時，四條「排在未來 tick 的工作」佇列（`delayed` / `randomArea` /
   `chainLightning` / `dashOnEnd`）總和是 **0**
2. 每一回合開打時的實體數不比**這一場自己的第一回合**多（基準線是自己，⛔ 不是出貨值）
3. 非空性：這一場真的打滿多回合、真的排過班、真的生過怪

⛔ **一個出貨數字都沒有進斷言**，也⛔ 不斷言任何耗時（會因機器而異，並用錯誤的訊息紅）。
守的是「成長」這個**形狀**：`每回合越來越嚴重` 在資料上的樣子就是**有一池只進不出**。

**突變（真的跑過）**：`effects/delayed.ts::delayedSystem` 結尾整段 compaction 拿掉
（＝付完的班永遠留在佇列裡，逐字就是 owner 描述的症狀）
→ 紅：「第 2 回合開打時還帶著上一回合的排程: expected 8 to be 0」。

## ⚠️ 撤回過的一個「修法」（留著記錄，因為它是**閘不是判準**的又一次示範）

我一度加了 `SimWorld.clearScheduledWork()` 並在 `enterCombat` 呼叫它，理由是
「schema 上界 `10 + 32×10 = 330 秒` 遠比 resolution 那一段長，所以班**可能**跨回合」。
**突變驗證當場推翻了它**：把那一行拿掉，測試照樣全綠 ——
因為 `delayedSystem` 早就有 `settledZones.has(wave.zone)` 的沖洗，而回合結算時
**每一個 zone 都會進 `settledZones`**。⇒ 那四行是一個**不可證偽**的修法，已全部撤回
（`git diff` 對 `SimWorld.ts` 與 `MatchController.ts` 是空的）。

⭐ 留下的**真**觀察：那個沖洗是 **zone-scoped** 的。如果哪天出現一條「zone 不在這一回合
的活躍 zone 裡」的排程，它就不會被沖掉。今天出貨內容到不了那個狀態，所以⛔ 不值得一條守衛
——但值得記在這裡。

## ➡️ 給主 session

sim 這一半**不是** lag 的來源（1% 的 tick 預算，且不隨回合成長）。
剩下的候選全部在**這條 lane 的柵欄外**：客戶端渲染（每回合累積的粒子/模型/材質、
`persistentVfx`）、snapshot 編碼、Colyseus 的 patch 量。
另外 **GH#451（連鎖閃電 O(N²)）**是 sim 側唯一一個結構上會爆的形狀，但它與**回合數無關**
（同一回合內的範圍大小才是變數），本次量測沒有觸發到它。
