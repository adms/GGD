### ⛔ 量尺自證 —— 而**第一版的尺真的說了謊**

第一版量 `engine.getLoadedTexturesCache().length`。在真 WebGL 上是對的
（`thinEngine._releaseTexture` 會 `splice`），⛔ 但
**`NullEngine._releaseTexture(texture) { }` 是空的**（`nullEngine.js:560`）
⇒ 那份清單 headless 底下**永遠不會變短**，於是「生效」與「沒生效」量起來**一模一樣**（都是 3）。

⚠️ **而校準那一條當時是綠的** —— 因為校準只問「已知重複時量不量得到 3」，
⛔ 沒問「已知**不**重複時量不量得到 1」。⭐ **一把只驗過單邊的尺不算自證過。**
（今天量到的第四個量尺陷阱，已寫進 `textureDedup.test.ts` 檔頭。）

換成的尺：container 的貼圖真的指向**幾塊不同的 `InternalTexture`** ＋ Babylon 的**引用計數**
（歸零＝真引擎在那一刻呼叫 `_releaseTexture()` 刪 GPU 貼圖）。兩邊都驗：OFF→3、ON→1。

## ② 做了什麼

### A. `apps/client/src/render/textureDedup.ts`（新）＋ 接進 `AssetManager`

**⛔ 為什麼 Babylon 自己沒去重**（逐行讀 `@babylonjs` 7.54.3 的原始碼，⛔ 不是印象）：
Babylon **有** URL 去重 —— `BaseTexture._getFromCache()`（`baseTexture.js:499`）比對
`url` / `generateMipMaps` / `samplingMode` / `invertY` / `_useSRGBBuffer`，命中就
`incrementReferences()` 且**完全不上傳**。⚠️ 但 glTF 載入器餵的 URL 是每份 .glb 各自唯一的：

```js
// @babylonjs/loaders/glTF/2.0/glTFLoader.js:1948
const name = image.uri || `${this._fileName}#image${image.index}`;
const dataUrl = `data:${this._uniqueRootUrl}${name}`;
```

⇒ 逐位元組相同的圖**結構上命中不了** ⇒ 12 次上傳。

**做法**：載完之後用**我們自己算的圖片內容摘要**當鑰匙，把第 2…N 份的
`InternalTexture` 換成第 1 份的，走 Babylon 自己那條 `incrementReferences()` /
引用計數 `dispose()` 契約。

- ⭐ 共用的是 **`InternalTexture`，⛔ 不是 `Texture`**：每個 `Texture` 物件原封不動留在
  原本的材質上（`uScale` / `wrapU` / `hasAlpha` 各自獨立），⛔ 不必走遍每一種材質插槽改指標
  （漏一格 = 那張圖變黑，而且不會有東西紅）。
- ⭐ join key 是 `texture.url` 尾巴的 `#imageN` ⇒ 對回 glTF 的 image 索引 ⇒ 對回我的摘要。
  ⛔ 不是靠 `name`、⛔ 不是靠順序猜。認不出來就 `skipped++` 不去重（fail-open，但**有計數**）。
- ⚠️ 註冊表綁 **Scene**（`WeakMap<Scene,…>`），⛔ 不是 engine ——
  `IntermissionScene` 每回合建新 Scene，綁 engine 會讓第 2 回合指到已 dispose 的貼圖 ⇒ **整片變黑**。
- 鑰匙的四個旗標**逐字對到** `_getFromCache()` 比對的那幾格。

**🔁 rollback**：`localStorage["ggd.textureDedup"]="off"`（重整生效）或 console
`__ggdTextureDedup(false)`。出貨預設 **on**。
⚠️ 後台三住處（`content/config` + Zod + admin）**在柵欄外** ⇒ 要另一條 lane 補。

**守衛** `textureDedup.test.ts`（`@visual-proof`，4 條）：真 `AssetManager` × 真 glTF 外掛 ×
真 engine × 真出貨 .glb 位元組，⛔ 零夾具。含 CALIBRATION、引用計數、跨 Scene、
以及「什麼都沒變不見」（每張貼圖 ready 且尺寸非零 · 每個 mesh `isEnabled` · 材質 `alpha` 沒動）。

**突變**：拿掉承重那一行（`_texture = theirs`）⇒ **4 條裡 3 條紅**，
CALIBRATION 維持綠（正確 —— 它量的是尺，⛔ 不是功能）。

### B. 棘輪不再是一行 JSON 就收債（#382 驗收條件 4）

`--update-baseline` 以前寫 `accepted: current` **整包**，每一筆是一個**裸字串**，
20 筆共用一句 `note`，⛔ **沒有一個字說明哪一筆為什麼可以忍**。
⇒ 接受一個缺陷永遠的代價 = 一個指令 + 一行 JSON，而事後**沒有任何東西**分得出
「審過而且真的沒問題」與「盲目重生成」。

⭐ 現在理由是**資料，⛔ 不是散文**：
- `baseline.json` 多一格 `reasons{}`；`accepted` 陣列**形狀完全不動**（既有讀者全部照舊）。
- `--check` 對**沒有理由**的 accepted 列 **exit 1 並逐筆指名** ⇒ 重生成 baseline **買不到安靜**。
- `--update-baseline` **保留**人已經寫過的理由，新列蓋哨兵 `⛔ 未填理由`，然後 **exit 1** 叫你寫。
- 20 筆理由**全部填上**，每一筆帶**量到的數字**（省多少 MB、之後是多少、是不是真債）。

**突變**：刪掉 `scene:combat-skeleton/vramBytes` 的理由 ⇒ `--check` **exit 1** 並指名它。
**回歸**：`--check` 綠（`✓ no new budget regressions (20 breaches, all accepted AND reasoned)`），
且產出的 report 與 checked-in 的**逐場景 vram 完全相同** ⇒ ⭐ 我一個算術都沒動。

### C. 修掉一句**會變成謊話**的註解（第三守則）

`emit_report.ts` 原本寫「Texture does not dedupe across DISTINCT models …
byte-identical atlases in two .glb are two GPU uploads」——
那是**對今天行為的正確描述**，但它被寫成**物理定律**，然後被棘輪當成預算真理收下。
現在那一段明說：這是**一個已修的客戶端缺陷**，底下的算術**還沒跟上**，
所以它印的每一個 `vramBytes` 都是**高估**。

## ③ 最重要的一個發現

⭐ **棘輪把一個「可修的客戶端缺陷」記成了「預算現實」，而票上的解法瞄準了錯的欄位。**

三層都要看才看得出來：
1. 客戶端有一個結構性缺陷（glTF 載入器的 URL 讓 Babylon 的去重**永遠命中不了**）
2. 預算工具**把那個缺陷寫進了成本模型**，而且用一句聽起來像物理定律的註解守著它
3. 棘輪**把工具的高估收成「已接受」**，一筆一行、沒有理由，一路長到 20 筆

⇒ ⭐ 判準：**一筆「已接受的越界」如果寫不出一個能被反駁的理由，它多半不是債 ——
它是某個地方量錯了。** 這一次寫理由的動作本身，就把 11 筆從「債」翻成了「量錯」。
