# GH#508 K5 — 戰鬥相位整層停用焦點：兩段式 HUD 焦點模式

## 一句話
戰鬥中 `focusNavActive` 對 `combat`/`resolution` 回 `false` 是**刻意的**（方向鍵要瞄準、A 要施法），
所以 ⛔ 沒有把 `combat` 從 `COMBAT_LIVE_PHASES` 拿掉。改成**兩段式**：
預設仍然直接操控英雄，一顆明確的鍵（出貨 = Back/View，索引 8）切進 **HUD 焦點模式**，
焦點層接手 → #508 列的六個控制項全部聚焦得到；再按一次或按 B 退回操控英雄。

## 機制（⛔ 不是逐點修）
| 層 | 檔 | 是什麼 |
|---|---|---|
| 純規則 | `apps/client/src/ui/hud/padHudFocus.ts` | 閘 `padHudFocusActive`（= `focusNavActive(...) \|\| hudFocusMode`，⛔ 不是第二份相位判斷）· 狀態機 `nextHudFocusMode` · 欄位表 + 驗證器 + runtime 接縫 + 給 HUD 訂閱的小 store |
| 接線 | `apps/client/src/ui/PadFocusNav.tsx` | 讀那顆鍵的 edge、發佈模式、B 退出時**吃掉那一下**（否則同一幀的 `back` 事件會對 `document.body` 跑 `findBackControl`）；START→暫停選單的橋改看 `menuOwns`，所以在模式裡 START 仍然開得了暫停選單 |
| 視覺狀態 | `apps/client/src/ui/hud/PadHudFocusBanner.tsx` + `HudRoot.tsx` | 整個畫面一圈邊框 + 一條「🎮 介面操作模式」橫幅。⚠️ 看不出來的模式＝失敗形態① |
| 第六個控制項 | `apps/client/src/ui/hud/StatsHoverPanel.tsx` | 屬性面板是六個裡**唯一一顆可聚焦元素都沒有**的（整片 `pointerEvents:none`）⇒ 新欄位 `padTrigger`（`focus`/`off`，預設 `focus`）在模式下長出一顆可聚焦的「屬性」開關 |

其餘五個（陣亡投幣 · 前往觀戰 · 記分板 · 設定/音效 · 操作說明的 ✕）本來就是真的 `<button>` ——
閘一翻過來就聚焦得到，⛔ 一個檔都不用改。這就是「一個機制解鎖六個缺口」。

## 第一守則：新參數的三個住處

+ `SHIPPED_PAD_HUD_FOCUS` + `resolvePadHudFocusTuning`（**每格都有上界**，而且**回報**夾了什麼）
+ `applyPadHudFocusOverride` 接縫（形狀同 `applyGoreDoc`）。

⛔ **`content/config/pad-hud-focus.json` 與 Zod / admin 那兩個住處沒有在這條 lane 落地**，理由與
同目錄 `StatsHoverPanel` 的 `SHIPPED_HUD_STATS` 逐字相同：這條 lane 不擁有 `schema/config.ts`，
而一份 tag 不在 `zConfigDoc` union 裡的 config 文件會讓 `ContentLoader` 拒絕**整包內容** →
`main.tsx` fail-open 退回 2 隻骨架 → 網站看起來完全正常而沒有人能玩（2026-08-02 事故）。
而且這條 lane ⛔ 被禁止跑 `pnpm content:build`（全域鎖）。
⇒ **交接三個落點**（模組檔頭逐字列著）：`config.pad-hud-focus@1` + `DEFAULT_PAD_HUD_FOCUS`、
`content/config/pad-hud-focus.json` + build + **來源檔與產物一起 commit**、admin 五件套 +
`ContentDb.load()` 一行 `applyPadHudFocusOverride(...)`。
`StatsHoverPanel` 的新 `padTrigger` 併進**同一份**既有的 `config.hud-stats@1` 交接。
