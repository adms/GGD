## 1. ⭐ 本輪的關鍵發現：量到的，⛔ 不是讀程式推論的

`mapBgm` 是 **今天**（`9931441e`，#531 落地）才進 Zod union 的欄位，
而 `zConfigAudioMapDoc` 是 **`.strict()`**。

`content/` 是 **live bind-mount**（跟著 `git pull` 走），映像是 **build 時**烘的。
⇒ 一個 **#531 之前建的映像**，它的 Zod union 裡沒有 `mapBgm` 這個 key，
而 `.strict()` 對未知 key 是**拒絕**，不是忽略。

### 實測（⛔ 沒有碰正式站，本機重建 pre-#531 的 schema 形狀跑一次）

`git show 9931441e^:…/config.ts` 的 `zConfigAudioMapDoc` 逐字是
`{ id, schema, bgm, sfx }` + `.strict()`。拿它驗今天出貨的 `content/config/audio-map.json`：

```
OLD (deployed) schema accepts today's audio-map.json?  false
  first error: {"code":"unrecognized_keys","keys":["mapBgm"],
                "path":[],"message":"Unrecognized key(s) in object: 'mapBgm'"}
```

⚠️ **這正是 2026-08-02 生產故障的形狀**（CLAUDE.md 已經記著）：
四個欄位不在已部署映像的 Zod union 裡 → 內容載入**整份**失敗 →
fail-open 退回骨架 → 「選不到英雄 / 體素替身 / 商店空的」。
⭐ 而 fail-open 的代價就是**壞掉跟正常長得一模一樣** —— owner 只會注意到最明顯的那一項，
也就是他說的那句「地圖新音樂還沒接上」。
