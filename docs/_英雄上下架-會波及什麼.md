# 上下架一位英雄，會波及什麼

> ⛔ **這份文件不是清單，是索引。** 真正會擋下你的是
> [`tools/roster-guard/check.ts`](../tools/roster-guard/check.ts)，
> 它跟著 `pnpm content:build` 跑，失敗回非零。
>
> 這份存在的理由是 CLAUDE.md 的元規則：**判準沒用，只有閘有用**。
> 所以先講怎麼跑那個閘，再解釋它在守什麼。

---

## 怎麼做

```bash
pnpm roster:check
```

改完名單跑它。或者什麼都不用記 —— 你**本來就要**跑：

```bash
pnpm content:build
```

（改 `content/` 一定要跑，否則 `shippedBundleIsCurrent` 會紅。名單檢查掛在它的最後一步。）

---

## 上架 / 下架的**唯一真相**在哪

| 動作 | 改哪裡 |
|---|---|
| **下架** | `content/config/roster.json` 的 `retiredChampions` 加一個 id |
| **重新上架** | 從那一格**拿掉**就好 —— ⛔ 不用改程式、不用重新部署 |
| **開放新英雄** | `apps/platform/internal/curation/starter.go` 的 `starterChampions` 加 id |

⭐ `retiredChampions` 是**內容事實**不是營運開關：它擋在白名單之外，所以平台連不上
（客戶端 NO_FILTER / 伺服器 bypass）時照樣擋得住，而一次手滑的後台勾選也放不回來。

---

## 檢查器驗的六個**關係**

⚠️ 每一條都是**兩份東西之間**的關係，⛔ 沒有一條在驗單一名詞 ——
那是 2026-08-02 的教訓（四項後置條件全綠而網站不能玩，因為每項都只驗一個名詞）。

| # | 關係 | 破掉會怎樣 |
|---|---|---|
| ① | 下架名單 ↔ 種子清單 | 白名單閘把它丟掉 ⇒「種子說 53、實際開 49」而**沒有東西會叫** |
| ② | 種子清單 ↔ 內容樹 | 新裝拿到一個指向不存在英雄的名單 |
| ③ | `starter.go` ↔ `starter_content_test.go` | 兩份 Go 清單分開看都對，只有比對看得出來 |
| ④ | 經濟拆分 ↔ 名單長度 | 免費+付費 ≠ 名單長度。⚠️ **免費那格動了要問 owner**（那是經濟形狀，不是跟著名單走） |
| ⑤ | 測試裡的字面值 ↔ 名單長度 | **元守衛** —— 擋「又有人把長度抄進第 N 個地方」 |
| ⑥ | 說明文件 ↔ 名單長度 | 文件說謊，而下一輪接手的人會照著它做（第三守則） |

---

## ⭐ 為什麼要有 ⑤ 這條「元守衛」

2026-08-16 下架四位，**十條測試同時紅**。而每一條的訊息都在講自己的功能壞了：

> 「語音覆蓋率不對」「VFX 綁定少了」「可施放格數退步了」「替身普查對不上」

**沒有一條說出真相：名單變短了，十條全都是對的。**
追那十條紅花掉的時間遠超過改名單本身。

根因是**一個數字有十個住處**。修法不是把十個都改對（那只是把下一次的痛延後），
是把它收成一個：

```ts
// packages/shared/testkit/starterRoster.ts
starterRosterSize(repoRoot)   // 從 starter.go 推導
```

⑤ 就是那個「不准再抄第十一份」的閘。

## 名單變了但檢查器**不會**叫的東西（要人看）

這些是**量出來的普查數字**，只能重新量，⛔ 機器決定不了對錯：

| 檔 | 是什麼 |
|---|---|
| `apps/client/src/render/views/standinCensus.test.ts` | 幾種身體 / 幾位共用 / 幾組 / 幾位沒記 usca |
| `packages/shared/src/sim/castabilitySweep.test.ts` | 可施放覆蓋率（⭐ 已改成**比例**，名單長度不再影響它） |
| `apps/game-server/src/match/settlement.test.ts` | 情境重現的 seed（bot 選角變了就要重掃） |

⚠️ 遇到它們紅的時候，先問「**是分母變了還是機制壞了**」。
2026-08-16 那次全部是分母 —— 覆蓋率 53人 98.11% vs 49人 97.96%，其實沒退步。

---

## ⚠️ 一個容易讀錯的訊號

替身普查有一條盯著「地圖比例沒走到替身身體上的還剩幾位」。2026-08-16 它變成**零位** ——
**因為那唯一一位（賈修貝爾）被下架了，不是因為那個缺陷被修好。**

⛔ 不要把這種零讀成「債還完了」。那條測試的註解把整段理由寫下來了，
而且他重新上架的那一天它會自己紅並指名道姓。
