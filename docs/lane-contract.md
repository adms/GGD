# 平行 lane 契約（Lane Contract）

> ⭐ 這一份是**規則**，⛔ 不是說明書。它的每一條都是 2026-08-29／30 **真的踩過**才寫下的。

owner 2026-08-30（逐字，⭐ 這一份因它而存在）：

> 「你的工作流程常常會**重複做已經做好的**，甚至**後來做的更糟還覆蓋掉**」

---

## ⭐ 第零條：**開工第一件事讀票裡的進度標記**

owner 2026-08-30（逐字）：

> 「應該是要檢討你做之前有沒有**檢查做完** 或是 **做到什麼程度繼續下去**之類
>  **每次都要有標記在票裡**」

```bash
bash scripts/ticket-progress.sh read <票號>      # ⭐ 開工第一件事
```

| 讀到 | 你要做什麼 |
|---|---|
| `🆕 沒有進度標記` | 這張沒人動過 ⇒ 從**量基線**開始 |
| `狀態: 完成` | ⛔ **停** —— 它做完了。去問「那為什麼票還開著」 |
| `狀態: 鏈路已接上未驗收` | ⭐ ⛔ **不要重做** —— 讀「下一個人從哪裡接」 |
| `狀態: 卡住` | ⭐ 先解那個 blocker，⛔ 不要重跑一次同樣的路 |
| `狀態: 進行中` | ⚠️ 有別人正在做 ⇒ 確認柵欄不衝突 |

```bash
bash scripts/ticket-progress.sh write <票號> --state <狀態> \
  --baseline "<動手前它今天的行為>" --did "<這一輪做了什麼>" \
  --next "<下一個人從哪裡接>" --commit <sha>          # ⭐ 收工最後一件事
```

⚠️ ⭐ `--baseline` 與 `--next` **必填**：
`--next` 留空 ＝ **下一輪從零開始**（甚至重做一次）—— 那正是 owner 點名的那個病。

⚠️ ⭐ **狀態是封閉詞彙**（`未動 · 進行中 · 卡住 · 鏈路已接上未驗收 · 完成`）——
打錯字會讓它靜默分裂成兩種狀態，⛔ 而一份會靜默分裂的紀錄**比沒有更糟**。

⇒ 閘：`bash scripts/ticket-progress.sh check <票號…>` ——
**有人做過卻沒有標記** ⇒ 非零並指名。

## ⭐ 第一條：**先量基線，⛔ 再動任何東西**

⚠️ 這條是踩出來的。同一天四個實例：

| # | 已經是對的 | ⛔ 後來做的 |
|---|---|---|
| **#836** | 12:15 對齊完成 | 12:48 被產物重生成**整格覆蓋** ⇒ 後來又做一次 |
| **#663** | main 原本**擋得住** `<<<` | lane 修三個洞，⛔ **開了第四個** ⇒ 比原狀差 |
| **#877** | 三格誠實的 `—` | 換成**三句假話**（型別欄與說明欄自己打架） |
| **#822** | vfxKey 兩邊一致 | 開了一格**能寫壞它**的編輯格 |

⇒ ⭐ **動手之前先回答**：

```
基線：<這件事今天的行為是什麼 —— 用跑的、用量的，⛔ 不是讀票文>
```

⛔ 「票文說 X」不算基線 —— ⭐ **票文是過期的**（這個 repo 已經證明過非常多次：
「票文主張的現況今天在哪一個環境下還成立？」）。

## ⭐ 第二條：交付要有 **before → after**

⛔ 只說「我做了 X」不算數。⭐ 要能看出**方向**：

```
before: <量到的數字／行為>
after:  <量到的數字／行為>
```

⚠️ ⭐ **這一條是用來抓「做得更糟」的** —— 沒有 before，「更糟」看起來跟「做完了」一模一樣。
（#877 的 lane 把沉默 217→0 回報成勝利，⛔ 而那 0 裡有三句假話。）

## ⭐ 第三條：**你有沒有弄紅／弄瞎一條你沒跑過的閘？**

⚠️ 第三、四、五批**各發生一次**。⇒ 收工前**必跑**：
- 你改到的那個區域的既有測試
- 碰畫面層 ⇒ `bash scripts/visual-proof.sh`
- 改到產生器來源 ⇒ 它的 `*:check`，**以及同一份來源的其他消費端**
  （⭐ `claims.json` 有兩個消費端，lane 只重生成了一個）

## ⭐ 第六條：**複驗通過的 DONE，當場關票**

⚠️ 量到過 **4 張**複驗通過卻還開著（#627 #815 #827 #835）。
⭐ 根因：關票在流程**最尾端**，前面任何一件事都會把它擠掉 ——
⛔ 而「沒關」時**沒有任何東西會紅**。

⇒ 閘：`bash scripts/lane-close.sh <workflow-output.json>` ——
一個指令讀 workflow 的結果，逐張註解＋關閉，⛔ 不是每輪手寫一段腳本。
`--check` 列出「複驗通過但仍開著」的票並回非零。

## ⭐ 第七條：**schema 驗證跑在註冊之前** —— 寫內容時 tier 不能取代字面值

⚠️ 2026-08-30 踩到（#648）：一條 lane 寫了 `delayed{shape:"circle", radiusTier:"中"}`
⇒ ⭐ **那支技能連載入都載入不了**，還弄紅 14 個測試檔。

原因：`_shared.ts:286` 的 schema 逐字要求
`shape:"circle"` **一定要有字面 `radius`**（訊息：「沒有半徑的圓在執行期會直接
return，技能放得出來但什麼都不會發生」），⛔ 而 `resolveRadiusTier` 跑在
**schema 驗證之後**（`registries.ts` 的 `withTiers`）。

⇒ ⭐ **兩者不矛盾**：tier 是**載入時**解析的（第〇·四守則），
⛔ 但 schema 是**更早**的一道 —— 它要的是那一格今天就存在。
⇒ 寫內容時**兩個都要有**，或去看那個 effect 的 schema 到底要哪一個。

⚠️ ⭐ 判準：**動內容之前跑一次 `validateDoc`**（或那個集合的載入測試）——
⛔ 「schema 應該收得下」是判準，而它今天錯了。

## ⭐ 第八條：**你的轉換有沒有帶走一個玩家看得到的東西？**

⚠️ 2026-08-30 踩到（#401，⭐ **而且它已經通過了一次複驗**）：
把兩支技能從投射物翻成 `damageLine` ⇒ ⭐ **施法指示器畫不出來了**
（`skillshot` 的走廊靠 `projectile.maxRange` 推導）。

⭐ 那條測試的檔頭逐字寫著它為什麼存在：
> **a player cannot dodge what is not drawn**

⇒ ⭐ **轉換正確 ≠ 沒有損失**。判準：
「我拿掉的那個東西，**有沒有別人在讀它**？」（`grep` 那個欄位名）

## ⭐⭐ 第九條：**lane 的 commit 要真的進 main** —— ⛔ 「worktree 裡 commit 了」不算

owner 2026-08-30（逐字，⭐ 這一條找到了他那句話的**機制**）：

> 「你的工作流程常常會**重複做已經做好的**，甚至**後來做的更糟還覆蓋掉**」

### ⛔⛔ 量到的：**85 個 commit 擱在 69 條分支上**

`Workflow` 的 `isolation: "worktree"` 給每條 lane 一個自己的 git worktree
＋ 一條 `worktree-wf_*` 分支。lane 在裡面 commit ——
⛔ **而沒有任何一步把那條分支合回 main。**

⇒ ⭐ 這就是那個病的**機制**，⛔ 不是比喻：

| 步 | 發生什麼 | 看起來 |
|---:|---|---|
| ① | lane 做完 → commit 進 **worktree 分支** | ✅ 對的 |
| ② | 我讀 lane 的回報 → 關票／寫進戰情版 | ✅ 回報是誠實的 |
| ③ | 下一輪讀 **main** → 那個檔還是原樣 | ⛔ ⭐ **再做一次** |

⚠️ ⭐ **每一步看起來都是對的** —— lane 真的做了、回報真的誠實、main 真的沒有。
⛔ 而三者之間沒有任何東西在比對。

### ⭐ 判準：收 lane 的成果時，問「**main 有它了嗎**」

```bash
npx vitest run packages/shared/src/ops/noStrandedLaneCommits.test.ts
```

它問的是**兩個名詞的關係**：「每一條**新鮮的** lane 分支上的每一個 commit，
main 的 log 裡有沒有同樣標題的一個？」
（⭐ 比對**標題**，⛔ 不是 sha —— `cherry-pick` 會產生新的 sha。）

| 動作 | 指令 |
|---|---|
| **收回來** | `git cherry-pick -x <sha>` |
| **真的不要了** | `git branch -D <分支>` ⇒ ⭐ **那才叫「決定丟掉」**，⛔ 不是忘記 |

### ⛔⛔ 衝突落在**追加式帳本**上時，⛔ 不可以用 `--ours` / `--theirs`

⚠️ 2026-08-30 我就是這樣**吃掉自己的 5 列**（含另一條 lane 寫的 2 列）：
`--ours` 吃掉對方的列 · `--theirs` 吃掉我的列 —— ⭐ **兩個都是錯的**。

⇒ ⭐ 正解是取**兩邊新列的聯集**。
⚠️ 而它**不會有任何東西紅** —— 統計區會跟著變小，看起來完全自洽。
⭐ 抓到它的是 `rule-slip.sh --check` 的**計數**（123 → 119），⛔ 不是眼睛。
