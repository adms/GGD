# TTK tuning — maxHealth combat-env multiplier for round length (task #153) — TODO

Find the `combat-env.json` `multipliers.maxHealth` factor that makes a combat
round last **≥ 120 s minimum and ~ 180 s average**. At the shipped ×4 the fastest
duels resolve in ~35 s (rounds "feel too short"); TTK scales ~linearly with the
HP pool for fixed damage, so raising the factor lengthens rounds proportionally.

**Harness** (`tools/ttk-sim`). A headless time-to-kill sweep that drives the REAL
match combat — instantiates the actual `MatchController` + `AIDriver` (Tier-0
brain) and steps the authoritative `SimWorld` tick-by-tick through a live combat
round, reading round-end exactly as the server does (`teamAliveCount` hits 0 in
`checkCombatEnd`). Nothing in `packages/shared` or `apps/game-server` is modified;
only host config (`world.combatEnv`, arena rules, phase timings) is set before
tick 0. Sweeps `maxHealth ∈ {4,6,8,10,12,16,20}`, ~40 duels/value in two modes
(natural = fire ring off; production = fire ring on), and interpolates the
multiplier that meets both targets. Run: `npx tsx src/sweep.ts`.

**Finding.** Natural elimination TTK ≈ `13.8 × maxHealth − 4` s (mean),
`9.4 × maxHealth − 2` s (fastest). Both targets are met at **maxHealth ≈ 13.3**
(min 120 s at ×13.0, mean 180 s at ×13.3). The binding constraint is the MINIMUM
(fastest kill): the fire ring only ever SHORTENS a round, so it cannot fix a
too-short one — only more HP can. Full table + reasoning:
`data/reports/ttk-experiment-153.md` (regenerated by the sweep; GH#56 moved it out of version control). The value is applied to
`content/config/combat-env.json` by the coordinator (report-only from here).
