# Task #150 — champion render-SIZE audit + height-normalization

_Generated by `tools/w3x-import/gen_model_size_audit_150.py` from the headless `model_size_audit_150.mjs` sweep (Babylon NullEngine — the client's exact glb load path: `instantiateModelsToScene` + the same `getHierarchyBoundingVectors` measure `ChampionView` grounds by). Regenerate: `tsx model_size_audit_150.mjs && python3 gen_model_size_audit_150.py`._

## Problem

`ChampionView.tryUpgradeToGlb` used to set `glbRoot.scaling.setAll(doc.scale)` and ground the feet, but did NO height-normalization — so the rendered size was `doc.scale × the glb's native mesh height`, which varies wildly per champion. The #61 audit only checked the 2.5u ceiling, never RELATIVE consistency between champions.

Measured across the roster, the on-screen full-silhouette height (what the player sees, what grounding uses) spanned **1.70u..2.32u** (**1.36× spread**, median 1.71u). The four shared CC0 stand-in meshes are the oversized group — **champ.sela renders 2.32u** (小叮噹/godie-n00b and 17 others, the user's '小叮噹 too big') — while imported heroes such as **imported.heroshana render 1.70u** (夏娜/godie-e008), reading small next to them.

## Fix

`ChampionView` now HEIGHT-NORMALIZES every loaded glb: it measures the native full-silhouette height and scales the model so it stands ≈ **TARGET_HEIGHT = 1.8u** tall, REPLACING the raw-`doc.scale`-as-absolute. A per-champion **`relativeScale`** multiplier (default 1.0; `content/models/_standin-overrides.json`, keyed by championId, threaded through `EntityViewRegistry.modelOverrideFor` → `ChampionView.tryUpgradeToGlb`) then intentionally shrinks lore-small creatures / enlarges giants. #77's grounding + declared-scale reporting are preserved; `doc.scale` is kept only as a fallback for a degenerate (unmeasurable) glb.
