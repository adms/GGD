## 一、三個住處，判準是「**誰會讀它、怎麼讀**」

⛔ 分界**不是副檔名**，⛔ 也不是目錄。

| 住處 | 放什麼 | 判準 | 形狀 |
|---|---|---|---|
| **git** | 解析／轉換**程式** · 英雄與技能**設定 JSON** · 版本清單 · SHA-256 · 文件 | ⭐ **有人會讀它的 diff** | 一般檔案 |
| **S3 `assets/`** | ⭐ **要對外服務**的成品：icon · 3d model · voice · music | ⭐ **網站要能拿單獨一顆** | **逐檔可定址** `assets/<sha[:2]>/<sha><ext>` |
| **S3 `legacy/`** | 半成品 · 原始素材 · 大型解析傾印 | 只靠雜湊驗、⛔ 讀不了 diff；⛔ **不對外開放下載** | tarball 封存（分段可以） |

⭐ **一句話判準**：**一個位元組如果只能靠雜湊驗、不能靠 diff 讀，它就不屬於 git。**
⭐ **第二句**：**一個位元組如果網站要單獨拿它，它就不能只住在 tarball 裡。**

## ⛔⛔ 二、`s3_existing` 這個字騙過人 —— 它**不代表** S3 上有那個物件

2026-09-09 量到（Codex 交接 `outputs/` 時）：`coverage.jsonl` 把 **279,523 檔**標成 `s3_existing`。
⭐ 而逐筆讀 `location` 之後，它的意思是：

```json
{"coverage": "s3_existing",
 "location": {"kind": "s3_archive_member",
              "manifest_uri": "s3://…/legacy/…/manifest.json", "member": "…"}}
```

⇒ ⭐ **「這個檔的 sha256 被列在某個 tarball 的 manifest 裡」**，⛔ 不是「S3 上有這個物件」。

| 用途 | tarball 夠不夠 |
|---|---|
| **封存／回復** | ✅ 夠 —— owner 的裁決逐字是「不會對外開放下載使用」 |
| **網站拿一顆 icon** | ⛔ **完全不夠** —— 要先把 49 段全下載、拼起來、解壓 |

⚠️ ⭐ 而 **S3 沒有任何大小限制逼你切段**（單物件上限 5 TB，multipart 是傳輸層的事）。
分段是從 git 的 100 MB 上限帶過來的習慣，⛔ **那個限制在 S3 上不存在**。

⇒ ⭐ **判準：讀到「已上傳」時，先問「它是一個物件，還是某個封存的成員？」**

## 四、可重跑（owner 的第 4 道界線）

> 「模型／動作／特效轉換要保留**可重跑腳本、依賴、參數、來源與輸出雜湊**」

| 腳本 | 做什麼 |
|---|---|
| `tools/asset-cdn/outputs/inventory_outputs.py` | 逐檔 sha256 ＋ 大小 ＋ mtime → `files.jsonl` |
| `tools/asset-cdn/outputs/reconcile_outputs.py` | 比對本機清單與 S3 → `coverage.jsonl` |
| `tools/asset-cdn/outputs/backup_outputs.py` | 打包 ＋ 分段 ＋ 上傳 ＋ 逐物件 GET 驗雜湊 |
| ⭐ `tools/asset-cdn/outputs_reconcile.py` | **本文件第二節那個陷阱的閘** —— 見下 |
| `tools/asset-cdn/upload.py` | repo 內 `content/assets/**` → `assets/` |

```bash
export AWS_PROFILE=vibe-coding          # ⛔ 不要用別的 profile,⛔ 不要手動注入金鑰

# ⭐ ① 驗每一個被引用的封存**真的在 S3 上**（⛔ 不是相信 coverage 那個欄位）
python3 tools/asset-cdn/outputs_reconcile.py verify-archives

# ⭐ ② 把「要對外服務」的那一團變成逐檔可定址（hardlink ⇒ 零複製,同 sha 自然去重）
python3 tools/asset-cdn/outputs_reconcile.py stage --under community-hero-asset-integration
python3 tools/asset-cdn/outputs_reconcile.py push            # dry-run
python3 tools/asset-cdn/outputs_reconcile.py push --apply

# ⭐ ③ 抽驗:**重新下載**再比 sha256（⛔ 不是「sync 沒報錯」）
python3 tools/asset-cdn/outputs_reconcile.py verify --under community-hero-asset-integration -n 12
```

⚠️ ⭐ **`verify` 這一支自己踩過一次量尺陷阱**：第一版用 `aws s3 cp … -` 把物件讀回來比對，
而 capture 是 **text 模式** ⇒ 遇到 png/glb/mp3 直接 `UnicodeDecodeError` 而死。
⇒ ⭐ 一律**落地成檔**再 hash。（同族前科：canvas 背後緩衝、`readPixels` 讀到上一幀。）

## 八、安全（⛔ 這幾條沒有例外）

- 一律 `AWS_PROFILE=vibe-coding`（AssumeRole 臨時憑證），region `ap-east-2`。
- 權限刻意只有 **ListBucket · GetObject · PutObject** —— ⭐ **沒有刪除**。
  遇到 `AccessDenied` ⇒ 那是**刻意的界線**：報出被拒的 action 與 resource，⛔ 不要想辦法繞過。
- ⛔ 不要讀／印／改 `~/.aws/credentials`，⛔ 不要建新憑證，⛔ 不要用別的 profile。
- 閘：`packages/shared/src/ops/noAwsKeysInRepo.test.ts`（掃 git 追蹤的文字檔找 `AKIA`／`ASIA`／憑證欄位）。
