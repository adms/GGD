# 英雄技能組・描述 vs 實作 對帳清單（#247）

> **工作單位是「整組技能」，不是單支技能。** 連段條件會引用兄弟技能 —— 例如蒼月潮 E 寫「在"者、皆、陣"發動後 1 秒內施展可增加傷害」，
> 那個條件同時牽涉 W 與 E 兩支。所以檢查、修正、測試都必須**整組一起做**，每個英雄一個核取方塊。

- 英雄 **114** 位（出貨名單內 **50**）
- **99** 位至少有一支技能的描述承諾了 `effects` 沒有實作的東西
- 判定＝描述關鍵字 × 該技能實際 `effects[].kind` 的落差。**這是初篩不是判決**：每一列都要再讀 JASS 確認原作到底做了什麼

## 缺口類型統計

| 缺口 | 英雄數 |
|---|---|
| 持續傷害 | 57 |
| 位移/跳躍 | 39 |
| 治療/吸血 | 29 |
| 召喚 | 26 |
| 暈眩/定身 | 18 |
| 無敵/免疫 | 18 |
| 護盾 | 17 |
| 擊退/擊飛 | 14 |
| 減速 | 7 |
| 反彈傷害 | 3 |
| 層數疊加 | 2 |
| 連段條件 | 1 |

## 檢查流程（每個英雄一輪）

1. 讀該英雄**六支**技能的描述與 `effects`，以及 JASS 裡對應 rawcode 的真實 handler
2. 判斷每個缺口是「原作真的有、匯入時弄丟」還是「描述誇大、原作也沒有」
3. 前者 → 補實作或補模擬器原語；後者 → **改描述**讓它不再說謊
4. 測試**整組**：連段條件要跨技能驗，不能單支綠就算過
5. 勾掉核取方塊，記錄結論
