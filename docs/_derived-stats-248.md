## 0. 一頁摘要

1. **AP 是唯一真正新增的軸。** `content/abilities` 裡 370 個 damage effect 有 **195 個（53%）掛著 `ap` 係數**，
   今天全部乘以 0。智慧落地後：等級 1、技能 1 級時每個 effect 中位 **+6.5%**、平均 +20.3%、最大 **+540%**；
   等級 18、技能滿級時中位 **+9.1%**、平均 +33%、單技能最高 **+1392%**。
2. **HP 的 0.80× 是真的，AD 的 1.80× 是假的。** 現行卡片的生命剛好是派生值的 **0.800×**（111 隻裡 92 隻分毫不差），
   因為匯入器公式本來就寫 `(hp + 25×力量) × 0.8`。但 AD 的實測比是 **1.03×（中位）／1.05×（平均）**，不是 1.80。
   1.80 這個數字是「把 null 當 0」那次錯誤讀法的殘留（同樣算法我複現出 1.53×），或是拿「只有骰子傷害、不含力量項」
   當分母（那會得到 2.67×）。
3. **×8 → ×4 是大幅超調。** 用 #153 的同一套 harness 實測：派生數值在**同一個倍率下 TTK 幾乎不變**
   （×8 時平均 132s → 145s，×1.09，落在雜訊內），因為 +25% 生命被 **+38% 攻速** 和 **−25% 護甲** 抵銷掉了。
   所以「派生 HP 比較高所以倍率減半」這個前提，對 HP 單項成立，對 **TTK 不成立**。
   ×4 會把決勝對局的中位數從 **117.5s 砍到 42.4s（×0.36）**，最快的對局從 33s 砍到 18s。
   **要維持今天的節奏，倍率該留在 ×7.5～×8.4，也就是 ×8 不要動。**
4. **maxHealth 只影響英雄，不影響小怪和守衛。** 兩者都直接寫 `world.health`，沒有 StatsComp/ChampionComp，
   所以倍率碰不到它們。#244 把小怪數值搬進 `arena-rules.json` 之後**確實隔離了小怪的 HP**，
   但那反而讓 ×8→×4 變成**單方面削弱玩家**：小怪和守衛的傷害是固定值，玩家有效血量掉到 0.63×，
   等於小怪與守衛的致命度 **×1.60**。

### 3.2 「0.80× HP / 1.80× AD」查證

| 說法 | 實測 | 判定 |
|---|---|---|
| 現行卡片 ≈ 派生 HP 的 **0.80×** | `current/derived` p10 **0.800** / 中位 **0.800** / p90 **0.800**，平均 0.796 | **完全正確，而且是精確值** |
| 現行卡片 ≈ 派生 AD 的 **1.80×** | `current/derived` p10 0.792 / 中位 **1.029** / p90 1.320，平均 1.048 | **錯**。AD 幾乎不動 |

HP 的 0.800 不是巧合：`tools/w3x-import/w3xlib/drafts.py::hero_to_champion` 的公式就是
`hp = (w3x_hp + 25·STR) × 0.8`。**111 隻裡有 92 隻分毫不差是 0.800×。**

剩下 19 隻不是 0.800×，而且原因很乾淨：**匯入器當年用的 STR 是錯的。**
把 `current_hp / 0.8 = w3x_hp + 25·STR` 反解回去，有 **20 隻**的隱含 STR 與解析出來的真值不同，
其中 13 隻是 `stock:` 繼承、5 隻是 `map:` 繼承 —— 正好就是解析器修好的那一類。最極端的幾筆：

| 英雄 | 匯入器用的 STR | 真值 | 來源 | HP 差 |
|---|---:|---:|---|---|
| `godie-ogld` 美白大法師-黑人牙膏 | 16 | **22** | stock:Ogld | 440 → 700 |
| `godie-h00l` 時空勇者-林克 | 18（預設值） | **24** | stock:Hmkg | 480 → 750 |
| `godie-h01n` / `h01o` 黑崎一護 ×2 | 18（預設值） | **24** | stock:Hmkg | 480 → 750 |
| `godie-usyl` 殺戮之牙-異形 | 14 | **18** | stock:Usyl | 400 → 600 |
| `godie-umal` 北斗神拳掌門人-拳四郎 | 24 | **20** | stock:Umal | 600 → 650 |

至於 1.80× 這個數字從哪來，我複現了兩種可能的錯誤讀法：

1.80 落在這兩者之間，不論是哪一種，**它都不是從已解析的三圍算出來的**。

## 5. TTK —— maxHealth ×8 → ×4 實際會發生什麼

### 5.1 方法（用 #153 的同一套，不是估的）

`tools/ttk-sim/src/ttk248.ts`（新增檔，只讀 content、不改 sim）：

* 重用 #153 harness 的原件：`loadRoster` / `pickChampions` / `MID_MATCH_GRANT`，同一個
  `MatchController` + `AIDriver`（Tier-0）+ 逐 tick 推進真實 `SimWorld`，
  回合結束的判定與伺服器完全相同（某一方在該區的存活數歸零的那一 tick）。
* **兩處刻意的差異，兩處都是為了更貼近今天的線上狀態：**
  1. **content tree 變成參數**，所以同一組對戰可以先用現行卡片打一次、再用派生卡片打一次（受控比較）。
     派生樹是 `content/` 的硬連結副本，champion 文件在寫入前先 `os.remove` 斷開連結 —— repo 的 `content/` 全程零改動（`git status` 乾淨）。
  2. **combat-env base 從目標樹的 `config/combat-env.json` 現讀**，而不是 harness.ts 裡手抄的 `COMBAT_ENV_BASE`。
     那個常數還寫著 `cooldown 0.25`（線上已經是 **0.2**），而且**完全沒有 `maxMana ×3` 和 `manaRegen ×4`** —— 兩者都直接影響技能使用頻率，也就直接影響 TTK。
     **這代表 `docs/_ttk-experiment-153.md` 與 `docs/_ttk-retune.md` 的數字對今天的線上設定已經失效**（它們還假設 `damageDealt 0.5`，線上早就回到 1.0）。
* 對戰組合是 match seed 的純函數，與 content tree 和 maxHealth 都無關 → 每一格打的是**完全相同的對局**。
* 樣本：每格 60 場 × 2 個對戰區 = **120 個 duel**。`natural` = 火圈關閉（純淘汰 TTK，也是回合長度的下限）；
  `production` = 火圈照 `#195` 的真實排程（60s 起、20s 收縮）。
* 停滯率兩棵樹、每個倍率都是 50%，這是 #153 就記錄過的 Tier-0 對耗特性，不是新的瑕疵
  （我另外驗過：兩個區各自約一半決勝，不是某一區結構性卡住）。

### 5.2 natural 模式（火圈關閉）— 決勝對局秒數 min / p10 / 中位 / 平均

| maxHealth | 現行卡片 | 派生卡片 | 平均比 |
|---:|---|---|---:|
| ×2 | 8 / 11 / 16 / 18 | 9 / 12 / 19 / 20 | ×1.14 |
| ×3 | 11 / 15 / 24 / 29 | 14 / 19 / 29 / 33 | ×1.14 |
| **×4** | 18 / 24 / 37 / 44 | **18 / 28 / 42 / 54** | ×1.24 |
| ×5 | 21 / 35 / 55 / 62 | 24 / 37 / 59 / 70 | ×1.12 |
| ×6 | 25 / 41 / 73 / 88 | 33 / 51 / 78 / 98 | ×1.11 |
| **×8**（今天） | **33 / 68 / 118 / 132** | 52 / 68 / 113 / 145 | ×1.09 |
| ×10 | 50 / 89 / 160 / 174 | 67 / 96 / 136 / 162 | ×0.93 |
| ×12 | 70 / 124 / 194 / 207 | 80 / 122 / 190 / 219 | ×1.06 |

**第一個、也是最重要的讀數：同一個倍率下，派生卡片與現行卡片的 TTK 幾乎一樣**（平均比 0.93～1.24，中位 1.11）。
+25% 生命被 **+38% 攻速**（自動攻擊 DPS ×1.30）和 **−25% 護甲** 抵銷掉了。
**派生本身沒有讓英雄變耐打。** 「派生 HP 比較高，所以倍率要減半」這個推論對 HP 欄位成立，對回合長度不成立。

### 5.3 ×4 實際交付的東西

| 指標（natural） | 今天（現行 ×8） | 派生 ×4 | 比 | 派生 ×8 會是 |
|---|---:|---:|---:|---:|

| p10（穩健的「短回合」） | 68.3s | **27.8s** | **×0.41** | 67.7s |

**要維持今天的回合長度，派生卡片需要的 maxHealth：**

| 對齊哪個指標 | 需要的倍率 |
|---|---:|
| 今天的 min（33.2s） | ×5.97 |
| 今天的 p10（68.3s） | **×8.05** |

| 今天的平均（132.4s） | **×7.47** |

### 5.4 production 模式（火圈開著）— 為什麼「感覺沒差」是個陷阱

| maxHealth | 現行 回合平均 / 中位 | 派生 回合平均 / 中位 |
|---:|---|---|
| ×4 | 139.9s / 152.8s | 142.4s / 154.5s |
| ×8 | 153.6s / 158.4s | 154.2s / 158.7s |

火圈從第 60 秒起就開始收縮，所以**回合長度**幾乎被火圈綁死：×8→×4 只讓平均回合從 153.6s 掉到 142.4s（−7%）。
如果只看這一欄，會得出「×4 沒差」的錯誤結論。
真正變的是**能靠戰鬥分勝負的那些對局**：中位 117.5s → 42.4s。
換句話說，×4 不會讓回合變短多少，但會讓**「打贏」變成「秒殺」**，而且把更多回合推給火圈去收尾。

### 5.5 順帶查到的、與 #248 無關的既有落差

用今天真正上線的 combat-env（cooldown 0.2 / damageDealt 1.0 / maxMana ×3 / manaRegen ×4）量測，
**現行卡片在 ×8 就已經達不到 #153 當初訂的驗收目標**（p10 ≥ 120s、平均 150–190s）：

| | p10 ≥ 120s 需要 | 平均 150s 需要 | 平均 180s 需要 |
|---|---:|---:|---:|
| 現行卡片 | ×11.77 | ×8.84 | ×10.35 |
| 派生卡片 | ×11.86 | ×8.63 | ×10.64 |

這是 combat-env 從 #153/#169 之後漂移造成的（cooldown 0.25→0.2 讓技能頻率 +25%，damageDealt 0.5→1.0 讓傷害翻倍），
**跟這次的三圍派生無關**。要不要把倍率往上調回 #153 的目標區間，是一個獨立的決定 —— 但無論如何，方向都是**往上**，不是往下。

## 6. ×8 → ×4 的波及範圍

`maxHealth` 只在 `statPipeline.recomputeStats` 一個地方生效（`STAT_ENV_KEY[MaxHealth]`），
而那個函式的第一行就是 `if (!sc || !champ) return;` —— **沒有 StatsComp 或 ChampionComp 的實體完全碰不到。**

| 對象 | 會被 ×8→×4 影響嗎 | 依據 |
|---|---|---|
| 英雄（座位） | **會**，有效血量 ×0.625 | 唯一同時有 stats + champion 的實體 |
| 肉鴿小怪（#215/#244） | **不會** | `spawnMob` 直接寫 `world.health`，原始碼註解寫明「NO ChampionComp / seat / StatsComp」 |
| 競技場守衛（#89/#105） | **不會** | `spawnGuardian` 直接寫 `world.health`，「NO TeamComp / nav / stats / champion」 |
| 治療花 | 自動跟隨 | `chp.maxHp × healPctMax`，是百分比 |
| 火圈燒傷 | 自動跟隨 | `burnPctPerSec*` 是百分比 |
| 復活圈 | 自動跟隨 | `reviveHpPctMax 0.5` 是百分比 |
| 裝備的 flat maxHealth | **會**（跟著英雄一起縮） | flat 加總後才乘系統倍率 |

### 6.1 小怪：#244 確實隔離了，但那正是問題所在

`mobRulesFromConfig` 的 tier 1 分支：只要 `arena-rules.json` 的 `mob.baseHp` 存在（今天是 100），
小怪的血量曲線就完全由小怪卡片決定，**根本不看 `godie-zombiex` 的英雄卡**。所以：

* 小怪血量：第 3 場 300、第 5 場 500、第 8 場 800 —— **×8→×4 一點都不動**。
* 玩家打死一隻小怪的時間：**不變**（小怪血量不動，玩家傷害幾乎不動）。
* 小怪打死玩家的時間：**縮短 37%**。一隻小怪的 12 傷害 / 1.0s，對上 6 級中位英雄的有效血量
  5,280 → 3,300，理論擊殺時間 440s → 275s。每區上限 30 隻。

**結論：#244 的隔離讓小怪的絕對難度不動，但把 ×8→×4 變成單方面對玩家的削弱 —— 小怪的相對威脅 ×1.60。**
如果要動倍率，`arena-rules.json` 的 `mobWaves.mob.attackDamage`（12）必須同步下修，否則第 3 場之後的肉鴿波會明顯變凶。

### 6.2 守衛：同一個道理

* 守衛血量 `1450 × (1 + 0.28×(round−1))`（第 6 場 3480）—— **不動**。玩家推塔時間不變。
* 守衛的齊射傷害 `108` 是**固定值**（每場 +14%，可 ramp 到 ×2.0，一次 3 個標記、每 4 秒一輪）
  → 對玩家的致命度 **×1.60**。
* 守衛自己的抗爆上限 `maxHitPctMaxHp 0.15` 是「守衛自己最大血量的百分比」，不受影響。
* `rewardGold 150` / `restoreHpPct 1.0` 都是百分比或固定值，行為不變。

### 6.3 裝備經濟

flat `maxHealth` 詞條跟著英雄一起被乘上系統倍率，flat `ad`/`ap` 詞條不會。
所以倍率一減半，**血量裝相對於傷害裝直接弱化 37%**，`packages/shared/src/sim/economy/itemTiers.ts`
註解裡記的「eHP 上限 2.34×」那條平衡也會跟著失準。這一項不需要 owner 決定，但要記得它會跟著動。
