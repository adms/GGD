## #68 — per-clip orientation (no clip renders tilted / face-down)

Root cause: a subset of WC3-imported rigs bake a root-bone rotation that DIFFERS between clips (heropikachu Stand 99.7° vs Attack 0°), so no single scene transform can correct it (docs/todo/intermission.md #111). The bind pose is upright (identity) and the attack/death clips confirm 0° = upright, so `fix_clip_orientation.py` RE-GROUNDS each defective clip: it left-multiplies the root-bone rotation channel by inverse(frame0), making frame 0 upright and preserving any intra-clip motion. Only ANIMATION samplers are rewritten (fresh appended accessors), so geometry/bind-pose/scale — and the frozen bbox fixtures — are untouched.

**19 models, 26 clips re-grounded → all now start ≤15° from upright.** Two waves: idle/run/hurt clips ≥45° off (face-down resting/walking) and attack/cast clips ≥90° off (inverted swings/casts). death is left alone (it legitimately falls); borderline 47–74° attack/cast leans are left as intentional lunges.

## #73 — stray attachment geometry sweep (sphere/orb / team-glow)

Sweeping EVERY champion model, the un-merged 'sphere/orb attachment' family the 孫悟空 case belongs to is dominated by ONE pervasive stray: a WC3 team-colour GROUND BILLBOARD baked into the mesh as a low, wide, alpha-blended quad (`TeamGlow*` material). The client already draws its OWN team read (`ChampionView` ring + blob shadow), so the baked billboard is redundant and tints a neutral colour under the feet that does not match the assigned team. `strip_teamglow.py` removes it from all **36** models that carry one (these quads are low+wide, never defining full-bbox top/bottom, so the frozen bbox/scale fixtures stay valid).

**De-glowed (36):** `cloud`, `fox`, `fox2`, `goku`, `herobiggon`, `herobuu`, `herogirl`, `herohanzouhattori`, `herohehi`, `herohimurakenshin`, `heroichigo`, `herokunoichi`, `herokyo`, `herolight`, `herolingtong`, `heromusashimiyamoto`, `herooichi`, `heropikachu`, `herorider`, `herosaber`, `herosasuke`, `herosephiroth`, `heroshana`, `herotoshiiemaeda`, `heroxelloss`, `kikyou`, `linainvers`, `long`, `lubu`, `luffe`, `mfls`, `negi`, `rabbit`, `sesshomaru`, `ye-wuqi1`, `zy3`.

After the strip, the meshes still flagged by the footprint heuristic are all OPAQUE equipment correctly kept — Cloud's Buster Sword, Saber's Excalibur, linkstik's cap, sephiroth's Masamune, hats/sashes — matching the mdl-07 'weapons kept' policy. No effect-orb stray remains on any champion model.

**孫悟空 / imported.goku (headless):** the shipped body glb DOES carry head-region geometry (mesh_primitive0 crowns at y≈1.70 + a 37-vert cap mesh_primitive1 at 1.60–1.74); it also carried a `TeamGlow2` orb at the feet (now stripped). The separate `gokuhead.glb`/`goku3head.glb` are the ability-transform (Super-Saiyan) heads and are intentionally NOT merged into the base body. So goku is not headless in the shipped model; if it still reads headless in-engine, the remaining work is a head-attachment MERGE (heavier geometry surgery), flagged here rather than done blind.

## #61 — flying / sinking (grounding)

The in-arena `ChampionView` applied only scale + yaw to the loaded glb — no grounding — so a rig whose baked feet sit off the origin floated or sank: `imported.ma` floated **+0.72u**, `imported.picacugy` (−0.58) and `imported.gumdam` (−0.59) were half-buried, `imported.herofate` floated +0.17. `ChampionView.tryUpgradeToGlb` now lifts every model so its lowest vertex lands on the floor (`glbRoot.position.y = -min.y`) — the SAME shift `StorePreview` (#129) and the intermission mount (#111 int-32) already apply, ported to the arena view. Uniform for all champions (feet-at-0 models shift 0).

## #77 — stand-in fallback preserves the declared model + scale

A stand-in champion shares one of four CC0 meshes via its `modelKey`, so the shared `model@1` doc (keyed only by modelKey) cannot give it the SIZE the map declared — 小叮噹/哆啦A夢 (`godie-n00b`) should render at ~0.6 scale, not the shared mage's 0.77, and 18 champions on `champ.sela` otherwise render identically sized (docs/_suspicious-verification-list.md).

Render mechanism added (owned files only):
- `EntityViewRegistry` gains an optional `modelOverrideFor(e)` hook + `applyModelOverride(doc, override)`, applied to the resolved doc BEFORE the glb is adopted, so the fallback preserves a per-champion `{scale, glbPath?, clipMap?}` instead of the shared stand-in size.
- `ChampionView` now exposes `declaredScale` and never silently substitutes a default — the generic voxel stands in only when there is genuinely no renderable model.
- `content/models/_standin-overrides.json` (owned data) declares the override: `godie-n00b` → `scale 0.6`.

**Integration boundary:** the championId needed to key the override lives behind the seat table that `render/**` is walled off from (client-08), so the composition root `GameApp.modelDocFor`/a new `modelOverrideFor` must read `_standin-overrides.json` and feed the hook (one method — `GameApp.ts` is outside this wave's owned set). A dedicated blue-cat/panda MESH for Doraemon likewise needs a new authored asset; the mechanism swaps it in via `glbPath` with no champion-doc change.
